# KNOT VIEW / PYAT RECEIVING CONTRACT — SOURCE-GRADED, NO SECOND ATLAS
**Companion to [04_POST_ZL_RECOVERED_MACHINE_TO_PYAT_KNOT_SEQUENCE.md](04_POST_ZL_RECOVERED_MACHINE_TO_PYAT_KNOT_SEQUENCE.md).** New schemas below are **noncanonical projections/recipient decisions** from existing VMESTYE DATA and actual recovery sources, not a new accepted independent history, not a new programme law, and not a physical engineering blueprint.

## A. Minimal user-facing deliverables

1. **`RECOVERED_INTEGRATED_MACHINE.md`** — a source-qualified, human-readable explanation **by substantive knowledge-producing path**, not by folder or S-stage. Includes branched diagrams/cold links, historical original→recovery campaigns→modern relevance, and one specific information gain/loss or open proof per edge. Paths with no proven original execution are explicitly described as intended/source-located.
2. **`RECOVERED_KNOWLEDGE_PATHS.tsv`** — source-joinable many-to-many *view*: one path of transformations/branch diamonds and actual knowledge effects, built from canonical `FUNCTION_ATLAS/OPERATION_TRACES/RELATIONS/EVIDENCE/AUTHORITY_APPLICATIONS/CONSUMER_EDGES` and accepted immutable recovery returns. A path ID is not a new historical T.
3. **`PYAT_CAPABILITY_CONSERVATION_ROSTER.tsv`** — one historically substantive recovered *capability* or capability family, with source, stages, intended effect, modern specification consideration, stronger composed successors and owner. A capability can appear in multiple paths; one path can support multiple capabilities. `PYAT_REQUIREMENT_NOT_ACCOUNTED_CANDIDATE` is a **question for PYAT HQ**, not an adopted Sxx child or BUILD authorization.
4. **`PYAT_REQUIREMENT_IMPLEMENTATION_DELTA.tsv`** — **PYAT HQ-owned** separate incoming row for each roster finding, with two independent decisions: specification preservation and current implementation/first-reader qualification. Complies with existing five-test historical-succession work-selection law.
5. **`PYAT_OWNER_RECEIVING_AND_DECISIONS.md`** — actual competent owner accepts/holds/declines at pinned SHAs and maps approved requirement changes into existing S01–S11 sections/owner records. No scientist/actor/source issuer rights presumed.

**Storage:** The first three are **documentary derived views** owned by existing VMESTYE #814 custody *after* actual qualified #817 handoff; their source-of-truth IDs remain in the canonical VMESTYE atlas. Put resulting files under a clearly versioned `PRONGS/J_JOIN/POST_ZL_PYAT_KNOT_R1/` within the **existing** VMESTYE base folder on a named noncolliding, reviewable draft branch/PR, or a documented alternative under the existing sole #814 integrator custody. Never write to protected or to another agent's branch. The last two live with **existing PYAT HQ/PROGRAMMA governing owner** on an appropriate owner-controlled documentary branch/PR under its `PYAT_CONTROL_ROOM/PROGRAMMA_PYAT/05_ROADMAP/` context; those records reference but do not supplant VMESTYE. The `UNIFIED_LOG_R1/VMESTYE_CLOSURE_AB_R2/SHARED/` index holds **pointers**, not their canonical full contents.

## B. Literal header for `RECOVERED_KNOWLEDGE_PATHS.tsv`

```tsv

```

**Path semantics:**
- `ordered_ops_and_edges` is an **edge list** with typed `MUST|IF|ALTERNATE|BRANCH|JOIN` and stable old `OP`/VMESTYE relation IDs, NOT a false mandatory serial pipeline.
- `with_parallel_branch_ids` and `rejoin_condition_and_result` distinguish ordinary/J streams and what their composition created; a branch reference does not prove a meaningful consumed value.
- `information_into_each_edge`/`information_out_and_distinctions_lost` should be grounded by detailed human case, not prose like "all knowledge retained." Explicit respondent membership, category/indicator, branch node, weights/denominator, selected rule, time and status when relevant.
- `shared_compute_substrate_ids` can reference one old prepared-country/mask/data object reused by many paths; source-grade the actual economic effect, no unsupported old-vs-new benchmark ratio.
- `new_knowledge_produced` is what downstream stage could learn/select/qualify that a preceding isolated operation could not; state whether seen in code/output or only intended.
- Positive absence of a named old actual reader is `OLD_READER_UNPROVED`, never proof that a produced scientific result was useless or absent.

## D. Literal header for `PYAT_REQUIREMENT_IMPLEMENTATION_DELTA.tsv` — only PYAT HQ/owner writes decisions

```tsv

```

**Two courts, no shortcut:**
1. `SPECIFICATION`: necessity in the chosen Rawlsing design, the recovered distinct meaningful capability, stronger lawful composed alternatives, deliberate retirement/contradiction, new/updated requirement and actual selected Pyat owner. This court can say **specification omission candidate supported** without concluding it is accepted new law.
2. `IMPLEMENTATION`: protected/candidate actual implementation, real chosen source/rule/negative application, first consumer/knowledge outcome and runtime science/authority grade, including whether test-only or native. A roadmap sentence is **not** an operation; a schema-ref is not an applied authority; static callsite is not executed effect.

`historical_work_selection_tests_1_to_5` must **individually** evaluate (i) current necessity, (ii) no adequate same-or-stronger composed successor, (iii) real planned/current consumer, (iv) science/source/physical constraints, (v) reuse/adapt/compose/repair/build/hold/no-action comparative gain. Blank/unproved test→`COMPARE_ONLY_UNKNOWN/OWNER_DECIDE`, not BUILD.

## F. Four hostile acceptance tests, not new omnibus archaeological demands

1. **Reversed filter test:** choose one source-grounded original/recovery capability lacking a modern S01–S11 heading. Does the roster record it with source and potential purpose anyway, and route a requirement-owner decision? If omitted, fail.
2. **Compositional-loss test:** replace an effect-bearing V550/J→V551/J→V552/J join with a mere schema/reference edge. Does the handoff *reject* the claim of scientific/functional conservation until actual meaning is consumed? If not, fail.
3. **Representation-retirement test:** replace the original lossy attitude-cloud carrier with a better source-qualified modern representation preserving true same-person clouds. Does the handoff allow this replacement without mandating legacy data layout, while still demanding member-level capability proof? If not, fail.
4. **Computational-economy test:** claim source/wave/country prepared-population reusable across 100 distinct operations merely because caching code exists. Does the owner receipt demand source/rights/denominator/weights and material cost equivalence evidence before an optimization claim, while preserving historical reuse as valuable capital? If not, fail.

**Further omission challenge:** an independent examiner selects unexpected recovery-era output and traces it into a produced downstream knowledge claim; a second begins at an actual Pyat consumer and traces source/authority/backward old capability, or records genuine `CURRENT_ONLY_EXTENSION`. At a qualified pinned corpus, every genuinely omitted substantive path becomes a versioned delta and only affected countersearch reopens; source-native evidence absence does not mandate global archive restart.

## G. Material repair/stop rule

For each historical lookup request supply `exact_missing_item + known_search_boundaries + two distinct recovered-capability/Pyat-owner decisions it can change + minimal search + owner`. If no materially distinguishable decision exists, mark `NO_FURTHER_UNBOUNDED_RECOVERY_JUSTIFIED_AT_THIS_CUT` at qualified source scope and route other proof to its actual owner. A single 404 must trigger same-semantic-source alternatives and bounded cross-branch search, never global absence.

No self-acceptance, no rewriting original accepted prongs, no automatic authority promotion. This contract is a **usable exact source-graded handoff view**, not new adopted law or a request to build old DDM file formats.
