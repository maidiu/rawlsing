# HQR-20261112-R3S — MANDATORY STOP-AND-ADVANCE RULE (ANTI-HARDENING)

**Controlling correction to R3/R3C. This is a restriction on what the A/B workers MAY do, not a sixth acceptance gate, new commission, new code-hardening project, or permission to expand any packet.** The user's objective is completion of the specified machine, not indefinite improvement of each component.

## 1. FINISH IS A TERMINAL PREDICATE
A packet is **READY_FOR_RECEIVING** immediately when (a) its frozen, packet-specific mandatory G1–G4 and positive/negative/restoration cases pass at the legitimately available evidence grade, (b) the original contract's in-scope accepted functionality is preserved, and (c) there is no **reproducible in-scope SEV-0/1/2 failure**. At that instant the pair **MUST STOP CODING ON THAT PACKET AND SUBMIT THE FROZEN HEAD FOR NONAUTHOR G5**. No extra "just in case" tests, extra defensive wrappers, refactors, API polishing, broad compatibility surveys, generalized abstractions or performance pursuits outside the numeric/resource gates. A missing *external* scientific/issuer/host input is logged as HOLD, not used to invent additional code.

Upon actual independent `ACCEPT_SCOPED` or `ALREADY_SATISFIED`, that packet becomes **TERMINAL_CLOSED at exact SHA + grade**. **STOP means STOP: no further edits, iterative rounds, new "hardening" PR, or self-issued subcommission on that packet.** Advance to the next queued dependency-ready packet. Protected merge/integration remains a **separate** received process; no reopened pair work merely to improve a finished artifact.

## 2. FROZEN ACCEPTANCE UNIVERSE — NOT A GROWING WISH LIST
Before A writes, freeze: packet ID/old IDs, permitted sourcefree grade, owned files and changed-entry owner, exact selected first consumer, mandatory positive/negative/restore case IDs, existing regression tests, applicable resource/size ceiling and mandatory HOLDs. This is the closed acceptance universe. The G1–G5 checklist embedded in each commission is part of it.

No new requirement/test/optimization may be promoted to **mandatory** during the duel merely because an agent can imagine it. A new case is admissible ONLY when it includes (i) **an executed or minimally executable reproducible counterexample** showing (ii) breach of an **already-frozen requirement** at (iii) a real selected owner/first consumer, with expected/actual/result and legitimate evidence grade. A reviewer must apply the SAME rule. "Could be safer", "might scale better", "needs more hardening", "cleaner API", "potential future use", model-only conjecture, wider original35/actor science and unrelated technical debt are **not** completion blockers. Record optional ideas as **NONBLOCKING_DEFERRED** only, without implementing them or adding them to the task's finish criteria. A novel in-scope concrete regression is legitimate; a novel goal is not.

The existing required **6 GiB**/100k test is **not** optional hardening once its specifically designated integrated physical gate is reached. It must not be retroactively imposed upon each small sourcefree task that cannot produce the integrated artifact. Conversely, no resource threshold beyond an existing authorized budget can be invented to prolong the duel.

## 3. MAXIMUM UNREVIEWED DUEL
**A implementation → B independently attacks/repairs → A one counterattack** is the normal maximum before a forced disposition. At that point:
- All frozen G1–G4/cases green and no reproduced in-scope material defect → **immediately freeze and submit G5**.
- Specific reproduced in-scope SEV-0/1/2 failure → **one bounded repair+retest**, with defect ID and actual first-reader consequence; then mandatory nonauthor receiving or HQ adjudication of the *exact* unresolved defect. There is no permission for a third broad A/B exploration cycle.
- Missing competent external evidence/permission → **HOLD_EXTERNAL** for that grade; submit the finished lower-grade implementation for G5 if it passes and move onward. Never "harden" around absence of an issuer.
- Ownership/lease collision → **BLOCKED_OWNERSHIP**, no code mutation, move to independent eligible work or seek owner ruling.

An independent reviewer can require work **only** by writing `REVISE_EXACT_DEFECT` with a reproducible in-scope failing case tied to one frozen obligation; author repairs **that case only**, then refreezes and re-receives. Reviewer cannot demand aesthetic hardening, a new generalized service or expanded proof tier as a condition of accepted scoped completion.

## 4. MINIMAL CLOSURE RECEIPT
Every packet's existing machine-readable receipt must explicitly record:
- `contract_frozen_at_sha`, `mandatory_case_ids`, `mandatory_case_results`, `first_consumer_proof`, `material_open_defects`, `external_holds`, `evidence_grade`, `independent_receiver_decision`, `integration_state`.
- `stop_state`: `IMPLEMENT | READY_FOR_RECEIVING | TERMINAL_CLOSED | HOLD_EXTERNAL | BLOCKED_OWNERSHIP | REVISE_EXACT_DEFECT`.
- `nonblocking_deferred` suggestions may be logged but **do not create work** and **cannot prevent STOP**.
- If a packet is `TERMINAL_CLOSED`, any proposed further work needs a **new demonstrated breach of a previously accepted invariant** or a **distinct subsequently authorized product requirement**; neither can be self-commissioned by A/B, and neither retroactively invalidates a correctly scoped earlier acceptance without independent proof.

## 5. COMPLETION IS NOT MORE HARDENING
`NO_IN_SCOPE_FAILURE + ALL_APPLICABLE_FROZEN_CASES_PASS + INDEPENDENT_ACCEPTANCE = FINISHED_AT_GRADE`.

For conditional packet: `NOT_DEMANDED_PROVED` is terminal for that selected scope; the broader conditional obligation remains open **only if later truly selected**. For externally blocked grade: a sourcefree `ACCEPT_SCOPED` and an explicit native `HOLD_EXTERNAL` are compatible and sufficient to **stop the engineering pair**. Do not spin waiting for original source/actor science.

This applies to **all twenty task sections in #918, #919 and #920** and supersedes any wording ("hardening", "improve until", "no feasible consequential defect remains") that might be read as indefinite permission. **A stop-rule violation is an out-of-scope commission failure, not evidence of diligence.**
