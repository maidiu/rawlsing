# VMESTYE / ZAKONCHILOS — Unified Functional Reconnaissance Logging Standard R1

**Purpose:** Give every ZAK/VMESTYE reconnaissance worker the *same evidentiary grammar*, so that independent discoveries can be joined by stable IDs and evidence references without a later exercise in reconstructing what each worker meant. This is a **logging and reporting standard**, not new program law, an expansion of any frozen commission, permission to engineer, or an assertion that the historical estate has already been exhaustively inventoried.

**Priority requirements:** (1) provenance, (2) future utility, (3) navigability, (4) comprehensibility, and (5) comprehensiveness. All five are acceptance conditions; a verbose narrative without auditable rows, or a row count without substantive explanation, fails.

### Five independent quality gates

| Goal | A return is usable only if… | Typical failure |
|---|---|---|
| **Provenance** | Each meaningful old/new transformation, status, absence, negative and first-consumer claim has its own pinned evidence ID, exact source or observed execution, provenance/version and proof ceiling. | One bibliography covering many unsupported rows. |
| **Future utility** | The record tells a later competent owner what historically valuable code/knowledge can be reused, under which rights and interfaces, what has already been proved, what would falsify the claimed successor, and what exact bounded decision remains. | A past-tense archaeological essay that offers no actionable, lawful successor information. |
| **Navigability** | One can enter by an old function ID, an old code artifact, a source/rule, a modern component, an output or a first reader and follow stable links in either direction without rediscovering sources. | Separate free-form reports with no common ID/edge schema. |
| **Comprehensibility** | A newcomer can read an isolated case and understand the incoming data shape, operations and conditions, outgoing data shape and why anyone needed the result, including concrete example and changed mechanisms. | “Equivalent module exists” or “guard present” without a real data journey. |
| **Comprehensiveness** | The worker proves coverage of its **stated two-axis territory** and declared accessible historical search estate, with per-T×applicable-domain cells, independent omitted-function challenge, exact unsearched/held strata and no-drop identity accounting. | “17/17 traces” mistaken for “all historical functions discovered and reconciled.” |

**Source compatibility:** Use the adopted VMESTYE nine-file prong return interface (`00_RETURN.md`, `HUMAN_STORY.md`, `FINDINGS.tsv`, `OPERATION_TRACES.tsv`, `AUTHORITY_USE.tsv`, `EVIDENCE.tsv`, `COVERAGE.tsv`, `UNJOINS.tsv`, `CHANGED_FILES.txt`) and its principle that only the authorized ZL-15 integrator proposes central atlas dispositions, independently received. This R1 specifies four supplementary cross-agent registers: `MECHANISM_RECONCILIATION.tsv`, `SOURCE_SEARCH_LOG.tsv`, `REVERSE_CONSUMERS.tsv`, and `DATA_SHAPES.tsv`; plus `SCOPE_CONTRACT.md` and one `CASES/<case-id>.md` per substantive historical function. Do **not** overwrite protected VMESTYE files or silently replace an already-adopted TSV header: if that prong has a frozen schema, export these as a uniform `UNIFIED_LOG_R1/` sidecar with a documented field mapping. A technical import is still necessary; a new semantic reinterpretation should not be.

**Methodological source:** VMESTYE 00–14 and its evidence/closure laws at protected PRE-MAIN `6a5c12f04323d74001f9632063ec907f4fc4468e`; ZAK-00's original source/authority/effect and secondary functional-capital duties; *draft, unmerged* DDM VOSKRES PR #1039's original-first V540–V553 T/S/M and recursive omitted-function challenge. PR #1039 informs this recording method, but does not itself amend binding ZAK or VMESTYE ownership. All source cuts must be refreshed when research resumes.

## 1. Non-negotiable unit of truth

The atomic intellectual unit is **one historically substantive capability** (T), not one Python function, one PR, one file, one modern roadmap component, or one passing test. Under each T, identify *individually meaningful mechanisms/conditions* (S or M) and their distinct positive, negative and conditional outcomes. Preserve an original operation's output **as knowledge**, including what it made learnable, selectable, decidable or consumable.

For every T, the required human-readable proposition is:

> In historical generation **H**, capability **T** received **input shape X** (source, keys, respondent/universe, value/status/authority). It executed **operations C, D, E**, with precise predicates and negative paths, producing **output shape Y**, which **reader R** used **so that purpose P** was possible. During **Vozhd / Verkhovod / Dva / Trii / Chetiri / Long Memory**, these operations were **retained, refined, split, composed, rejected, superseded, stranded or unresolved** in exact places. Today, **modern modules I, J, K** receive **shapes M, N**, execute **operations Q, S**, emit **shapes U, V** to **actual reader W**. Mechanism **C** is [qualified status] for [specific reasons], **D** is [status] because [specific semantic difference], and **E** is [status]. The evidence is [claim-specific IDs and immutable references]; the earliest still-unproved edge and discriminating question are [exactly specified].

If the old function has no known present owner, record it anyway. **Do not use the modern roadmap as a filter on what historical functionality deserves discovery.**

### 1A. Three classes (T / S / M)

| Class | Log as | Coverage law |
|---|---|---|
| **T — substantive function / knowledge-producing transformation** | Stable `T_ID`, one case, old input→meaningful operation→output→first reader→purpose | Exhaustive discovery/accounting within *assigned historical estate*, with applicable-domain intermediate and current matrix |
| **S — meaning-bearing semantic rule/invariant/mechanism** | Child `S_ID` linked to T(s): exact selection, denominator, routing, identity, missingness, rank/stop, permission/refusal, branch | Thorough within affected T and real consumer paths; promote to T if it independently changed knowledge, selection, decisions, outputs or downstream capability |
| **M — implementation/computational mechanism** | Child `M_ID` linked to T/S: cache, batching, Parquet layout, index, codec, runtime sharing | Record its enabling role and actual cost/correctness evidence; investigate successor only where it changes distinct capability, meaning, fidelity, safety or economically consequential throughput |

Never multiply all minor M mechanisms by every unrelated historical branch. Never disguise an independent old analytical capability as an M merely to reduce scope.

## 2. Before any substantive case: publish an explicit scope contract

`SCOPE_CONTRACT.md` must state the worker's **two independently specified scope axes**:

**Historical axis:** `NAMED_SET` (list every assigned T/obligation and source set); `ALL_APPLICABLE_TO_MODERN_TERRITORY` (open discovery from source/output/consumer evidence, not a pre-enumerated function list); or `WHOLE_ASSIGNED_ORIGINAL_ESTATE` (declare the actual bounded branches, versions, code/output/register sources). Do not claim historical `ALL` because all *known* cases were examined.

**Modern axis:** `NAMED_COMPONENTS`, `DEFINED_PIPELINE_REGION`, or `ALL_RELEVANT_CURRENT_DOMAINS`. Give exact owner/roadmap/consumer IDs and the **entry, exit and IF/ALTERNATE boundaries**. Boundary-crossing functionality is logged and referred to the actual adjacent owner, not silently dropped or claimed as yours.

State exact original-version scope (including pre-Vozhd where applicable), declared Vozhd/Verkhovod/Dva/Trii/Chetiri/Long Memory strata, current protected and candidate cuts, existing inherited registers, original commission/obligation IDs, excluded strata with evidence, overlaps with other workers, named independent reviewer, available tool/host/rights and **engineering restrictions**. Every scope change is a versioned amendment with reason and affected coverage cells.

**Assignment sentence (mandatory):**

> I was assigned **[historical axis + denominator/discovery rule]** against **[modern axis and precise boundaries]**. I am **not** claiming **[explicit excluded or shared territories]**. The number of discovered historical functions is **[T count]**, and the number of assigned historical functions is **[known finite denominator or OPEN DISCOVERY—NOT YET CLOSED]**.

Do not let a worker's own convenient seven examples become its denominator. For an open historical axis, use a **declared finite source/corpus/branch search estate**, source-discovery log and independent omitted-function challenge. A worker may close its assigned inquiry with precisely typed unresolved evidence, but not assert that it has exhaustively *discovered* functions without a warranted source-universe closure.

## 3. Original-first and bidirectional completeness

**Stage 0 — original:** Reconstruct the old V540–V553 ordinary/J and pertinent predecessors, input/output contracts, what knowledge was produced, operative algorithms, selects/branches/stops, source rights, downstream consumers and historical execution grade. Draw on prior VMESTYE/Long Memory/VMC-T1/ZAK records as **seeds, not a proof of an exhaustive original function list**.

**Stage 1 — historical successors:** For each T, search the applicable distinct successor domains—**pre-Vozhd, Vozhd, Vozhd Verkhovod/Verkhovod, Dva, Trii, Chetiri, Long Memory, and any other evidenced branches**. Each relevant T×domain cell records `FOUND`, bounded `NOT_FOUND`, `UNRESOLVED`, `NOT_INSPECTED`, or justified `NOT_APPLICABLE_DOMAIN` with a search receipt. A `FOUND` locator is not yet a behavioral-success verdict. Revisit Stage 0 after successor searches to discover originally missed capabilities. Add new T IDs with provenance; reopen affected cells.

**Stage 2 — current:** Compare each T to relevant PYAT/PROGRAMMA/S/W/October 28/current code/branch domains and actual terminal/first consumers. Do not treat roadmap presence as code proof, sourcefree as original-native, or historical source files still being present as active current succession. Revisit Stage 0 to attack omissions; reopen both Stage 1 and Stage 2 cells if new old functions appear.

**Stage 3 — dispositions:** For *each original T*, distinguish `RESTORED_AND_IMPLEMENTED`, `FULLY_PRESENT_IN_PLAN_BUT_NOT_IMPLEMENTED`, `SUPERSEDED` (with actual equal-or-stronger effect), `CONCERTED_RETIREMENT_PURPOSE_FULFILLED`, `CONCERTED_RETIREMENT_PURPOSE_PLANNED`, `PARTIAL`, `OPEN_FUNCTIONAL_GAP`, `OPEN_PROOF_GAP`, `STRANDED_CANDIDATE`, `OUTSIDE_OWNER_WITH_RECIPIENT`, or `DISPOSITION_UNRESOLVED`. These are **research descriptors**, not automatic replacements for VMESTYE's adopted ten statuses or Authority39's six terminal LMX classes; explicitly supply the permitted canonical mapping when proposing central receiving. Never say `SUPERSEDED` or `RETIRED` based solely on current-program silence.

**Recursive return:** Stage 0 ↔ Stage 1, Stage 0 ↔ Stage 2, Stage 0 ↔ Stage 3 until independently challenged at the claimed accessible/source-cut scope, or give a precise `HOLD_EVIDENCE`. Independent countersearch must test **missing historical capability classes**, not merely whether the already-enumerated rows were filled. Concurrent research is allowed; the closure **claim** must respect the inquiry dependencies.

**Modern-first cross-check:** Inventory the assigned current domain's actual important operations and first consumers, including current-only functions, and backtrace selected result/permission/negative lines to source and historical obligations. A modern function absent from the old estate may be an extension, not a mistake. A historical T with no modern equivalent must not vanish.

## 4. One compatible package: files, IDs, and exact minimum schemas

**Delivery root:** `UNIFIED_LOG_R1/<agent-scope-id>/` on the already authorized documentary return surface, or a clearly separated textual return when writing is not authorized. Every agent uses the **same filenames and columns**, UTF-8 TSV, a literal header row, one primary entity/edge per row, no embedded literal tab/newline, no invented `PASS`, and links by stable IDs. Long prose is in `CASES/` and `HUMAN_STORY.md`; TSV stores short auditable assertions and pointers. Additional source-specific fields go in `EXTENSIONS.tsv` or a separately named supplementary file, never by silently changing common headers.

**Stable identifiers:** Prefer inherited immutable historical IDs (LMX/LMQ/F/AR, exact old output ID), and separately record aliases. When an actual unique T does not have an inherited ID, mint a *provisional namespaced* `ZAK02:T:0001`, `ZAK03:T:0001`, etc., with original file/blob/semantic-grain evidence. `S`, `M`, `OP`, `SHAPE`, `EV`, `SEARCH`, `EDGE`, `GAP` get namespaced IDs. Preserve source IDs, links and aliases when later canonicalized: never silently replace or double-count them. Where two workers touch the same T, identify one `primary_record_owner`; other references are `CROSS_REFERENCE`, not another independent conserved function.

### 4C. The required case structure

1. **Identity and reason:** `T_ID`, aliases, historical era/version/campaign, original location/source SHA+blob+lines, exact reason it mattered and what knowledge it produced.
2. **Old inbound data:** predecessor, exact schema/data objects, keys, grain/universe, source/wave/respondent/time, typed statuses, eligibility, selected rule and authority. Give at least one small *actual or explicitly illustrative* field-level example.
3. **Historical transformation:** enumerate C/D/E or S/M child IDs; formulas/algorithm in plain language, decisions, branches, conditions, refusal, rank/stop/replay; distinguish historical *code present* vs *executed output observed*.
4. **Old output and consumption:** fields/formats/schema, meaning created/changed/lost, named produced files/artifacts and first real or static code reader; why a consumer needed it; earliest historically unproved edge.
5. **Intermediate history:** a row each for applicable pre-Vozhd/Vozhd/Verkhovod/Dva/Trii/Chetiri/Long Memory and other located branches: precise operation/ref, what was retained, modified, repaired, narrowed, abandoned, candidate-only or not found *within specified search scope*.
6. **Modern reality:** *all located* relevant current operations and branch candidates; current input shape M; exact guards/transforms Q; output shapes P/Q; actual importing first reader, conditional routes, proof ceiling; distinguish adopted code from reviewed/unreviewed unmerged code and documented plan.
7. **Mechanism-by-mechanism comparison:** one old S/M child at a time, associated modern edge(s), what was preserved/changed/split/composed, loss/refusal/risk/denominator effects, negative examples and warranted equivalence grade. An unproved mapping remains `UNPROVED`, not `SUPERSEDED`.
8. **Cross-references and evidence:** every relevant `EV`, `SEARCH`, `EDGE`, `SHAPE`, `OP`, modern requirement, historical function and attached other-agent case; stable relative links plus pinned GitHub URLs.
9. **Dispositions and future utility:** historical knowledge still reusable, already reusable code/branch and owner, accepted current successor if any, missing requirement vs missing implementation vs open proof vs justified retirement, smallest discriminating check, precise future qualified decision owner. **Recommendations are not work authorizations**.
10. **Plain-English summary:** 4–8 sentences of “old X received Y, changed Z, produced W; modern A/B do C/D; E is conserved, F differs, G unproved; therefore …”.

### 4D. Example of the *required distinction*, not a new adjudication

Historical **F6M nonpooled synthesis** takes source-indexed evidence, target population/period and composition/overlap policy. It tests source and target eligibility, overlap/transport and nonpooling conditions; if lawful it emits covered subprobabilities, uncovered target mass and partial-identification bounds, refusing a falsely point-identified distribution. Modern `guard_estimand_composition` can verify authority/estimand/overlap eligibility but **is not itself** the numeric source-mixture/bounds producer. The correct row is a *partial related guard*, with numerical composition **not proved conserved at that current site** and actual N7→N9 consumption separately examined. This comes from the supplied ZAK-04 re-audit and must be independently source-graded before admission; it is not a finding of global loss or a rebuild command.

## 5. Provenance and proof: no combined green statuses

**Provenance belongs to every claim and edge, not only each file.** Prefer `commit_sha::path#exact_line_range_or_row_id` plus Git blob SHA (and data content hash where applicable), branch/PR standing at inspection, source version/authority issuer, and exact run/reviewer receipt if executed. Exact code presence, importer existence, test-only first reader, observed native first reader, source/legal authority and scientific legitimacy are **different** claims. Attach separate evidence IDs. If an old source is identical on modern protected, record **`SOURCE_RETAINED`**, not `CURRENT_OPERATIONAL_SUCCESSOR`.

**Proof dimensions must be individually stated:** `source_observation` (S0/S1), `execution` (NOT_RUN / actual test-only S2 / actual source-native if separately authorized), `authority` (source available / rule selected / applied / refusal proved / issuer accepted), `consumer` (named hypothetical / static importing code / executed test-only / actual non-test call), `scientific` (descriptive historical / bounded supported / formally accepted). No `PASS` without a specific scoped receipt, and no naked `NOT_FOUND` without a declared bounded negative search. Unknown is not absence; schema match is not semantic equivalence; candidate branch is not protected adoption.

**Retain negative capital:** `REJECT`, `BLOCKED`, `INAPPLICABLE`, `KNOWN_ABSENT`, `UNKNOWN`, `ZERO_OBSERVED`, `REVIEW_REQUIRED`, conflicting authority, same-respondent/denominator scope, missing selected rule, unobserved temporal pair and restoration behavior where germane. Different negative types must not be collapsed. A claimed replacement must specify what happens on each **material** old positive and negative, not just a convenient happy path.

**Owner semantics:** A source/semantic/science/structural/PYAT/SOROK issuer must be independently authorized for its exact decision. A reconnaissance agent **does not** create authority, accept its own review, decide global zero-loss, approve engineering or delegate it.

## 6. Completeness reporting — the only permitted use of the word “all”

Report **five separate completion judgments** in `00_RETURN.md`, each with denominator, source universe, exact accepted/reviewed evidence, open residual and grade:

1. **Commission/identity accounting:** `assigned_obligation_IDs_accounted / assigned_obligation_IDs_expected`; `old_return_rows_imported / original_rows`. These are *not* historical T counts.
2. **Historical capability discovery:** `T_discovered`, T source/branch strata actually searched, independently attacked omitted-capability classes; `T_UNIVERSE_CLOSED_AT_DECLARED_SCOPE` **or** `OPEN_DISCOVERY`. A named modern requirement denominator cannot substitute for original T discovery.
3. **Cross-domain matrix coverage:** `applicable T×domain cells inspected / applicable T×domain cells declared`, with `FOUND`, bounded `NOT_FOUND`, `UNRESOLVED`, `NOT_INSPECTED`, `NOT_APPLICABLE` **separately counted**. If new T discovered, dynamically expand/revisit dependent cells and show version of denominator.
4. **Mechanism and consumer reconciliation:** `old S/M outcomes traced / identified relevant S/M outcomes`; `qualifying current first readers / required or eligible readers`; count `same-grain-proved`, `partial`, `analogous`, `not-proved`, `candidate/stranded`, and gaps **separately**. A modern 21/21 roadmap check proves only that those 21 modern IDs were examined.
5. **Evidentiary/independent closure:** number of functions with actual current qualified proof, with static-only, test-only, original-native and review-held split; independent reviewer, exact corrections, discrepancies and unresolved work. Distinguish `ACCOUNTING_COMPLETE` from `FUNCTIONAL_CONSERVATION_EXECUTED` as separate possible outcomes; each needs its own scope and authority.

**No semantic double-counting:** A T split across three modern modules is still one historical T with three edges; seven administrative outcomes of one code function can be S children or independent T only when their independently valuable purpose warrants it. 44 LMX, 30 LMQ, 29 F, 58 AR, modern roadmap IDs and 1,740 atlas records are **overlapping identity estates**, not an additive count of unique functions. Preserve anti-joins and provenance of every alias/duplicate.

**Terminal completion sentence (required):**

> **Contract identities:** [x/y]. **Historical discovery:** [closed at exact accessible strata + independently countersearched / open]. **Applicable T×domain matrix:** [x/y, unresolved/not inspected counts]. **Mechanism and consumer reconciliation:** [x/y with proven vs partial vs unknown breakdown]. **Independent evidence grade:** [S0/S1/S2/native and reviewer]. **What the findings can legitimately be used for next:** [exact bounded actions/decisions]. **What cannot yet be claimed:** [explicit].

## 7. Operational workflow and handoff without post-hoc semantic reconciliation

1. **Freeze one common schema first.** Every agent uses the same file names, typed enums, ID policies, source-reference syntax, stage/domain vocabulary and line-item case structure. Do not let an agent invent its own `PASS` language. Only version the schema once centrally; additions are additive with a migration map.
2. **Declare the scope and denominator before examining examples.** Register assigned IDs and all domain boundary rows, including out-of-owner links. In `SOURCE_SEARCH_LOG.tsv` log the inspected/unavailable universe *as work occurs*.
3. **Register old T and source knowledge first.** Create provisional ID and CASE, old shapes, semantic/knowledge output, selected rule, old consumer, submechanisms; do not filter old findings through current components. Reuse older accepted case evidence by ID, not by copy-paste speculation.
4. **Fill Stage 1 and Stage 2 cells and mechanisms in parallel where feasible.** Every new discovered T triggers explicit coverage denominator/version updates and a bounded check for omitted old operations; preserve all positive/negative/candidate evidence.
5. **Use reference links rather than copying another agent's conclusions.** Where workers overlap, `primary_record_owner` is explicit; cross references carry exact original IDs/Evidence IDs and do not mint independent T copies. Differences stay `CONFLICT_PENDING` with counterevidence until qualified adjudication.
6. **Publish the entire return together**, with broken-link checks and reciprocal foreign keys (`T_ID`, `OP`, `SHAPE`, `EV`, `SEARCH`, `EDGE`, `UNJOIN`, CASE). Add summary manifest of these actual files and state `READ_ONLY_CHAT_RETURN` if no repo publication rights. Do not call conversation-only research committed.
7. **Independent review challenges claims and coverage, not just formatting.** Reviewer selects unexpected original outputs, contradictory branches, seven-mode semantic losses, selected-rule/QUC exceptions, consumer reverse traces, omissions and negative effects. New findings cause targeted case/matrix reopening; legitimate holds stay explicit.
8. **Only appointed VMESTYE integration authority maps qualified returns into accepted central atlas.** Because each worker's rows share a schema and ID references, integration is a mechanical join plus exact *material disputes*, not a redesign of four incompatible interpretations. Do not declare zero reconciliation work categorically; legitimate contradictions still require adjudication.

## 8. Readiness and rejection checks

A worker's return **fails this logging standard** if any of the following applies:

- It says `all found` while the historical axis or current scope is unspecified or its discovery denominator is a few convenient examples.
- It reports 17 traces, 21 roadmap requirements or nine contracts as if they were 17/21/nine unique historically reconciled functions.
- It identifies a similarly named current module but omits **old/new inputs, transformation, output, negative branch and actual consumer**.
- It says `superceded`, `obsolete`, `lost`, `implemented` or `not found` without specific meaning-bearing proof and scope (the operative status spelling is `SUPERSEDED`).
- It drops an original capability because the modern stage list has no requirement for it.
- It flattens Vozhd / Vozhd Verkhovod / other branch-only work into Dva/Trii/Chetiri without an actual search and source qualification.
- It conflates code-retained with used, sourcefree with native, authority referenced with selected/applied, or first-reader static with observed invocation.
- It lacks exact source/branch/commit/blob/line or record-level references needed to reproduce a material claim.
- Its historical mechanisms and current mechanisms cannot be compared individually, or its case cannot be understood without the agent's chat.
- It leaves T×domain cells implicit (a blank does not mean `NOT_FOUND`) or omits precise unjoins and owner-held next proof.
- It authors a duplicate canonical atlas, claims independent acceptance, begins engineering, modifies production code, runs unauthorized tests or delegates implementation. **This logging standard grants none of these permissions.**
