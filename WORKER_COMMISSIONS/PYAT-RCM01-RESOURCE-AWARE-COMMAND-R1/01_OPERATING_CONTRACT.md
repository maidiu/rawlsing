# RCM01 — Selection, evidence and authority contract

## Decision unit
A commission is one coherent intended product or exact scientific HOLD, not a model session. Record `commission_id`, `outcome`, `product_milestone` (M1–M5 / F1–F8/AT), `dependency_wakes`, expected consumer, positive-output criterion, authority requirements, required capabilities, originality/semantic risk, intended review, immutable source/control refs and exact permitted terrain. Preserve actual 35-wave denominator; never rank by number of reports/tests instead of downstream functionality.

## Resource unit
Distinguish `provider`, `model`, `variant`, `account_alias`, `plan`, `machine_id`, `runtime_environment`, `privacy_ceiling`, `tool_capabilities`, `quota_window`, `remaining_normalized_allowance`, `reset_at`, `money_cap`, `forecast_confidence`, `availability` and `measurement_timestamp`. Two account envelopes must not be conflated into one balance; one Go pooled allowance must not be multiplied per model. Do not store actual credentials, secrets, private source text or account identifying values in Git. Store only pseudonymous labels and approved aggregate usage snapshots. Logs that could expose data live under approved local custody.

## Hard eligibility (pre-score)
1. A task needing local subprocess, Python, pytest, Native C, Mac FS or raw custody cannot be handed to GitHub-only Browser as an executed runtime proof; Browser can be scientific/documentary owner with a separate execution helper.
2. No work on raw source without an exact separate source permission and host custody. No non-zero data-training/private-code export unless explicitly permitted by owner after examining provider terms.
3. No source-science or security/issuer determination by a low-capability model alone, however cheap. Model competence is empirically updated by accepted proof, not marketing model names.
4. Require actual branch/worktree identity, single-writer confinement, non-overlapping mutable terrain and dependency-ready inputs. Resumable active session takes priority over duplicate assignment; no destructive reset when startup changed due to lawful local progress.
5. Reviewer independence and prior expectation custody cannot be waived by scheduling convenience.
6. A missing local budget, unclear pool/reset semantics or disabled paid overflow yields `REQUIRES_BUDGET_EVIDENCE`, not an inferred free pass. `known_spend > cap` is an absolute NO.
7. A missing tool or scientific issuer remains an explicit blocker, not a prompt to spend more tokens.
8. Avoid future-platform terms violations, including creating extra accounts to evade limits.

## Optimization
For each eligible (task, resource, configuration), estimate only from observed runs or expressly tagged estimates:
`expected_time_to_accepted_result = queue_delay + setup + solve + expected_retry_and_review`;
`expected_money`, `expected_normalized_quota_consumption`, `expected_operator_touches`, `expected_semantic_rework`.
The policy may use configurable weights after hard gates, but must preserve Pareto visibility and a deterministic tie-break. Apply higher urgency to critical-path downstream unlocks **without pretending to know probability of success**. Unknown estimates remain null, are visible and trigger an exploratory bounded probe if permitted; never silently become zero. Time-to-product includes Browser/GitHub round-trip latency, waiting for resets and review. Rank by completion/acceptance probability, not raw model output speed.

## State transitions
`NEW_NEEDS_LAUNCH`, `EXISTING_ACTIVE_NOT_RETURNED`, `RETURNED_LOCAL_PUSH_REQUIRED` (requires local attest), `PUSHED_READY_FOR_HQ_INTAKE`, `ADOPTED_CLOSED` only on competent decision. Separately track `BLOCKED_UPSTREAM_SCIENCE`, `BLOCKED_RUNTIME`, `BLOCKED_QUOTA`, `REQUIRES_INDEPENDENT_REVIEW`, `UNKNOWN`. Neither GitHub commission existence nor remote unchanged entails session state. Planned routing never appends ACCEPTED/publishes CURRENT; only governing HQ protocol can.

## Escalation and stop
Stop no-new-evidence analysis loops, unexpected cost, provider errors and repeated identical hostiles. After two substantially identical failed attempts diagnose mechanism before model upgrade. Maintain prior candidate and local evidence; do not restart cleanly without exact forensic reason. Escalate to Codex/GLM only when harder intelligence/local execution materially helps; to Astra only on reserved meaning/authority/program-direction decisions. Require a bounded spending envelope and no automatic paid overflow.

## Observability
Use a local-only run log: exact task and model IDs, intended/actual tool environment, started/ended UTC times, API billing or plan-equivalent usage if known, counts of tools/retries/errors/operator interventions, tests/commands and exits, real product/consumer/review status, exact return SHA. Report absence explicitly. One independent verified completed positive is more valuable than ten self-certified passes.

## Authority hierarchy
Existing accepted semantics, source owner, model/use issuer, HQD124/HQD125/HQD216, shared-store law, exact handoff and actual owner contracts outrank scheduler suggestion. Scheduler grants NOTHING; it cannot issue sources, E/EE12, B5 CURRENT, G0b, EE14, or V3. Astra is reserved for strategic recalibration and is not a magical override of missing original evidence.
