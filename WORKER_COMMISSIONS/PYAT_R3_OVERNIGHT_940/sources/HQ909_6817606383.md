# HQR-20261112-R3C — BINDING PACKET COMPLETION / ADVERSARIAL SATURATION COURT

**This is an acceptance-contract amendment to [R3's 20-packet programme](https://github.com/maidiu/rawlsing/issues/909#issuecomment-6817019151), NOT a new architecture, implementation phase, commission, or source/science grant.** It applies to [Pair1 #918](https://github.com/maidiu/rawlsing/issues/918), [Pair2 #919](https://github.com/maidiu/rawlsing/issues/919), [Pair3 #920](https://github.com/maidiu/rawlsing/issues/920). It addresses an omission in R3: named falsifiers alone do not establish a mechanically adjudicable end condition, and "no consequential feasible defects remain" without a severity/evidence rule invites both premature claims and endless exchanges.

## I. Closed outcomes and accounting (never conflate)
Every packet must end with exactly one signed **engineering disposition** at its actual evidence grade:
- `ACCEPT_SCOPED`: implemented or existing code demonstrably satisfies **all in-scope hard gates**, independent nonauthor receiver accepts exact frozen SHA. May carry separately named native/scientific/host/actor external HOLDs. This means **packet engineering accepted**, NOT protected merge, original35 scientific acceptance or whole machine completion.
- `ALREADY_SATISFIED`: exact existing accepted/protected owner and actual first-consumer proofs meet the same contract at the same grade; independent receiver verifies that doing nothing is valid. A source stub/import is not sufficient.
- `REVISE_EXACT_DEFECT`: reproducible, consequential, **in-scope and feasible** failure against one specified gate; submit failing command/input/expected/observed, exact owner, suggested minimal repair. This cannot be called complete.
- `HOLD_EXTERNAL`: every feasible in-scope implementation/proof has been done or boundedly attempted and a specified missing competent source, issuer, science rule, actor/host or rights decision prevents the remaining positive evidence. Identify precisely the external owner and smallest witness. **Do not mark a sourcefree engineering bug HOLD simply because original35 permission is unavailable.** A HOLD is honest terminal *for that claim/grade*, not `ACCEPT_SCOPED` for unimplemented functionality.
- `NOT_DEMANDED_PROVED`: only for an IF-conditional packet, citing the exact selected consumer/IF rule that makes the function inapplicable in the current target scope, and preserving the pending broader conditional obligation. No speculative implementation or blanket deletion.
- `BLOCKED_OWNERSHIP`: required writer lease, file owner, frozen immutable input or authorized scope unavailable; identify conflicting owner and do not mutate. Not a success.
A separate **integration flag** `UNMERGED | ACCEPTED_INTEGRATION_BRANCH | PROTECTED_RECEIVED` must accompany every engineering disposition. No agent may mark `PROTECTED_RECEIVED` without protected receiving's actual commit/decision.

## II. Five binary receipt gates per packet — proof OR explicit lawful exception
`G1 EXACT CONTRACT`: Original R3 packet ID(s), selected source/semantic/scientific owner, immutable tested base+candidate HEAD and source blob, *actual* first consumer and governing input/output ABIs, accepted scope and typed negative statuses. Pass only if **all original packet obligations are accounted for** (including anything collapsed from old 25).
`G2 REAL EXECUTABLE POSITIVE`: Working module/function **and actual normal first-reader invocation**, changed valid upstream input -> changed expected result/identity, restoration -> original exact output, or for receive-only packet a rerun of the existing implementation's real first-consumer tests. Model-only/unit-only, imported symbol, constructed record or passing self-rehash is **NOT** native first-consumer proof. For a strictly negative gate, use an actual first-consumer refusal and valid restored positive.
`G3 HOSTILE NEGATIVE + CONSERVATION`: Mandatory item-specific RED controls, exact source/universe/authority/as-of binding, illegal widening/absence/zero/currentness denied, non-loss of already accepted functionality, exhaustive source/operation/fact/negative/held states within **declared input census**, regression suite and known historical counterexamples. Wrong source is never 'valid null'. No output-truncation or inferred origin.
`G4 CUSTODY + RESOURCES + RECOVERY`: If packet owns persistent state, certify versioned content-addressed root, independently anchored trust, corrupt/partial/orphan refusal, cold fresh-process selected read, replay/migration; if it is read-only/stateless, mark `NOT_APPLICABLE_PROVED` with no invented durability claim. If it changes physical/materialization, report exact test row count, process-tree peak RSS, elapsed cold/repeat, retained/peak disk, source-open count and cap result; do not substitute a tiny fixture for the **later integrated 100k** criterion. Whole 6 GiB test is mandatory at S2 integrated resource gate, not automatically passable by a small module test.
`G5 INDEPENDENT NONAUTHOR RECEIVING`: One reviewer other than both current A/B authors, genuinely independent of the reviewed artifact, inspects exact frozen descendant HEAD and original packet contract, reruns the critical positive/red/restoration and regression/owner/grade checks, and writes one of the closed outcomes above. **No green CI, author's self-review, A/B agreement, or prose alone satisfies G5.** Rewritten code after review invalidates G5 until received at its new SHA.

No packet may be declared `ACCEPT_SCOPED` if any applicable G1–G5 is FAIL/NOT_RUN. A test marked XFAIL, historical-passed, absent host, or theoretical is not green. If G2/G4 is genuinely impossible due external authority, record `HOLD_EXTERNAL`, while a demonstrably complete lower-grade sub-scope may separately be `ACCEPT_SCOPED@S2` with its exact boundary. Never infer S3/original35 from S2.

## III. Stop/adversarial iteration: finite without arbitrary pass
1. Before implementation, record the packet's **closed mandatory case IDs** (from pair-specific R3C comment), positive reader, negative reader, preservation suite, exact proof ceiling and fixed resource budgets. A implements strongest actual work with frozen HEAD. B independently challenges and, if it finds a consequence, repairs on its **own** branch descended from that exact A HEAD; A counter-challenges. Every challenger must report executable failure/reproduction, actual first reader, semantic consequence, scope and grade.
2. `SEV-0` = incorrect positive authority/scientific/currentness/source claim, data loss or false absence; `SEV-1` = actual eligible first-reader wrong value, incomplete required selector/denominator/operation or broken exact replay; `SEV-2` = resource violation, crash/recovery or parity/compatibility loss within agreed envelope; `SEV-3` = cosmetic/hypothetical outside demonstrated contract. Any **in-scope reproducible SEV-0/1/2 stays REVISE** until repaired and tested at frozen successor SHA or, for genuine inaccessible external evidence only, independently adjudicated HOLD. SEV-3 cannot force open-ended rounds; record deferred item without changing acceptance.
3. After A→B→A (one implement, one attack, one counterattack) **either** submit for independent receiving if every mandatory gate green, **or** make one narrow bounded correction/retest exchange for remaining specific SEV-0/1/2 cases. If defects still recur, send the exact unresolved case/source/ownership to HQ for `REVISE/HOLD/CHANGE_OWNER` adjudication—**do not automatically reopen broad reconnaissance or declare victory due a round limit.** A serious reproducible in-scope failure blocks acceptance no matter how many iterations occurred.
4. Reviewer must attempt at least one independent hostile variation not authored as a happy-path case by A/B, using the actual first reader, but is not commissioned to reinvent the scientific programme. Reviewer may `ACCEPT_SCOPED`, `REVISE_EXACT_DEFECT`, or `HOLD_EXTERNAL` against **the complete original packet contract**; no 'accepted except one in-scope red test'.
5. Upon scoped acceptance, freeze one descendant implementation HEAD and proof/receipt, mark integrated/not-integrated separately, advance to the next packet whose **genuine dependencies are present** without another HQ permission. If HOLD_EXTERNAL or NOT_DEMANDED_PROVED, move to other independent lawful packets; retain pending obligation in programme census.
