# CHECKPOINT + COST LAW — ASTRA HQ247 DELTA

## Bank by events, not by hoped-for usage-limit detection
- First verified baseline and source inventory: commit+push.
- After every material, independently grounded new finding or falsified hypothesis, and every bounded reverse-service slice: commit+push.
- Before a big new inquiry whose cost may exhaust quota: commit+push current useful state.
- Before EACH mandatory model change or account/machine transfer: consolidate, commit+push, verify remote head, STOP.
- If user reports low quota (~15–20%, only a precaution, not an assured meter), enter CHECKPOINT_ONLY, halt investigative work and maximize verified evidence + exact successor state in last push.
- Never assume the model can itself read Astra-specific usage, predict remaining inferences, or change accounts/models. Bank often enough that unexpected exhaustion loses at most unfinished slice.

## Priority of banked data
(1) exact non-obvious evidence / Git SHA / citations / falsification; (2) actionable critical-path discoveries and disputed claims; (3) exact next command/reader; (4) narrative. State which source/ref was read fully vs excerpted. Compress current NEXT_OPERATOR.md to <=150 lines when practical; deep reasoning is in linked phase reports. Existing September Astra Atlas is inherited, not reprinted.

## Low-context Git implementation
Stage only exact paths in this audit workspace or permitted worker return terrain, inspect `git diff --check`, `git commit` meaningful milestone, `git push origin HEAD:refs/heads/agent/astra-pyat-hq247-functional-endgame-delta-audit-r1`, verify `git ls-remote origin refs/heads/agent/astra-pyat-hq247-functional-endgame-delta-audit-r1` equals committed HEAD. If equivalent connector actions used, fetch direct branch ref after writing. Local commit != remote handoff. No force push/merge/rebase or other worker paths. Do not dump huge full diffs in chat.

The Git operations use relatively little reasoning when outputs are concise. Full-text report rewriting, repeated huge tool outputs, excessive cadence and tool-loop retries can consume appreciable usage. No exact quota fraction assumed. Save after one to three substantive units, not each trivial command.

## Cross-account / cross-machine
Keep machine B authenticated to its existing permitted account. Do not copy Codex auth files, session databases, tokens or cookie stores. Use one canonical clone and isolated sparse worktree per machine, not duplicate clones or a shared live worktree. The transferred source of truth is the audited Git branch and its STATE/NEXT_OPERATOR checkpoint, NOT the raw Codex log. An optional session transfer must not be necessary. If no authorized worktree is prepared, STOP and request local bootstrap, do not self-create an unauthorized clone.

## Checkpoint credibility
On each bank update STATE.json: phase, gate_status, baseline_control_head, latest_pinned_checkpoint, most_recent_verified_remote_heads, evidence grades, next_model, first_next_action and open investigations. The SHA written inside the same commit cannot self-identify that final commit: record a previous verified milestone in-file and independently report and verify newest remote HEAD. Failures must report attempted command, local SHA and last verified origin SHA without secrets. Never claim a push succeeded without readback.
