# 01 — Argument genealogy: preserve every turn, including reversals

**Purpose:** Record how the proposal developed, which claims have been corrected, and why the next workshop must not simply inherit the most recent neat architecture diagram. This is a **reasoning ledger** (not execution evidence). Statuses distinguish a surviving invariant from a once-plausible suggestion.

## A. Problem setting before the immediate discussion

- Earlier route-B and A/B/C architectural deliberations tried to select a realizable source-backed C11→I03→I05→learned-product lane, preserving exact R5 / GT1 / GT2 identity, source permissions, negatives, and pre-FF continuity. Different physical carriers were once live possibilities. The user demanded finite scientific/operational proofs and eventual selection, not endless parallel architecture maintenance.
- October 28 selected a complete compact source-governed, cold-persistent 13-family C11 architecture rather than an eager giant in-memory object graph. Later W03/W04 experiments showed old carrier/memory ceilings and incomplete cold reuse. The November 11 Stone/columnar hybrid was useful investigative capital, **not an adopted production replacement**.
- The later sourcefree S2-B/C/D implementation established real thirteen-family Parquet/Zstd and native cold-reader components, but whole-survey-shaped end-to-end economics were not proven. User insisted that material functions of pre-FORGE DDM must survive in a better successor, and that all future analysis serve the *whole* terminal person/world objective rather than a convenient small query canary.
- VOSKRES and ZL-15 exposed the danger of confusing old DDM's respondent/country prepared analytic behavior with the number of historical files or outputs recovered.

## B. Explicit user methodological correction

The user rejected the assistant's repeated plan to build several physical alternatives and then benchmark them. The methodological demand is:

> **Use architectural reasoning to identify viable options, anticipate the likely consequences of each, reject weak ones analytically, select a design, and use bounded tests to falsify actual defects. Do not spend days on needless bake-offs.**

This is an **active design constraint**, not an invitation to suppress necessary integrity tests. Reasoning has to consider correctness, compute, memory, provenance, reversible representation, future consumers, owner authority and opportunity cost *together*. Where quantitative inference cannot be made honestly, state that the predicted direction is structural rather than inventing a speedup.

## C. First proposal: optimize staged publication

Original sketch: one authorized SAV/DTA decode → upstream semantic certification and direct Parquet staging → compare source and physical commitments → atomically publish canonical C11; retain body_json initially; share downstream index/cohorts. Suggested removing 13 JSONL journals, second I02 proof and per-object full physical reconstruction, adding compact numeric IDs to proof SQLite, then a persistent derived index.

**Why it seemed promising:** multiple representations and complete-object serializations looked redundant; constructing a large SQLite proof and a per-operation postings index looked wasteful; direct Parquet/Zstd was already working; source/semantic proof should remain distinct from physical fidelity proof.

**Its critical defects, now banked as REJECTED_AS_PROPOSED:**

1. **Wrong measured denominator:** the expensive 100k **direct writer** path already consumes family iterators; it is not the S1-E JSONL journal path. Deleting S1-E journals cannot explain away direct-writer time.
2. **Unsafe removal of I02:** the second proof in the integrated bridge also establishes a connection between the initially certified source and replayed/transformed stream. A direct replacement must independently bind staged bodies to source truth.
3. **Self-confirming proof danger:** hashing a wrong projection generated by the same defective encoder proves the defect was stored consistently, not that semantic projection was right. Independent body↔selector↔source/authority↔I02 invariants remain necessary.
4. **Compact-ID romanticism:** integer dictionary substitution could add conversions, duplicate mappings, key-order reconstruction and trust complexity; no proof it dominates simpler SQL changes.
5. **Persisted-index optimism:** an authenticated index must still handle corruption, release changes, revocation, reopens and permission; persistence alone is not authority.
6. **Wrong primary bottleneck:** index reuse is a bounded improvement, while whole-query respondent traversals, body reads, predicate work and large outputs remain.
7. **Scientific myopia:** optimizing for modern I03 F1–F4 could strand recursion, same-person patterns, signed evidence, multiwave/uncertainty, FF and continuing-person needs.

**Surviving insight:** avoid redundant whole-corpus work, but distinguish bridge cost, proof cost, reader construction cost, query computation and output-materialization lower bounds before choosing a change.

## D. Reconstructed proposal: fix measured writer, prioritize shared computation

A second design retained existing physical C11 and proof obligations; proposed more efficient I02 SQLite ingestion (batching, removal of genuinely redundant lookups, delayed secondary index construction **if equivalent**), then direct source→staged physical writing without JSONL detour; keep independent physical readback until equivalent verifier exists. Proposed prepared respondent-aligned/variable-aligned access, shared eligible populations, exact branch masks and later derived persistence.

**Correction:** These SQL improvements remain **plausible code-specific candidates**, not measured or adopted fixes. Removing a lookup is lawful only if errors, negative states and conflict scope remain equivalent. Deferred indexes may trade insertion speed for final sort/index build cost; do not assume gain.

**Surviving:** optimization should attack actual code paths rather than trendy formats. One source of truth; derived access structures; exact proof separation; reuse prior author work rather than duplicating it.

## E. Stage 2/3/4 plain-language clarification

- **Stage 2 = build:** source record processed, semantic checks and private staging, independent fidelity validation, then atomic publication. Incomplete construction never becomes approved.
- **Stage 3 = what was built:** full thirteen-family, authenticated, persistent C11 with exact respondent/routing/weight/source/authority/replay distinctions; Parquet is storage, not analytic intelligence. CURRENT checks whether use is legitimate now.
- **Stage 4 = how it is used:** reusable respondent→events, question→respondents, eligibility/routing and prepared condition populations, under exact source/current/authority identities. A prepared group is not a final statistical fact.
- Example: Lebanese 30–40 cohort used for unemployment, economic insecurity and trust analyses. Every new target changes eligible/answered population and possibly weight/denominator; group membership alone cannot justify a result.
- Stage 4 is not another authoritative corpus. It is a versioned, bounded derived execution representation, potentially retained where rebuilding is expensive.

## F. Deeper Stage 4 inspection: prepared session is only first repair

The new `PreparedSavedC11Admission.prepared_i03()` branch reuses one `DirectEstateI03Session` rather than rebuilding per distinct operation. Author reported ~1.69–1.70× on two small sourcefree suites with exact parity; remote commit later became available. **This does not mean general shared scientific computation exists.**

The actual evaluator loops over respondents for each query, gathers routing/condition/target/weights and builds exact facts/replay. Modern `I03GroupedExecutionScope` shares a compatible *whole measure-independent core*, not arbitrary subpredicates or cross-target population preparation. It is explicitly refused for current native `DirectEstateI03Session`.

This led to **two-way access** (question-first and respondent-first pointers to one body) and reusable exact, evidence-bearing condition/intersection computations. Dense bitmap example: 100k respondents occupy roughly 12.5KB for one simple membership bitset, **excluding** typed states, provenance, identity mapping, selectors and indexes. Never mistake bitmap size for whole proof or whole population.

## G. Output lower bound and witness proposal

The fact/replay builders contain explicit risk and denominator respondent refs, plus source object/authority provenance. In a high-volume case, 100k refs × 1k facts = 100 million ref appearances; at 64 bytes each that is 6.4 GB before overhead. This is an **illustrative lower bound**, not observed current benchmark.

Proposed *versioned population witnesses* could refer to one authenticated membership representation many times and allow full materialization when necessary. **This cannot silently rewrite v1 EmpiricalFact or replay hashes.** It would need a new separately owned output/evidence contract with exact names, ordering, independent witness validation, negative cases, and qualified first readers. Current v1 remains compatibility authority.

## H. The downstream challenge overturns I03-centered design

The user then asked whether all this reflected **the *full* eventual requirements**, especially lost pre-FORGE DDM functionality. The accurate response was **not adequately**.

The further design is not just an I03 acceleration layer. It is a **shared empirical computation and composition substrate** whose reusable products include source-qualified access, population relationships, full same-person joint distributions, recursive/conditional/diagnostic intermediates, branch ancestry, provenance and explicit scientific claim-grade distinctions. It must support computations *not yet implemented* in modern I03 without pre-authorizing those semantics. Current I03 is a correctness/compatibility oracle only for its supported functions.

## I. Present position — deliberately not a selected design

**Surviving strongest direction (DESIGN_CANDIDATE):** canonical C11 evidence; one independently qualified publication; derived dual-direction access; reusable typed/evidence-bearing population and joint computations; incremental dependency/conservation graph; existing scientific fact/FF issuers; no unauthorized structural/causal promotion; economical cold/repeated execution. But this is **not** yet the optimal arrangement adjudicated against the exhaustive downstream requirement.

**Still live rivals/questions:** whether the canonical physical layout should be modified; how much projection to pre-materialize; whether batch/whole-scan approaches beat individual getters; how proof granularity and replay affect gains; whether output-witness versioning is essential; which historic scientific statistics remain indispensable; what N9/N10W/actor first readers actually require; what the right cross-source and temporal representations are.

**Process stop:** Do not write a new implementation commission based solely on a pretty Stage 4 sketch. First run ANVIL's full reverse-requirements and factor court in [08](08_FACTOR_COURT_AND_OPEN_DECISIONS.md) and [12](12_ANVIL_WORKSHOP_PROCEDURE.md).
