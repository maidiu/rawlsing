## C. User-level concepts and distinctions that must be intelligible

- *Why do we have both canonical storage and analytic preparation?* One preserves evidence; the other makes many computations economical without another corpus.
- *Why do we distinguish producer proof from physical proof?* An incorrect value can be faithfully persisted; independent validation must rule out common mistakes.
- *Why doesn't one saved index solve querying?* Index re-use stops rebuilding locators, not repeatedly evaluating respondent conditions or emitting huge fact/provenance outputs.
- *What makes two calculations genuinely shareable?* Exact source, question, population, routing, authority, measure/estimand, predicate semantics, time and valid evidence/negative rules—not superficial textual similarity.
- *Why can't we just intersect bitmaps?* Because not-asked/unknown/inapplicable are not false; some predicate evidence is evaluated even when booleans could short-circuit; branch ancestry matters.
- *Why does direction matter?* `P(Y|X)` and `P(X|Y)` have different denominator populations and inference meaning.
- *Why do k-way joint patterns matter?* Persons can combine attitudes in ways not reconstructible from separate averages or pairwise tables.
- *Why isn't a historical function conserved by reading the old code?* It needs a valid estimator and actual modern consumer; some old code contained denominator/label/branch defects.
- *Why might Stage 4 be more than I03?* Later producers need entropy/gain/recursion, signed/neutral relations, nonpooling/temporal reasoning, possibility and world products not covered by the narrow existing query language.
- *Why can't we let FF/N9 infer class or power directly from demographics?* Attitude/response distribution is observational; ownership/control/institutions/activity require independently meaningful evidence.
- *Why must whole downstream requirements be known first?* Otherwise we can optimize the wrong scientific machine and structurally foreclose missing functions.

## D. Working decisions and their actual status

**Strong but UNADOPTED candidate direction:** canonical complete C11, qualified staged publication, independent semantic/physical proofs, compact bidirectional access, qualified reusable condition/joint/branch intermediates, exact governed scientific issuers, durable/lazy result lifecycle and world/person consumers with separate owners.

**Ideas REJECTED AS INITIALLY PROPOSED:** removing proof by shared hashes; presuming eliminating JSONL speeds direct S2-C 100k writer; immediate integer ID rewrite of I02; immediate generalized persisted cache; declaring Parquet automatically economical; reducing C11 purpose to present I03 query speed; replacing pre-FORGE functions with a simple `P(Y|X)` API; choosing a backend by performance bakeoff.

**Still OPEN:** complete source→C11 future information sufficiency, full lost functions/estimands, exact Stage4 reusable representation, proof/cold/cache architecture, per-result output contract, realistic processing economics, qualified FF and SOROK first consumers, whether accepting the current physical layout is still wise after all factors.

## E. No rhetoric instead of proof

ANVIL must not include confident numerical speedup predictions unsupported by actual profiling. “Likely” means an argument grounded in number of passes, memory residency, asymptotic complexity, full output size and real consumer behavior, with explicit uncertainty. Claims such as “everything is covered”, “all downstream needs known”, “100k practical”, “source rights qualified”, “G5 accepted”, “protected now” must identify exact source and scope or remain explicitly unproven.

**Future questioning:** Work through the unresolved factors in ordinary language first; preserve the user's opportunity to critique each premise. Do not start every session by restating an immaculate final architecture that has not yet been adjudicated.
