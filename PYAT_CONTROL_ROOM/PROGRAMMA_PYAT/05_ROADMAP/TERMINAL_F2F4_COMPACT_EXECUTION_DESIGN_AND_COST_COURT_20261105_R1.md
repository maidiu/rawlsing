## 1. Three-layer physical model — one truth, optional accelerators, views

1. **Immutable source-backed semantic layer (authoritative):** exact sample/respondent/occurrence/routing facts and sparse measures, source grants, risk/denominator, original release root. May be full logical objects or certified compact-sealed representation, never an invented statistical ontology.
2. **Derived economical analytical working set (regenerable, not authoritative):** dictionary-coded categorical values/typed-state masks and *measured-benefit-only* optional per-code respondent postings (e.g., compressed bitmaps). One respondent index per scope/version/risk; reference-only rows for repeated uses; stable key = source edition/release/authority/measure/typed topology/engine version/semantic root. Retained original bit-exact event values and routing/multiple-response structure must be recoverable. Cache misses recompute; invalidation handles version/permissions. Current Arrow/Parquet selector and I03 index are the mandatory first comparison point.
3. **Sparse conditional/joint result working sets (derivatives):** on-demand exact `P(Y|C)` counts/denominators or observed k-way configuration counts, *including explicit valid zeros and applicable-domain coverage*. Reuse computed same-risk/coexposed conditioned cohorts where the identical source/measure/permission scope repeats. Content-addressed by exact query/predicate/risk/target-order/weights/issuer/currentness; bounded LRU/TTL or run-scoped retention only after measurement. Do not materialize all `2^k` binary configurations or a database of every pair; higher-order unobserved categories still need domain/zero/typed-state semantics even in sparse storage.

**Native execution example:** for jointly administered same-respondent binary items `A,B,C` under demographic `D=d`, use qualified respondent mask `M_D`, AND it with `M_A` and `M_B`, then group all **eligible** C outcomes once (distinct NULL/DK/routing states retained). The conditional fraction comes from sums of exact same-risk cells. An inverse `P(D|A,B)` changes condition and denominator over the same sealed incidence, not a casual algebraic reversal of a GF1 classification. Efficient shared masks are physical optimization; original query-result ref identity remains unchanged.

**Rough asymptotics:** independently scanning N events for each of Q conditions can approach `O(NQ)` per release; building a reusable index may cost `O(N)` or more plus later intersect/group work. This is a shape comparison, **not** a performance measurement. Full cross-product of k binary outcomes has `2^k` cells, but a sparse observed joint can aggregate at most the actually observed complete-case combinations (bounded by respondents) while retaining complete domain and zero-support metadata. Source-specific survey routing/nonresponse means effective N differs by joint target; no global `N` denominator.

### The three different things people call a “graph” must not be conflated

1. **Physical postings/bitmap graph or columnar index:** no new social meaning; simply accelerates exact empirical queries.
2. **Factorized probabilistic graphical model (Bayesian network/factor graph/conditional model):** *new modelled capability* for sparse/unobserved compositions or sample→population transport, but conditional independence, learned parameters and uncertainty need independent validation and rule/version identity. It is not a substitute for same-respondent truth.
3. **Field Forge semantic/structural relation graph:** explicit governed interpretation of empirics as institutional/material relations only if competent owner + named N5/N6/consumer demand. It does not turn association into mechanisms or produce a dyad.
Do not commission a “universal cloud graph” without choosing precisely which of these needs an actual deficit; a name is not an engineering requirement.

## 3. Precise benchmark design and sourcefree tests (no S2 claimed here)

**Freeze first:** accepted I03/PR684/PR686 and sourcefree E41 31-op oracle, exact C11 release identities; independent risk/test matrix with domains/routing/permissions/missing/weights/cold process before writing optimization; avoid building expected output from optimized result.

**Cases:** (i) first cold one query; (ii) 100+ compatible queries with shared risk/target domains; (iii) many incompatible releases/permissions/denominators; (iv) k-way 3+, XOR/Simpson/minority and same pair marginals different third-order joint; (v) reversed query direction; (vi) multi response/repeated/household unit, record topology or fail closed; (vii) observed zero vs ZERO_SUPPORT vs NOT_ASKED vs unvisited; (viii) weighted if qualified original design/estimand, else typed unavailable; (ix) cold recovered cache and one-byte/source/authority mutation; (x) memory-constrained small host as well as larger host, temporary overrun and recovery.

**Metrics:** source/first-consumer exact fact and receipt equality; miss/refusal type, complete cell + denominator including absent categories; CPU/user + wall per query family; peak RSS and memory fragmentation; on-disk bytes per release; cold build and cold restart; number of release-index builds; hashes and cache invalidations; request identity (including condition VALUES); frontier coverage/unevaluated states. Report sourcefree vs original native separately; no false-ready. Validate all proposed methods on unchanged *first consumer*, not standalone arithmetic.

**Operational selection policy:** run P0/P1 baseline and P2 minimal kernel/index reuse first. Admit P3 or P4 only when repeated request cost/working-set pressure is measured and source/version/security/negative/replay equality is proven. Choose per-source/scope data shape where needed, not a universal performance boast. Do not reopen October physical choice or silently cancel the selected **function** of compact, regenerable acceleration merely because a particular algorithm is weak.
