## 2. One schema, typed relations, exact source and qualification

Each material item—source wave, eligible operation, empirical claim, scientific alternative, historical source/function, current code, world/structural object, N11/N12 gate, acceptance evidence, blocker, reviewer, owner and flight—has a stable exact identifier, reuse canonical existing IDs rather than silently assigning replacements.

Missing provenance remains `UNKNOWN` or `SOURCE_NOT_FOUND`, never invented. A frozen manifest verified against real Git objects plus an independent refresh checker is necessary for `SOURCE_EXACT`. ## 5. Mandatory continuous return→map update transaction

Every significant source/empirical/scientific/code/worker return requires one coherent update within existing owner/CAS discipline:

1. **Identify** exact immutable branch/head, source object/time, original owner and sourcefree/native grading; verify whether local worker is actually running/returned or just has a branch.
2. **Classify** the new discovery/negative/counterexample, exact function and source, eligible operation and first consumer; preserve old and rival versions.
3. **Attach** it across all relevant program workstreams, source×wave/operation, F/N outputs, downstream Sorok interface and original scientific/authority edges, not just in `CURRENT_PROGRESS`.
4. **Regrade** only the dimensions truly evidenced; propagate source invalidation/denial to dependent operations and terminal readiness. Do not auto-green downstream F8 or N11 because a C11 test passed.
5. **Recompute** map gaps, valid U/E_pre extent, source/grant bottleneck, genuine release readiness, scientific options, largest lawful coherent parallel commission and cross-HQ interface.
6. **Commit** reviewed, competence-authorized source/control update with exact CAS or mark `RETURNED_UNADOPTED_PENDING_OWNER`; preserve immutable transition history, review and reason.
7. **Readback** prove the current single reference *and* canonical Pyat progress/hand-off, where authorized, now agree on version and scope; explain `WHAT_ADVANCED / WHAT_REMAINED_HELD / WHAT_BECAME_RED / WHAT_NEXT / WHY`.

Triggers: new source-native result; original-source correction; eligibility change; 35-wave data or option materialization; time/comparability/science decision; source grant or denial; independent review; new live code/function; worker return, running-state evidence or altered external Pyat/Sorok input; discovered required requirement; new original data/negative witness. An unreviewed branch may update the CANDIDATE view but cannot change accepted canonical status.

No delayed append-only worker ledger masquerading as integration. If a decision uses the map to choose a new flight while already-returned consequential evidence is unincorporated, **that Programma view is stale and cannot support the asserted priority**.
