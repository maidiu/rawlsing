# Economics, performance, resource controls and operations law

## One selected architecture; benchmarks tune it
No A/B/C bakeoff, no physical-route rankings, no re-approval ritual. The chosen source-authoritative hybrid is a design decision. Empirical benchmarks are required ONLY to tune, verify and accept its physical/cache/query implementation. Baseline old/current vs optimized exact functions, never weaken science for speed. If a real technical impossibility is proved, escalate a concrete contradiction to principal; do not autonomously relaunch route selection.

## Cost model and per-query separation
Lifecycle cost must be measured as independent quantities, not one invented scalar:
C_source: SHA/open/decode + source admission; C_projection: scientific value/state/event mapping; C_validate: full C11 identity closure; C_cache_build: columnar encode, compression, manifest, atomic publication; C_cache_open: hash/authentication + mapping; C_query: predicate compilation, membership/risk resolution, grouped counts; C_domain: complete zero-domain construction; C_provenance: used objects/evidence closure; C_fact: canonical native fact/hash/replay; C_release: learned/serving lifecycle; C_rebuild: stale/missing cache; C_consume: real N10E/FF/world request; C_cleanup: temporary storage and crash recovery.
Separate one-time, per-session, per-operation, and per-source-authority-change costs. Track cold process, warm process, fresh cache, deleted cache, stale cache, production replay and end-to-end mixed workload.

## Default performance targets (targets NOT measured promises)
- New source-backed compile does not require repeated physical serialization of millions of self-describing public objects.
- No routine full-size second 7.91GB carrier; cache smaller than source-derived giant bundle with measured compression and peak temp requirements.
- Run under actual 16-GiB host capacity with headroom; no swap/OOM reliance; scratch storage pressure measured/guarded before write.
- Amortize source/authority verification and respondent-key alignment across all lawful operations per exact session.
- Materially reduce full end-to-end native operation cost versus current executor. Avoid declaring victory from fast bincount if fact/replay still dominates.
- Maximize *products accepted and consumed per total machine hour* subject to full source/scientific/replay integrity, not just operations/second.
- Recover/serve existing completed facts without rerunning raw source or fabricating cells.
- Cross-session cache saves meaningful repeated build cost; if measured benefit small, retain architecture but set optional cache eviction policy (not redesign route).

## Workload benchmark (scientific parity first)
1. Complete regression of existing 177 unaries +31 joints from accepted actual aggregate evidence under authorized source runtime, or a bounded representative selection with full digest/check counts where full replay too costly.
2. Independently selected low/moderate/high-cardinality, sparse/complete zero, physically missing, DK/refusal/special, original/normalized value and held/inapplicable cases.
3. At least two compatible conditional directions plus unequal-risk/missingness cases that must NOT share denominator.
4. Real k=3+ branch-conditioned co-signature, complex multiple-response/rank/repeated topology, unknown routing and invalid scope.
5. Blind fracture-map fixture with hidden planted minority and interaction where two-way marginals fail, and actual named real-source acceptance when authorized.
6. Real original-source discovery/learned result and downstream request, including altered-input/restore under grant.
7. Source authority/decoder/projection stale, cache mutation/corruption, cache deletion/full rebuild, crash/restart, support-zero versus not-computed, cold query, exact-ref negative.
8. Source-family and scale differences: SRC04, a second family already admitted, WVS/LiTS where authorized; do not infer all35 performance from SRC04.

## Timing/profiling protocol
For each case: old baseline runtime + selected optimized runtime (where old is safe); timing by named phase and number of source opens; peak RSS and swap; bytes compressed/uncompressed and temporary; object constructions, canonical hash calls, native fact size; result/consumer hashes and support states; failure reason; cold/warm/cache/rebuild variants. For unavailable real authorizations, use source-free synthetic fixtures for engineering and mark as fixture-only, never promote to original scientific proof. Host runtime and component versions recorded.

## Storage/invalidation rule
Persist source immutable; durable source/semantic receipts and learned products; versioned regenerate-on-demand Parquet/Zstd acceleration only where safe and useful. Cache manifest binds source SHA, current accepted decoder, source-native config, crosswalk, projection, exact science authority roots, topology, code version, cache schema and payload digests. Cache must be locally private outside Git. No raw original respondent data in worker PRs or public receipts. Atomic staged write + fsync/manifest commit; verify before reuse; corruption deletes/quarantines derived cache, not authoritative source. Cache losing ability to regenerate is an integrity failure, not permission to take cache as truth.

## Full-domain vs sparse counting
Implement sparse observed joint maps for counting, but retain exact declared value-domain identity and supported explicit zero cells in native released fact. Use streaming domain expansion where required; high-cardinality Cartesian output can dominate mathematical count work. Distinguish undefined ratios and zero denominators from 0 support. No unbounded dense cross product that OOMs a 16-GiB host; obey existing refusal semantics.

## Search/computation economy
Avoid blind all-pairs first. Execute legally required full catalog when the acceptance law actually demands it, with shared grouped computation. Run high-value substantive recursive, conditional, source-position frontiers through appropriate science grammar, not hardcoded manual questions. Keep complete source/operation reachability ledgers, negative/held distinction, not yet executed. Support repeated query reuse and source-released native products. No premature pruning that hides minority or high-order patterns; rank for work scheduling only under approved non-exclusive policy.

## Negative economics traps
- Compressing 7.91GB pickle files only: disk may improve but object loads and I03 repeated queries persist.
- “batch runner” scheduling with per-query I03 hot path: no shared counts proven.
- New standalone SQL engine: risks a second semantic owner, query divergence and prolonged integration.
- Putting all events into persistent Python dict and calling it virtual: no memory economy.
- Precomputing all conditionals for every value of every variable: potentially huge and unnecessary without an explicit consumer/catalog obligation.
- Treating cache hashes as scientific/authority identities; treating source SHA alone as permission.
- Requiring complete all-pairs before a real consumer: unnecessary dependency.
- Attempting complete structural or actor production from survey correlations alone: scientific authority failure.
