## Why this exists

The principal requires whole-project historical and functional fidelity, production-economical engineering, and no worker assertion accepted through confidence alone. An independent worker cannot be guaranteed infallible. This HQ therefore **does not use “fully grokked” as a substitute for bounded scope and verifiable evidence**. No independent worker is granted sovereign whole-machine judgment.

**Choose exactly one mode for each task before launch:**
- **HQ-OWNED DECISION / DIRECT INVESTIGATION:** Browser Architecture HQ reads the originals, analyzes and settles the issue itself. Delegate only narrow corroborating facts if necessary. Mandatory for changes to the selected architecture, C11 logical/physical boundary, scientific meaning/identity/replay, query-estimand law, Authority-37 fracture-map preservation, cross-subsystem contracts and final Codex goal integration.
- **BOUNDED RABOCHII INVESTIGATION:** Worker examines a closed list of exact files/refs/symbols or one precisely limited interface/question. Output is **evidence and a candidate engineering recommendation, not an adopted decision**. Worker must positively delimit what is outside scope and unknown. This is the default for parallelizable forensics and mechanical specifications.
- **FULL-CONTEXT INDEPENDENT INVESTIGATOR:** Only with an explicit exceptional commission containing the complete mandatory source corpus and a realistic verifiable orientation test. Full understanding must be demonstrated, not promised; still not sovereign. **No such task is currently commissioned.**

If a question cannot be bounded and its facts cannot be independently verified without reproducing whole-project reasoning, HQ retains it directly. Time pressure does not relax this.

## Minimum bounded commission contract (no omissions)
1. **Exact question and boundary:** one testable deliverable, explicit upstream input, exact consumer/expected output; no “solve the system.”
2. **Source cut:** repository/ref and full startup commit SHA, file path+blob SHA for every material code file, version of current user packet and relevant adopted governing docs. Verify the material is actually available before claiming an inspection.
3. **Positive inspection list:** symbols/methods/files/tests actually read; range or whole-file status; search commands and scopes where the worker asserts nonexistence.
4. **Explicit exclusion list:** files/branches/waves not examined; source permissions absent; whether actual process/runtime/response values were available; incompatible contemporaneous code still unknown.
5. **Claim/evidence ledger:** for every material claim, stable ID, category, exact citation/path+line/symbol/ref, confidence tied to evidence, affected output/invariant, alternative explanation, what would falsify it.
6. **Epistemic labels:** DIRECT_CODE_OBSERVATION, EXECUTED_SOURCEFREE_PROOF, EXECUTED_ORIGINAL_QUALIFIED_PROOF, ADOPTED_AUTHORITY, MEASURED_HOST_COST, INFERENCE, HYPOTHESIS, NOT_INSPECTED, BLOCKED_BY_PERMISSION, HISTORICAL_ONLY. Do not promote between labels.
7. **Narrow recommendation:** one candidate implementation adjustment *within the already-selected architecture*, what existing function it reuses, exact interface and risk; no unreviewed changes to semantic ownership/identity.
8. **Negative/uncertainty disclosures:** precision of any nonexistence or impossibility assertion, unresolved conditions and science questions, relevant counterexamples, nonvalidated assumptions and missing host measurements.
9. **Acceptance oracles:** source-free positive, negative and restoration; real-source tests only under specific grant; exact SHA/native-ref/replay/denominator/zero/topology/consumer checks; independent oracle avoiding common-mode error.
10. **Handback:** exact stage and CodeX receiving owner, writer conflicts, anticipated CPU/RAM/disk, verification cost, and a concise “WHAT I HAVE NOT PROVEN” section.

**Prohibited:** assertions of global completeness from branch-local search, negative evidence from a nonexhaustive repository search, inherited PASS from unrelated source/estimator versions, fixture-to-original promotion, speculation labeled measurement, a worker ranking or changing A/B/C, code changes or source execution outside commission, self-certification, a new architecture proposed as an accidental dependency.

## HQ fact-ingestion / non-contamination gates

**G0 SCOPE:** Reject any return lacking exact bounded question, cut, inspected corpus and exclusions. A “fully grokked” assertion is never a PASS.

**G1 SOURCE IDENTITY:** HQ fetches and reads the actual referenced source for every design-critical claim. At minimum independently check file blob SHA, relevant function, actual caller/consumer and a potentially contradictory adjacent owner. For nonexistence claims require positive enumeration of search scope and unresolved unsearched areas; absent source implies UNKNOWN, not MISSING_CODE.

**G2 SEMANTIC JURISDICTION:** Reconcile every worker proposal with accepted C11/I03/I05/I04 contracts, original semantic owner, source permission, all35 and the direct DAG. A proposed useful computation does not make an admissible structural/person claim.

**G3 INDEPENDENT ORACLE:** For every critical code/evidence identity claim, require an independent old/accepted or otherwise separately constructed oracle, exact expected outputs and negative/restore. A worker's own test of their own calculation is insufficient. “TEST PLAN” is not “EXECUTED TEST.”

**G4 COST EVIDENCE:** Explicitly separate mathematical cost estimates, source-free microbenchmarks, actual native host timing, complete cold/warm lifecycle, and expected multi-wave scaling. Never declare a ratio measured if not measured.

**G5 CROSS-SEAM INTEGRATION:** HQ personally reconciles P01 C11, P02 physical cache, P03 query, P04 provenance, P05 consumer/replay, P06 fracture map and downstream P07–P10. A plausible local patch is not architecture-complete.

**G6 ADVERSARIAL REVIEW:** P11 is performed by an independent reviewer of the **integrated** design. HQ still reads and independently adjudicates each material falsifier and preserves unresolved risks. Reviewer's silence or sample checks do not globally certify unexamined work.

**G7 CODEx READINESS:** Only an HQ-integrated specification with exact edits, types, algorithms, tests, resource ceilings, permission gates, rollback and actual consumer can become a Codex commission. Build worker then needs no A/B/C strategy choice. Design guidance and code execution rights remain separate.

Every return yields **ACCEPT_AS_EVIDENCE / ACCEPT_WITH_BOUNDS / REJECT / HOLD_UNVERIFIED / ESCALATE_SPECIFIC_OWNER** for each claim, not one giant holistic PASS. HQ maintains the accepted claim ledger and resolves contradicting returns against actual source.
