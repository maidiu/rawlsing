# Target architecture: exact boundaries, invariants, data flow and implementation choices

## A. Non-negotiable meaning
The output is a source-grounded possibility/world/person machine, NOT a survey dashboard or all-pairs table compiler. No generated respondent biography, class mechanism, personality or historical transition follows automatically from an observed response. Facts, interpretations, structural admission, situated world opportunities, actor realization and speech belong to distinct producers.

## B. Source-to-person DAG (logical, not one physical courier chain)
SAV/DTA immutable evidence [source/decoder authority]
 -> physical incidence and exact source-normalized events [existing decoder/admission]
 -> governed source projection, value/state/topology mapping [current source config, GovernedC11Projection]
 -> logical validated C11 release/repository [I02 ownership]
 -> transient/optional cached exact respondent-aligned computational view [nonsemantic implementation]
 -> I03 exact query + native fact issuer [existing authority/predicate/denominator]
 -> I05 exact AND result-driven recursive discovery [scientific authority]
 -> N3 family validation, learned empirical release, service [applicable qualified owners]
 -> N10E empirical possibility slices (can also consume I03 directly as authorized)
 -> F5 Field Forge structural/context admission + N6 world-object producers
 -> F6 source-indexed field composition, F7 comparable waves/time
 -> N9/ N10W objective world + conditioned possibilities + N11 acceptance
 -> separately authorized Sorok/V3 dynamic person, relationships, need/pressure mediation
 -> V2 permitted expression.
Direct producer reuse and DAG edges are valid; a stage is not required to recopy every upstream artifact. Pipeline does not serialize all arrows unnecessarily. Source-not-world, world-not-person, person-not-expression.

## C. What is physically authoritative and durable
P0: Original immutable source snapshots (.sav/.dta) and SHA, authorized documentary codebooks/metadata, source rights/custody.
P1: Frozen parser/decoder/canonicalization version, exact source/semantic owner authority and source/time/identity/crosswalk sidecars that cannot be inferred from bytes.
P2: Logical C11 source-release identifiers, essential irreducible bindings, exact certified replay/closure roots and original successful release receipts.
P3: Accepted empirical/scientific learned products, per-operation source/denominator/contract references, valid negatives, family adjudications, published release manifests and exact resolution identities.
P4: Accepted independently produced structural, temporal, positioned-world and actor-independent publication products.
Non-authoritative Pcache: compact respondent-aligned data, event tables, decoded dictionaries, predicates, bitmasks, materialized group counts, row lookup. All strictly rebuildable; deletion cannot change what is theoretically queryable, supported or refused.

## D. Exact source identity and row/event topology
Key source by exact snapshot SHA and versioned decoder/configuration/authority roots. Key respondent by exact source-scoped respondent identity (source_snapshot_id, row ordinal or validated source respondent key), not by arbitrary dataframe index. A question may have 0/1/many component occurrences and ordered/ranked/multiple-selection relations. For scalar-authorized fields use typed integer code arrays, with explicit source-value dictionaries and state masks. For non-scalar fields use a typed event/occurrence table and fast source-scoped indexes; do not deduplicate by (respondent, canonical_question) unless proved. Retain original physical missing states distinct from semantic answer states and routing applicability. Country, time, household, coordinate and weight/design domains must be explicitly governed.

## E. Source-backed cache interface (existing owners, no new public semantic family)
Use a PRIVATE implementation adapter behind accepted facade/repository contracts; do not create a second scientific owner. Suggested internal capabilities:

- open_verified_view(exact_source_release_ref, allowed_operation_scope) -> immutable working view
- iter_physical_cells(), iter_response_events(), lookup_exact_event(ref), lookup_respondent(source_key), vector_for(source_question/component)
- qualifying_mask(condition_ast, risk_set, response_state_policy), resolve_exact(ref)
- count_grouped(operation_specs), produce_native_evaluation_inputs(op), reconstruct_native_release_or_object(exact_ref)

These are illustrative *internal* seam signatures, not granted or existing published interfaces. Browser interface court must nail actual signatures, call paths, return types, and who owns every check before Codex edits.

No new route-selection logic inside this adapter. It implements selected source-authoritative hybrid behavior.

## F. Backend commitment and implementation bounds
- In session: source-native dictionary-encoded numeric/string code vectors, typed state arrays/masks, optional packed bits by actual predicate frequency, exact source/event references. Use NumPy/Arrow-compatible immutable structures; no generic SQL query engine re-owning I03 semantics.
- On disk: source/release/version-keyed **Parquet with Zstd compression** for permitted/qualified regenerable columnar/event accelerators, plus a small hashed manifest and atomic publication. Reuse verified original V550 shared-index patterns and A69 R5 compact/codec/integrity code where code-dependency-compatible; no compulsory historical R5 persistent canonical substrate.
- Preserve event-table generality. Never claim Parquet replaces native source meaning; the source and authority remain reconstruction determinants.
- If currently deployed dependency constraints prevent Parquet/Zstd, Browser architecture group must return exact dependency blocker, minimum pinned addition or function-equivalent physical detail WITHOUT reopening A/B/C choice. No unconstrained tool shopping.

## G. Cache identity/invalidation
Cache key includes exact source SHA, decoder implementation and compatibility identity, source config/crosswalk/projection digests, semantic/response authority roots, source universe/topology version and cache schema/algorithm version. Query/predicate/risk masks bind full operation and authority/risk scope, including missingness policy and version. Never treat cache presence as authorization; query execution still passes native permission/authority checks. Fail closed on source mismatch, stale authority, corruption, bad manifest, wrong topology and partial write; atomic replacement and deterministic regeneration. Prove stale/missing cache changes wall-time only, never output or allowed discovery graph. Stable logical output/replay hashes independent of the cache hit (where current contract says so).

## H. Logical C11 adaptation is the highest-risk seam
Current C11LogicalRelease holds full public_objects/internal_records tuples and C11Repository globally indexes exact native objects; SourceBackedFacade builds full candidate tuples. This is why naming a view 'virtual' did not make hot-path computation cheap.
Required implementation:
1. Keep accepted logical release identity and sealed validation (no constructor bypass).
2. Separate source binding/certification, computational state and public native object realization. A verified lazy resolver may reconstruct exact semantic objects on demand; a streaming source projection may calculate exact release root without all objects resident concurrently.
3. Native repository consumers must see identical exact identity, closure, event ordering, negative states, right/refused operations and replay; preserve arbitrary exact ref lookup.
4. Use a compatibility facade for any legacy owner that still requires materialized C11LogicalRelease; keep this bounded and explicit; never silently attach unvalidated arrays to repository.
5. Avoid mandatory creation of complete public_objects.pkl and replay_manifest.json expansion on every compile. Either stream exact canonical projection to signed/digested logical release, or retain minimal compact reconstruction proof and expand exact native objects only when consumer requires them. Changes to required canonical representation/field identities are a separate versioned owner decision.

## I. Compute API within existing I03 engine
Use existing EmpiricalQuerySpec, EmpiricalPredicate, AuthorityRegistry, risk/routing owner, observed-response contract, QueryExecutionResult, EmpiricalFact and exact replay owners. Add/replace implementation planner/executor only behind their approved native API:
- Compile predicate/risk/missingness once per scope; evaluate exact membership.
- Share respondent-aligned source vectors and masks.
- Batched marginals, compatible joint/fractional conditional evaluations, k-way conditioned patterns and branch intersections. Exact denominator is operation-specific; eligible/observed/weighted estimands never conflated.
- Complete declared output domains and supported zeros are maintained, with sparse numeric internal counters only if native expansion is preserved.
- Native issuer constructs each actually requested/required fact and preserves query-specific provenance, full support and exact replay. Deriving ratios from shared joint counts is not publication of both directional conditional products.
- High-cardinality controls are memory-safe: no automatic dense Cartesian allocation of gigantic numeric domains; explicit refusal or streaming domain enumeration according to approved contract, never omission disguised as zero.

## J. Evidence materialization and replay
Current native EmpiricalFact@1.0.0 and _make_execution_replay_ref hash inline membership/cells and used object refs. First optimize WITHOUT changing their semantic projection: precompute canonical invariant fragments, avoid redundant object decoding, stream deterministic canonical hash material, reuse immutable provenance determinant structures internally, emit old exact objects. Only when a measured bottleneck remains may an independently authorized versioned compact-evidence-reference successor replace inline refs; treat as an explicit contract and consumer migration, not hidden optimization.

## K. Operational scheduling
- Stream/commit per-operation durable native facts and truthful exact receipts, no in-memory-only 91-operation progress.
- Recovery resume MUST reload exact fact/cell/consumer content or resolve it by exact ref; empty cells=[] placeholders cannot stand for valid native results.
- Consumer executes as soon as its exact unary/conditional/discovery preconditions pass; does not wait for other 15,575 pairs.
- Scheduler maintains states: planned, authorized, selected, executed, refused, held, resumable, native-released, consumed. Cached calculator availability is NOT executed fact state.
- Workload construction is source-complete within lawful authority and scientifically meaningful frontiers; no arbitrary field limit; preserve residual denial ledger.
- Separate cold build from warm reuse and actual all-35 programs. Current SRC04 q217 held; do not make a mapping issue a global block.

## L. How we preserve the actor destination
Source empirical patterns condition warranted social possibilities, not direct actor beliefs. Field Forge provides separately qualified structural priors/fields/relations. V3 generates own relationships, family histories, needs, contradiction, encounter, choices and change. V2 renders only what actor may know/express. No privacy-violating source respondent copying into an actor record. Variation, minority, social position, history, absence and misrecognition must survive every information-losing boundary.
