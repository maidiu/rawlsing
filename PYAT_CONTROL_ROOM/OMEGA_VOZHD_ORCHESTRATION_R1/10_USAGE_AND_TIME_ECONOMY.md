# Usage and elapsed-time economy

[Start](README.md) · [Routing](02_CAPABILITIES_AND_ROUTING.md) · [Metrics template](templates/economy_sample.template.json)

## Optimization objective

Maximize independently accepted, reusable functional progress while preserving all required semantics and proof. Minimize finite-model usage, user coordination, repeated retrieval and avoidable elapsed time. Do not optimize tokens by concealing uncertainty, dropping required scope or skipping a necessary execution.

Treat browser Sol High's zero finite-usage impact as a user-supplied account premise, not a measured universal product fact. CI compute, storage, session limits, user intervention and review time can still be costly. Track actual telemetry when available; use null plus a reason when unavailable. No invented token counts, zeroes or speedup estimates.

## Default allocation

Browser Sol High does the ordinary reading, code, tests via supported execution routes, review, evidence assembly and HQ coordination. Deterministic scripts do counts, hashes, reference checks and table joins. Codex is a bounded fallback. Astra handles Omega-1/Omega-2 and triggered disputed decisions, normally on High. Extra High is considered for a particular consequential unresolved synthesis; Ultra only when a demonstrated hard problem justifies the additional effort. No worker silently upgrades itself or recursively dispatches paid work.

## Context economy

Each worker receives one job, exact base, output, allowed paths, required input list and acceptance cases. Include three knowledge bands: MUST_READ_NOW, READ_IF_TRIGGERED, and BACKGROUND_LINK_ONLY. The full atlas remains available but is not mandatory repeated reading. Extract each inspected artifact once into an exact evidence record and reuse it. Reopen only on identity drift, contradiction or a named missing detail.

The HQ hot context contains current checkpoint, short task board, contracts currently being changed, acceptance deltas and unresolved decisions. Store full logs and historical proof in repository artifacts; report links plus decisive excerpts. Use a fresh scoped worker/context when it is cheaper than repeatedly compressing an overloaded chat. Preserve task/branch/return identity across the handoff rather than rerunning completed research.

## Concurrency economy

Initially keep at most three productive C1/C2/C3 lanes plus a reviewer role when capacity allows; this is an adjustable scheduling default, not a claimed platform limit. Increase concurrency only for disjoint outputs with ready inputs and an available reviewer/integrator. Shared decoder or analytical interface files have one writer. Do not run competing implementations of the same task unless an explicit experiment will decide between them.

HQ dispatches the next ready task on a meaningful event: completed return, blocker, failed test, contract change or capability change. Use supported completion/status tools; do not repeatedly reread entire chats or poll unchanged branches. Long waits and dormant sessions require an explicit supported continuation mechanism; never promise that an idle browser agent will autonomously wake itself.

## Avoid busywork

No broad historical archaeology after a competent exact binding exists. No 35 redundant source runs when generic law and explicit exception proof cover the required scope. No giant suite after a documentary-only change. No new administrative document for every message: update the task record, contract or receipt that owns the fact. Seal control state when the handoff protocol requires it, not for every exploratory thought.

## Measurement and adaptation

After the first representative return in each lane, record elapsed time, active reasoning/turns/tokens if exposed, test run time, queue time, finite usage charged if known, reviewer defects, accepted-case coverage, retries and rework. Compare total time-to-accepted-result, not time-to-first-patch. Do not run expensive duplicate-model benchmarks just to justify the strategy.

Escalate to Codex on a verified capability blocker or when observed browser repair/coordination cost outweighs one bounded Codex job. Return ownership to browser HQ afterward. Escalate reasoning to Astra for the judgment triggers, not for volume. Stop successful testing once the required affected checks pass unless a new change, failure or unresolved concern justifies more.
