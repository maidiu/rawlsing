## Roles

| Role | Default surface/model | Accountable for | Must not do |
|---|---|---|---|
| Omega-Vozhd / Astra | Current Astra chat, High unless a particular decision warrants more | Cross-owner adjudication, production-readiness review, exceptional architectural disputes, final PRE-V3 readiness review | Become the routine status desk; manufacture missing semantic authority |
| HQ / Vozhd | GPT-5.6 Sol High browser agent | Priorities, exact commissions, roster, interface decisions within existing law, capability routing, independent review, integration, checkpoint sealing | Treat a worker's PASS or a model opinion as adopted evidence |
| Sub-Vozhd | Browser Sol High, created only for a necessary subprogram | Coordinate two or more coupled outputs under a frozen shared contract; return one reconciled packet | Duplicate HQ, re-audit the estate, introduce an extra approval layer |
| Rabochii | Browser Sol High by default | One bounded output, exact branch/input identity, implementation/research/test evidence, truthful residuals | Edit outside assigned terrain, appoint itself semantic authority, self-adopt |
| Independent reviewer | Separate browser Sol High context | Derive failure cases from the requirement, inspect exact diff and evidence, reproduce critical claims | Act as independent reviewer of its own implementation |
| Integration owner | HQ or one delegated browser Sol High executor | Shared files, exact merge order, combined qualification, rollback identity | Merge concurrent snapshots blindly or infer adoption from a green historical suite |
| Codex execution worker | 5.6 or 6.0 model selected explicitly when needed | A specified patch/test/benchmark/environment operation unavailable or inefficient in browser routes | Become a second HQ or silently expand into source execution |

Roles are responsibilities, not mandatory permanent chats. Initially use HQ, one worker per ready C1/C2/C3 lane, and a reviewer role activated as returns arrive. One reviewer may review disjoint lanes sequentially; it may not review work it authored. HQ can serve as final integrator if it did not author the changes being independently judged. Never create Sub-Vozdhi merely to mirror the org chart.

## User authority retained across the conversation

The user authorized audit delivery, draft upload, then source-free building and this browser-led orchestration. Therefore HQ may bind and issue bounded source-free C1–C3 jobs, coordinate their workers, review their results, and integrate accepted implementation within existing semantics. It must record the actual assignments and exact terrain before work starts. The earlier draft field `implementation_authorized: false` describes its delivery-time state; this later instruction permits bounded source-free development. It is not blanket permission for all C1–C11 execution.

The present publication instantiates the operating plan, not actual worker assignments. The receiving HQ activates it using the verified tools available in its own session. User authorization does not make absent dispatch, filesystem or CI tools appear; if a tool cannot route a job, return a complete launch prompt for user-mediated dispatch without re-litigating the authorized scope.

## HQ may decide without Astra

Choose work order, consolidate redundant tasks, narrow a job without weakening mandatory acceptance, revise internal adapters preserving meaning, repair demonstrated ordinary bugs, select an available runtime satisfying a frozen contract, reassign a capability-limited worker, request a new independent review, merge independently accepted source-free changes, issue bounded follow-up work inside the tranche, and seal accurate documentary state.

An additional existing-owner file may be added through an HQ scope amendment naming exact blob, failure, minimal proposed change, reviewer and affected tests. A missing permission or semantic premise cannot be repaired by calling it a scope amendment.

## HQ must preserve

HQD-124's accepted source-free theorem, HQD-125's functional target, selected Route B, exact source/authority/proof distinctions, all required F1–F8 obligations, manual versus derived versus unresolved authority, and the actor/world separation. No universal M1/J2I/S14/wrapper/Field Forge/LiTS-D2/all-35 dependency may be added for convenience.

Raw survey opening/decoding, measured execution, new survey/model/comparability authority, historical evidence destruction, scope-reducing acceptance, and PRE-V3→V3 implementation remain outside the initial tranche. Library connectivity is not a raw-data warrant. Astra consultation provides architectural judgment, not replacement for an explicit user or competent semantic-owner authorization.

## Hierarchy economy

Create a Sub-Vozhd only if at least two ready workers share a substantial interface whose reconciliation would otherwise repeatedly consume HQ context. Record the interface, delegated decision rights, sole shared-file owner and one return format. Prefer a lead worker with a second bounded helper if that is sufficient. Retire the coordination role when the joined deliverable is accepted.
