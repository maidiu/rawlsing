# When HQ should consult Astra

## Two expected consultations; exceptions are event-driven

**Omega-1 — production readiness.** When the first scoped source-free analytical join has independent acceptance and enough authority/physical-path evidence to propose the next production/structural workload, ask Astra to assess that scope, the minimal proving set, contract fidelity and residual risks. Do this before acting on that new production decision. If a proposed source/semantic boundary arrives earlier, consult then with the available evidence. Do not wait for irrelevant C2/C3 work. Independent source-free work can continue while the affected scope waits.

**Omega-2 — PRE-V3 readiness.** After C9 presents competent joined F1–F8 evidence, consult Astra before claiming full objective-world readiness or recommending the later actor seam. Astra may recommend continued deferral; an empty/refusal-only world or unresolved mandatory positive obligations cannot pass. User/competent authority still controls any actor implementation.

These are deliberate control points in this operating plan, not claims that Sol is inherently unable to reason about those topics. They concentrate finite Astra usage on decisions whose errors propagate through the program. No periodic Astra status meetings, mandatory review per PR, or obligatory check-in after every subphase.

## Recognizable scope boundaries

| ID | Observable trigger | Required first response | Astra? |
|---|---|---|---|
| E01 | Two adopted authorities prescribe incompatible behavior for the same exact grain | Freeze the affected decision, resolve chronology/succession and obtain independent comparison | Yes if not resolved by explicit later authority |
| E02 | Proposed repair changes semantic grain, required proof, owner jurisdiction or established negative meaning | Preserve a minimal before/after example and exact owner contracts | Yes before that change |
| E03 | A mandatory capability cannot be represented by current owners without loss | Show downstream requirement, attempted current routes and minimal counterexample | Yes; no architectural layer by aesthetic preference |
| E04 | Source-free proof is proposed as permission/readiness for a new live or structural workload | Package exact workload, selected identities, authority, runtime/oracle and retention plan | Omega-1; separate source warrant still needed |
| E05 | Full-estate/F1–F8/world maturity or actor-seam readiness is about to be asserted | Submit complete required claim/evidence ledger and residuals | Omega-2 |
| E06 | Worker/reviewer disagreement persists over required behavior after exact evidence and one independent diagnosis | State competing interpretations, counterexample, tests and downstream consequences | Yes if HQ cannot resolve using existing authority |
| E07 | Integration exposes loss of provenance, negative states, currentness or dependencies across owners | Attempt a bounded existing-contract repair and re-test | Yes if repair needs new meaning/ownership or the contradiction remains |
| E08 | Fix would reduce required scope, waive an acceptance obligation, infer new pooling/comparability/model law or wake actors | Stop that proposal; identify missing competent authorization | Astra for judgment plus user/semantic owner for authority |
| E09 | Suspected corrupted evidence, identity tampering or silent source access invalidates trusted proof | Quarantine affected claims; preserve evidence; diagnose exact extent | Astra if program-relevant trust/claim validity is disputed; user for access incident |
| E10 | Apparently small decisions accumulate into a materially new interface/program scope | Compare cumulative contract diff against last accepted scope | Yes before treating the new scope as inherited |

A missing authority cell is usually a truthful typed residual, not an Astra emergency. Escalate it when the required next scope cannot proceed lawfully and owner/precedent adjudication is genuinely unresolved. Likewise, a code defect, missing dependency, unavailable Library item, merge conflict or runner failure is not automatically above HQ's scope.

## Routing test at every material decision

Ask: (1) Is the actual capability available? (2) Is the action already authorized? (3) Does a competent exact rule decide the behavior? (4) Can the claimed result be reproduced at its stated grade? (5) Would this change a downstream contract or acceptance obligation?

Capability failure routes to an execution worker or user-assisted launch. Missing access/permission routes to the user or resource owner. Ordinary bounded defect routes to the worker. Missing authority routes to its owner with a typed residual. Unresolved cross-owner meaning, changed acceptance or program-level proof upgrade routes to Astra. If several apply, keep all routes; Astra cannot waive the other requirements.

The machine classifier is only a routing aid for already-classified facts. It does not infer truth from a worker's confidence or prove a semantic premise. Unknown issue types return HQ_TRIAGE rather than auto-proceed.

## Minimal Astra packet

Use one decision question, preferably with at most three meaningful options and HQ's recommendation. Include trigger ID, exact current checkpoint and affected commit/blob identities, a reproducible counterexample or accepted proof, relevant contract excerpts, attempts already made, material downstream implications, what may continue independently, and the exact requested decision. Aim for a 1–2 page decision brief with linked artifacts; include necessary evidence regardless of length.

Do not send a whole transcript, a request to redo the audit, or a batch of routine status reports. Batch related issues sharing one contract; keep unrelated questions separable. Ask Astra for a decision and conditions, not for another general plan.

Astra response states scope, evidence, decision, limits and next review trigger. HQ persists it and updates only affected commissions/checkpoints. Silence, elapsed time or model unavailability is not approval. Keep the affected transition waiting while advancing unrelated authorized work.
