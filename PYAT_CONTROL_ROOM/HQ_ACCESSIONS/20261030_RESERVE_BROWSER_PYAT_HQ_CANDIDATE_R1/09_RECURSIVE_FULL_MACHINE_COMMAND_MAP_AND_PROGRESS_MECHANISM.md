## Design principle — a complete map that can be traversed at arbitrary scale
Use **one logical capability/evidence graph** with multiple derived views, not many competing enumerations. The node is *a distinct required/implemented/claimed function and its actual effect*, not one branch, one source item, one document or one worker. A branch may support several function nodes; many branches may share a function. Every significant claim ties to a content-addressed source + owner + maturity + real consumer. Unknown is explicit.

**L3: Verified implementation and authority edges.** Exact owning functions/classes, source releases and grants, program DAG dependencies, foreign imports, review/test/defect edge, actual observed-world output, transport identity and real selected consumer; show separate SOURCE/SCIENCE/ENGINEERING/REVIEW/ADOPTION grades. **L4: Small coherent execution packages.** Concrete first input, permitted transformation, expected output, current receiving function, falsifier, reviewer, model/editor/host/cost and lease, status and last verified exact commit. A package must demonstrably move its L3 parent and terminal L1/L0 effect, or state why it is a crucial prerequisite (not a terminal substitution).

No manual cherry-picking. U_item / U_unit / U_app / E_pre distinct.

Every L5 item references its parent L4 operation and L3 implementation; every L4 package references L3/L2/L1/L0; every L1 macro traces real N11/actor-world terminal test. The UI/reader must be able to zoom in/out; there is no global “70% done” across unlike classes. Provide filters by source wave, science type, function, branch, owner, blocker, milestone and consumer.
