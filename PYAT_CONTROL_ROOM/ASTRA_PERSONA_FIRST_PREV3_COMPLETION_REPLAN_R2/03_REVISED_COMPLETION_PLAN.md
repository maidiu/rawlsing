# Deliver a usable loop, then strengthen and scale it

The owner's decision needed at implementation issuance is concrete: **permit a bounded V3 prototype using versioned provisional model policies before full PRE-V3 estate completion.** This audit does not activate V3. One approval should cover normal reversible parameter/method choices within that envelope, avoiding a new permission ceremony for every imperfect estimate.

Two lanes run concurrently: product T00→T01/T02→T03, and coverage/trust T05/T06→T07/T10. T08 strengthens historical/material inputs alongside the product lane. Full production T11 retains the complete certificate; the first useful person does not wait for all 35 waves.

Planning estimate, not a measured promise: aim for the first inspectable loop within 3–5 focused engineering days after issuance. T01's first-session smoke result controls that estimate. If the runtime cannot execute, return the smallest failing seam and repaired smoke run, not a new general architecture report. Start with one engineer per writing terrain and a distinct reviewer; parallel lanes may be sequential on one machine without changing logical dependencies.

A research timebox ends in a method choice or an explicit fallback. It does not automatically extend. Broad priors, ordinal categories, nearest qualified temporal anchors and simplified family transitions are acceptable prototype modes. Preserve unsupported uncertainty rather than fabricate evidence or block every dimension. Freeze an as-of snapshot when lawful prototype use does not need production CURRENT selection.

## T00 — Delivery contract and provisional-policy decision

Owner: Product owner + existing model-use owner. Depends on: none. Timebox: First session.

Freeze usable output, two contrast scenarios, fallback ladder and bounded V3 prototype scope. Pin candidate runtime and interface; a manifest is sufficient.

Exit: Owner accepts bounded prototype policy and eight-case evaluation contract; engineering can implement without repeated method permission requests.

Discriminating failure: Policy ambiguity cannot create observed facts; source access and actual trust requirements remain operation-local.

## T01 — Pin and run the inherited developmental baseline

Owner: Developmental/runtime engineer. Depends on: T00. Timebox: One focused session.

Compare adjudicated archive against local V3/V2 manifest; select one baseline; run its permitted isolated source-free smoke path.

Exit: One replayable actor history and state-backed expression, even with declared broad priors; exact blocker repair if run fails.

Discriminating failure: No first-candidate bypass, unlogged randomness, invented diagnosis or renderer mutation.

## T02 — Bind useful retained inputs to a world/possibility snapshot

Owner: World-service/C1 integration engineer. Depends on: T00. Timebox: One focused session in parallel with T01.

Reuse M1–M4, rich C1 and P04 seams; carry selected release, context, joints, uncertainty and evidence modes to a concrete developmental input.

Exit: Saved snapshot plus receipt proves consumer reads values, not just context IDs. One genuine retained empirical dependency plus explicit model fallbacks.

Discriminating failure: False joint, wrong population, denominator loss, ignored world payload, CURRENT claim on frozen snapshot.

## T03 — Deliver the first evaluated person loop

Owner: Integration engineer + independent product reviewer. Depends on: T01, T02. Timebox: Target 3–5 focused engineering days from issuance, contingent on baseline smoke test.

Wire snapshot→developmental transitions→state→expression. Deliver 16 seeded cases across matched contrasts, browseable biography and evidence trace.

Exit: Eight-case suite in 02/06 passes at prototype scope; user can inspect and compare real outputs. Report failures and ship the honest simpler mode.

Discriminating failure: A generic biography pasted over unchanged state, deterministic stereotypes, empirical labels on priors or fabricated childhood facts.

## T04 — Improve only the weak methods exposed by the loop

Owner: Methods engineer + independent held-out evaluator. Depends on: T03. Timebox: One method decision per focused session.

Compare baseline against at most one stronger candidate per gap: pooling, temporal smoothing or proxy/latent mapping. Keep same inputs/consumer.

Exit: Demonstrated product/calibration benefit or explicit no-replacement decision; deploy simpler fallback if inconclusive.

Discriminating failure: Training-test leakage, minority erasure, spurious certainty and higher cost without downstream benefit.

## T05 — Integrate original-work automation and omission oracle

Reuse P01/P05 constructors, freeze original U/E before execution, integrate exact candidate delta and bind first lawful real slice.

Exit: Original→expected→declared→durable result→actual consumer receipt; positive omission adversary fails.

Discriminating failure: Output-derived expected set, held item silently dropped, directional/J-only omissions, inconsistent recovery.

## T06 — Close invoked release and recovery trust gaps

Owner: Lifecycle/security owner + distinct reviewer. Depends on: T00. Timebox: Parallel; prerequisite only for invoked protected mode.

Preserve N04 correction; test P02R/N04R remaining history, wrapper and external-root gaps on exact selected path.

Exit: Declared trust promise proved for exact modes; current/as-of effects and affected descendants correct.

Discriminating failure: Self-consistent forged history, revocation bypass, unwrapped CURRENT access, false independent root.

## T07 — Expand generalized source and operation coverage

Owner: Source/design owners and empirical production engineer. Depends on: T05. Timebox: Rolling small resumable batches.

Keep all 35 sources and finite issued operation frontiers; prioritize product demand then remaining functions. Use generic contracts, not bespoke selected-question scripts.

Exit: Per-source original/operation/consumer reconciliation, typed holds and no silent loss. Full35 remains separate exit.

Discriminating failure: False N/A, skipped battery child, raw design fabrication, suppressed low-frequency branch, partial frontier called complete.

## T08 — Complete useful institutional and temporal channels

## T09 — Qualify richer product and independent release

Assess source transfer, minority configurations, cohort effects, parent priors, replay and narrative fidelity; use live outputs.

Discriminating failure: Pretty prose conceals invariant state or unsupported confidence; reviewer merely repeats author oracle.

## T11 — Full production activation decision

Owner: Project owner and competent release authority. Depends on: T09, T10. Timebox: Separate final decision.

Review full certificate, product evidence, runtime custody and support/recovery plan.

Exit: Explicit full-production activation decision; bounded prototype approval is not automatically full activation.

Discriminating failure: Silent scope escalation from prototype, stale exact candidate or self-adoption.

## Working rule for the next HQ

Every new commission names the next artifact a product user can inspect, or the specific failing dependency needed to produce it. Every method hold names an alternative mode, its honest ceiling and its owner. Research resumes only when its result could change a current implementation decision. Technical PASS, independent review, adoption and activation remain distinct; do not create duplicate tests merely to rename a historical owner.

Do not expand native/runtime hardening onto the product critical path unless the selected mode actually invokes that trust boundary. Conversely, a frozen development mode must not silently bypass a required protected call. This is scope selection, not permission evasion.
