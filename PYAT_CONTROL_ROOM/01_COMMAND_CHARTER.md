# VOZHD PYAT — COMMAND CHARTER

## Mission

Create one authoritative, zero-loss, current-state synthesis of everything Rawlsing needs to move from governed survey sources through Route B and the complete PRE-V3 machine into a standalone V558 structural artifact set.

Pyat must answer five questions without ambiguity:

1. **What must the machine do?**
2. **Which of those functions/semantics are already settled?**
3. **Which are actually implemented and where?**
4. **Which have real-source and end-to-end proof?**
5. **What exact dependency-ordered work remains?**

## Canonical outputs

Pyat must produce:

1. **MASTER_MACHINE_MAP**
   - source → B/C11 → empirical learning → structural production → V553–V558;
   - exact producer ownership;
   - exact consumer edges;
   - no duplicated semantic ownership.

2. **ZERO_LOSS_FUNCTION_LEDGER**
   - each materially meaningful old DDM V550–V552/J function or later successor obligation;
   - prior adjudication;
   - current owner/successor;
   - architecture status;
   - implementation status;
   - proof status;
   - retirement proof if retired;
   - residual action if open.

3. **AUTHORITY_ARCHITECTURE_IMPLEMENTATION_PROOF_MATRIX**
   Each item gets independent dimensions:
   - `VISION_ONLY`
   - `ARCHITECTURE_ADOPTED`
   - `AUTHORITY_ADOPTED`
   - `IMPLEMENTED`
   - `SOURCE_FREE_PROVED`
   - `REAL_SOURCE_PROVED`
   - `COMPOSED_END_TO_END`
   - `SUPERSEDED`
   - `FORMALLY_RETIRED`
   - `OPEN`
   - `BLOCKED`

4. **SEAM_AND_ARTIFACT_CONTRACT_MAP**
   - exact objects/references crossing each producer→consumer boundary;
   - permanence/replay ownership;
   - negative/unresolved state preservation;
   - no downstream reach-back into historical build directories.

5. **DEVELOPMENT_DAG**
   - dependency order;
   - parallelizable work;
   - explicit authorities/implementations/tests needed;
   - canary sequence;
   - 35-source qualification sequence where applicable;
   - final source→V558 acceptance court.

## Scope

Pyat owns program synthesis across:
- current B-route PRE553;
- historical-to-current learned-world function conservation;
- Field Forge canonicalization/adoption planning;
- V553–V558 current architecture/implementation differential;
- all seams required to compose one production chain.

Pyat does not own:
- V3 redesign;
- V2 redesign;
- reopening B vs A/C;
- new survey acquisition;
- ungoverned semantic invention;
- treating exploratory Field Forge language as authority;
- rewriting already-closed Dva architecture absent a concrete contradiction.

## B-route consequence

B means:
- source bytes remain the authoritative physical evidence;
- exact decoder/config/source identities remain replay determinants;
- C11 remains the logical empirical contract;
- Rawlsing semantic authorities persist separately;
- transformed respondent/event payload need not persist merely to preserve truth;
- persistent products should begin where they buy actual semantic/structural value, not merely because an upstream carrier once existed.

## Zero-loss law

Representation may change. Function may not silently disappear.

For every inherited capability, Pyat must show exactly one:
- current owner;
- exact successor;
- formal retirement/supersession with no terminal demand;
- unresolved residual requiring work.

`NO_UNDISPOSITIONED_HISTORICAL_FUNCTION`

## Anti-redo law

Existing Dva/Trii/Chetiri/Long-Memory/W31-W35 archaeology and crosswalks are presumptive starting capital.

Do not re-enumerate old V550–V552/J from raw history unless:
- existing crosswalks conflict;
- current successor is missing/ambiguous;
- current OPEN ledger explicitly requires deeper recovery;
- consumer-demand audit reveals a function absent from the inherited ledger.

## Field Forge law

Field Forge is valuable but exploratory.

Every Field Forge concept must be classified as one of:
- `CURRENT_SUBSTRATE_ALREADY_OWNED_ELSEWHERE`
- `ADOPTION_CANDIDATE__PRE_V553`
- `ADOPTION_CANDIDATE__V553_TO_V556`
- `V3_OR_LATER_CONCERN`
- `EXPLORATORY_RESEARCH_ONLY`
- `SUPERSEDED_OR_DUPLICATIVE`
- `BLOCKED_PENDING_AUTHORITY_OR_IDENTIFICATION`

No promotion by rhetoric, filename, or conceptual attractiveness.

## Completion criterion

Pyat Phase 1 closes only when another engineer can read the master synthesis and know, without archaeology:
- what is current;
- what is historical;
- what is open;
- what is missing;
- which file/module/authority owns each thing;
- what must be built next and in what order.
