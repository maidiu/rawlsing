# PYAT — mandatory no-stranding extension for BOTH Browser and Codex HQs
**Proposal / no canonical mutation.** Apply after actual incumbent HQ intake at the exact reviewed SHA; does NOT grant source, scientific, model, live worker or PRE-MAIN authority.

## Why this adds something the existing laws did not mechanically force
The shared \`HQ_JUDGMENT_BEARING_RETURNS_INTAKE...\` already requires judgment-bearing returns; \`HQ_PARALLEL_FLIGHTS...\` already requires an execution flight board; \`HQ_TERMINAL_DELIVERABLE...\` already forces first consumers; \`PROOF_INTEGRITY...\` already prevents vacuous greens; Pyat \`CONTINUOUS_DEVELOPMENT/\` already has a flight board and immutable handoff. Yet an accepted capability on an older branch can still vanish from the next HQ context because neither current HQ "new commission" nor "new checkpoint" unconditionally checks **unintaken branch deltas and equivalent existing producers**. This narrowly adds that gate.

## Gate PBR-0 — first 60 seconds at each HQ resume
1. Read canonical \`HQ_HANDOFF/LATEST.json\` and dereference its **immutable** checkpoint SHA; read \`PYAT_CONTROL_ROOM/CONTINUOUS_DEVELOPMENT/FLIGHT_BOARD.json\` and \`RESUME_CHECKPOINT.md\`. Compare real remote branch heads and observed controller/job/host state only if connector/host qualified. **A Git ref is not a running worker.**
2. Read \`DISCOVERY/00_CENSUS_COHORT_INDEX.json\` plus last \`01_PYAT_AND_PREDECESSOR_RECOVERY_QUEUE.json\` and any newer *accepted* HQ custody tail. Scan **heads moved/newly created since last trusted cut**, and exact new worker/review returns. Material changed/unlinked candidate -> create/reopen custody ID with \`UNINTAKEN\` status, intake owner and next action.
3. Before coding/designing a claimed missing capability, search the Pyat/precursor candidate index AND exact function/accepted review in current code. Evidence of old code -> existing-code/adaptation lane. Missing unverified original science -> authority lane, NOT engineering greenfield. Branch older than Pyat is not obsolete by date alone.
4. If no actual current process known, set \`UNKNOWN_PROCESS\`; never automatically redispatch. If same qualified worker is actively running unchanged, don't create a competing worker.

## Gate PBR-1 — at Browser scientific/design dispatch
Require both a *source/authority/falsifier* and *existing-function search* for every new design. Cite specific old/current blobs and downstream consumer. If the capability is already solved at some grade, commission only the remaining unsolved **scope delta**. Source-free fixture and original original-data readmissions never share an unqualified PASS. Browser cannot appoint itself source/semantic issuer or Codex HQ.

For each code-changing ticket:

- first code consumer (method and readset) and negative/severance expectation;

Prioritize currently stranded HQ282 checkpoint \`open_session\`/\`recover\`/\`admit_saved_receipts\`, Authority37 Z02/C01R2 \`FractureMapController\`/invalidation, and SRC04 original source-to-I03/Lane D. ## Gate PBR-3 — on worker return and independent reviewer result
The returning worker writes exact code/ref and source SHA, tests and negatives and source-science scope. The receiving HQ must record separate:
\`RETURN_PUBLISHED; FIRST_INTAKE; REVIEW_CUT; OWNER_DECISION; TARGET_FUNCTION; FIRST_CONSUMER_PROOF; NATIVE_SOURCE_PERMISSION; OPEN_FALSIFIER; NEXT_ACTION\`.
Review acceptance at sourcefree grade may close *that bounded court* but not its original I03/FF/world/actor first consumer. No independent reviewer provided -> \`REVIEW_PENDING\` or named HOLD, never silently accepted. A later code edit invalidates the assumed exact reviewed code SHA unless reviewer independently adjudicates the diff.

## Gate PBR-4 — every material HQ checkpoint and handoff
Checkpoint must include an explicit **CUSTODY DELTA**:
- New branch heads and previously returned code since prior checkpoint
- Current first consumer / actual accepted target ref for each material promoted candidate
- All \`RETURNED\` or \`REVIEWED_SCOPED\` branches NOT YET consumed
- Rejected/superseded evidence and preserved reasons
- Known process state vs UNKNOWN and lease identity if legitimately read
- Same-name different SHA and duplicate SHAs adjudicated without deletion
- Next qualified owner action; mark missing source/science grants genuinely held.

No sealed checkpoint may claim "nothing stranded" without reconciling at least the changed heads since last read. Historical cohort backlog remains separately declared until function-level screening is complete. Pyat HQ does not need to recrawl all 2,831 on every turn: incremental updates against a pinned trusted census + risk-ranked older backlog. Pure no-change resumption is low-overhead.

## Gate PBR-5 — consumer-grade completion, branch disposition and control change
- To mark **current capability ADOPTED**, provide exact receiver code SHA/old-or-new function, independent scope-appropriate review, original competent source/semantic grant, first executed actual consumer and causal/negative evidence.
- To mark branch **SUPERSEDED**, show equivalence of its unique claimed function and accepted reviewed consumer, or preserve unresolved unique claims as open.
- To mark original science/routing/weight/eligibility **accepted**, only competent issuer's original source/court can do so; branch custody has no scientific vote.
- Nonmaterial older branch names may be archived in the index *at metadata grain* only; no semantic deletion/retirement claim from title or age.
- To modify canonical HQ flight/checkpoint, follow existing Handoff Protocol and authoritative PRE-MAIN source-mutation law; the proposal branch itself is NOT canonical authority.
