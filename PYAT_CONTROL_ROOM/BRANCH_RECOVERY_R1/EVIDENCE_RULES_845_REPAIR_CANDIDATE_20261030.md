## Allowed composite conclusions (derived from fields; never asserted first)

**NO_ACTION_CODE_PRESENT**: exact same code function at current receiving scope, or proven current behavioral replacement, with explicit evidence. If source original rule is missing, its scientific concern remains separate.

**SUPERSEDED_BETTER** only when (a) behavior/function truly same, (b) exact historical positive/fault-negative assertion is reproduced or deliberately replaced on current receiver, (c) current approach demonstrably improves relevant correctness/safety/science/custody or explicitly removes defective reliance; link original and current receipts. Same-path changed AST yields `DIFFERENT__COMPARISON_REQUIRED` otherwise.

**INDEPENDENTLY_REBUILT_EQUIVALENT** only after independent alternate path/current owner, observable matching behavior and negative boundaries, no false persons or target-authority substitution. AST/file/name heuristics yield `EQUIVALENCE_CANDIDATE` only.

**READY_FOR_SOURCEFREE_INTEGRATION_COURT** only if original merits/negative record checked, current distinct function demonstrably missing, ABI/schema/permission/consumer checks specified and qualified tests of candidate + current receiver performed and passed (or explicit isolated sourcefree test path still required; classify `PREVIOUSLY_ACCEPTED_SCOPED_NOT_CURRENT_READY` until executed). This is **not** original/native/world/actor readiness. A previously adopted exact blob whose current ABI has changed is NOT ready by prior review.

**TRASH/INVALID** only with a direct scientific/behavioral falsifier **at the claimed function scope** and original negative owner/reviewer or independently reproduced concrete counterexample. A harness, fixture, audit, review, superseded tool, unused script, doc-only or non-product material is instead `EVIDENCE_ONLY | NON_PRODUCTION | SUPERSEDED_PROVEN | UNKNOWN`; never "trash" just because no production function or first consumer.

**SOURCE_AUTHORITY_HOLD** only for an exact proposed operation that *requires* an actual authority that is ungranted (identify competent issuer, consent/use, target universe and rule); remain allowed to investigate, compile/test *sourcefree* current ABI or first consumer where lawful. Source-access engineering code is not itself necessarily source-native permission. Separate actual restricted R→O→I edge from work that can continue.

**USEFUL/UNIQUE** must separate `HYPOTHESIZED_VALUE` (function could serve mission) from actual proven absent function and current integration priority. Unique code text alone is not unique capability.

## Evidence strength ladder and rules

`E0` branch name/README/author claim; `E1` exact Git tree/blob/AST and source-code static behavior; `E2` original independent reviewer exact assertion + test/negative custody (historical limited scope); `E3` independent current-receiver sourcefree positive+fault negative & regression execution; `E4` competent original-source/scientific/natively measured operation and actual source identity/permission; `E5` independently witnessed real first consumer/whole-machine integration + relevant accepted scientific and actor/world boundaries. These are **different dimensions**, not one ordinal that mechanically implies higher-grade authority. An E3 executable pass does not grant E4 or E5. Negative E2 can prevent a claimed positive E3 until the specific defect is fixed and falsified. Cite refs, SHAs, reviewer identity and proof limit for *every* asserted classification; if evidence absent, record `EVIDENCE_UNKNOWN`, not promotion.
