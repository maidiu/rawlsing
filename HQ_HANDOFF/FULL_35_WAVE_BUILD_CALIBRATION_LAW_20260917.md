# FULL 35-WAVE BUILD CALIBRATION LAW

Status: `ADOPTED_GOVERNANCE__NO_GOLDEN_PATH`

Date: 2026-09-17

## Governing holding

All generic empirical build moves in Rawlsing must be **full-governed-35-wave-aware and calibrated**. A bounded proving wave may supply the exact current instantiation, but no proving wave may become an architectural golden path.

For the present Chetiri/PRE553 closure, WVS7 is an exact proving instance only. It may determine the WVS7-specific emitted object identities for the final court. It may **not** determine the generic implementation architecture.

## Required distinction

`WAVE_SPECIFIC_AUTHORITY_AND_OUTPUTS != WAVE_SPECIFIC_GENERIC_CODE`

Lawful:

- exact wave/source-specific semantic, routing, topology, universe, risk-set, and replay inputs;
- exact wave-specific emitted PRE553 objects/refs/hashes;
- source/wave-specific adapters or declarative authority packages where source-native heterogeneity requires them;
- bounded WVS7 benchmark outputs for the current final P2 court.

Forbidden:

- hard-coding WVS7, Q291G5, Q291P5, the 13-country set, WVS response codes, or WVS topology into generic PRE553 issuance/runtime machinery;
- designing generic constructors around one source's row layout, variable naming, special-code conventions, routing shape, or topology;
- treating successful WVS7 execution as evidence that generic cross-wave calibration is unnecessary;
- postponing known cross-wave heterogeneity under a future 'generalize later' obligation;
- any `GOLDEN_PATH_SOURCE` / `GOLDEN_PATH_WAVE` semantics.

## 35-wave awareness requirement

Any newly built generic issuer/runtime/bridge used by Chetiri, Trii/Empirical Engine, PRE553 query/discovery, replay, or downstream carrier-neutral empirical production must consume source/wave variation through exact authority/configuration inputs rather than embedded source assumptions.

Before such generic machinery is adopted, its public contract and validation surface must be calibrated against the exact governed 35-wave corpus authority envelope sufficient to prove that:

1. source family and wave/release identity are explicit inputs;
2. native question/coordinate identity is not assumed globally stable;
3. response-state and special-code semantics are authority-driven;
4. topology/multiplicity/order/rank are authority-driven;
5. routing/applicability/risk sets are authority-driven;
6. weight/design/estimand authority is optional and source-local rather than silently defaulted;
7. source-universe/currentness and cross-source relation semantics are explicit;
8. replay/source-content identities are exact and wave-scoped;
9. unsupported/missing authority fails closed rather than falling onto a favored source path;
10. no code branch treats the current proving wave as the default semantic universe.

Calibration does **not** require opening or executing all 35 empirical source carriers for every bounded build move. It requires the generic architecture, schemas, parameterization, validation, and failure behavior to be checked against the governed 35-wave authority/manifest heterogeneity before adoption. Exact empirical execution remains separately commissioned.

## Immediate effect on EE-P2F2

EE-P2F2 remains bounded to issuing the WVS7 objects required by the final P2 court, but any code/mechanism it adds must be source/wave-parameterized and reusable across the governed corpus without source-specific semantic hard-coding.

If the existing commission can be satisfied entirely by current generic PRE553 constructors plus declarative WVS7 authority inputs, no redesign is required.

If satisfying the commission would require adding WVS7/Q291-specific logic to generic machinery, the worker must stop and return the smallest exact generic-calibration blocker instead of implementing a golden path.

Any new generic code must include a 35-wave calibration receipt or equivalent contract-level proof against the governed corpus authority envelope. The receipt may use metadata/authority/manifests only; no unauthorized source/outcome access is implied.

## Future law

This governance applies project-wide to new empirical build moves unless a later explicit HQ act narrows it for a genuinely source-specific adapter whose source-specificity is itself part of the architecture.
