# 1. Why this audit exists

The immediate trigger was not an abstract desire to modernize source handling.

The project was attempting to finish **EE-P2X**, the A/B/C equal-work court for how the survey-data substrate should physically participate in the redesigned PRE-MAIN DAG.

P2X repeatedly stopped on execution/integration defects:

1. an adopted runtime substrate existed but had not been fully fanned into the P2X execution tree;
2. a correct authority object existed but the runtime pointed at the wrong exact path;
3. a WVS materializer wrapper shadowed and recursively called itself instead of the accepted generic binder;
4. S17 driver sequencing contradicted its own adopted verifier lifecycle;
5. failures were terminalized at candidate scope even when they were actually common infrastructure, making lawful retry impossible without ledger reconciliation;
6. runtime/package dependencies were often being assembled from historical worker-return paths and exact blobs rather than from one mechanically enforced inheritance/composition surface.

These are diagnostic.

They do **not** primarily say:

`SOURCE SEMANTICS WERE NEVER SOLVED`.

They say:

`AUTHORITATIVE FUNCTION MAY EXIST WITHOUT THE CURRENT EXECUTABLE GRAPH ACTUALLY CONSUMING IT CORRECTLY`.

This is the central succession-integrity problem the audit must understand.

# 2. The architectural history the next HQ must internalize

The pre-Dva/Trii/Chetiri V550/V551/V552+ pipeline organized many logical functions as numbered serial stages, frequently producing another comparatively complete artifact at each boundary.

Dva/Trii/Chetiri were not simply a rewrite of those stages.

Their project was to preserve:

- functionality;
- semantic distinctions;
- manual/adjudicated authority;
- source-native truth;
- topology/multiplicity;
- routing/applicability;
- response semantics;
- source relations;
- provenance/replay;
- typed UNKNOWN/BLOCKED/manual-review states;
- downstream capability;

while **changing the physical architecture** into a more economical producer-owned DAG with direct reuse, selective persistence, transient composition, and governed references.

The key law is therefore:

`PRESERVE_FUNCTION_AND_AUTHORITY__NOT_HISTORICAL_CARRIER`

and also:

`LOGICAL_DISTINCTION != REQUIRED_SERIAL_PHYSICAL_STAGE`

Do not infer that an old function is absent merely because there is no current stage/file with the same shape or name.

Do not infer that an old file surviving means the function is currently inherited.

The burden is executable functional succession.

# 4. The five senses in which an old function can appear to “survive”

For every inherited function, distinguish:

1. old bytes still exist;
2. doctrine is documented;
3. authority records survive;
4. a new component approximately performs similar work;
5. the current executable DAG **actually consumes the authoritative successor and reproduces the required distinction at the required boundary**.

Only **5** proves functional succession.

Recent P2X defects repeatedly demonstrated states 1-4 without 5.

This is why the audit cannot be satisfied by file inventories, module tests, or statements that “the authority exists.”

It must prove **consumption in the live execution composition**.
