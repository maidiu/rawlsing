# Sorok — Portal Occupancy, User Absence, and No-Autopilot Alpha R1

Status: PROVISIONAL_ALPHA_SPEC_DIRECTION

Date: 2026-09-30

## 0. Core recommendation

For alpha, prefer **no autonomous player autopilot**.

Maintain this asymmetry:

> **The persona has continuous generated life. The user has continuous relational identity/history, but meaningful player agency exists only when the external human actually acts.**

Therefore:

`PERSONA CONTINUES AS PERSON`
while
`PLAYER PARTICIPANT PERSISTS AS IDENTITY / HISTORY / MATERIAL ANCHOR`
but
`PLAYER DOES NOT ACQUIRE AN AUTONOMOUS OFFSCREEN PSYCHE OR SOCIAL AGENT`.

---

## 1. Portal occupancy

Physical co-presence is tied to portal occupancy.

Possible states:

### ACTIVE_PORTAL
External user is currently embodied in a live portal scene.
- SAY / DO / ATTEND available;
- physical co-presence possible;
- meaningful player action occurs;
- scene-time advances by realized action duration.

### OUTSIDE_PORTAL / CONTACTABLE
User is not physically present in the generated world but established communication channels may remain available.
- messaging can occur;
- invitations can arrive;
- no physical/social action is silently authored for the user;
- world/persona calendar continues.

### OUTSIDE_PORTAL / UNREACHED
No active user response.
- persona/world still continue;
- messages/attempted contacts may become history;
- time-sensitive opportunities may expire;
- no autonomous user response is invented.

These are product/causal states, not persona knowledge labels.

---

## 2. Persistent player identity without autonomous behavior

Between scenes, preserve:
- stable player-world participant ID;
- established relationship history;
- local material/social position already admitted;
- dwelling/access anchors where applicable;
- resource/obligation state where mechanically maintained;
- message channels;
- explicit commitments;
- known routine constraints.

Do NOT generate:
- novel speech;
- new autobiographical disclosure;
- opinions;
- relational initiative;
- promises;
- intimacy;
- apologies;
- conflict repair;
- consent/refusal on meaningful matters;
- new friendships;
- user psyche.

---

## 3. Offscreen material maintenance may continue

Certain nonexpressive state transitions may proceed automatically if already governed:
- rent/resource accounting;
- sleep/time passage at coarse grain;
- established work schedule as availability/resource constraint;
- ordinary consumption/maintenance;
- pre-existing transport/access status;
- other mechanically necessary shell state.

This is not 'the user behaving.'

It is world bookkeeping needed to keep the homologous position coherent.

`MATERIAL CONTINUITY != AGENTIAL AUTOPILOT`.

---

## 4. No need to explain every offscreen hour

Rawlsing does not need to fabricate a detailed account of where the user was while outside the portal.

Canonical truth may simply be:
- user was not physically co-present;
- user was unreachable/available through whatever channels actually existed;
- ordinary player-shell material continuity proceeded.

If another actor later asks:
> Where have you been?

the user may answer.

Rawlsing does not need to pre-author that answer or verify its external truth.

---

## 5. Nadia never knows 'the app was closed'

Persona access is limited to diegetic facts.

Nadia may know:
- she sent a message;
- it was delivered where channel semantics expose that;
- it was read if read-receipt semantics lawfully expose that;
- no reply arrived;
- user did not appear at an agreed meeting;
- user has not been physically encountered recently.

Nadia may NOT know:
- app open/closed;
- notification viewed;
- user battery state;
- real-human reason for absence;
- whether user was intentionally ignoring her.

She may infer any of those things wrongly from the evidence she actually has.

---

## 6. Read state is a real relational fact

If the messaging surface supports read receipts:
- opening the relevant thread/message can establish read;
- notification preview alone should not silently establish read;
- no system should claim the user saw content merely because a push was delivered.

This matters because:

`UNREAD SILENCE`
!=
`READ + NO RESPONSE`.

Different personas may interpret them differently.

---

## 7. Contact attempts become world events

If Nadia:
- sends a message;
- calls;
- knocks;
- invites user somewhere;
- asks for help;

the attempt can become canonical history whether or not the user responds.

If user is unavailable and the opportunity expires:
- world resolves without a fabricated user choice;
- Nadia acts under her own constraints;
- later relationship consequences arise from the actual event/history.

Example:
> Can you watch Sami tonight? I'm stuck at work.

If user does not respond before the relevant time:
- Nadia finds another solution or suffers whatever lawful consequence follows;
- Rawlsing does not invent a `yes` or `no`;
- Nadia later interprets the nonresponse from her own relation model.

---

## 8. Explicit commitments create real stakes

If the user explicitly commits to a future meeting/action:

> I'll be there Friday at seven.

and Friday passes without user action/cancellation:

the default should be a **real missed commitment**, not silent autopilot fulfillment.

This is one legitimate source of Tamagotchi-like guilt.

It is not product punishment; the user actually made a promise inside a present-coupled relationship.

---

## 9. Commitment acceptance should be temporally legible

Because present-coupled appointments can impose real-world timing burden, the product should make the temporal consequence clear before admitting an exact commitment.

Possible interface support:
- show current diegetic date/time;
- render exact agreed time clearly;
- optionally display local real-calendar equivalent where portal geography/time zone differs;
- allow natural refusal/counterproposal;
- notify user of approaching commitment neutrally.

Do not sneak real-calendar obligations into ambiguous prose.

---

## 10. No-show is not moral diagnosis

If user misses a commitment:
- store the event;
- do not infer why;
- do not mark moral character;
- Nadia may react according to her generated state/history;
- user may later explain, apologize, lie, refuse to explain, or dispute expectations.

Rawlsing does not know whether the external human had an emergency.

---

## 11. Physical chance encounters while user is absent

Do not silently instantiate meaningful co-presence with an autonomous player shell.

If a physical opportunity arises while user is outside the portal:
- it may become a missed-opportunity event;
- another actor may knock/call/message;
- the opportunity may expire;
- no substantive user conduct is authored.

Portal occupancy is the gate for meaningful physical co-presence.

---

## 12. User can enter portal without summoning persona

Opening the portal should not mean `spawn Nadia`.

The user enters their local world-anchor at the current lawful time/place.

Nadia may be:
- home;
- at work;
- elsewhere;
- busy;
- asleep;
- with other people;
- unavailable.

The user can act in the world, message, wait, leave, or pursue another lawful route.

This preserves non-player-centric life.

---

## 13. Meeting opportunities create portal-entry affordances

Messaging/world events can create a reason to enter:

> We're going to the fair in an hour. Want to come?

If user accepts while opportunity remains:
`MESSAGE SURFACE -> PORTAL ENTRY -> FAIR SCENE`.

If user does not answer:
Nadia goes or does not go according to her own life.

The event does not wait indefinitely for the user.

---

## 14. Notification controls alter delivery, not reality

User may:
- mute notifications;
- schedule quiet hours;
- suppress push;
- disable noncritical reminders.

These settings do not:
- freeze Nadia;
- suppress Nadia's actor-owned decision to send;
- erase sent messages;
- halt world time.

On return, the user may encounter accumulated history.

---

## 15. Background persona computation can be event-gated

Present-coupled life does not require continuous 24/7 LLM thought.

Possible background triggers:
- scheduled V3/world transition;
- explicit persona agenda/event;
- external current-event admission;
- relationship/message response window;
- user commitment deadline;
- bounded daily/periodic focal-person checkpoint.

Most intervals are code-side/event-sourced compression.

LLM calls occur only when concrete particulars, actor decisions, or emitted communication require them.

---

## 16. Spontaneous persona messages require real background causality

If Nadia messages while user is away, the message must arise from:
- an actual background event;
- remembered unresolved matter;
- current relation-state;
- her own agenda/cathexis;
- some lawfully generated trigger.

Do not generate `thinking of you` messages merely because engagement has been low.

---

## 17. Long absence

If user returns after a month:
- one month passed for Nadia/world;
- current external events may have entered lawfully;
- relationships/jobs/projects may have changed;
- user did not accrue invented relational actions;
- missed invitations/messages/commitments remain history;
- Nadia's interpretation of absence depends on actual history.

Long absence can therefore change the relationship without turning the user into an autonomous synthetic actor.

---

## 18. Why this is better than autopilot

Autopilot creates a severe identity problem:

> the system begins deciding what the real user would say/do while the real user is absent.

That undermines the central Sorok division:

`PERSONA = GENERATED HUMAN`
`PLAYER = EXTERNAL HUMAN PARTICIPATING THROUGH PORTAL`.

Therefore alpha should begin with **no meaningful player autopilot**.

If later usability requires bounded routine automation, it can be added only for nonexpressive material continuity.

---

## 19. Deep theorem

> **Nadia continues living when you leave. Rawlsing does not continue being you.**

And:

> **The cost of absence comes from what actually happened while you were gone—not from a hidden decay meter and not from an AI impersonating your participation.**
