# Sorok — Q-PRIV-001 User Data, Praxis, Deletion and Export Constitution R1

Status: `PROVISIONAL_PRODUCT_CONSTITUTION__Q_PRIV_001_CLOSED_FOR_ALPHA_SPEC__NON_DISPOSITIVE_TO_LEGAL_POLICY`

Date: 2026-10-01

## 0. Question

`Q-PRIV-001`:

> What user data is required for longitudinal relational modeling, what should never be collected, and what deletion/export boundaries are required?

## 1. Core theorem

> **Preserve the relationship's history; minimize the dossier about the human.**

Rawlsing needs enough user-related state to make actions, commitments, memory, consequence and longitudinal relation causally real.

It does **not** thereby acquire authority to construct an unrestricted psychological profile of the external human.

`EXTERNAL HUMAN != PLAYER PARTICIPANT != USER-SUPPLIED FACTS != PLAYER EVENT HISTORY != PERSONA MODEL OF USER != SYSTEM PRAXIS HYPOTHESIS`.

These categories require different authority, retention and visibility.

## 2. Minimum alpha user-data classes

### A. Account / security / operational identity

Only what the service needs for access, security, billing/entitlement or abuse prevention.

This layer is operational, not psychic.

It must not silently become simulation input.

### B. Governed player-participant state

Facts required for diegetic causality:
- current portal occupancy / presence;
- admitted player location within the synthetic world;
- assigned local resource/power envelope;
- possessions/resources already admitted in-world;
- admitted capability claims where necessary;
- active commitments, access, roles and channels.

These are properties of the run's participant binding, not claims about the external human's essence.

### C. User-authored / user-supplied facts

Main-mode default remains zero-profile.

A real-world fact enters only when:
- the user explicitly supplies it;
- the product has a named function for it;
- the use is purpose-bound.

Examples:
- accessibility constraint;
- language/capability;
- selected identity continuity fact;
- off-stage obligation;
- selected relationship existence.

`USER-SUPPLIED FACT != VERIFIED EXTERNAL-HUMAN TRUTH`.

### D. Canonical player event history

The simulation may retain admitted facts about what the user actually did inside the continuity:
- SAY / DO / ATTEND acts;
- promises/commitments;
- grants/refusals;
- realized participation;
- salient omissions only where world law makes an omission an event;
- consequences and later repairs;
- user-authored testimony as testimony.

This is necessary because relationship history cannot be causally real if the system forgets the user's own acts.

### E. Actor-local models of the user

Synthetic actors may form their own models of the user from lawful evidence.

These models:
- belong to the actor/relationship;
- can be wrong;
- can disagree;
- are not system truth about the external human;
- must not be silently pooled into a global user essence.

### F. System praxis evidence / hypotheses

Rawlsing may derive bounded longitudinal descriptions from realized play, such as recurring attention allocation, repair behavior, promise-keeping or response patterns.

These must remain:
- evidence-linked;
- scoped to relevant contexts/personas;
- uncertainty-bearing;
- non-diagnostic;
- non-essentializing.

A system hypothesis is not a hidden fact about the user.

## 3. Purpose limitation

Every user-supplied real-world fact must have a named purpose.

Candidate purpose classes:
- `PLAYER_SELF_CONTINUITY`;
- `PORTAL_HOMOLOGY_INPUT`;
- `WORLD_CONSTRAINT`;
- `ACCESSIBILITY`;
- `CAPABILITY_INPUT`;
- `LANGUAGE_MEDIATION`;
- `OFFSTAGE_OBLIGATION`;
- `PRAXIS_CONTEXT`.

A fact supplied for one purpose does not authorize unrelated use.

Example:

Providing religion so the portal does not falsify a user's social/religious continuity does not authorize a psychological or political profile.

## 4. Main-mode collection minimization

Alpha main mode should not require:
- exact real income or assets;
- employer;
- full education/credential history;
- exact home address;
- exact real social graph;
- contact-list import;
- full family/friend graph;
- browsing history;
- social-media history;
- unrelated connected-account data;
- continuous device/location surveillance;
- psychometric intake;
- personality test.

The homologous portal should generate the local material envelope rather than importing the user's real socioeconomic power.

## 5. Sensitive attributes

Rawlsing must not silently infer sensitive external-human attributes merely because some behavior could be interpreted that way.

In particular, without explicit separately governed authority it must not infer as external-human truth:
- psychiatric diagnosis;
- trauma history;
- hidden sexual motive/orientation;
- medical/disability status;
- stable moral character;
- criminality;
- political allegiance;
- religion/nonreligion;
- race/ethnicity;
- real-world relationship conduct;
- unconscious motive.

Some sensitive facts may be explicitly supplied by the user when a known product/accessibility function genuinely requires them.

That does not convert them into general-purpose inference features.

## 6. Observation is allowed; diagnosis is not

Rawlsing may preserve what the user actually did.

It may say, with sufficient evidence:

> In several conflicts you returned first to the practical problem and rarely revisited the other person's interpretation.

It may not silently promote that into:

> You have avoidant attachment.

Behavioral evidence may support bounded hypotheses about praxis.

It does not authorize clinical, moral or essential identity claims.

## 7. Cross-persona aggregation

Cross-persona user modeling is the most sensitive layer.

For alpha:

- raw relationship histories remain continuity/persona scoped;
- actor-local models remain actor scoped;
- system-level praxis aggregation may combine only evidence classes explicitly admitted for reflection;
- each aggregate proposition must retain source/provenance and contextual scope;
- contradictory behavior must remain representable;
- one persona's interpretation must never become another persona's knowledge;
- cross-persona summaries must not be injected into persona behavior as secret omniscient reputation.

`SYSTEM PRAXIS MODEL != SHARED ACTOR REPUTATION`.

## 8. No external-use conversion

For alpha, relational/praxis data must not become:
- advertising profile;
- marketing segmentation;
- referral targeting;
- engagement-optimization score;
- pricing discriminator;
- public reputation;
- cross-user social ranking.

The product may use bounded operational telemetry for reliability/safety/cost only under separate operational authority, without turning psychological/relational content into a growth asset.

## 9. Reflection control

Player praxis reflection should be separable from causal simulation.

The user may disable reflective summaries without disabling the ordinary memory required for persons/worlds to remember what happened.

Therefore:

`RELATIONSHIP MEMORY != SYSTEM SELF-ANALYSIS FEATURE`.

Disabling reflection prevents new user-facing/system-level praxis synthesis from being used as a reflective product feature.

It does not force Nadia to forget an argument that actually occurred.

## 10. Inspection

Users should be able to inspect the classes of external-human data the platform treats as user-owned or system-level user modeling, including:

- explicit profile/self-continuity facts;
- purpose tags;
- admitted capability/identity declarations;
- system-level praxis hypotheses;
- their provenance/context/confidence where represented;
- whether reflection is enabled;
- operational categories that are linked to the account.

Do not expose actor-private psychic state merely because it contains a model of the user.

Persona opacity remains gameplay law.

The user can know that actor-local modeling exists without receiving Nadia's hidden current internal representation as a privacy dashboard.

## 11. Correction

A user must be able to correct or withdraw a user-supplied external fact for future use.

Correction means:
- future use changes immediately;
- dependent derived system hypotheses are invalidated/recomputed where appropriate;
- the old supplied fact is not silently treated as still current external-human truth.

Correction does **not** silently rewrite already-admitted world history.

If an old fact caused a historical portal binding/event that cannot be removed without contradiction, the history remains historical inside that continuity unless the continuity itself is reset/deleted.

## 12. Deletion has scopes

### A. Delete optional profile / external-human fact

Remove it from future user-profile use.

Invalidate derived user-level hypotheses whose only support was that fact.

Do not silently retcon already-admitted world events.

### B. Delete system praxis/reflection model

The user may remove system-level praxis hypotheses/summaries separately from the underlying continuity.

The product may later derive new hypotheses only from still-authorized evidence and only if reflection/modeling remains enabled.

### C. Delete a continuity

Delete the stored player/person/world relationship history for that continuity, subject only to separately governed security/legal minimums.

Because causal history is the continuity, selective deletion of arbitrary past events while preserving the same continuity would create false history.

The honest product operation is therefore continuity deletion/reset, not invisible narrative surgery.

### D. Delete the account

Remove user-associated data according to the applicable service/legal retention contract.

This product constitution does not invent legal exceptions.

## 13. Actor-local memory and deletion

While a continuity exists, the user does not receive a magic right to command a synthetic actor to forget a real admitted event merely by deleting a profile field.

If the user requires removal of the underlying interaction history from storage, the corresponding continuity must be deleted/reset rather than preserved with falsified memory.

This preserves both privacy agency and causal integrity.

## 14. Export

Provide a structured export of user-governed data sufficient to understand what the service stores about the external human and the user's own history of participation.

At minimum:
- explicit user-supplied profile facts and purpose tags;
- admitted player declarations/capability bindings;
- user-authored interaction/event history or an exact accessible representation of it;
- commitments/roles/access facts involving the user;
- system-level praxis hypotheses and their evidentiary provenance where stored;
- reflection/privacy settings.

Actor-private hidden psyche need not be exposed in active-play export merely because the actor models the user.

A full continuity archive may export objective shared history without exposing hidden actor-private causal state.

## 15. Unknown / withheld is a legitimate state

If the user declines to provide a real-world fact, Rawlsing must not fill it by covert inference merely because the fact would be convenient.

`WITHHELD != NEGATIVE`.
`UNKNOWN != DEFAULT PERSON`.

The portal may use synthetic/homologous local bindings where product law allows them.

## 16. No external-human omniscience through LLM inference

The renderer or analytic model may not "figure out" a private external-user truth and then install it into canonical user state.

Model inference can create:
- a bounded hypothesis;
- an actor-local belief;
- a prompt for optional clarification;

but not verified external-human truth.

## 17. Data visible to personas

A synthetic actor may know only user information available through lawful channels:
- what the user said/did;
- what the actor perceived;
- what another actor lawfully told them;
- world/public facts available to them;
- established relationship history.

The actor cannot access:
- private Portal Profile fields not diegetically disclosed;
- system praxis analytics;
- account/security metadata;
- another persona's private model of the user;
- off-platform user data.

## 18. Research / advanced profile modes

A future explicit research/deep-profile mode may collect more real-user context.

It must:
- be separate from default main mode;
- state what additional facts are requested;
- state what analysis they enable;
- preserve purpose limitation;
- permit omission;
- weaken claims when evidence is missing;
- never silently upgrade default users into deep-profile subjects.

## 19. Hostile cases

The constitution must survive:

1. user gives no profile data at all;
2. user provides religion for continuity but never discloses it to Nadia;
3. user supplies disability only for accessibility;
4. user changes an autobiographical fact after years of play;
5. user wants system praxis reflections erased but wants the relationship to continue;
6. user wants the entire continuity deleted;
7. Nadia has a wrong model of the user;
8. two personas form contradictory models of the user;
9. cross-persona behavior appears inconsistent;
10. model predicts a sensitive trait from behavior;
11. marketing wants to segment users using relationship style;
12. growth wants to target invite prompts using praxis data;
13. user asks what hidden actor model Nadia has of them;
14. user asks what user-profile data Rawlsing itself stores;
15. user roleplays experimentally for one continuity.

Expected result:
- world history and user dossier remain distinct;
- actor-local wrong models are lawful;
- cross-persona omniscient reputation is forbidden;
- sensitive inferred truth is not installed;
- optional reflection can be deleted/disabled;
- full history deletion ends/deletes the continuity rather than falsifying its past;
- user-supplied profile data remains inspectable, purpose-bound and removable for future use.

## 20. Q-PRIV-001 disposition

`Q-PRIV-001 = PROVISIONALLY_ANSWERED / CLOSED_FOR_ALPHA_SPEC`.

Alpha privacy law:

1. default zero-profile main mode;
2. collect only data needed for causal participation or an explicit named function;
3. purpose-bind user-supplied real-world facts;
4. preserve canonical in-world user acts because relationships require history;
5. keep actor-local user models actor-scoped and fallible;
6. allow bounded system praxis hypotheses but never diagnosis/essence claims;
7. forbid silent sensitive-trait inference as external-human truth;
8. forbid praxis/relationship data from advertising, growth targeting, pricing or public reputation;
9. permit reflection-model deletion/disable separately from relationship memory;
10. permit profile correction/deletion for future use without silent historical retcon;
11. continuity-level history deletion deletes/resets the continuity rather than rewriting it;
12. expose/export user-governed profile and system-user-model data plus objective participation history while preserving actor-private opacity;
13. unknown/withheld remains lawful and must not be backfilled by covert inference.

Remaining work is implementation/data-governance architecture and prototype UX, not alpha product-spec ambiguity.
