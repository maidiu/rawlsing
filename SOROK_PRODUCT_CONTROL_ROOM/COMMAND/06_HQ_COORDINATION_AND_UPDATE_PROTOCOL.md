## 5. Hard maturity and acceptance semantics
Engineering level 0 named/unresolved; 1 scoped contract; 2 separate actually exercised code; 3 real predecessor and intended consumer joined in one qualified chain; 4 same chain causal positive/negative/held and severed edge; 5 original source/science plus independent operative qualification; 6 actual ongoing person/product capability. Science owner action: UNVERIFIED_ISSUED, ISSUED_SCOPED, WITHHELD_SCOPED or REQUIRE_MORE_EVIDENCE; only the original competent owner supplies the actual source/readset, rivals, conditions and version. Temporary code fixture is never issuance. Original Rule T absent is HELD, not TRUE_NO_CHANGE_EVALUATED.
Source permission: distinguish actual granted use from documentary read, future granted use and unknown. Integration: producer/consumer actual code and selected source SHA, not two fixture values that happen to match. Native: actual Pyat N11/N12, C11/C12 and A0–A5 acceptance separate. Whole-person grade cannot go up solely because a fork, test harness or transport piece passed.
**Progress measures:** show exact 19-grade distribution, 12 reviewed requirements versus actual issued rules, actual producer→consumer edges newly accepted, original scientific decisions settled, remaining critical blockers and native count. No arbitrary global percentage or equal-weight aggregation of an alpha milestone and a bootstrap fix. Progress = changed capability under acceptance requirements, not reports or tests per se.
