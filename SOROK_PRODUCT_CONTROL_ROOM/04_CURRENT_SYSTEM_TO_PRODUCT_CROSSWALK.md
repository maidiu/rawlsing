## 2. What the product vision strengthens rather than invalidates

The existing governing spirit already treats:
- persons as relationally embedded;
- mediation as the route by which structure becomes life;
- parents as generated lives;
- relationships as generated histories;
- households as causal fields;
- personhood as becoming rather than classification;
- Enneagram-like patterns as developmental attractors rather than essences;
- LLM output as expression rather than ontology.

The new product work **sharpens the downstream consequence**:

V3 cannot be adequately specified as a monadic personality object with relational behavior improvised later.

## 3. Candidate ownership decomposition

### PRE-V3 should continue to own
Objective, actor-independent or actor-prior conditions:
- world;
- institutions;
- household structure;
- kinship positions;
- material conditions;
- historically admitted events;
- structural relations;
- temporal consequences;
- accessible carriers / mediations at the lawful grain.

### PRE-V3 → V3 seam may need to guarantee
Enough exact historical/relational input for V3 to derive:
- learned relational expectations;
- attachment-relevant developmental history;
- role-conditioned behavior;
- trust / need / conflict / reciprocity grammars;
- histories of isolation / recognition / dependence;
- caregiver and household relational histories;
- prior friendship / love / betrayal / authority histories where generated.

This is a **candidate terminal-demand requirement**, not current Pyat law.

### V3 candidate responsibility
V3 should likely produce a person whose psychology includes:
- dispositions;
- developmental organization;
- relational priors;
- role-conditioned tendencies;
- defenses;
- need / trust / conflict grammars;
- self-model and other-model capacities;
- dynamic attractors and health potentials.

V3 should not own the entire future relationship with a particular user.

### Post-V3 relational runtime candidate owner
A separate dyadic / network runtime may need to own:
- user↔persona relationship state;
- mutual models;
- admitted shared history;
- commitments;
- injuries;
- repair;
- trust dynamics;
- dependency;
- invitations / access;
- network consequences;
- relationship-conditioned activation of V3 priors.

Whether this belongs in PFF, V2, application runtime or a new named layer is OPEN.

### Expression layer
The LLM should render only lawfully accessible state and should not silently update canonical relationship or person state.

## 5. Design criterion

The product vision should change upstream architecture **only where the finished experience would otherwise be starved**.

Do not route every product concern backward.

Apply the same whole-picture / bounded-jurisdiction discipline already used elsewhere in Rawlsing.
