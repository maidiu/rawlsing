## 3. Worked architecture question

**Question:** How could a historically particular care interaction change what a person later does under a new encounter, without pre-selecting a universal learning law?

**Answer at design grain:**

1. E1 is an objective world occurrence with source/owner/clock, not a story. C8 admits it; ADP017 creates an actor-access record; C9 creates an immediate response/no-change/held record.
2. If the actor actually received the care and the competent CAN011 owner issues a transition, a `DurableDecision` can create/maintain/transform a scoped `FunctionalRelation` (for example, a relation between a care-related operation and later support-seeking operation), with exact origin event, access, support/contradiction evidence, scope and rule hash. If the owner does not issue the rule, the result is `HELD_MISSING_RULE`, not a fabricated relation.
3. E2 is a genuinely later event with independent world/B, actor access and the then-current state. C9 queries active relations by **scope and value** under the event context; it does not read a hash or a label. If no formed relation exists, E2 has no learned effect. If external B/resource support changed, that is a resource difference, not evidence of a learned relation. If only temporary coactivation occurred, it is an activation trace, not a durable edge.
4. N+1 retrospective is built only from the realized/accessible prefix, not from E1's prose. A self-account may be proposed in the same call; it becomes native only after SCI05 admission. If denied, dependent prospective proposals are invalidated; independent proposals may still be considered.
5. The architecture can support this trajectory, but it does not assert that a particular care event produces a particular relation or coefficient. That is the scientific owner's finite decision.

**Not claimed as executed.** This is a worked design/mechanism example, not a native child, empirical law or C12 positive.
