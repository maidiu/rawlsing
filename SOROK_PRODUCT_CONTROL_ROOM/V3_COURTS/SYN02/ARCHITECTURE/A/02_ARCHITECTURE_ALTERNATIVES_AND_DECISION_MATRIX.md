## The design problem is not 'what graph database?'

The product needs **persistent and potentially novel ways a particular person's activities, expectations, acquired operations, attention, practical means, reflective concepts and relational commitments condition each other**, without positing a neuroscience simulator, every-context personality vector or causally free LLM rewriting. It must also allow coherent/stable histories where no new links are justified. Representational generality alone is cheap; *qualified formation/semantic consumption*, historically grounded world action and bounded recomputation are hard.

### Criteria (architecture requirements, not weighted personality coefficients)
1. **Ontology/science:** activities, object/need, practices, actual support and absent/rejected/no-effect learning remain different.
2. **Causal discrimination:** trace what event or internal act caused a new relation/operation and what later consumer's real behavior changed; rival unchanged value/world explanation testable.
3. **Scope/plurality:** simultaneous and opposing context-limited patterns possible, not universal.
4. **Computational bounds:** sparse state and local dependency-trace evaluation; no all-to-all O(n²) psychic interaction, exhaustive life replay per event or hidden global scalar.
5. **Compatibility:** V3 existing state, pressure-flow, time schedule, stored/derived, CAN008 R2 generic coupling, CAN011 middle states, ADP016/017, current S39–S52 and C12 one-person lineage; old formulas may be quarantined.
6. **Authority:** only named owners can create real world facts, formed operations, relation semantics, actor memory or native release; no schema feature equates to scientific truth.
7. **Evolution:** represent early embodied practical distinctions without requiring adult words and later conceptual mediation without retroactive infant beliefs.
8. **Audit/testability:** exact time/parents/provenance, explicit failure/no-change and readable fault-controlled E1→E2 semantics.
9. **Error resistance:** no source-denied B as independent caregiver; no narrator-to-state, default 50/hopeful, stage/type bootstrapping or forbidden analyst knowledge.

## What 'hybrid' means operationally (not a blank-slate engine)

**Keep current owner modules** for world/source, actor response, middle state, memory and expression. A *typed relation overlay* is an immutable-history-indexed description of **which named input/operation semantics can influence or qualify another at a specific context**, not an independent generalized causal executor or duplicated mutable psyche. Examples:
- A context-limited \`CAN010 expectation:caregiver_A_available\` can condition \`CAN008 evaluate_offered_help\` only where a domain-issued rule says so. This is old-value conditional recruitment unless a new relation is historically formed.
- A newly learned practical sequence may link \`notice_person_asking\` to \`perform_help_procedure\` under specific accessible constraints; an explicit new condition-to-operation edge only when competence was **demonstrated under qualified ownership**, not because the concepts occur near each other in narrative.
- A historically acquired interpretive commitment can affect consideration of an opportunity in a school/union setting but not generalize to unrelated family decisions absent a transfer rule.
- Another person’s actual help may make the action possible while actor has not acquired ability; store **world affordance and coactor participation** separately from internal edge.

**Execution**: owner-scoped registry catalogs capabilities; a canonical actor state records which legally formed operations and relations have committed lifecycles; at each admitted event C9 asks domain CAN008 to assess jointly eligible streams, using current person/world facts and owner-specific evaluators. It may return several transient effects with explicit target-owner handoffs. The CAN011 owner independently evaluates any durable update proposal under *specific issued rule*, optionally including new relation type if registered by competent extension; no spontaneous relation creation by the graph walker. Later C9 reads a semantically typed *value* and decides action/response. A single event may recruit several contradictory operations, cause no effect, or be held. Nothing here prescribes a numeric energy conservation or all-to-all influence.

## Provisional decision rule — what would change this choice?

Architecture G is **not** accepted merely because it can be drawn in Mermaid. It must pass four independent gates:
1. **Representability / ontology court:** CAN010/011 and V3 owner determine which new relation type actually belongs in existing CAN011 registered \`MEDIATOR/TENSION/PRACTICE\` payload/scope versus requires a limited new governed state kind; no illicit fourth kind. If existing field is enough, **adapt** it rather than add redundant generic psyche graph.
2. **Causal scientific court:** Original developmental issuer defines at least one real-life case where qualification differentiates new operation/relation from changing input magnitude, external scaffold, context eligibility or label/impression. Strongest discriminator is later E2 with actual value read under independently sourced world/coactor. A scientific *negative* may rule out relation acquisition while permitting stable practice or no-change.
3. **Engineering court:** Existing pressure-flow joint conditioning and working-copy transaction are reused at tested semantic scope; reliable atomicity, stored/derived and error-boundary repairs added; provenance and performance verified at growing graph size under adversarial cycles/contradictions. No performance claim before run.
4. **Authority/product court:** C8 independent B, C9 actual same-person source, native C11/C12 plus Pyat/ADP release and A0–A5 available. Typed sourcefree demonstration does not satisfy this.

**Fallback if (1) or (2) fails:** retain typed operation registry + contextual **fixed** owner-issued rules plus person-world distributed supports; represent relation change as **unsupported/held** instead of creating links. Fallback still supports historical personhood to degree of accepted functions, but cannot assert open-ended acquired interwiring. **If observed evidence indicates a genuinely simpler stable program in a particular domain**, use it there rather than force global dynamic edges.

## Cycles and propagation — finite and governed, not mystical 'interpressure'

Event-local dependencies may feed several fields and have reciprocal structural significance, but direct mutual recursion at one logical time can create nontermination or self-justifying meaning. Candidate bounded evaluator:

1. Build admissible actor-specific **active input set** from source-qualified event, current state and registered context/operation predicates.
2. Construct a typed, owner-labeled dependency slice \`G(e,s,t)\` containing only applicable **already issued** functional relations; incomplete predicate evaluation yields \`UNKNOWN/HOLD\`.
3. Partition acyclic and cyclic dependencies. Order acyclic by upstream owner dependency. **For cycles**, no guessed convergence or universal relaxation coefficient: require a separately issued fixed-point semantics/solver and termination/uniqueness rule for that domain; else report \`DEFERRED_CYCLE_SEMANTICS\` and do not mutate.
4. Evaluate domain-specific CAN008 response streams and sub-owner material/effect rules; keep competing paths separately. Failure/contradiction does not secretly take the max or average. Resolve only under rule-defined precedence/compatibility; otherwise \`AMBIGUOUS_COMPETING_EFFECTS\`.
5. Propose durable changes to source owner, validate parent/rule/effect and commit atomically with immutable trace; later event sees committed state; no mutation from render or analyst diagnosis.

**Complexity controls:** only relations indexed by actor+scope+semantic target, incremental snapshots/cold replays, no unrestricted string predicates, explicit bounded dependency expansion by actual owners (limits are resource budgets, not developmental parameters), garbage-collect materialized indexes while preserving immutable audit data, mark state as \`UNKNOWN/held\` on excessive complexity rather than drop an effect silently. Future empirically estimated weights are optional and *must* use named owner/domain-specific admissibility; this document sets none.

## Reuse versus new architecture

**RETAIN:** one V3 person/PFF integration conception, stored state identity and relevant history, selected trace/pressure functionality, working-copy routing as a candidate engineering technique, immutable render at immediate function grain, event selection interface, owner-specific CAN008/CAN011/ADP types and original entity/time ledger. **ADAPT:** single-winner channel to multi-stream when domain rules exist, timestep granularity from year to event+interval, real actor/source event and true nochange, capability/operation source qualification and conditional relations. **REPAIR/REMOVE:** default parent safety, demographic/age cracks/framework/typology, placebo environmental scalars, "free" learned weights, forced event/rupture, unledgered premerged deltas, narrator→psyche, derived writebacks, transactional leak, errors converted to no-effect. **CREATE ONLY AS NECESSARY:** sparse relation semantics evaluator/adapters, owner-governed conditional formation relation representation, full batch transaction/retrospective safe compilation and semantic next-event C9 read. New implementation work requires separate commission/permission.

**Confidence:** moderate that hybrid is representationally sufficient and economical to test; **low/unknown** that any unissued original-domain relation-creation rule is scientifically warranted, and **unverified** that current C9/C12 actually executes it. Thus \`ARCHITECTURE_SELECT_FOR_INDEPENDENT_REVIEW\`, **not** production adoption.
