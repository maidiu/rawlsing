2. **C9 CandidateStore SQLite is the SINGLE authoritative actor writer.** Proposed additive actor_head, actor_version, decision_receipt, processed_event, projection_outbox and reconciliation_fault tables extend existing transactions, preserving current C9 response/target/receipt readsets. One SQLite BEGIN IMMEDIATE must CAS head and insert actor version or held decision, durable receipt and outbox together. Old transaction.py does NOT already implement this. If the observed code cannot support an exclusive C9 writer and an exact atomic head/receipt/outbox commit, grade RED; choose a proved alternate physical store, never a silent second psyche.
3. **C12 retains authority for its existing objective episodes, perceptions, branch/world checkpoints and a READ-ONLY C9 actor mirror with monotonic C9 commit watermark.** Mirror is never an independent Rule T source. C12 cold open/fork reconciles C8 source clock and C9 receipt/watermark first; stale or conflicting = SYNC_HELD or FORK_HELD_INTEGRITY, never CLEAN.
4. **ADP/V2/narration/derived state are nonauthoritative projections.** No hidden M26 writes, M19 narration-to-psyche feedback, compulsory wounds/skills, historical age/type/parent seeded psyche or fourth CAN011 kind. One historical actor plus separate material social history is not a requirement for one database.
