## 3. Science outcome

`SCIENCE: HOLD / RULE_UNISSUED`. The source review is accepted as a **source-grounded differential**, not as a new developmental law. No numerical coefficient, type effect, care rule, alienation rule or readiness rule is issued.

### 3.1 Required distinctions

1. **Objective material circumstances vs the child's experienced care.** M02/M04 carry scalar constraints; they do not carry actual care transactions, co-care, presence/absence or the child's received significance. `capacity.social_support` and `caregiving_load` are not care.
2. **A parent's love/intention vs practical availability and realised caregiving.** The old code can set parent warmth/authority/material support and derive a child baseline, but cannot represent “loves the child, works two shifts, grandmother provides daily care.” Parent metrics are behaviour priors, not realised care.
3. **Independent other actors vs relationship labels/personality presets.** M20 magnets are labels/intensities with no entity reference; the `who` field is dropped. M31 parent-type tables impose fixed child-type effects. Neither is an independent actor history.
4. **Socially produced desires/practices vs demographic/Enneagram presets.** `identity_to_backbone` seeds practice stack and magnets from SES/age/religion/urbanicity; M31 seeds types. These are demographic priors, not activity-produced motives.
5. **Actor-accessible impressions vs analyst-only history/narrator fabrication.** The surface allowlist excludes `analyst_pressure_account`/`pressure_flow_history` (good), but M30's `NarrationSupport` turns LLM-rendered prose word counts into V3 psychic state. That is narrator fabrication becoming causal.
6. **Challenge/complication/threat are actor-context relations, not required valence levels.** M06's broad estrangement and M20's magnet intensity cannot express a challenge to a valued activity, an objective hazard, a practical complication, or a repair. M07's gates are scalar, not content.
7. **No lawful NO_CHANGE by missing rule.** If a care/actor/memory rule is not issued, the result is `HELD_MISSING_RULE`, not `NO_CHANGE`. The old code's missing values become 50/0/100, which is neither.

### 3.2 Worked counterexamples

**Case A — loving but work-constrained caregiver.** Parent warmth 85, authority 45, material 20; parent works long hours; grandmother provides daily care. Old code: low material support can yield status/competence forbidden; high caregiving load raises hostage; mother/father magnets exist regardless; no grandmother entity; no actual care record. It cannot represent simultaneous parental love, parental absence, and adequate co-care. The child's warm expectancy and worldly insufficiency cannot be lawfully derived from the separate adult scalars.

**Case B — materially present but coercive parent.** Parent warmth 30, authority 80, material 80. Old parent-type inference can label type 8; child model can become safety/autonomy forbidden; but there is no independent parent act and no separation of material provision from coercion. The old code can associate high material with low warmth, but not represent “present, providing, coercive” as an enacted relation.

**Case C — competing co-care.** Mother absent for work, aunt warm and present. Old code has one `caregiving_load`, parent magnets labelled mother/father, and no aunt actor/co-care ledger. It cannot distinguish which caregiver supplied which care or how the child experienced it.

**Case D — narrator fabrication.** Hold V3 state/events fixed; render one scene full of “love/care” and one neutral. `NarrationSupport.warmth` changes, and next-year metabolization/psychological capacity can change. This is a V2-prose cause, not an objective care event.

**Case E — typology.** Same life history, different random draw → different Enneagram type; parent type 8 → fixed child-type boosts; type fixed at 7. A descriptive label cannot carry this causal weight.
