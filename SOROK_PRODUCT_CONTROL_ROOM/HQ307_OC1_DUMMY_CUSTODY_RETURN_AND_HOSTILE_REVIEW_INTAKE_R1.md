## Source inspection — precise concerns, not yet an independent executed hostile verdict

These are observable code contracts; a separate reviewer must stage exact bytes and execute real counterexamples **before HQ adopts any stronger fail-closed implementation claim**.

1. **Role authority is not enforced at escrow operation:** `EscrowState.unblind(capsule_id, holder_person_id)` accepts an arbitrary string and checks only existence and whether already unblinded; `release(capsule_id)` only checks that `unblinded` exists. Neither checks holder's assigned role, currently valid signature, expiry/revocation, purpose, capsule semantics, release authorization or issued custody authority. The original h05 test manually raises `RevocationError` in its own `if revoked` clause without calling `EscrowState.unblind` for the revoked case; it does **not** establish engine-enforced revocation.
2. **Attested content unbound from capsule:** `require_second_signature(capsule, sig1, sig2, content_digest, context_id, nonce)` never dereferences `capsule` or compare `content_digest` against `capsule.content_digest` or role assignments. The test passes `None` for capsule while declaring a custody-positive lifecycle. Valid test-only fixture signatures for an unrelated digest could be accepted; test-only signer semantics may remain dummy, but never call this authoritative capsule authorization.
3. **Ledger rollback and tamper:** `rollback_ledger(seq)` *truncates* the ledger, then `verify_ledger_integrity` checks only whether remaining sequence numbers are consecutive. Original h13 explicitly calls this a “legitimate rollback” and verifies PASS; there is no append-only external anchor, cryptographic linkage, persistence or state-versus-ledger consistency proof. The negative test only rejects out-of-range rollback, not valid-range historic erasure.
4. **Blind pairing does not enforce exact multiplicity:** `verify_blind_pairing` builds a `set` of arms per nonce and only checks that it has size 3. A four-row nonce with A,A,B,C can pass even though the block isn't 1:1:1. Duplicate trial IDs, case/family mismatches and planned-row joins are not checked.
5. **Signature identity is self-asserted at TEST_ONLY grain:** `MockSigner` derives its “secret” deterministically from publicly chosen `person_id:role:EPHEMERAL_FIXTURE` and verification re-instantiates `MockSigner` from signer assertions. A caller can therefore impersonate another role at the mock level. This is explicitly labeled `TEST_ONLY`, not a flaw in an issued credential; it cannot support claims of authenticated real person/role separation.
6. **Leakage filter is lexical:** `detect_leakage` scans JSON text for a small denylist, not schema-bound packet field authorization/noninterference. Variant encodings, unexpected nested structures or semantically revealing output may evade the keyword scan; benign text can trigger false positives. The prototype may still be adequate as a demonstrative denylist, not strong firewall evidence.
7. **Freeze/manifest audit ceiling:** `frozen_negative_expectations.json` asserts `frozen_before_execution:true` but commit graph on the one published return does not independently demonstrate an earlier committed freeze. The author's reported timing might be true but preregistration custody is not proven by that field alone. `environment_passport_delta.json` uses `computed_at_return_time` placeholders rather than source-hash hex for several artifacts; manifest completeness not independently established.
