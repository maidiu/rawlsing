# 4. Residual D — common-cause resonance retrieval is a concrete engineering seam

Transcript source:
around lines 3046–3074.

The chat does not stop at:
> common generative organization may produce resonance.

It identifies the technical operation:

when Nadia/user connects facts A and B, the machine should be able to ask whether:
- A and B share upstream authoritative V3/history antecedents;
- one actually caused the other;
- neither relation is supported;
- actor access to the relevant antecedents exists.

If shared antecedents exist, an actor interpretation may gain evidence.

If none are found, the actor may still form the interpretation.

Therefore:

`NO SHARED ANTECEDENT FOUND`
does not imply
`INTERPRETATION FORBIDDEN`.

And:

`SHARED ANTECEDENT FOUND`
does not imply
`INTERPRETATION OBJECTIVELY TRUE`.

The architecture must support a provenance-bearing **derived resonance query/view** without precomputing a global symbolic-meaning graph.

This is an exact engineering extension of SPD-0232:
derive resonance from current authoritative causal/provenance state first.

The live `Q-MEANINGSTRATA-001` must explicitly own:
- retrieval inputs;
- causal-provenance evidence;
- common-antecedent query semantics;
- actor-access boundary;
- counterevidence;
- false-positive/unsupported interpretations;
- no WORLD.MEANING promotion.

# 5. Residual E — late shared-root resolution needs an explicit active-continuity propagation policy

Artifact 69 preserved the statement:

> exact inheritance of newly resolved but causally inert facts into already-running branches remains an implementation question.

The live questions did not expose that exact seam.

Example:
- User A resolves a previously unknown pre-contact fact at root time T0.
- User B already has a branch from the same root.
- the new fact would not have changed B's admitted history;
- or perhaps it would have changed some already-resolved intermediate detail;
- or B's branch was forked under an earlier root version.

The system needs an exact policy for:
- cache/root versioning;
- compatible continuities;
- automatic inheritance versus version-bounded noninheritance;
- causally inert vs causally active late facts;
- already-resolved conflicting particulars;
- replay/provenance receipts.

Strong constraint:

> **Shared pre-contact truth may expand; active continuity history may not be silently rewritten.**

But that does not by itself answer:
> which already-running branches may lawfully see a newly resolved root fact as "always true" from now on?

This belongs in `Q-LAZY-001` / `Q-PERSONSHARE-001`, not in an assumed policy.
