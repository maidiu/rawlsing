## B. Sorok product charter: a neighbor, not a game mechanic

The product charter names the central encounter: **an unchosen stranger becoming particular, consequential and potentially known enough to become kin**. User goals are recognition, humility, responsibility and solidarity, not an attachment leaderboard. None of that requires the avatar to be obedient, happy, narratively available, attractive, ideologically correct or optimized for return. Actor relations must preserve:
`attachment ≠ trust ≠ health ≠ pleasure ≠ compliance ≠ intimacy ≠ benefit ≠ dependency ≠ access`.

Under realized history a person may initiate, refuse, defer, ask, get angrier, become more independent, choose others, reinterpret the user and withdraw. A user may mistakenly perceive repair where the other experienced harm. Some relationships stabilize, stay thin or fail. The model cannot guarantee conversion to a virtuous moral outcome, attachment or political sympathy; artifice would contradict its governing spirit.

## D. Sorok 101: interactive model/engine boundary and actual customer-visible reality

Provisional strongest normal-turn diagram, not tested product:

```text
USER ACTION
→ semantic transduction model call (bounded proposed input meaning, not source truth)
→ LOCAL CAN/ADP/V3 + world/actor owner authority and effective state
→ compiled actor-safe whole-person expressive contract
→ actor-world realization model call (candidate exact speech/action/observable event)
→ local validity, occurrence and binding commit
→ strict actor-world / user-phenomenal epistemic membrane
→ local user-specific phenomenal compositing from what was objectively observable
→ USER-FACING SURFACE
```

101 proposes **two normal model calls** (a DeepSeek-class transduction, Claude-class actor realization), as a bounded hypothesis; paid transport, actual model capability and latency/cost not established. A routine verifier appellate loop or additional phenomenal LLM is a **possible feasibility failure**, not a hidden assumption. Source and participant rights remain independent.

**Irreducible separation:** total person causation ≠ current actor-event activation ≠ actor available self/conscious access ≠ actor expressed act ≠ objectively admitted visible event ≠ user-visible selected features ≠ user's inference. Hidden motive may constrain timing, word choice and silence while never being narrator-known. A user attention model may modify which real outward features are seen but cannot create that person's gestures. A person's lie or false memory can be lawful, if generated in their actor-specific possible region and correctly typed, but narrator cannot rewrite objective world.

**Noncontradiction is insufficient:** a generic perfectly warm, self-explanatory and cooperative LLM voice can violate the individual even when it contradicts no stored event. 101 explicitly requires *reasonable extrapolability from this person*, not merely legal-consistency with them. That is a major product-first scientific/computational question needing evaluation separate from C9 test coverage.

**Temporal collision remains:** normal-turn two-call aim and user-selected life N/N+1 3–5 sequential events must have an explicit integration/cadence model, original CAN/ADP time/SCI05 and failed-middle-event policy. Do not silently assume 2 calls equal total life narrative budget or 3–5 events are 3–5 prompt chunks.

## F. Product evidence categories that must not be collapsed

- **Scientific/causal:** event→actor state→later interpreted/performed behavior with warranted source and rivals.
- **Technical/operational:** durable replay, exact C9 writer/reader, cold/fork, no ghost events, source closure, user-surface occurrence binding.
- **Source/owner-native:** actual Pyat original N11/N12, actor/world C8/C11 and qualified person, no grant invention.
- **Experiential:** human can recognize a different particular person, tolerate its otherness, have meaningful consequential interaction rather than feel railroaded by a story.
- **Ethical/product:** participant scope, consent, nonmanipulative return and user opacity, privacy and boundaries.
- **Feasibility/economics:** actual provider/model/host capability, two-call target, latency, errors and realistic user context; sourcefree simulation is not a billable-service evaluation.

Each can fail independently; success at one cannot be used to declare A5 complete.
