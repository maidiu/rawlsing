### Read the row along six *independent* dimensions

1. **Artifact type** `artifact_type`: original idea, product question, formal function contract, runtime code, test/proof, reviewer text, historical source pointer, operational code, validator. Do not conflate a proposal with software.
2. **Functional relationship** `function.owner_ids`, `owner_link_grade`, `first_consumer_text`, `functional_cluster`: exact original functions where explicit; historical first-reader **text** retained as text. An index reference does not establish a working import or first-consumer proof.
3. **Implementation/receiving status** `integration.state`: historical, code present, candidate, protected archival sourcefree, reviewed at original cut, etc. Never promote candidate, test or borrowed grade into protected/current.
4. **Code/idea lineage** `source.exact_ref`, `blob`, `path`, `relationships`, `original_record`: preserve exact immutable identifiers, input user-language fidelity, alternatives and successor dispositions. A duplicate pointer remains a pointer, not an extra implementation.
5. **Independent evidence axes** `evidence`: source inspection, author execution claims, reviewer conclusion, native-science/actor authority **separate**. No absence claim from a zero-result search.
6. **Production chronology** `dates`: `first_produced_on` **null until original creation can be actually proved**; `selected_version_observed_at` verified Git commit author timestamp (689 rows), `first_path_committed_on` verified **added** status for 117 current candidate paths, and `unverified_reference_date_hint` when filename has apparent date. A branch/file-name date is NEVER silently used as actual production date. If physical git history is available, `enrich-dates` produces a separate provenance overlay; first history-visible file creation can predate or follow code copied from a different branch.
