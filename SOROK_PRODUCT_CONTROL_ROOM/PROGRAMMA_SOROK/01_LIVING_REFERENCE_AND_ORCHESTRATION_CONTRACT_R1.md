## 0. Invariant — the reference IS the operating control surface

It is a **single logical, continuously reconciled whole-project model**, with multiple views of the *same authoritative underlying record and edges*. **A separate recovery list, issue tracker, project board, source atlas, curriculum or thesis is a view/source of Programma, not a substitute for this integrated model.** There is only one coherent Programma *logical reference*, assembled from existing actual authoritative source systems and explicitly typed candidate supplements. ## 3. Status is multidimensional; "everything green" means genuinely qualified completeness

**Never use one boolean or one linear color for an entire person/product/component.** Distinguish at least:

- **Requirement coverage:** known definition, mapped relations, uninvestigated alternatives/phenomena, missing first consumer.
- **Historical recovery:** source discovered, read, original bytes verified, reconstruction distinguished, function identified, current integration existence.
- **Scientific warrant:** proposed theory, owner-scoped method/issuance, evaluated NOCHANGE, competing interpretation, empirically qualified, genuinely unresolved.
- **Engineering:** not built, code candidate, sourcefree author-tested, independently reviewed scoped, current actual consumer tested, merged/adopted with exact CAS.
- **Source and actor permission:** original empirical/source grant, CAN/ADP/SCI05 or actor/trust custody, downstream lawful use/denial, Pyat boundary.
- **Product/human evidence:** proposed experience, simulated fixture, bounded reference-person demonstration, actual participant evidence, alpha-specific or generalized.
- **Operational state:** not commissioned, SEALED prompt, dispatched by user, local running *verified*, returned immutable SHA, in review, adopted, blocked, superseded, rejected.

For each dimension: `UNKNOWN`, `MISSING`, `IN_PROGRESS`, `HELD`, `RED`, `PARTIAL_SCOPE`, `REVIEWED_SCOPED`, `QUALIFIED_FOR_THIS_CONSUMER`, `NOT_APPLICABLE_WITH_REASON` (not all states apply to all dimensions). Every promotion requires immutable evidence, competent authority, updated dependencies and an actual relevant consumer where the claim entails one. An agent's self-reported PASS is never scientific issuance, independent acceptance or production adoption. `HELD` is not evaluated `NO_CHANGE`.

"Green" can mean **only** `QUALIFIED_FOR_THE_DEFINED_SCOPE_AND_FIRST_CONSUMER`, with needed engineering, science, authority and real-product evidence independently satisfied. ## 5. A return is not "folded in" unless its consequences are propagated

Each material work or science return triggers a **single coherent Programma intake transaction**, without creating an extra bureaucratic court:

1. **Locate:** exact immutable branch/head, original owner/reviewer, source object and local process status; determine whether actual submitted code and source/permission context changed.
2. **Classify:** new requirement, new primary source, existing function, candidate code, independent review, original science, RED, rejection, supersession, native grant or product evidence. Keep negative and conflicting versions.
3. **Attach:** update all affected original ID nodes and typed edges, not just append a worker row. Link first actual consumer and its upstream/downstream owners; preserve disputed alternatives.
4. **Regrade:** update only the dimensions genuinely demonstrated; propagate any invalidated/changed evidence to dependent consumer, requirement and terminal readiness. Do **not** auto-green descendants.
5. **Reassess:** recompute gaps, blocked terminal outputs, meaningful progress, alternative paths, current priority/parallelism and the largest lawful coherent flight.
6. **Commit:** qualified owner applies an exact reviewed atomic update to living Programma/canonical progress/handoff using existing CAS/source authority (or explicitly returns `NOT_ADOPTED_PENDING` with candidate refs). Keep the old source/history.
7. **Readback:** confirm actual current graph/reference changed and source cut matches; user-facing report states `WHAT_ADVANCED`, `WHAT_DID_NOT`, `WHAT_BECAME_RED_OR_HELD`, `WHAT_IS_NEXT` and precise owner.

If an author branch or PR exists but owner has not adopted it, the graph may reference `RETURNED_UNADOPTED` as **candidate capital** without changing canonical accepted status. Never quietly mutate source-owner scientific records as part of Programma update. The same source, state and edges inform subsequent scientific adjudication and priority.

**Mandatory update triggers:** original primary-source recovery/false-negative correction; source owner/reviewer decision; tests or runtime defects; new code implementation; actual native adoption; ongoing worker return/lease change; changed Pyat interface/proof; changed scientific alternative; new user/product requirement; an actual human alpha result; invalidated prior claim. No "we will update later" if current priorities are being selected from stale state.
