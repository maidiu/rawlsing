# Sorok Court 8E — Zero-Profile Main Mode / Anti-Self-Construction R1

Status: PROVISIONAL_MAIN_MODE_CORRECTION__SUPERSEDES_22D_AS_DEFAULT_ONBOARDING

Date: 2026-09-29

## 0. Correction

The optional Portal Profile explored in 22D is useful as a design-space / advanced-mode possibility, but it should **not** define the main Sorok onboarding.

Requiring the user to decide how each part of themselves should be carried, translated, hidden, homologized or contextualized asks them to construct an explicit theory of themselves before relation has begun.

That conflicts with Rawlsing's deeper premise:

> self-knowledge should emerge through life and relation, not through pre-game psychographic self-curation.

Main-mode default:

**NO CHARACTER CREATION. NO SELF-TAXONOMY. NO PERSONAL-DOSSIER INTAKE.**

---

## 1. Main-mode portal law

The user is presumed to remain themselves.

The portal owns only the minimum transformation required to make that self causally present as a homologous peer in the generated world.

The user does not need to decide this transformation field by field.

Candidate sequence:

1. Rawlsing rolls the persona and local field.
2. Portal generates a homologous player position and thin relation-sufficient embodiment.
3. User receives a short constitutional briefing and concrete local facts they need to act.
4. Play begins.
5. Real-user autobiography enters only when the user naturally says/does something that makes it relevant.
6. Portal applies governed translation lazily and shows any material realization change.

---

## 2. What may be asked upfront

Only facts required for safe/basic interaction, preferably at the level of functional constraints rather than identity narration.

Candidate minimal asks:
- how the user wants to be addressed, if not already available;
- pronouns / social address only if required by language/world interaction;
- language/interface preference;
- accessibility requirements that affect interaction;
- age/adult-status if required for lawful embodiment/mode access.

Even these should be minimized and separated from psyche.

Do NOT ask main-mode users upfront for:
- ideology;
- religion;
- personality;
- socioeconomic class;
- trauma/loss history;
- family map;
- income;
- employer;
- relationship style;
- self-described cultural identity;
- moral values;
- hobbies/tastes;
unless a later product mode has a specific, transparent reason and explicit user opt-in.

---

## 3. Portal-generated player shell

The portal should generate, not ask the user to design:
- local dwelling / adjacency;
- peer-comparable material/resource envelope;
- local livelihood/time burden at sufficient causal grain;
- transport/access;
- local institutional position;
- thin social legibility needed for ordinary interaction.

The user learns these as facts of the portaled reality.

This preserves the veil: the player does not optimize their starting position.

---

## 4. Actual self enters through behavior, not intake

The user's real:
- beliefs;
- memories;
- humor;
- prejudices;
- convictions;
- knowledge;
- relational habits;
- tastes;
- interpretations;
- autobiographical facts;

need not be preloaded to be causally real.

They enter the simulation when the user actually:
- says them;
- acts on them;
- invokes a skill;
- remembers something;
- makes a comparison;
- discloses a relationship;
- reacts according to them.

Thus the game learns the user through the same basic epistemic route by which another person does:

> **through encounter, behavior, testimony and accumulated history.**

This symmetry is productively aligned with the whole project.

---

## 5. User testimony is not portal truth

If the user says:
> My father died when I was twenty.

that becomes a user-authored testimony event unless another explicit authority class governs otherwise.

The persona may believe it, question it, remember it, misunderstand it, or respond to it.

Rawlsing does not need to have pre-registered the fact before the user can speak it.

The system likewise must not infer hidden biography merely because the statement seems plausible.

---

## 6. Contextual fact admission instead of profile completion

Sometimes the user's natural action raises a capability/constraint fact that the portal genuinely must know.

Example:
> I start playing the piano.

If piano skill has not been established, the engine should not silently grant virtuosity or force a 40-question profile.

Possible bounded responses:
- conservative realization;
- lightweight contextual clarification;
- explicit user claim recorded with appropriate authority;
- later verification through performance where modeled.

Main principle:

`CONTEXTUAL NEED → MINIMUM FACT ADMISSION`

not

`POSSIBLE FUTURE NEED → EXHAUSTIVE PROFILE`.

---

## 7. Private real-user settings remain infrastructure, not identity construction

Some information may exist outside diegetic play for:
- accessibility;
- interface language;
- privacy choices;
- content boundaries;
- account preferences.

These should remain product settings unless an explicit lawful bridge makes them diegetically relevant.

Do not conflate product personalization with player-world ontology.

---

## 8. Optional deeper profile becomes secondary/advanced

22D remains useful for later:
- research mode;
- structural replay;
- alternate-self experiments;
- high-fidelity personal transposition;
- users who explicitly want stronger continuity.

But default Sorok should not ask users to become administrators of their own ontology.

Advanced profile data, if ever used, must remain purpose-bound and optional.

---

## 9. Better user experience

Instead of:
> What crosses the veil with you?

the main mode can simply say, in effect:

> **You remain yourself. The portal will translate only what it must to make you live here. If that changes what your action or words become, you will see the result. You do not need to build a character.**

Then the user enters.

---

## 10. Why this is philosophically cleaner

The user should discover both the persona and themselves through relation.

A long identity questionnaire encourages:
- self-description before action;
- self-branding;
- idealized self-construction;
- premature explicit theorizing;
- Goodharting of later praxis;
- treating Rawlsing as a personality mirror before it becomes a life.

Zero-profile mode instead preserves:

`LIVED PRAXIS > SELF-DESCRIPTION`.

---

## 11. Scope consequence

This also reinforces the Court 7A theorem:

> the persona carries the thick alternate-life burden;
> the player's identity only needs to be relation-sufficient at entry;
> post-entry history becomes thick through actual life.

Therefore pre-entry data hunger should be treated as a design smell.

---

## 12. Current main-mode candidate

**Press button → receive portal constitution → receive thin local situation → meet the neighbor.**

No character builder.
No personality survey.
No autobiography intake.
No SES conversion questionnaire.

Everything else should earn its way into the system through actual relational relevance.
