# Sorok Dockets

A docket is a bounded investigation created only when a registered question needs sustained work.

Naming:

`D###_<SHORT_SLUG>/`

Initial planned dockets:

- `D001_RELATIONAL_ONTOLOGY_V3_BOUNDARY/`
- `D002_ALPHA_CORE_LOOP_ACTION_SURFACE/`
- `D003_FLOURISHING_INDEPENDENT_OF_ATTACHMENT/`
- `D004_TIME_LIFE_ADVANCEMENT_ASYNC_CONTACT/`
- `D005_EVENT_MEMORY_DYAD_PERSISTENCE/`
- `D006_PLAYER_PRAXIS_MODEL/`

A docket should end in a return that either:
- closes a question;
- narrows it;
- identifies required evidence;
- produces a prototype;
- or explicitly defers it.

A docket must never silently become governing product law. Its accepted conclusion is serialized into the decision ledger.

Cross-cutting discovery docket:
- `D007_KERNEL_SIFTING_AND_DERIVATIONAL_COMPRESSION/` — active home for `Q-KERNEL-001`; maps conversation/product laws into candidate generative forms, derivation strength, tensions and hostile falsifiers. D007 must never silently promote a candidate formulation to the Rawlsing kernel.
