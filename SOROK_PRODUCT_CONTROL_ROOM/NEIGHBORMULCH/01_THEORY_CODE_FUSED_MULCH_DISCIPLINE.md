# 01 — THE MULCH DISCIPLINE
## Theory-MULCH, code-MULCH, then the single reciprocal act that transforms both

**Research/construction discipline.** Not an autonomous new scientific law, new decision owner or permission to rebuild proven functions. This is a concrete method for developing Rawlsing under original-source, functional-conservation, world/actor and receiving constraints.

## 0. MULCH is not aggregation, consensus, dilution or stylistic synthesis

MULCH means making **the real contradictions inside and between existing conceptual and computational arrangements productive of a new, more adequate arrangement**.

Not "integrate these viewpoints" as prose; not "theory says X, code implements X" as a one-direction waterfall; not "put interface A onto B"; not "make all existing components fit by leaving every assumption intact"; not hostile critique detached from construction; not source archaeology as a permanent substitute for building.

A theory that cannot survive the first running consumer **changes**. A working implementation that cannot explain which human/world function it preserves or whose rights it crosses **changes**. Existing code is materialized intelligence: preserve capability, not necessarily the exact algorithm or its mistaken assumptions. A sourcefree approximation can operate provisionally without claiming unique scientific validity.

MULCH must yield:
1. **A new positive conception** of the entity/process, not only a list of missing functions.
2. **Material source and code operations** which embody that conception, reusing real existing owners.
3. **Executed, falsifiable interactions** in which the code can prove the conception inadequate and force another round of theory.
4. **Durable no-drop history**: what was conserved, modified, refuted, held, superseded, tested and still not demonstrated.

## 1. THE FIRST MOTION — THEORY-MULCH

### 1.1 Recover the real problem, not only the technical request

State the end-product phenomenon **on its own terms**: a human user meets a materially independent, self-developing Other in a continuing world. Ask the historical-material questions: by whose activity did this world arise? What can the person actually do? Whose perceptions, needs, meanings, resources and constraints exist independently? What does this encounter change, for whom, and at whose cost? How can the world simultaneously form, support and constrain people who remain variable?

Read original user decisions, rival theoretical sources, original mechanics, inherited code, first consumers and failure reports. Distinguish:
- user-settled aim versus agent speculation;
- original phenomenon versus a convenient data representation;
- mechanism versus explanatory narration;
- world fact versus actor belief versus user perception;
- historical formation versus current recruitment versus retrospective self-account;
- material rights and action possibilities versus semantic or psychodynamic attraction;
- sourcefree simulated operation versus empirical/scientific authorization.

### 1.2 Recover *contending* positive claims in their strongest forms

Do not caricature P4/P6 as "old toy game" or R21 as "the real psyche." The inherited Mechanisms implement subtleties (historical world depth; gaze and recognition; directional vision, hearing, embodied actor initiative) the newer research organism may not have. Conversely, the organism implements deep historically modified project/recruitment/psychodynamic and SQLite life that a P6 scene-context model cannot simply conjure.

For each claim construct a compact **theory-function card**:
- exact source, date, source status, user/authorial intention;
- what reality it models and what causal difference it produces;
- what it expressly refuses to infer;
- where its limits become visible under counterexample;
- direct code owner/test when present;
- which better conception might preserve both its achieved function and its resistance.

No newer-by-date rule. No false equality of empirically grounded and merely conjectural proposals.

### 1.3 Make the contradictions specific and irreducible

Examples:
- "World detail exists independently of user attention" AND "user only ever sees a finite, historically mediated subset."
- "A person feels and recruits private psychological organization" AND "nobody, including the actor, has transparent access to all of it."
- "Nadia may hear steps behind her" AND "she cannot visually know where an unseen person is looking."
- "A user can inspect privately" AND "only outwardly realized conduct can change Nadia's evidence."
- "Historical completion may reconstruct an object's earlier history" AND "the actor cannot retrospectively remember an event their actual life never included."
- "Mechanism III responds to player conduct" AND "the response must be generated by actual actor history, not role prompts."
- "Protected P4/P6 already have a valid event history" AND "the R21 organism also has eventful history" AND "there must be **one** actual event, not two aligned stories."
- "Nadia is psychologically deep" AND "most of her life before user contact is heavily compressed, ordinary and offscreen."
- "One user action may be materially inert" AND "its occurrence and opportunity cost are still a real historical event."

These are not reasons to choose a winner immediately. They are the forces to preserve in a transformed conception.

### 1.4 Produce an immanent transformation rather than a compromise

For each apparent conflict:
1. Identify the *valid* function of each inherited arrangement.
2. Identify the assumption which makes them falsely exclusive.
3. Propose a more adequate **causal relation** in which both functions survive in differentiated places.
4. State what this new relation would computationally need to exist.
5. State its strongest falsifying example and what would force the theory to change again.

Example: not "replace current actor_access with Mechanism III perception" and not "wrap the coarse actor_access call in a Mechanism III adapter." Reconceive **situated actor access** as a multi-stage material/sensory/attention/history operation: independent event affordance → bodily oriented access → modality, occlusion, hearing, divided attention → actor-conditioned notice → fallible interpretation → consequence for recruitment. Retain MIII sightline/behind-hearing **and** organism's needs/history/recruitment; choose or transform source owners only after their actual semantics are examined.

### 1.4A The jagged-shard invariant: MULCH is sharpened contradiction, never false fit

**Direct controlling user correction (November 23, 2026):** MULCH *“always means keeping the sharpest jaggednesses of the shard, and drawing them out in heightened contradiction with anything else, until the deeper ground is discovered”*; it is **“never, ever smoothing shit over falsely and losing resolution to make the pieces fit.”** This governs the present THEORY-ONLY completion phase. Prior instructions to build or test software do not justify leaving the unfinished NEIGHBOR theoretical HOME for construction now.

A recovered shard is indispensable only if it contributes a **distinct causal possibility, historically grounded determination, negative limit, irreducible experiential distinction or generative contradiction** not already adequately available to the mature encounter. Do not mistake a historical author's speculative product feature, a richly phrased duplicate, an incidental example, or an allegedly missing module for such a shard.

For each admitted shard, preserve **five tensions** rather than reducing them to agreeable prose:
1. **The source at maximum strength:** what did it claim, on what actual historical evidence or provisional status, what was its most uncomfortable example, and what conclusion did it *not* license?
2. **The conflict at maximum strength:** which existing HOME determination does it resist? If both claims were true, what must be distinguished—objective occurrence from interpretation, joined routine from separate actor feeling, a real Other from their visitor-facing tip, shared pleasure from unequal burden, a real collective practice from one user's social control?
3. **The nontrivial ground:** show what *new causal relation or developmental possibility* permits both claims to remain true without abolishing their opposition. Do not make the contradiction disappear by saying "both matter" or by redescribing it in a more beautiful abstraction.
4. **The residue of nonreconciliation:** preserve actual dissent, asymmetry, uncertainty, unequal costs, contextual exceptions, counterexamples and open questions. A historical synthesis that would require a person's psyche, a relationship or a class antagonism to become internally harmonious is suspect.
5. **The exact changed HOME function:** identify which already existing movement becomes more determinate; replace or relocate blunter material in place where possible. A new paragraph must *earn* its space by changing the reader's conception of what the encounter can actually become, not by repeating its philosophical oath.

**Conservation is semantic, not merely textual.** Keeping the immutable source foundation or the old version in Git is necessary but does not prove the active HOME retained each important *distinction*. Conversely, retaining every old formulation verbatim in the active argument can prevent synthesis. Preserve the original at exact source; transport its sharpest operative distinction into the correct current chapter; put out-of-game product choices in OUTSIDE HOME; record rejected or unresolved alternatives with reasons in the ledger.

**Example, not a substitute for the work:** historical relational theory says two people can genuinely acquire a shared practical/humorous routine; constitutive psychology says their affects, models of one another and underlying investments can remain distinct and mutually mistaken. The synthesis is **not** "they form a close relationship" or "intimacy is complex." Its harder center is an *objective jointly acquired competence whose reproduction can increase ease and increase unequal vulnerability at the same time*, without authorizing a new supra-personal psyche or a hidden affinity score. That changes what NEIGHBOR must render as socially possible.

**Do not run the code-MULCH, acceptance-test or construction programme as the answer to a user's request to complete theory.** Current theory work may cite existing program evidence to establish a historical owner's boundaries, but it does not write new code, new modules, new tests or pretend implementation. Code-MULCH follows a separately authorized construction stage.

### 1.5 Require provisionality with precision

The system can approximate a fictional person creatively and substantially while the scientific model is incomplete. But don't call an LLM-generated motive a discovered human law. Don't confuse generative intelligibility with deterministic fate. Don't make contradiction resolution automatic, compulsory, morally progressive or reducible to a scored personality axis. Unknown and unobserved are positive distinctions.

**Theory-MULCH return:** an operative positive account + source-anchored alternative/contradiction table + declared unresolved assumptions + direct desired first-consumer behavior. It is NOT complete if it merely says "further research needed."

## 2. THE SECOND MOTION — CODE-MULCH

### 2.1 Reopen exact owners *before* writing a missing function

Start from canonical PROGRAMMA, SOROKUDA, existing 144-function/38-seam guide, source/test status, protected receiving and the precise first consumer. Search only the specific disputed function further. Reuse an existing producer; extend it if incomplete; if a function is better implemented historically, recover its behavior with exact evidence. Prefer bringing a real causal producer into one world to adding a second renamed store.

**Engineering proof of reuse:** which existing file/function emits the relevant evidence? Who consumes it? What identity/provenance/capacity/source grade does it carry? What test exercises the seam? Which negative has previously failed? How does the proposed change conserve that function?

### 2.2 Demand an owner/authority and provenance map

For every state:
- canonical root, branch and time;
- world fact vs user action attempt vs world realization vs actor received sign;
- actor private history vs outward activity vs user-visible occurrence;
- source issuer and prior event identity;
- write transaction boundary, retries, idempotency, replay/cold reconstruction;
- actor/source/rights/privacy/science grade;
- prior first consumer and whose method must remain authoritative.

If two runtimes can each commit an equivalent event, **that is an unresolved authority collision, not a successful integration.** Never solve it by merely double-writing and later comparing text.

### 2.3 Preserve historical functional intelligence without laundering defects

For each implicated function compare actual producer, data semantics, first consumer and tests across protected Mechanisms/P4/P5/P6, old legacy V3/CAN/ADP, the R21 research organism, the later R23–R25 development, and SOROKUDA's alternative R5 kernels. Choose preservation, safe reuse, extension, selective transplant, supersession with proof, or explicit hold; never overwrite a tested function wholesale with a newer unexecuted file.

Examples of *must not regress*: MII private gaze cannot write Nadia; MIII footsteps behind without gaze omniscience; Mechanism I source-time admission/revocation; actor/world refusal gates; R21 cold SQLite; source actor identity; body/age capacity; inhibited psychoform not revived; independent Other consent; R23–R25 developed psychology must not be silently discarded when the encounter code first runs.

### 2.4 Build connected capability, not fragments

Prefer one vertical operation:
- actual input from user or actual independent actor;
- existing world/physical eligibility and event settlement;
- actor-specific sensory/attentional receipt;
- actual acquired actor recruitment and voluntary/exploratory choice;
- world consequence independent of actor rationale;
- actor-lived afterlife; MII finite exposure; next day/history;
- cold replay and a second encounter affected by the first.

A mock can establish a narrow negative or algorithmic check. It is not proof that this connected path executes. A standalone narration demo is not an organism.

### 2.5 Engineering falsifiers are compulsory

Include **positive and negative controls**: same user move/different acquired actor histories; same world/private gaze variation; hearing-but-no-seeing; zero direct observation of a private intention; false actor source; fabricated memory; duplicated event; absent Other; bodily limits; institutional rights; counterfactual branch; source revocation; crash-before/after-commit; cold restart; invalid candidate atomic rollback; unrelated user who never meets Nadia. Run normal + -O, focused and inherited suites at the **new exact SHA**. Do not claim donor PASS transfers to the modified branch.

**Code-MULCH return:** changed original owner functions, newly connected first consumers, exact SHA, executed results, whole-system regression status, specific first faults, scientific/rights limits and receiving status.

## 3. THE THIRD MOTION — *FUSED* MULCH

The first two alone are insufficient. **Fused MULCH means code is not a downstream illustration of the theory: running the code can change what we think the process IS, and the transformed conception changes the code again.**

### Cycle A — Theory challenges code

E.g., constitutive psychology says recognition and practical orientation are already historically operating *before* a familiar event cue is labeled. If the current engine only reacts after named tags, identify the concrete limitation, preserve existing attentional producers, extend pre-cue recruitment, and construct an actor-difference test.

### Cycle B — Code challenges theory

The new test exposes that an alleged "user attention" change is private and cannot be observed by Nadia, or that the event owner creates co-presence without directional vision. This is not only a failing test: theory has incorrectly conflated **visibility, notice, interpretation and response**. Reconceive the relation and change both the source explanation and executable owner path.

### Cycle C — The historic accomplishment survives transformation

The final code retains the previous lawful sensory distinction, actor autonomy, user agency, independent material consequence, cold memory and the new developed psyche. The new theory articulates their *single causal process*, not independent layers. Then prove the reunited behavior in a **real first consumer**, not the same unit fixture that generated the claim.

### Cycle D — Return a new open contradiction and keep building

Every successful integration reveals a next frontier: e.g. a person attends in the kitchen but their work and family commitments have been constructed as detached action labels; or an object acquires history but actor value is still only narrated. Write the newly exposed contradiction and directly select the next original-owner construction. **Do not create an indefinite theory-only loop.**

## 5. Six strict anti-patterns

**(i) The adapter fallacy:** A transforms state into B-shaped data while A and B still each claim sovereignty. Require one causally authoritative state transition.

**(ii) The model-as-person fallacy:** Mechanism III's LLM generates Nadia's motive/choice from prose descriptions independent of actual recruited organization. The LLM may construct bounded hypotheses/expressions; source owners must govern admission and activity.

**(iii) The clean rewrite fallacy:** A newer module silently removes old sensory/access/recovery operations because they are inconvenient. Compare exact capabilities and their first readers, then preserve and transform.

**(iv) The documentation-completion fallacy:** Three speculative 20-page documents do not equal one executed 20-step causal loop. Every conceptual advancement must point toward source change.

**(v) The validator-as-destiny fallacy:** Perfection of a sourcefree test cannot certify empirical personhood, native human science, moral truth, autonomous agent rights or production.

**(vi) The permanent repair detour:** A builder's unexecuted tests or integration first faults are the builder's responsibility. REMONT independently hunts bounded consequential defects *after* author first consumers exist, not as substitute builder or global brake.
