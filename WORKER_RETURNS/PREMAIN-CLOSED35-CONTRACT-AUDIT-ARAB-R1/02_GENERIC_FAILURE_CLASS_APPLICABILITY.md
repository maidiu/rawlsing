## Cross-wave adjudication

The same generic hostile question may apply to multiple waves, but its substantive answer remains source-local. No WVS7 or LiTS value mapping, risk membership, successor scope, routing rule, weight rule, ID rule, or response semantics was imported.

### LiTS-style risk-set/successor machinery

`NOT_APPLICABLE` as a source-wide Arab realization mechanism.

What **is** conditionally applicable is generic PRE553 routed-target membership once a runtime package actually declares such a target:

`documentary source route -> governed RoutingEligibilityFact -> exact risk_set_ref -> replayable member_set_replay_ref`.

That chain must be built per admitted Arab target. It is not inferred from missingness and is not a reason to create a LiTS-style historical-successor authority.

### Current source defenses already proved at realization grain

- W1: literal text, replay identity, Morocco/non-Morocco route boundary, design UNKNOWN, cross-wave firewall.
- W2: ordinary zero/system missing separation, ranked slots, Lebanon route, no default WT, code-0 UNKNOWN.
- W5: noninjective ID, design-carrier nonselection, dictionary noncollapse, ranked/split topology, Unicode preservation.
- W8: ID=0 and blank-string preservation, Q1/STRATUM nonalias, select-all topology without invented native MR metadata, design nonselection.

These defenses specifically answer `LAWFUL_AUTHORITY_REPRESENTATION__CONSUMER_IGNORES_FORM` and `CURRENT_PRODUCT_SHAPE_MATCHES__SUBSTANTIVE_PRIOR_TRUTH_NOT_PROVED`; runtime packaging must preserve them rather than re-derive them.
