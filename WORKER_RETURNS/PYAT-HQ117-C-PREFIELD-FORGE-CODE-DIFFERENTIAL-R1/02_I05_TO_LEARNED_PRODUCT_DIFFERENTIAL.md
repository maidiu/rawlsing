# I05 → learned-product differential

## Exact post-I05 object graph

`CarrierNeutralResearchExecutor.execute_i05()` returns `ExactBoundedDiscoveryResult` from `pre553_discovery_exact.py`. The result closes over exact `DiscoveryResultReceipt`, `EmpiricalFact`, `EmpiricalPredicate`, and `EmpiricalQuerySpec` preimages plus exact discovery authority, candidate grammar, evaluated frontier and replay refs. It requires `candidate_count == covered_candidate_count`; exact-bounded mode cannot silently claim complete coverage over a partially evaluated declared frontier.

## Discovery receipt is not promotion authority

`DiscoveryResultReceipt@1.0.0` records candidate identity, winning predicate, empirical/validation facts, coverage, ancestry, uncertainty and replay under the discovery authority. It does not own structural admission, causal interpretation, actor state or Field Forge ontology.

The hostile whole-machine acceptance test makes the boundary explicit: an `EmpiricalFact` plus provenance and even a discovery receipt remains nonpositive for structural use without separately owned exact I04 authority.

Therefore this generic edge does not exist and must not be invented:

`DiscoveryResultReceipt -> automatic validated structural/Field-Forge relation`

## I04 exists now

`pre553_structural_admission.py` implements `evaluate_structural_empirical_admission()`.

Its semantic inputs are the exact `EmpiricalQuerySpec` and `EmpiricalFact`, an exact requested structural-admission `AuthorityRef`, an exact `StructuralAdmissionRule` if available, an exact `StructuralAdmissionRequest`, and an `AuthorityRegistry`.

`StructuralAdmissionRequest.discovery_result_receipt_refs` carries discovery lineage into dependency closure. It does not substitute for the admission rule. Only `ADMITTED` permits positive `StructuralEmpiricalAdmission` semantics and direct M1 projection. Missing authority, DENY, DEFER, negative-only, noncomparability, insufficient evidence, unresolved target, temporal/scope mismatch and integrity failure remain nonpositive.

Current disposition: `CURRENT_IMPLEMENTED_DISCONNECTED__CLAIM_CONDITIONAL` from the generic selected-B executor.

## Execution receipt is not learned-product release

`learned_empirical_execution_receipt()` creates `PRE553_LEARNED_EMPIRICAL_EXECUTION_RECEIPT@1.0.0` with `claim_kind = LEARNED_EMPIRICAL_EXECUTION_ONLY` and explicitly false structural, causal and actor-V3 effects.

It is appropriate output for the commissioned execution compositor. It is not evidence that a learned empirical product has been published or selected current.

## Product-specific learned-world code exists

The absence of a generic release owner does not mean no learned products exist.

- `field_forge_conditional_support.py` emits a producer-preserving actor-independent conditional-support relation from exact joint I03 fact/query.
- `pre553_effective_n.py` emits `EffectiveNProduct`, explicitly a measurement receipt and never empirical truth authority.
- `source_backed_positioned_subject_possibility.py` emits `PositionedSubjectPossibilityResult` from exact evidence plus model/walkback/proxy authorities.
- `pre553_structural_admission.py` emits `StructuralEmpiricalAdmission` only under exact structural admission authority.

These families have distinct semantic owners. A future composition layer must preserve that noncollapse rather than create one new owner over all learned products.

## Direct I03 → Field Forge path

`produce_exact_conditional_support_profile()` proves a direct lawful edge:

`EmpiricalQuerySpec + EmpiricalFact -> Field Forge exact conditional-support relation`

at the frozen GT2 contract grain.

`wave1_gt12_i03_positive_facts.py` demonstrates that current exact I03 code can produce the Q86A/Q86B joint fact shape demanded by this relation. That adapter is source/claim specific and does not generalize to selected-B all-source production.

Therefore a mandatory generic I05/learned-release stage in front of every Field Forge product would introduce a false dependency.

## Stronger relation → structural path

Once the actor-independent relation itself is the object to be structurally mediated, requirements strengthen:

`Field Forge relation -> exact relation admission -> admitted relation projection -> M1/V554 SIG-004`

`wave1_ff_prev3_relation_admission.py` owns the frozen GT2 relation-admission decision at that bounded grain. `m1_admitted_field_forge_relation_v554_ingress.py` then accepts only exact positive admitted relation material and requires semantic identity, participant role/order/cardinality, native scope, source/risk, permissions, authority/current-selection/dependency/provenance, replay and equivalence closure.

This does not establish a generic relation-admission owner for every future Field Forge product family.

## Missing generic learned-product layer

No generic current `rawlsing_next` owner was identified for the full learned-product lifecycle: release identity, publication, current selection, supersession, rollback, dependency invalidation/rebuild and serving selection.

`pre553_authority_maintenance.py` supplies these lifecycle concepts for semantic **authority**, not learned empirical product releases. Fixed repo-native/canary transports likewise do not generalize that ownership.

## Differential holding

Post-I05 there is no single missing monolith. There are three categories that must remain separate:

1. existing current product/consumer implementations that are not generically composed from selected B;
2. claim-specific authority gaps where code must remain dormant unless an exact rule/current selection exists;
3. a genuine generic lifecycle/composition gap for learned-product release/currentness across product families.

Collapsing those categories would recreate the authority/promotion errors the PRE553 contracts are explicitly designed to prevent.
