# Compositor scope correction

## Holding

The HQ116-C `thin compositor` diagnosis is **correct at one grain and incomplete at the next**.

It is correct that the audited base lacks one production entrypoint that packages the already-existing selected-B execution chain:

`physical/native incidence -> governed projection -> source-backed C11 repository -> carrier-neutral executor -> I03/I05 -> execution manifest/receipt`

It is incomplete if read as:

`therefore everything from selected B through Field Forge is only one missing thin compositor`

That stronger reading is contradicted by current code.

## What the commissioned compositor should own

`pre553_route_b_production.py` should own only deterministic production composition of already-authorized execution inputs and outputs:

- exact physical-incidence input accepted from the caller;
- exact caller-owned `GovernedC11Projection`;
- exact `RuntimeObjectCatalog` and runtime authority set;
- exact `DiscoveryAuthority` selection supplied by caller/current package;
- `build_source_backed_c11_repository()`;
- `bind_repository_builder()` / `CarrierNeutralResearchExecutor`;
- exact I03/I05 execution;
- exact `learned_empirical_execution_receipt()`;
- deterministic object/replay/accounting manifest.

It should expose typed failures from underlying contracts and should not recover by latest/default/fuzzy selection.

## What it must not own

The execution compositor must not absorb:

- source-specific semantic projection construction;
- source-universe relation invention;
- structural admission policy or I04 rule creation;
- discovery-result promotion into relation truth;
- adaptive/recursive discovery policy selection unless separately requested under exact authority;
- Field Forge relation semantics;
- relation-admission semantics;
- positioned-subject model/walkback semantics;
- learned-product publication/current selection/supersession;
- authority creation or maintenance;
- V3/person state.

## Existing code it bypasses by design

The narrow compositor can finish successfully without calling all of the following current modules:

- `pre553_structural_admission.py`;
- `pre553_discovery_adaptive.py`;
- `pre553_recursive_handoff.py`;
- `pre553_source_relations.py` unless the selected query/product requires multi-universe composition;
- `pre553_effective_n.py`;
- `pre553_component_authority_vector.py`;
- `source_backed_positioned_subject_possibility.py`;
- `field_forge_conditional_support.py`;
- `wave1_ff_prev3_relation_admission.py`;
- `m1_admitted_field_forge_relation_v554_ingress.py`.

That bypass is not itself a defect. Those modules belong to downstream or alternate claim-specific branches. The defect is only the absence of an exact later dispatcher/composer when Rawlsing wants to activate one of those already-authorized branches from selected-B output.

## What the compositor does not close

After the compositor lands, these remain separate:

### 1. Product dispatch/composition

Which exact product contract is requested, what input object family it consumes, and which current producer/rule is authorized?

### 2. Product lifecycle/currentness

How does a produced learned object become a named immutable release, which exact release is current for which consumer/scope, and how do supersession/rollback/invalidation work?

### 3. Source-specific projection coverage

How does each selected-B source obtain its exact governed projection without semantic inference?

### 4. Claim-specific structural admission

Does the fact/relation have exact current authority for a particular structural use?

### 5. Field Forge adoption

Which exploratory Field Forge product families have actually been adopted as current Rawlsing semantics? W48 says the broad frontier remains nonbinding.

## HQ wording recommendation

Use:

> `The first code repair is a thin selected-B execution compositor. It closes Route-B execution packaging, not the whole pre-Field-Forge compiler. Current downstream product/admission implementations already exist at several grains; what remains after the compositor is exact composition/dispatch plus a separately governed learned-product lifecycle/currentness surface.`

Do not use:

> `Only one thin compositor remains between Route B and Field Forge.`

The latter would erase both existing implementation capital and the real lifecycle gap.
