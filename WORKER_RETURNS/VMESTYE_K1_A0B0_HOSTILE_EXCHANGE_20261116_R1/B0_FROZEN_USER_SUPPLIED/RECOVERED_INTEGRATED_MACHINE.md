## 3. Computational intelligence: shared preparation made *multiple* scientific tasks tractable

### A. What was actually shared

V550's country prefetch collects the selected country/question source frame once in a qualified path and reuses prepared rows across distinct question analyses. V549 made a respondent-by-variable pivot and memoized parent-derived conditional masks; V549b *reconstructed* rather than automatically shared V549's cache. V550J separately prepared source/wave/country **family populations** reusable across active J families, each still computing its own statistics. Another mechanism resumed a V550 question if a marker and **matching question-use-contract hash** existed. Those four are different physical and semantic activities; none can be dismissed or replaced on the strength of the word “cache.” VOSKRES A/B independently reconstructed these source-code sharing strategies. Its corrected report explicitly retracts an earlier false claim that checkpointing tested existence only.

**Why composition mattered:** One prepared respondent frame could support base answer frequencies, per-country frequencies, marginal positions, conditional answer-by-indicator matrices, information/ranking, recursive branch nodes, subgroup deviations and attitude co-travel—all with different population masks and outcomes. Shared extraction does **not** prove identical denominators or one computation of every metric. Example: `P(X)` for respondents with observed position X is not `P(Y | X)` for those who supplied a usable question response. Collapsing them into a cached response probability is a science error, not merely a performance issue. See paths `K1B0:P01`, `P02`, `P04`, `P15`.

The primary V550 code's `secondary_indicator_summary_rows` first identifies a primary from k indicators, then compares alternatives against that primary. It does **not** execute a universal k×k pair sweep. Its recursive branch procedure defaults `max_depth=3`, but depth is configurable; its explicit child expansion takes at most two values at each node, and `pure_or_near_pure` is a label, not a separate unconditional return. Source: original `ddm_v550_branching.py#8f6d40e0`, L203–328 and L372–432. The enabling substrate should be preserved as the *economic ability to ask multiple questions of one coherent population*, not the old algorithms' incidental wrong results.
