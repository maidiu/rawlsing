# Local Codex Boundary After FIABC Wave 2

Local-machine Codex is intentionally deferred until Wave-3 browser implementation is complete and fanned into one integrated tree.

## Work that must remain browser-side first

- successor diagnostic/effective-N implementation;
- Candidate-C production binding;
- runtime-package rebinding/fan-in;
- independent parity-oracle code;
- equal-work instrumentation code;
- mechanized succession-preflight code;
- final terminal/verifier code;
- hostile tests and integration planning.

Codex must not be asked to rediscover architecture, authority, source semantics, Candidate-C law, comparison boundary, or accounting law.

## First lawful local packet

The first local packet should contain only deterministic mechanical steps against a named integrated commit:

1. materialize/check exact required local source/runtime files by SHA;
2. run the named unit/hostile/integration test commands from Q02;
3. apply the already-qualified R6X tool to the exact stopped ledger, with required stopped-ledger SHA precondition;
4. materialize the independent WVS oracle from exact source + frozen authority and seal its hash;
5. run non-dispositive six-cell premeasurement qualification in isolated processes;
6. collect qualification receipts and stop on any invariant/accounting/preflight failure.

No measured performance court is authorized by steps 1-6.

## Second lawful local packet

Only if the integrated tree passes every qualification gate:

1. start from the reconciled governed ledger state;
2. verify succession preflight PASS;
3. verify candidate-neutral oracle already frozen and read-only;
4. execute each source×candidate cell under the isolated measurement constitution;
5. require the exact I05 terminal and all parity dimensions;
6. run final verifier;
7. preserve full receipts/metrics without ranking interpretation until HQ adjudication.

This design keeps local Codex as laboratory technician rather than project historian/architect.
