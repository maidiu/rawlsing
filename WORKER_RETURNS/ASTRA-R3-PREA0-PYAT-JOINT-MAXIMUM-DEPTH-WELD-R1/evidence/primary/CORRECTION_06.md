# 2. What PRE-V3's generic possibility machinery is actually for

PRE-V3 should provide a governed empirical-social possibility service.

In human terms:

> Given some already-known facts about a socially positioned person or configuration, what additional configurations are empirically plausible in this world/source universe, with what alternatives, minority/counterpatterns, uncertainty, support and use ceiling?

The current generic Pyat machinery is already close to this:
- `PositionedSubjectPossibilityQuery`;
- `PossibilitySliceEvidence`;
- exact conditioner bindings;
- joint/conditional composition;
- specificity walkback;
- minority/counterpattern preservation;
- uncertainty;
- source/release/authority identity.

Crucially, the generic current modules inspected contain no parent/coparent/household generation semantics.

This generic service can support **both directions**, where the evidence and operation authority permit:

```text
demographics / position / world
→ plausible attitudes / practices / configurations
```

and:

```text
attitudes / practices / configurations
→ plausible demographics / positions / social configurations
```

as well as multi-condition combinations.

The direction of a query does not change empirical ownership:
PRE-V3 provides a distribution/possibility field, not an actor fact.

# 4. Intended genealogy algorithm — mother first, conception-conditioned second parent

The intended Rawlsing genealogy has been stable at the product-vision level for months and should be treated as a first-class design requirement.

It differs from both:
- a PRE-V3 "parent prior" interpretation;
- the older symmetric V3 sketch where two complete parents are generated independently before their encounter.

## 4.1 Generation order

### Step A — Generate and recurse the mother first

V3 generates the mother as a whole person and develops her through her life until the exact conception of the focal child.

The focal child may be:
- first;
- second;
- third;
- later.

No assumption is made.

At conception time, the mother is already a historically generated person with:
- demographics;
- attitudes;
- beliefs;
- practices;
- relationships;
- personality organization;
- conflicts;
- desires;
- material position;
- social world;
- mobility history;
- institutions/routes;
- current life phase.

### Step B — Form the conception-situation envelope

At the conception point, construct the actual historically situated field:

```text
MOTHER_t
+
WORLD_t
+
MOTHER'S ACTUAL POSITION_t
+
MOTHER'S ACTUAL ATTITUDES / PRACTICES_t
+
MOTHER'S RELATIONSHIP / SEXUAL / SOCIAL SITUATION_t
+
AVAILABLE ENCOUNTER ROUTES_t
+
ALREADY-GENERATED CONCEPTION CONTEXT
```

This field constrains who the second parent could plausibly be and how the conception could occur.

Examples of lawful variation:

- conventional woman from a religious local family → candidate field may cluster around demographically/socially proximate men;
- same background but black-sheep/wild-streak history → much wider relational/attitudinal/encounter field;
- random hookup → possibility of highly dissimilar personality or demographic profile;
- small-town relationship → demographic similarity can coexist with major personal incompatibility;
- travel/study/work abroad → plausible cross-national conception route;
- short but genuine romance → non-enduring couple with respectful future coparenting;
- later mother same-sex marriage → fully lawful later life and child environment.

No single scenario is privileged merely because it is "typical."

### Step C — LLM proposes a finite candidate set

Given the exact conception situation, an LLM may propose several concrete plausible second-parent / conception scenarios.

Each candidate should include structured claims such as:
- encounter route;
- demographic configuration;
- salient attitude/practice configuration;
- relationship status/context;
- compatibility / mismatch dimensions;
- required world premises;
- reasons the candidate is plausible given the mother's exact state.

LLM output is proposal, not probability truth.

### Step D — PRE-V3 generic possibility queries constrain the candidate set

For each candidate, V3 may query PRE-V3's generic positioned-subject possibility machinery.

This is where the desired bidirectionality matters.

Example:

Mother is known:
- location;
- class;
- religion/family background;
- education;
- some attitudes/practices;
- actual institution/route.

V3 may ask:
- given these demographics, what attitude/practice configurations are supported?
- given the candidate attitudes/practices, what demographic/social positions are supported?
- given multiple known conditioner values, what remaining candidate configurations have empirical support?
- what minority/counterpattern configurations remain lawful?

PRE-V3 returns **possibility distributions / support / uncertainty**, not "the father."

### Step E — Governed relative plausibility + seeded stochastic selection

The candidate set is checked for:
- structural/world plausibility;
- actual encounter-route plausibility;
- contradiction with mother history;
- empirical possibility support where available;
- impossible/unsupported premises;
- exact uncertainty.

The system then selects one candidate using a governed stochastic mechanism weighted by qualified plausibility.

Important:

```text
LLM PLAUSIBILITY JUDGMENT != EMPIRICAL FREQUENCY
```

and:

```text
SELECTION PROBABILITY MUST NOT PRETEND TO HAVE MORE EMPIRICAL PRECISION THAN THE EVIDENCE SUPPORTS
```

### Step F — Back-generate the selected second parent

Once the conception endpoint is selected, V3 generates the second parent's whole prior person/history backward from the endpoint constraints.

This is:

> **RETROSPECTIVE CONSTRAINED ACTOR GENERATION**

The system knows:

```text
At T_conception this person exists,
has configuration C,
and plausibly arrived at encounter E.
```

It then generates enough of the second parent's prior life to produce a coherent independent person who could lawfully have arrived there.

This must populate the same relevant computational domains expected of a generated person:
- organismic/developmental history;
- structural positioning;
- attitudes/practices;
- expectations/strivings;
- memory/trace;
- psychic relational organization;
- category relations;
- independent projects;
- relationship capacity/history;
- other V3-owned state.

The second parent is **not** merely a father-profile shell.

### Step G — Distinguish generation order from represented causal time

Hard noncollapse:

```text
RETROSPECTIVE GENERATION DEPENDENCY
!=
IN-WORLD CAUSAL PARENTAGE
```

The conception endpoint constrains how the software generates the earlier biography.

Inside the represented world:

```text
SECOND PARENT CHILDHOOD
→ SECOND PARENT DEVELOPMENT
→ ENCOUNTER
→ CONCEPTION
```

Conception does not causally generate the father's childhood.

### Step H — Continue both parents forward

At conception, the two generated parents now have:
- independent whole-person state;
- an objective shared event;
- actor-specific models of one another;
- a relationship configuration;
- power/recognition/category dynamics;
- possible ongoing or terminated relation;
- future independent lives.

From conception forward, both parents and their relation continue recursively as part of the focal child's developmental world.

Possible futures include:
- marriage;
- breakup;
- respectful long-distance coparenting;
- conflict;
- absence;
- remarriage;
- same-sex later partnership;
- migration;
- new siblings/households;
- different cultural/language effects;
- changing financial/emotional involvement.

These are generated history, not preset family categories.

# 5. "Created from the rib" — precise technical interpretation

The metaphor should mean:

> the second parent enters the simulation through the already-realized mother's historically concrete conception situation, but once selected is back-generated as an independent person rather than copied from the mother.

Therefore:

```text
CONDITIONED ENTRY INTO GENEALOGY
!=
DERIVED PERSONHOOD
```

Similarity to the mother can be high or low depending on:
- encounter route;
- social closure;
- mobility;
- institutional field;
- mother's own history;
- candidate attitude-demographic support.

No requirement that spouse/partner be demographically similar.
No requirement that demographic similarity imply psychological similarity.
No requirement that dissimilarity imply rebellion.
All such claims must be generated from the actual trajectory.

# 6. Structural world and conception scenarios

PRE-V3 is the right owner for the **empirical-social field** needed to constrain the scenario, because that field is derived from the governed survey/world program.

PRE-V3 is not the owner of:
- the mother's current desire;
- why she is attracted to one candidate;
- the encounter as an actor event;
- the relationship;
- sexual/romantic meaning;
- conception;
- second-parent biography;
- household;
- parenthood;
- child genealogy.

Those are V3.

The correct division is:

```text
PRE-V3:
"Here are the lawful empirical-social possibilities in this world."

V3:
"Given this exact generated woman in this exact life,
here are candidate encounters/persons;
which are compatible with those possibilities;
which one occurs;
who is that person;
what history produced him;
what happens between them?"
```

# 8. Suggested new kill test — K11 genealogy back-generation

## K11 — conception-conditioned second-parent back-generation

Generate the same mother to the same conception-time checkpoint.

Produce multiple lawful candidate scenario sets under controlled world/route changes:
- socially closed/local conventional route;
- locally available but personally discordant route;
- high-mobility/travel route;
- unconventional/random encounter route where lawfully generated.

For each selected candidate:
1. back-generate second-parent history;
2. verify endpoint constraints are satisfied;
3. verify biography contains substantial independent variation not reverse-engineered from desired child/personality outcome;
4. continue both parents forward;
5. verify child developmental environment responds to the resulting parents/relationship;
6. verify PRE-V3 only supplied generic possibility/world evidence.

**Pass:**
- endpoint-consistent but independently coherent second parent;
- no PRE-V3 parent object;
- no demographic→psyche shortcut;
- no child-outcome teleology;
- alternate seeded selections produce different lawful families;
- replay exact.

**Fail:**
- father's past is obviously constructed to justify a desired current trait;
- parent-specific PRE-V3 semantics are necessary;
- father remains a profile shell rather than person;
- candidate probabilities are presented as empirical frequencies without authority;
- represented causal time is rewritten by generation order.
