## B. Concrete CI deployment contract (requires later authorization)

1. An HQ-approved `universal-capability-policy.json` and independent fixture/oracle suite live at an **immutable protected ref outside worker write authority**. Pin policy blob SHA, exact F1–F8/all35 obligations, fixture type signatures, original rights expectations and source/operation IDs. The candidate branch must not be able to replace the oracle under the same provenance name.
2. A required protected CI workflow checks out the candidate by pinned reviewed commit and the policy by independently authorized SHA; the workflow must check the branch/PR promotion level from HQ-adopted state, **not** a self-selected claim label in candidate metadata. It must always run on attempts to change universal acceptance/production entrypoints or adopt candidate into that program.
3. The trusted runner itself constructs independent nonrespondent fixture data/semantics in an isolated worktree, executes the real candidate-facing sourcefront, old PRE553 owners, role/counterexample and actual consumer. It generates events; it **never consumes a worker-supplied 'passed' Boolean** or trusts candidate `expected_operation_ids` as oracle.
4. Emit tamper-evident, exact-commit job artifacts with positive and counterfactual source/operation/consumer/digest links; proof_integrity_gate changed-test RED is a useful additional check, not sufficient. A **separate independent reviewer** inspects sensitive scientific and semantic contracts; no CI scalar test can issue original source or scientific meanings.
5. `09_trusted_oracle_prefilter.py` can check roster/shape/expected operation crosswalk using such independently pinned policy and trusted runner result; it outputs only `STRUCTURAL_CROSSWALK_READY_FOR_INDEPENDENT_NATIVE_VALIDATION` even on green. It is a reference **sourcefree prefilter**, not the CI runner, signature/attestation verifier, native run, or adoptive gate. No required workflow was installed by this court.
6. A promotion-status check must require R0–R7 and Gate A *only for the level being promoted*. Source-specific local component fixes can be tested and accepted without global original rights; no semantic privilege propagates. If any universal required edge is held, the honest `REVISE` verdict preserves the local success and the named next owner. If a previously certified generic shape later regresses, invalidate corresponding promotion by exact code/contract version; do not silently grandfather a code change.
7. Expose a machine-readable `pending_global_obligations` **monotone ledger**. A commission can progress an item only by an independently accepted implementing/proof/owner decision. `SOURCE_RIGHT_HOLD` stays pending rather than count-as-complete. A next commission may choose new independent work, but cannot name the same LiTS success as a newly closed universal obligation. The program should not be held hostage to rights on *one* arbitrary wave while other compatible original tranches can run.
