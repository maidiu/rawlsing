# R61-R08V finite defects

Verdict: **REVISE**. The callable boundary is real and its positive/cold/actual-evaluator path is witnessed, but it does not satisfy the hostile K-to-producer/cache requirements. Three finite, reproducible defects remain. Full J42/P41/E04 adoption is separately NOT_REACHED for an ownership/allowlist reason, not counted as a local module defect.

Severity order: D1 (critical) > D2 (critical) > D3 (medium).

## D1. Wrong request K can be rebound to the same actual P1 producer and served as exact support

**Expected:** changing the requested condition, typed value, source/edition/digest, direction, role, design, weight, risk or clock must either refuse or legitimately change the same consumer output. Arbitrary request labels must not authenticate a producer unrelated to that request.

**Observed:** the exact forward P1 producer was rebound to requests whose K names `POSITION=P2`, a BOOLEAN `true`, a NULL, an INTEGER 1, an extra/reordered condition tuple, and changed edition/digest/as-of/direction/role/design/weight/source. Every case resolved `SUPPORTED`, denominator 60, canonical provenance, and `EvidenceConsumerReader.read()` accepted the values-read (which carried the wrong request labels).

Exact observations: `outcomes/hostile_observations.json` keys `wrong_condition_rebind`, `wrong_typed_bool_rebind`, `wrong_typed_null_rebind`, `wrong_labels_rebind`. Failing probes: `probes/test_r08v_hostile.py::test_wrong_condition_rebind_must_not_authenticate_p1_producer`, `...::test_wrong_typed_value_rebind_must_not_authenticate_p1_producer`, `...::test_null_and_integer_value_rebind_must_not_authenticate_p1_producer`, `...::test_extra_and_reordered_conditions_must_refuse`, `...::test_wrong_edition_direction_role_design_clock_rebind_must_refuse`.

**Why it passes:** `EmpiricalProducerBinding.__post_init__` at `rawlsing_next/pre553_universal_evidence_binding.py:568-604` checks only the request's consumer query ref, producer query ref, predicate ref/hash, release ref, model rule hash, single-conditioner fingerprint, source universe, target, risk set and ordered target refs. It never checks `ordered_conditions` occurrence/typed value/domain against the producer predicate or consumer binding, and never checks edition, byte digest, instrument, units/links, estimand, weight, design, uncertainty, direction, role, consumer use, grammar, custody, observation/reference/as-of/publication clocks or permission against owner determinants. `request_from_empirical_case` at `:462-548` accepts those fields as free labels and derives only the conditioner fingerprint from the consumer query. `_produce` at `:892-990` re-checks composition refs but not the full request K. `_consumer_values` at `:821-842` copies the requested conditions, and `EvidenceConsumerReader._assert_association` at `:1321-1350` compares the values-read only to the same wrong request.

**Minimal correction direction:** derive/validate the full K material from the actual owner objects at bind time, or have the binding store the exact owner-derived K material and require equality with `request.material()` before resolution. At minimum, bind ordered condition occurrence, typed value and domain/state version to the producer predicate leaf and consumer conditioner witness; bind edition/digest/instrument/units/estimand/weight/design/uncertainty/direction/role/consumer-use/clocks/permission/custody to their owner refs or reject them as unserialized labels. A consumer reader must not accept values whose request K was never tied to its producer.

## D2. Self-sealed cache accepts forged cross-source producer/evidence/result and serves forged values

**Expected:** a checksum is not issuer authentication. A self-sealed/recomputed-digest forged producer/evidence/result preimage, wrong request association or cross-source transposition must be refused (or be explicitly outside the untrusted cache boundary). A cache entry must bind the full K plus permission/clock/currentness and producer/evidence/result association, not only a request-key hash.

**Observed:** a reviewer-built cache entry with the victim request key, the changed-source (`CHANGED_SOURCE_LAW`, different universe/release, denominator 70) evidence/consumer query/model rule, a resealed payload, and forged result cells/denominator 999 was accepted by `EvidenceResolver.import_authenticated_cache`. `resolve(victim)` returned `SUPPORTED`, denominator 999, and `EvidenceConsumerReader(victim, result).read()` returned denominator 999. The forged evidence's source universe differs from the victim request's source universe.

Exact observation: `outcomes/hostile_observations.json` key `forged_cache` (`import_accepted: true`, `denominator: 999`, `consumer_values_denominator: 999`, differing universe hashes). Failing probe: `probes/test_r08v_hostile.py::test_self_sealed_cross_source_cache_forgery_must_refuse`; structural probe: `...::test_cache_entry_must_carry_full_k_not_only_hash`.

**Why it passes:** `export_cache` at `:1083-1103` exports only `request_key`, result material, evidence, consumer query and model rule. It does not export the request material/K preimage. `import_authenticated_cache` at `:1105-1191` verifies only the self-computed seal, that `result.request_key` equals the entry `request_key`, that evidence/query/rule reconstruct, that the evaluator replays the supplied `consumer_result_hash`, and that `evidence.evidence_ref` matches the result ref. It never recomputes the full K from a cache preimage, never checks victim K identity against evidence/query/rule/source/target/conditions, never checks permission/currentness/as-of, and never checks the result denominator/cells/values against the evaluator. `_replay_cache` at `:1027-1081` copies `cached.consumer_values_read` and overwrites only `request_key` and `cache_seal`, then `EvidenceConsumerReader.read` re-runs the evaluator but keeps the forged denominator/cells from the cached values. The constants/provenance at `:57-87` call this `AUTHENTICATED_CACHE`; the author's limits acknowledge it is only a canonical SHA-256 seal, not issuer authentication.

**Minimal correction direction:** include the exact canonical full-K preimage in the cache payload and recompute/compare `semantic_hash(request_material) == request_key`; require the cache's evidence/query/rule/source/target/condition/clock/permission/custody material to match that K; recompute denominator/cells/values from the actual evaluator rather than trusting cached values; refuse cross-source/edition/clock/currentness mismatches. If the cache is only trusted-supervisor input, expose it under an explicit trusted boundary and do not advertise hash-only, caller-supplied preimages as authenticated evidence. The current self-sealed forgery must fail the intended public API assertion.

## D3. Valid null/diffuse/empty products collapse to `support_state == "NO_SUPPORT"`

**Expected:** valid zero/null/diffuse/empty products are not conflated with no support; the total summary must preserve their distinct state.

**Observed:** reducing a single `VALID_NULL`, `DIFFUSE`, `VALID_EMPTY`, or `OBSERVED_ZERO` result yields `support_state == "NO_SUPPORT"` while `productive_all_required == True` and `result_counts` retains the valid state. This is internally contradictory and makes the top-level summary unusable as the status oracle.

**Why:** `reduce_required_support` at `:1430-1483` sets `support_state` only to `VALID_EMPTY` for a zero-length frontier, `EXACT_SUPPORT` for all SUPPORTED, `PARTIAL_SUPPORT` when any positive, else `NO_SUPPORT`. It does not map a valid non-positive product to its own state.

**Minimal correction direction:** derive a support-state value that preserves `VALID_NULL`, `DIFFUSE`, `VALID_EMPTY`, `OBSERVED_ZERO`/zero-cell, and `ZERO_SUPPORT` as distinct non-`NO_SUPPORT` outcomes, or explicitly rename the field to positive-support summary and expose the product state separately. Do not let a valid null/diffuse product read as no support.
