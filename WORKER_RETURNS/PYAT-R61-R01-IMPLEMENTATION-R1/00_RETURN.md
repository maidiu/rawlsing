## Plain-English function delivered

R01 now compiles a complete, finite, prospective symbolic frontier from a frozen
source-owned typed inventory and a grammar policy. Membership is decided before any response
value is read. Each considered operation receives a disposition and reason; nothing is
silently pruned because a label is unfamiliar, a topology is awkward, a respondent is
unadministered, or a resource budget is small.

The semantic lowerer maps eligible operations to the actual imported current PRE553 I05
candidate grammar contract. A lack of native support is a typed `UNSUPPORTED_RUNTIME` record
with an exact reason, never a historical `None`. The real I05 engine is then called in the
proof test, and actual receipts are anti-joined to the expected exact operation/rule set.

## Real capability delta

- Arbitrary occurrence identities: item, option, form and repeat are separate key components.
  Duplicate occurrence keys are refused before dictionary construction.
- Roles are typed (`OUTCOME`, `EXPOSURE`, `IDENTITY` in the synthetic proof) and direction is
  an explicit grant over ordered target/conditioner roles. Reversing target and conditioner
  roles requires its own grant; no literal `Y` carries scientific meaning.
- Ordered target tuples and ordered conditioner tuples produce distinct operation identities.
  Multi-target and multi-conditioner shapes are enumerated under issued J/K/D bounds.
- Repeat, form, MR/set and rank topologies remain in the considered ledger as typed
  `UNSUPPORTED_RUNTIME`; they are not removed.
- `NOT_ADMINISTERED` is held, unknown administration remains unknown, and an all-missing value
  store cannot shrink the prospective eligible frontier.
- Every operation binds exact occurrence keys, target/conditioner roles, unit, topology,
  measure/estimand, common risk refs, direction ref, form scope and administration states.
- The frontier has a complete operation disposition index, an occurrence inventory ledger,
  a stable partition root, lazy deterministic partitions, exact E_pre proposal roots when the
  inventory is complete, and no E_pre when it is incomplete.
- `conservation_report` is an exact identity anti-join. A count-preserving substitution of one
  operation for another still fails. `native_receipt_anti_join` performs the same check against
  actual I05 `DiscoveryResultReceipt` objects.
- Native lowering imports and validates the current `pre553_discovery_exact` contract
  (`I05_CONTRACT_ID`, grammar schema, candidate families, predicate forms and validation
  kinds), asks a supplied native catalog for exact refs, and lowers DIST, conditional, fork,
  interaction, joint and co-travel shapes. Missing catalog refs/capabilities are explicit typed
  refusals.
