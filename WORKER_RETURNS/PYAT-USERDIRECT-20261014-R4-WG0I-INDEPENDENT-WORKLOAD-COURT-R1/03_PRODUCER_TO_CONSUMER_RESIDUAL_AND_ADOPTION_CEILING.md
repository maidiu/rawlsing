## Six decisive defects with precise science effect

**WG0I-A. Artificial source and artificial number as if a result.** WG0P's five `NativeItem` objects are literal hand-authored fixtures with `GRANTED_FIXTURE` strings. It invents a `C11LogicalRelease` exact ref with a hash derived from its own label, inserts built-in `object()` into `C11Repository._by_ref`, assigns all eligible jobs kind `QUERY`, and supplies `make_executor(item_table)`. The callback itself returns a `WG0P_COMPUTED_FRACTION` ref based on caller-specified numerator/denominator, or **1/2 if operation missing**. It never dereferences native response events, route eligibility, weight/design, respondent population, or accepted empirical query results. Therefore even an actual `COMPLETED` batch receipt can prove only that this invented callback ran. Local independent test actually confirms the fallback `1/2` and **15 refusal/coverage failures**, without pretending its declared dependency stubs were accepted PRE553 modules.

**WG0I-B. No conditioning without source-native join.** `(unit,wave,source_id)` equality is not proof that two question instances were presented to/answered by the same respondent or covered by the same qualified joint risk set. Same wave may contain disjoint subsamples, split ballots, incompatible routing, household vs selected-adult carriers or withheld joins. WG0P neither stores individual respondent refs/identities nor issues exact permissible linkage and joint denominator evidence. Independent hostile constructs two same-scope respondent-form items and observes **two `PRODUCED` conditionals**, notwithstanding absent joint-record evidence. No eligible conditional is exercised at all in the original five-item fixture.

**WG0I-C. Rights and original semantics absent from identity.** Only literal `grant == "WITHDRAWN"` is held. Unrecognized `WITHHELD` and `NO_SOURCE_ISSUER_OR_LICENSE` are marked `PRODUCED` by actual sourcefree code. `canonical_identity()` and `freeze()` hash only `source_id|wave|form_id|version`, excluding item/carrying unit, options, missing codes, routes and permission. Thus rights withdrawal or altering the native scale yields exactly the **same** frontier digest; `build_executable_plan` generates equivalent test ref identities for changed native meanings. Colliding form keys with different carriers are labeled `DUPLICATE_IDENTITY` without a typed conflict ledger.

**WG0I-D. No-drop is not a mirrored five-fixture enumeration.** Independently count the original five item instances and ordered non-self pairs **before calling the builder**: 5 marginal opportunities, 20 directional pair opportunities. WG0P emits exactly **15** operation candidates: 3 `PRODUCED` marginals, 2 `HELD` marginals, 10 `INADMISSIBLE` conditional pairs, zero `PRODUCED` conditionals. Its filter drops **all 8** pairs touching the withdrawn item and both directed same-scope pairs between the routed-held item and the eligible respondent item (without preserved held joint decision). Only **3** manufactured marginals become `BatchManifest` units; the other 12 enumerated items have no output sidecar on `ExecutablePlan`. This does not imply every mathematical pair deserves scientific qualification, but the **initial finite frontier must record a typed decision** for applicable candidates, not silently vanish during rights/routing filtering. WG0P `oracle_eligible_operations` is a separate function but uses the **same five fixture literals and nearly the same enumeration filters**, not a source/issuer-pinned external inventory. An exact oracle-vs-builder test is internal agreement only.

**WG0I-E. Numeric data validation and identity are not enforced by source.** The arbitrary numeric table can be negative and still become a `Fraction`/result ref; a missing key silently becomes `1/2`. Altering a source item’s native choices changes neither `BatchUnitSpec` identity nor the callback’s table lookup. A duplicate `op_id` can overwrite `units_by_op` while referring to conflicting target/conditioner payloads. Observed zero `0/16` and minority `1/16` *are accepted synthetic test outputs*; there is no original population count or provenance to distinguish them from arbitrary entries. Equal results across reruns prove self-determinism of the synthetic table, not data provenance.

**WG0I-F. Sharding/resume/revocation tests cover too little.** WG0P's author tests of `max_units=1` and subsequent prior-receipt resume demonstrate operational scheduler semantics on only three synthetic marginals in author environment. The “revoke source” test **removes already-WITHDRAWN `SRC-B` from a new builder and checks unchanged W1 candidate dispositions**. That neither revokes a formerly positive signed source in an already completed receipt nor invalidates an original-item-derived consumer or verifies a changed C11 source release after resume. `WG0P` has no operative source-qualified invalidation proof and no held/inadmissible no-drop receipt ledger in its batch plan. No cold process restart with versioned authority was independently run.
