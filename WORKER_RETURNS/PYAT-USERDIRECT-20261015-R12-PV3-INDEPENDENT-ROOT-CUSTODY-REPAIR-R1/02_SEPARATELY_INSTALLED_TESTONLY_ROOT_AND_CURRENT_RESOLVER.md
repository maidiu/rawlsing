# Separately installed fixture root and current resolver

`repro/provision_owner.py` is a trusted deployment step run before exposing `deployment.api`. It verifies pinned installation documents, including the unchanged independent oracle, complete exact original expected records, register binding and six original consumer links. It provisions the current decision store once. A replay/request never provisions or recreates a missing store. `observations/fixture_owner_installation.json` and cold `*.installation.json` retain the complete installed expected preimage before caller fixture/producer execution.

`FixtureInstallation`, its read client and `RequestAPI` are frozen dataclasses. The endpoint receives an already-bound read client and execution attestation capability at composition time. Request work/register arguments cannot select an owner, installation file, expected root or profile. The complete checked original expected payload must equal the installed immutable payload and root. This binds every original field, including original item-scope, release, universe, routing, role/order, metadata, source options, negative scope and both HELD obligations. Request register binding and root must also equal the installed decision, rather than a second caller-computed hash.

The baseline expected root is `4d83bf57f8cd12c3492eb42f6d14094c53a6c33cc5e4178f1594ce6a469548f2`; its register root is `49f0f51866d3327aca2b7d8910517c0317a85c6b7fd3f011c9ffd6634c6218bf`. Numerical source trials use separately selected TEST_ONLY deployment profiles R2_Y1 and R1_Y0. They change only the literal authorized A source inventory/edition; no request can install these profiles. Their acceptance arithmetic stays in the unchanged independent tests.

Current decisions are keyed by original namespace/native-source edition. The trusted owner store is outside caller ledger/work/register paths, atomically replaced with file and directory fsync. `_resolve` rereads that store on every native-source read. Withdrawal and clock/asof advancement are owner control operations. Grant identity, issuer and ceiling are fixed TEST_ONLY; current policy must match the installed owner/expected root and complete source set. An absent store fails closed. Optional request edition/clock/asof checks can only constrain use.

`observations/selective_revocation.json` proves A denial with B's full current response bit-identical and historical links unchanged. `persisted_selective_revocation.json` proves a distinct PID sees A withdrawn, B unchanged, cannot serve an old request history offline, and does not rewrite policy. The two-client and missing-store guards test actual shared-state resolution and refusal to recreate authorization. The direct API rejects altered grant scope/issuer/ceiling/revoked snapshots without changing owner state.

The legacy PV2I revocation guard supplied its only event as a replaced register. The explicit test adapter translates that particular guard input into an owner-control withdrawal, then tests old-snapshot denial. This is disclosed test control, not the production API's trust rule. Every original assertion still executes unchanged. Other tests exercise the direct API and actual persisted resolver independently.

This is independence from ordinary request arguments on a trusted local Python host. The implementer does not claim institutional independence, real signatures, OS isolation from arbitrary Python/filesystem compromise, or a competent original U/E issuer. The pinned full-record snapshot comes from the predecessor's retained freeze; the separate independent oracle constrains the eight obligations. Installation precedes this new execution; it does not retroactively prove real pre-D custody of the predecessor.
