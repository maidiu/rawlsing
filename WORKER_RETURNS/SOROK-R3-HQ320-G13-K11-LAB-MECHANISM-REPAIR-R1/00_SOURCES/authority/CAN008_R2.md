# 5. Three input roles

Every R2 concrete coupling rule must distinguish three semantic roles.

## 5.1 `PRECIPITATING_EVENT_STREAM`

A precipitating event stream is an exact generated/admitted **occurrence** that can lawfully initiate or jointly precipitate the response transaction.

It must retain, at minimum at the semantic level:

- exact actor/subject binding;
- event identity and immutable hash;
- event authority and version;
- event kind/family;
- effective causal time and ledger anchor;
- exact source/producer provenance;
- any actor-facing event-feature refs that the event authority actually exposes for downstream use;
- any required causal-use permission;
- exact stream identity for independent-stream preservation.

A static state record is not a precipitating event merely because it can causally matter.

Examples:

- an admitted ADP-010 `OEE_EXPOSURE_OCCURRED` can precipitate;
- an ADP-019 admitted external interaction can precipitate;
- an actual V555/V556 realization event can precipitate where its owner exposes it and the concrete CAN-008 rule names it;
- an actual ADP-009 mobility/position-transition event can precipitate where lawfully named;
- the actor's current position state by itself does not precipitate merely by existing.

A response transaction may have one or several exact precipitating event streams. Multiple events remain independently addressable unless a separately lawful multi-parent occurrence already exists.

## 5.2 `CONDITIONING_PERSON_STATE_BINDING`

A conditioning binding is an exact, read-only state/history fact that may alter the evaluation of this precipitating event under an exact CAN-008 R2 rule.

A binding must preserve:

- source owner;
- source authority ID/version;
- exact state/record/effect identity and hash;
- actor/holder identity;
- effective time;
- exact scope/target/counterpart relation where relevant;
- epistemic/access class where relevant;
- the concrete CAN-008 rule's granted causal-use role;
- provenance sufficient to verify the state was valid at the evaluated causal time.

A conditioning binding:

```text
IS NOT a new event
IS NOT a copied CAN-008 state
IS NOT a new durable person record
DOES NOT change source-owner lifecycle
DOES NOT become actor-accessible merely because CAN-008 reads it
```

Examples include exact CAN-010 expectations/strivings, CAN-011 mediators/tensions/practices, ADP-015 perceived relationship state, ADP-016 causal traces, ADP-017 epistemic/access state, CAN-009 embodied state and prior exact CAN-008 response history.

## 5.3 `MODALITY_CURRENT_OR_INTERPRETIVE_EVIDENCE`

This is optional evidence whose meaning belongs to a specific runtime modality and which is permitted by the concrete CAN-008 rule to help evaluate the precipitating event without becoming a substitute occurrence or a new durable person state.

Examples may include, only under separately lawful modality authority:

- bounded discourse/pragmatic interpretation attached to an actual admitted external interaction;
- current/session residue;
- current attention/effort context;
- current actor-local counterpart hypothesis;
- other fast/live context explicitly admitted by the future PFF interface.

```text

MODALITY_EVIDENCE != EXTERNAL_TRUTH
MODALITY_EVIDENCE != DURABLE_V3_PERSON_STATE
```

Machine-side interpretive evidence may be richer than actor uptake. It is evidentiary input to the coupling evaluation, never actor meaning by fiat.

# 7. Actor receivability

## 7.1 Meaning

`ACTOR_RECEIVABILITY` is the evaluation-local, rule-governed determination of which bounded aspects/relations of an exact precipitating event are eligible to become operative in actor uptake **for this actor at this time**.

It is not a persistent actor state and does not require a standalone authority or storage object.

It answers a narrower question than knowledge or consciousness:

> Given that this event objectively occurred or was objectively presented, what event material may lawfully participate in this actor's current reception?

ADP-010 exposure remains objective presentation/impingement and explicitly does not establish noticing or understanding. ADP-017 remains canonical knowledge/belief/claim-access authority and does not decide current event reception. CAN-008 R2 binds the immediate response-side bridge without taking either jurisdiction.

## 7.2 Receivability law

A concrete rule may evaluate event material as positively receivable, negatively/non-receivable, unresolved/deferred, or valid-empty under its declared scope. R2 does not impose one universal categorical implementation.

The rule must preserve:

```text
SYSTEM_CAN_PARSE_X != ACTOR_CAN_RECEIVE_X
OBJECTIVE_EXPOSURE_TO_X != ACTOR_RECEIVES_X
ACTOR_CAN_RECEIVE_X != ACTOR_FOCUSES_ON_X
ACTOR_CAN_RECEIVE_X != ACTOR_BELIEVES_X
```

Actor receivability may depend only on exact lawfully admitted bases named by the concrete rule. It may not be inferred from demographic stereotypes, type labels, renderer convenience, missing data, or analyst omniscience.

## 7.3 Partial and multiple receivability

An event may have several bounded features/readings while:

- some are receivable;
- some are not;
- some remain unresolved;
- some are receivable only under a particular counterpart/scope;
- some are receivable but later low-significance;
- some are receivable but not used in final response.

R2 rejects universal `EVENT -> ONE HEARD-AS STRING`.
