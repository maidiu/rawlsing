## Principal findings

### 1. One source-free preparedness gap: EVS 1999 typed missingness

EVS1999 freezes an exact SAV compatibility reader with `user_missing=True`, but its `R35_REQUIRED_PHYSICAL_DIMENSIONS` omits `typed_missingness` and the realization exposes no typed missing-state projection.

That means exact user/system-missing noncollapse is not source-free proved by the present realization contract.

This audit does **not** infer that any particular EVS1999 raw code is missing, nor does it expand the accepted source's semantic missing vocabulary. The required repair is contract-level preservation: retain decoder missing-state/declaration evidence, or establish an equally exact governed reason that no such distinction belongs in the preservation burden.

### 2. EVS 2008 is source-law ready but needs an explicit runtime state/representation adapter

EVS2008 already preserves:

- physical-only latin1 compatibility;
- exact 13-set MR topology;
- alias/overlap noncollapse;
- typed 0 versus producer-authorized negative missing states;
- documentary routing rather than missingness-derived routing;
- `BOUNDED_UNKNOWN` outside exact authority;
- v372 as an unresolved member of the producer negative-missing domain rather than an invented row-level subcode.

The current PRE553 consumer does not accept arbitrary source-specific state strings as generic response terminals. A future runtime package therefore has to map only exact authorized grains into generic C11 states while retaining source-specific detail. This is runtime packaging work, not a defect in the realization.

### 3. WVS1 is deliberately bounded; do not “repair” its unknowns by inference

WVS1 is well prepared for the physical failure classes that motivated this audit:

- S007 raw magnitude is independent from F2.0 display metadata;
- system missing and user-missing value/range states stay distinct;
- all-system columns remain source information;
- V3/S007 cannot become replay identity merely through naming or snapshot uniqueness;
- all 13 weight carriers remain preserved;
- no default weight, design, or estimand is synthesized.

Its routing/applicability authority is explicitly incomplete. Exact risk-set membership is therefore `AUTHORITY_BLOCKED` where a workload would require authority not present in the accepted packet. Missingness incidence and all-system columns cannot close that gap.

### 4. Latinobarometro 2011 is physically/source-law ready, but questionnaire and released storage must remain separate forms

LAT2011 correctly keeps three documentary layers distinct:

1. questionnaire wording/routing/instrument response codes;
2. released-data variable/storage semantics;
3. methodology sample/design/weight descriptions.

The `P1ST=-2` witness means a future adapter cannot equate questionnaire code form with SAV storage form by numeric similarity.

`WT` is a preserved carrier with documentary role “Weighting”; that does not supply the design+estimand authority required for generic PRE553 analytical weight admission. Any default or pooled estimand remains unauthorized unless separately admitted.

### 5. Exact R5 representation is a later qualified-source gate for all four

Current PRE553 physical binding keys include:

- exact decoder-observed raw value encoded by the R5 typed codec;
- exact physical missing state;
- exact source missing declaration.

R5 intentionally distinguishes equal-looking host values of different types. Therefore documentary code material cannot be converted directly into runtime physical keys by numeric or string equality. Each runtime package needs the qualified decoder representation, then must construct exact keys from that representation.

No source execution was performed here to discover those types.

### 6. Historical/current provenance is already relevant; catalog enforcement comes later

All four sources are historical. Their source roots and documentary release scopes are already governed and must not be replaced by ambient current documents.

The runtime form of that rule — exact immutable `AuthoritySnapshot` closure, frozen catalog identity, and bounded historical-successor scope — belongs to the future current PRE553 package.

### 7. Dynamic-query and post-I05 failure classes are runtime-only for these realizations

None of the four realization modules generates dynamic queries/facts or contains an I05/post-I05 consumer. The relevant failure classes are therefore mapped as applicable after runtime packaging, with hostile tests requiring:

- generated-ref preimage retention;
- exact semantic input refs;
- no static-catalog-only resolution;
- no post-I05 consumption of a fact whose construction preimage is missing.
