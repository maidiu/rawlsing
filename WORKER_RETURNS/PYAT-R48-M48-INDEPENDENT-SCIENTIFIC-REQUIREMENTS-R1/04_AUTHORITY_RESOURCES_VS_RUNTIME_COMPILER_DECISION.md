# Resource versus code decisions

A = source-specific governed facts/decisions; B = generic derivation; C = independently judged conditional scientific assertion; D = source/host/purpose legal/use permission; E = learned empirical product. An object can contain separately typed fields from several categories. Packaging them in one signed envelope does not make their authorities interchangeable.

Alternatives adjudicated:

* Pure static whitelist: auditable but becomes combinatorially large, excludes novel conditional work and duplicates decisions; acceptable only as compiled output/cache or explicitly bounded legacy scope.
* Pure runtime inference from labels/source bytes: cannot recover adjudicated meaning, missing/not-asked distinctions, design targets, typed relation truth, or legal scope. Reject as scientific issuer.
* Generic code with arbitrary caller U/E_pre: useful executor/admission boundary, inadequate producer or completeness proof.
* **Recommended hybrid**: immutable governed fact/decision resources; versioned class-level grammar and validation policies; generated indexes/manifests; independent expected-operation accounting; authenticated deployment; released learned-world objects. Native runtime remains generic.

This conclusion challenges the missing-single-compiler framing without asserting a complete historical producer is absent. Known capital performs parts: V550 source/response/branch/J compilers, P10 preservation, P2 selection/P3 composability, selected B, I03/I05/Batch, and U43 transport. B43/I44 wire admission and receipts; they do not resolve source science. Historical mechanisms may be replaced only after same-grain content/use/negative-law preservation, not because a new schema is tidier [P10/W47].
