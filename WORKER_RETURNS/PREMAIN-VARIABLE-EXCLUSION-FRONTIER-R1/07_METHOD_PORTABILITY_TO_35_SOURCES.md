# METHOD PORTABILITY TO THE 35-SOURCE ESTATE

The method is portable, but the result is source-specific.

## Portable court

For each source/wave:

1. enumerate the exact physical variable inventory;
2. bind source-native semantics, routing, response-scale, design/weight, identity and provenance authority;
3. map current/foreseeable consumption roles from PRE-V3, Field Forge, SDTF and the clean-room V3-border seam;
4. identify repeated template families;
5. determine the required consumption grain;
6. separately determine whether instance identity/order/time/target is itself information-bearing;
7. authorize class A only with one of:
   - `SEMANTICALLY_OUTSIDE_ENVELOPE`;
   - `REPEATED_TEMPLATE_CARDINALITY_EXCESS`;
   - `DUPLICATE_PHYSICAL_INSTANCE`;
   - `SUPERSEDED_DERIVED_OR_ADMIN_VIEW`;
   - `SOURCE_PLACEHOLDER_OUTSIDE_REQUIRED_GRAIN`.
8. otherwise classify B/C/D and retain.

## What does not port automatically

- LiTS household/job/year cardinality conclusions;
- WVS recode/parallel-geography conclusions;
- any source-specific derived/administrative alias;
- any claim that one architecture's proving slice is the production frontier.

## Priority for estate-wide use

Run first where codebooks expose obvious physical expansion multipliers or multiple deterministic views: later LiTS waves, merged/harmonized releases, recode-heavy sources, and sources with form/ballot expansions. Do not infer runtime savings from column counts.

Terminal: `METHOD_PORTABLE__SOURCE_SPECIFIC_PROOF_REQUIRED`
