# PROGRAMMA SOROK W1-E — Findings and architecture recommendation

**Independent research candidate; no canonical implementation or adoption.** Source examination: authenticated private GitHub S0–S1 and native ChatGPT Library; no local Python, tests, model calls, GUI, worker leases or source-native experiments. Startup f8b7a6af792e2d65b0616fbb5272d1ce9c500c62. Intended decision recipient: the joint PROGRAMMA synthesis and the rightful Sorok operating/engineering owner.

## Executive decision

**Provisional choice: evolve the one O-LIVE persistent reference, not replace it.** Keep its Python graph, typed status axes, Git-identified sources, commands and derived projections. Add a strictly separated append-only evidence/event ledger, deterministic reduction into a clean candidate state, a compact source-and-traversal UI projected from that state, and authenticated owner/reviewer admission only where evidence actually requires it. Do NOT introduce a second database, graph server, controller, mandatory knowledge-ontology rewrite or agent review ladder. O-LIVE is currently a substrate prototype, NOT the whole reference. Its synthetic state contamination makes even its scoped candidate currentness unsafe to rely on without reset/replay.

Four decisive observations:

1. The full objective is an independently constituted person and human encounter, not source recovery. The user-directed 00A anti-drift gate explicitly names original purpose, 00–87+ Sorok, Astra, V3/Neo, Q/D/R, scientific alternatives, actor/world/call paths, human impact, current work and missing functions. It expressly calls an R3-derived complete index a WHOLE_PROGRAMMA_SCOPE_FAIL.
2. The O-LIVE code already contains useful mechanisms: build/refresh/merge, one JSON state plus snapshot, exact Git object checks, source manifest verifier, typed edges, two-way zoom, dimensioned axes, dynamic gaps and work-now, read-back, source-cut delta, negative-dependency propagation, O-SCIENCE candidate ingest and return intake. Replacing those before disproving them would be waste.
3. The R2 demonstration has crossed the provenance/authority boundary. Its script constructs a SOURCEFREE_REVIEW with reviewer_role=INDEPENDENT_I3_ENGINEER and review_status=PASS from the very state it is testing, applies REVIEW_PASSED_SCOPED and INDEPENDENT_ACCEPT_SCOPED, creates a fake 40-character return SHA (a repeated 40 times), injects SOROK_R2_NEW_REQUIREMENT, and saves the resulting state.json/SNAPSHOT.json. The saved demo receipt reports 212 nodes, 649 edges, 38 gaps, nine history events and 23 author tests; those numbers cannot certify authentic independent review or real new requirements.
4. No actual PROGRAMMA terminal critical path is computed. The existing blocked-chain traces typed predecessor blockers, while critical-path is explicitly labelled a legacy shortest-path illustration. Work-now sorts within groups by downstream required node count and asks HQ judgment. Neither proves durations, resource availability, alternative routes, legal authority or terminal utility. Never advertise a number-of-descendants score as the single next best job.

## What source actually does now, and what to reuse

**Source and persistence.** living_reference.py at a89e5ccbe67400168aaea8367f7aa00ca0de7625, blob bfbd876a5e16577d9339badfbfee6cd6f7c83d5a: lines 417–494 create graph and eight status axes from seed files; 507–582 merge structure, observe Git changes and preserve history; 583–615 read/write state and snapshot through per-file atomic replace and self-contained SHA-256. This is durable *candidate* persistence; two destination replacements are not atomic as a pair, its digest is not an independently custodied signature, and existing history entries carry event digests rather than a complete verifiable journal with independent source evidence. Retain data shapes and predictable semantics; add a single serialized canonical state write with revision/CAS and recoverable event log, then rebuild the export/snapshot as projections.

**Sources.** verify_source_manifest.py blob 1496aba7ff8d76c3832f19c8658b2f785d4b3b3f checks 144 Sorok rows plus three reference items, commit:path object type/id, timestamps, tree entries and manifest digest. The R2 receipt says this qualified local test passed, but W1-E has not executed it. It proves object identity, NOT truth of a source's semantic assertion, adopted permission or actual current importing runtime. The seed registry/manifest is R3 recovery-derived: retain its objects in a source-loss annex, but seed the logical whole program with source-backed purpose/product/theory and open unknown edges, not with this index as its governing spine.

**Relations and traversal.** _classify_edge (239–300) derives required/causal flags using substring heuristics in relation names. This is helpful for old imports but fragile as general semantic truth. _neighbors (616–636) walks both directions but offers an unfiltered neighborhood JSON dump; consumer (1697+) filters outbound L4 or name contains 'consumer'; source and alternatives are exact-ID CLI queries; no interactive progressive disclosure exists. Preserve current edges but use a small explicit predicate registry and grade per relation before granting blocker propagation. Source exactness, conceptual dependency, actual function import, tested behavior, independent reviewer and original authorization must NEVER be inferred from the same 'edge' label.

**Dynamic state.** _apply_transition (1195–1340) handles evidence kinds, source SHA verification and negative invalidation; _invalidate_required_dependents (1176–1194) makes downstream consumer INVALIDATED. But on restoration it assigns every affected consumer CANDIDATE_READY instead of re-evaluating all prerequisites or restoring precise prior grades; other independent blockers may remain. _recompute (1028–1052) recalculates gaps and blocked views, but a change should derive grades from the *full active evidence set* (positive and negative, scope, exact cut, owner, effective time), not mutate truth to the last requested status. There is no justified auto-green.

**OSCIENCE/returns.** ingest_oscience (1358–1555) has useful digest-based deduplication and adds 17 workstream upserts, 14 missing-function candidates, 226 typed edges, 102 legacy definition records with grade UNREVIEWED_CANDIDATE_EVIDENCE. Those counts are a specific patch contract, not a universal architecture requirement. intake_candidate (1556–1620) accepts a caller-provided return id/branch/SHA and new_requirement without verifying the SHA/claim's author or competent owner, then materializes a gap immediately. Preserve this as *quarantined proposal intake* only; promotion and canonical gap addition require origin/object check and relevant endorsement. The history ID H0007 is not inherently a genuine historical event.

**Operational views.** CLI supplies overview, zoom, gaps, blocked-chain, work-now, coverage, workers, source, consumer, alternatives, history, export, intake-return and apply-authorized-transition. _critical_path (965–985) is only a DAG illustration and explicitly disclaims priority. _impact adds descendant counts and historical workstreams (695–713). _initial_workers is static; branch existence is not process liveness. These are valuable views, but cannot yet answer a new HQ's full question.

**Tests.** Test source contains 11 original unittest methods and 12 R2 pytest functions, covering seed/refresh, known source/consumer refusal, source withdrawal and repair, scoped transitions, return intake, O-SCIENCE dedup, cold reload, Pyat boundary and manifest. The R2 author receipt reports 23 passing tests (23 passed in 20.16s) and a cold export with equal digest. This is attributed author S2 evidence only, not W1-E execution or independent acceptance. Crucially, tests that accept a self-written SOURCEFREE_REVIEW are themselves part of the defect.

## The trust defect and the smallest real cure

Do not merely delete the bogus requirement or tell reviewers to be careful. Four small boundary changes:

1. **Fixture isolation:** r2_live_transaction.py must default to a temporary independent state path, never call _save with the real STATE/SNAPSHOT, and refuse an --operating-state path when synthetic inputs are present. Tests may create deliberate fake reviews inside tmp_path and prove they never appear in operating outputs. Mark all fixture-origin evidence as incapable of promotion in any dimension, including review/engineering (currently the SYNTHETIC_DEMO restriction focuses on science/authority/human and leaves other requested transitions possible).
2. **Quarantine, then clean replay:** archive the original contaminated candidate state/SNAPSHOT and its receipt as non-operating demonstration evidence; regenerate clean state from verified seeds and explicitly imported real, independently qualified events. Do not silently delete historical knowledge or replay self-reviews as valid. Record old→new revision, excluded event identities, provenance and why they were excluded. A full self-contained file digest does not launder these events.
3. **Proof before status:** SOURCEFREE_REVIEW is a claim type, NOT an independent credential. _apply_transition currently checks only that reviewed_sha is a real commit and the referenced source object matches a Git object. A worker can write those plus 'INDEPENDENT_I3_ENGINEER' into its own input. Require an *external, independently identified* reviewer-return object at an immutable ref, distinct review principal from author, exact reviewed target SHA/assertion/scope, valid negative/limitations, and a competent owner-granted (or expressly held) adoption event. If these cannot be verified, store PENDING_REVIEW / UNADOPTED without changing review or engineering acceptance. Git commits prove bytes, not reviewer independence, signature legitimacy or source authority. The owner/rightful intake actor may authenticate verified roles through existing control/lease records; do not create a new identity provider.
4. **Reduce, do not blindly restore:** append proposed evidence and qualified decisions as immutable records, then rebuild derived axes, blockers and consumer status from all still-relevant evidence. When S5 source is restored, rerun requirements for every dependent and preserve separately failed reviewers, incompatible source cuts and other missing predecessors; do not give CANDIDATE_READY by generic reverse mutation.

Stop hardcoding demo-only names such as SOROK_R2_NEW_REQUIREMENT in actual current operating state. The known persisted state files have the same Git blob ID 44ae533cfad0825e6fee926a39dc3a889abc29dd and the R2 transaction expressly writes to both; W1-E's GitHub fetch of their very large content was empty, so their full interior bytes were **not independently inspected here**. The persisted contamination finding is directly grounded in the executed script's save path plus the author transaction receipt, rather than a false claim that every JSON row was independently read.

## Smallest logical model (do not install a competing schema)

Keep **four logical notions** inside existing graph+history/state; this is interface guidance, not a new repository-level ontology.

- **Object:** stable semantic ID (preserve Q-HEALTH-001, SPD-0003, S5, original V3 symbols, C9C12 cut identities); type among purpose / phenomenon / rival theory / historical question or decision / requirement / function / source / implementation / test or negative / evidence / owner or work / human obligation. Separate enduring concept identity from each immutable version/cut of its code or claim. Store title, one-sentence user-facing function, read depth and relevant domain.
- **Relation:** from→to with explicit predicate such as REQUIRES, ALTERNATIVE_TO, CONTRADICTS, DECIDED_BY, IMPLEMENTS, CALLS, FIRST_CONSUMED_BY, TESTS, REVIEWED_BY, AUTHORIZED_BY, BLOCKED_BY, SUPERSEDES, PRODUCT_EFFECT, LOCATED_IN; preserve inverse query without false reciprocal causality. Every consequential edge carries exact evidence IDs, source scope, epistemic grade, time/cut, and whether it is a *candidate* or qualified dependency. Missing relation should be a first-class UNKNOWN edge request, not invented symmetry.
- **Evidence/change event:** immutable ID, asserted proposition/edge or test outcome, actor/role (claimed vs independently verified), exact source cut/blob and line/section, event time and intake time, target review SHA/assertion, contradicted/superseded event, reviewer/owner decision refs, scope, source status and reversible withdrawal. Author says 'tests passed' is a preserved claim; source and author assertion verification, independent replay, original grant and human trial are separate events.
- **View:** one reducer-derived current model with statuses for source/semantic read depth, scientific warrant, engineering, first real consumer, independent review, original authority, human/product outcome, operation/freshness. History stays queryable. No second system stores its own authoritative state. Progress is named terminal obligations and failed/unproven prerequisite edges, not percent of 212 nodes.

For each relevant object show status as a *matrix of separately scoped evidence*, not 'approved'. Semantic 'title only' is not 'source read'. REVIEWED_SCOPED is not NATIVE_ISSUED. An original historical decision may be superseded while its file remains authentic. A negative review never deletes a positive author test; it alters its permissible interpretation.

## Navigational design: laptop-sized, not a hairball

**Home (L0):** one paragraph 'what are we making?', 5–7 substantive terminal obligations with current scope status, truly blocked vs parallel frontiers, recently changed claims/negative evidence, and source freshness (PRE-MAIN and Library cut times). Show a visible WHOLE_SCOPE_NOT_YET_PROVEN notice. No arbitrary completion percentage.

**Focus page (L1–L5 zoom as one axis):** heading, plain-language 'what is it / what would it do / what actually works', horizontal status chips by evidence dimension, 3–6 closest supporting/contradicting links, two expandable panes 'upstream causes & rival explanations' and 'downstream consumer & human consequence', exact source/reviewer links, missing edges and owners. Breadcrumb to whole home. A click on an edge opens the *relation claim*, not just both documents. Hover/reveal explains grade.

**Lateral tabs:** why/purpose; scientific alternatives/falsifiers; code/function/first consumer; historical decision timeline; source/provenance; active work and owner; UX/ethical/business impact. These tabs query the same model, never write copied state. Default compact 1–2 hops, opt-in expand/sort/filter and search by exact ID, title, symbol, text, source SHA, people/owner or predicate; preserve source locators.

**Comparison view:** two rival scientific or architecture spines, their necessary assumptions, genuine tests, contradicted source, withheld owner decision and common product requirement. No implicit forced winner.

**Work-now view:** top 3–5 lawful coherent flights *with rationale*, not all 38 gap entries. Show prerequisite/issuer, exact first consumer, test that would go red/green, expected effect on terminal requirement, confidence, cost/host, next available worker and nonconflicting parallel actions. Reserve final selection for qualified HQ/owner.

**Portable first presentation:** a read-only, generated static HTML bundle with clickable graph rows and GitHub/Library deep links (where authorized) is enough for first tranche; retain CLI and JSON output. Do not start a web service or ship a big graph visualization library until real users cannot traverse these pages.

## Intake, concurrency and HQ durability

A return's minimal intake is: immutable author return SHA/path, precise changed objects/relations, tests and logs at exact cut, current negative and alternative, claimed first consumer, requested state changes, rightful reviewer/owner references. Mechanical validation checks Git object/cut, source object/type, existing IDs, deduplicated event hashes, reviewer-author separation and authority binding. It adds unreviewed candidate evidence as such. Meaningful scientific and owner decisions require their *existing* competent issuers; no generic mandatory review for metadata.

One Programma update uses expected branch head (compare-and-swap): read current ref, stage delta/events in isolation, verify, replay over current event base, commit only if expected SHA matches, otherwise reconcile parallel events by immutable ID/conflict predicate before retry. No lost updates. Cross-host requests/leases and worker liveness remain referenced from existing Codex/controller, never guessed from Git branch. Library is a continuity reference and historical user intent, not code canonical; its current LATEST pointer requires a fresh read at HQ handoff, not a hard-coded 2026-10-31 forever. mainMac remains targeted S2 test/source authority, not an automatic source crawler.

An evidence withdrawal tombstones/invalidates its evidential effect, does not delete its contents. A clean cold session loads events/source vector, reduces current state, compares snapshot digest against event replay and exact Git refs; a stale source retains last-qualified grade at old cut plus CURRENTNESS_STALE until reverified. Do not claim every changed Git ref invalidates every scientific assertion; trace exact affected source identities.

**Critical-path calculation:** Build a directed *qualified prerequisite* graph where each terminal obligation has AND prerequisites, explicitly model OR alternatives, held owner gates and required next acceptance tests. Find unresolved eligible frontier nodes whose required predecessors are available and whose owner/host permissions exist. Present several alternative unblock routes with plain-language value/cost, uncertainty and active noncollision, not an opaque scalar. Mark scheduling duration UNKNOWN if no observed estimates and resource leases UNKNOWN if unverified. The present blocked-chain function is a useful precursor; legacy _critical_path is not the real answer.

## Joint synthesis decisions and falsifiers

1. Adopt option A for first tranche unless W1-A–D exposes a required traversal or concurrent-source operation that cannot fit one logical graph and event log. Strongest counter: real intake concurrency or source estate scale makes event replay/cold queries intolerable.
2. Decide the authentic initial whole-program *entry projection* from original purpose/Charter, Astra, V3/Neo and human A5 instead of elevating R3's recovered IDs. Do not impose a single scientific kernel: original 05 and Vision worker retain KERNEL_UNRESOLVED.
3. Decide what existing HQ/owner custody record counts as a competent reviewer/owner authentication proof. Existing Git SHA is only an artifact identity. No new identity bureaucracy, but no self-declared role acceptance.
4. Have the qualified source owner select one C9/C12 cut and one independently verified first consumer for tranche demonstration; permit test-only status, retain owner/native HOLD.

**Falsify this design** if at least two real Sorok examples cannot preserve competing historical scientific claims and distinct owners as first-class qualified edges; if source disqualification cannot be replayed without rewriting unrelated history; if demonstrably independent concurrent intakes cannot be reconciled without data loss; or if an HQ cannot retrieve a relevant answer and source/consumer/owner in two navigational hops plus optional deeper expansions.
