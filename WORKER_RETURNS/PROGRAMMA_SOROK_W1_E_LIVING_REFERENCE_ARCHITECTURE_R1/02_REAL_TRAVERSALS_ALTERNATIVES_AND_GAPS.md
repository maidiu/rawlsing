## Navigation and usability acceptance for the selected architecture

The first screen must answer in under one conceptual view: what Sorok is for, what proof actually exists, what major missing gates remain, and which one or two source-justified moves matter now. Selecting a card yields no more than 3–6 nearby relevant edges, with expandable source/reviewer/history/alternative panes, back/breadcrumb and clickable exact Git/Library refs. The system must support **both directions** for all eleven cases; a cross-domain lateral tab must never turn an association into a tested dependency. A user can inspect the precise reviewer negative and source without learning graph nomenclature. Cross-family missing links remain visible as explicit "not evidenced" stops.

The answer is *falsified* if source counts make a case look complete while its first consumer is absent; if changing source cuts silently assigns a new owner; if a story becomes prettier but one material opposite fact disappears; if no further actor-source permission exists yet the diagram paints a contiguous native-person path; if the current HQ cannot identify the next competent owner; or if a fabricated independent review persists after cold restart.

## Three architecture comparisons under adversarial use

- **O-LIVE event/reducer + derived HTML (preferred):** preserves all eleven as different paths through one source-backed object/edge evidence set; only two primary semantic connector imports needed to make a real demonstration. Weakness is present hardcoded R3 seed/read-depth and untrusted transition gate, which the first tranche must correct; concurrency/latency unmeasured.
- **Per-file Wiki/PR records plus generated graph:** good for reading documents, but query 9 must join authority, test cut and regrade of dozens of consumers atomically; per-file annotations risk forgotten links and multiple competing present statuses. Demonstrate it reduces real work before considering as owner store.
- **SQLite/graph service:** makes temporal/branch queries and concurrency easier at large size, but no proven current workload exceeds 212/649 graph; it would add custody/backup and a separate runtime before the critical authenticity problem is solved. Require measured failure of option A on an authentic traversal or simultaneous intake before migrating.
