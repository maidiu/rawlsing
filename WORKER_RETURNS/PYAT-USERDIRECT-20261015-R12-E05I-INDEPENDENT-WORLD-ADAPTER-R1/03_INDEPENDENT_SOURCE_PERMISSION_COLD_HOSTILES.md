# Independent hostile court

## Confirmed defects in the exact E05 candidate

The tests assert the required behavior and remain failing on original E05. They do not assert that a vulnerability should occur, and no failure is marked xfail.

1. **Request/acceptance binding fails at serve.** `serve` verifies the stored acceptance and snapshot but never compares the supplied request hash to the accepted request hash. A request for `A|Y=1` returns actual **18/29**, while its receipt carries the old request hash for `Y|A=1,B=1,C=1`. A smaller structural readset and a different selection clock are also served under that old hash. See `DEFECT_request_substitution_{target,readset,clock}.json`.
2. **Acceptance does not bind requested clocks to selected clocks.** A real registered current snapshot is supplied to `accept` with a historical request (`valid_at=2026-06-01`, `published_asof=2026-03-01`). It produces a complete receipt for current values `False/8`, instead of the frozen historical `True/2`. Snapshot integrity and successful M4/M5 validation do not prove the requested selection was honored. See `DEFECT_accept_clock_substitution.json`.
3. **Native source lifecycle is frozen at acceptance.** Replace the registry with an original N9C registry whose NCA record is `REVOKED_TEST_ONLY` after acceptance. A new actual N9C read reports `SOURCE_REVOKED`, but E05 serves both cached native fields and `SELECTED_WORLD_VALUES_SERVED`. A new same-value native release identity likewise leaves the old ref in a complete receipt. E05's own `invalidate(NCA_NATIONAL_MOBILE_DATA)` raises `UNKNOWN_PERMISSION_SCOPE` because the underlying catalog has only structural/empirical scopes. See `DEFECT_late_native_revocation.json`, `DEFECT_native_rekey_after_acceptance.json`, and `DEFECT_native_invalidation_scope.json`. Registry replacement is a hostile input, not an owner implementation patch. E05 demonstrably does not revalidate the currently attached registry before fresh serving.
4. **Consumer payloads are copied, not authenticated or bound.** Supplying one foreign-snapshot consumer, one partial consumer, or fabricated joint/person weights yields a complete E05 receipt. These use the public `consumers=` argument; actual consumer code is not modified. In the modeled probability attack, actual consumers first return `None` weights and route probability; the hostile caller changes their detached dictionaries, which E05 copies unchanged. See `DEFECT_consumer_{foreign_snapshot,partial_as_complete,forged_joint_probability}.json`. This is an envelope integrity failure, not a claim that original E04 clients themselves infer persons.
5. **ZERO_SUPPORT loses its type at the adapter boundary.** Remove stratum111 via E04's original `support_loss=True`. Actual owners and both clients retain progressive denominators **24,8,0** and final `ZERO_SUPPORT`, no invented probability. E05 assumes every step has positive-only `binding_order`/`route` keys and raises `KeyError: 'binding_order'` at original adapter line 462. See `zero_support_before_adapter.json` and the actual traceback in `independent.log`.

## Genuine cold replay

`repro/run_cold.py` starts two distinct Python interpreters. Each reconstructs exact source fixtures and original owners, without inherited caches; the second compares complete serialized request/acceptance/receipt records, not only selected fractions. Cases cover current, historical, pre-NCA partial, genuinely changed empirical source/release, GSS withdrawal and NCA withdrawal. Old snapshots are refused by a newly constructed changed-source service. Reconstructed fixture grants are explicitly distinguished from continued authority: in-memory revocation is lost on fresh fixture construction, and the replay records this limit with `new_issuer=False`, `operative_OC05=False`.

The initial replay harness compared Python tuples against persisted JSON lists; it was corrected to normalize losslessly before comparison and both processes rerun. Two later hostile setup errors used incorrect universe/ref constructors and were corrected using original constructors, with their initial logs retained. These reviewer setup errors are not candidate defects. Final cold logs/exits and final independent JUnit govern the counts.
