## 3. Finite Astra entry/exit triggers

### Enter Astra / High only when all of these are true

1. The question is **not** answerable by exact documentary lookup or a bounded existing test.
2. There is a real conflict or novelty at the level of **whole-person causal meaning, native scientific rule, cross-owner architecture, or a proposed C11/C12 weld** — not merely a missing file, stale status, or ordinary adapter.
3. A wrong answer would materially change the native/authority ceiling, not just the wording of a report.
4. The minimum useful artifact is finite: one decision memo, one architecture patch, one test design, or one precise owner request.

### Do **not** enter Astra for

- reading a known file or refreshing a SHA;
- formatting, JSON, Git, or commit mechanics;
- rerunning an existing test whose provenance is already clear;
- a bounded sourcefree adapter join with known interfaces;
- a generic “review the review” request;
- a task that is only expensive because it is large, not because it is causally hard.

### Leave Astra immediately when

- the finite artifact is banked, or
- the remaining work becomes mechanical/documentary, or
- the user directs a downshift, or
- the observed quota reaches the user's bank threshold (roughly 75–80% of the observed window; exact figure is user-owned).

### Bank before/at every true transition

Before a model/gear change, at ~75–80% observed quota, and at session end:

1. commit all meaningful work on the authorized branch;
2. push non-force and record the exact 40-hex head;
3. write a one-screen recovery checkpoint: current refs, what changed, what is NOT_RUN, next lawful action, and a paste-ready continuation prompt;
4. leave no important staged tree uncommitted;
5. do not rewrite or force-move a returned worker branch.
