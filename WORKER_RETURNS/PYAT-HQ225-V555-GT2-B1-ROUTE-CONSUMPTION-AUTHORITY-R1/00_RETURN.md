## Six commissioned answers

### 1. Is B1 publication required for lawful V555 consumption?

Not as a matter of implementation topology. Legacy M2 consumes an in-memory `M1Evaluation` carrying F1/B1 and validates B1 directly, so synchronous owner-authentic consumption does not technically require a durable B1 publication.

But for **this current SIG-004 lane**, that does not make internal consumption lawful. The current rule/bundle forbids V555. A future authority could expressly authorize in-process B1 consumption while preserving B1 nonpublication, but that would be a **new bounded authority decision**, not an interpretation of current law.

### 2. May cross-process/persisted V555 replay receive a V555-only bounded B1 exposure?

Not under current authority.

Current authority expressly excludes `B1_PUBLICATION` and provides no alternate V555 custody namespace. Any durable or cross-process B1 exposure usable as V555 custody would create a new governed boundary surface and therefore requires explicit new bounded authority. Calling it "V555-only" does not make it already authorized.

### 3. Could a relation-specific M2 authenticate V554 eligibility without consuming B1?

Only under a new exact alternative-closure authority.

Published F1 plus exact rule/current-selection/admission/provenance material contains enough ingredients that a new SIG-004-specific M2 contract could in principle re-authenticate the relevant eligibility closure without a durable B1. But the existing M2 contract does not do that: it requires B1, verifies B1's exact F1/F2 closure, and carries an exact B1 ref into route/replay material. No adopted authority currently substitutes a different closure for that B1 function.

### 4. Is B1 merely a legacy implementation convenience?

No.

Historical/current architecture classifies B1 as a governed `V554_V555_HANDOFF` boundary/interface object rather than a V554 semantic meaning family. Legacy M2 enforces it as the exact authorization closure for positive V555 intake. Its **publication form** is separable from its semantic function, but the function is not accidental code residue under the existing contract.

For SIG-004 specifically, the M1 owner reuses the accepted B1 constructor and computes an exact current-rule B1; the adopted GT2 publication/use authority then deliberately declines to publish or authorize that interface downstream.
