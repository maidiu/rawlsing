## Five-test decision

1. **Current necessity.** W05/P03 requires respondent-coherent cross-operation sharing under exact native publication. At the first admitted reader path the baseline rebuilt sealed release topology once per I03 operation, including I05 candidates. The proof is fewer builds and lower whole-operation cost with the same directional facts, domains, releases and replay.
2. **Current successor and uncovered behavior.** Existing I03 indexes one release/universe and reuses derived branch memberships within a predicate. The facade caches a full validated release where supplied, Batch conserves exact work, and R04 resumes native outputs. Their lawful composition still rebuilds I03 respondent maps per operation. Existing Parquet/R4/R5 do not serve that in-process topology to I03. Adapt the existing builder without porting a historical engine.
3. **Receiving need.** The first consuming call is I03 under the carrier-neutral executor and I05 on the admitted PR646 R03/R04 path. Its facts and discovery receipts feed actual R05/P41. The measured missing edge is reuse across operations against the same exact repository release, including compatible distinct calls and calls that must use different risk sets.
4. **Suitability.** I02's exact release resolver and query authority gates run before each reuse. Cache keys are exact release and universe refs, and the same sealed release instance must still resolve. Each cached map is read-only and each row group is a tuple of immutable I02 objects. The cache retains no risk selection, predicate binding, current authority, counts or facts. Runtime authority state is supplied by an evaluation-local copy. Locking serializes first construction within a repository. Different repositories, source releases and universes build their own index. The cache lifetime follows its repository.
5. **Comparative gain.** Repairing the hot path by composing a source-byte cache with Batch would leave the per-operation topology work. Porting a historical carrier or creating a grouped executor adds an independent ABI and proof surface. Reusing the owner index removes most builds on the actual fixture with bounded code and unchanged public API. No-action keeps the measured repeated cost. The optional choice of technique and rollout remains reviewable against other implementations of the selected capabilities.

**Historical durability decision:** `PRESENT_COMPOSED_NO_BUILD` for the demonstrated R04/P41 first-reader contract only. HQ282 `73d45f3ac6a50fbee6666ad3a5023840f01ef196` is branch-only. Its `DurableCheckpointStore.save/load` takes a durable checkpoint and identity under an fsync/lock protocol. Its `open_session/run_to_completion/recover/admit_saved_receipts` adds journal and recovery disposition, and `run_integrated` wraps that candidate session. The current R04 callable takes an exact joined checkpoint/ref and admitted workloads, restores native custody and resolves the pending units through the existing owner. These interfaces answer different persistence contracts. The actual P41 read after R04 restore exposed no requirement for a second scheduler or journal. The older SRC04 adapter and its torn/foreign/refusal modes remain conditional on proving a current receiving edge. Power-loss semantics and original-source custody require their own actual owner and proof.
