# FIABC-A05 — Documentary vs Mechanized Governance

## Holding

The project did not lack inheritance law. It lacked a universally enforced bridge between **inheritance law** and **runnable graph construction**.

The key distinction is:

`GOVERNED_AUTHORITY_EXISTS`

is not the same proposition as:

`CURRENT_EXECUTION_ROOT_BINDS_AND_CONSUMES_GOVERNED_AUTHORITY`.

## What was strongly mechanized

### Exact historical/current distinction

Canonical governance explicitly separates:

- current authority;
- runtime status;
- Git ancestry;
- preservation;
- historical/exploratory status;
- BLOCKED/REJECT/open state;
- delegated authority versus global sovereignty.

The canonical read order and anti-resurrection index provide machine-readable status surfaces and exact successor refs.

### Exact-ref / no-fallback law

Law 38 and later commissions repeatedly require exact authority refs and prohibit fuzzy/latest/default substitution. R6T is especially clear: the correct LiTS authority bytes already existed and the repair was only to bind the exact pinned path; no fallback was authorized.

### Typed semantic non-inference

Law 38 mechanizes the boundary in the sense that accepted runtimes/contracts must not infer missing semantic authority from labels, codes, distributions, similarity, source incidence, or implementation convenience.

### Fail-closed authority absence

R6Q demonstrates successful enforcement. The projection could have been made mechanically binder-valid by promoting `B_COUNTRY`, but the worker rejected that result because binder validity was not semantic authority.

## Where governance remained documentary / court-dependent

### 1. No universal executable succession receipt at the runnable root

No reviewed surface proves that P2X construction itself was impossible unless every inherited obligation resolved through:

`inherited function -> exact current authority/producer -> exact runtime binding -> actual consumer`.

R6U therefore reached execution with adopted R6A modules/fixtures omitted from its tree.

### 2. Exact authority identity did not guarantee exact consumer path

R6T shows that the authority object and pinned commit could be correct while the backend path component was wrong. Governance specified exactness; the runnable package still had a stale path reference.

### 3. Producer ownership did not generate the call graph

R6V imported the accepted binder yet locally shadowed it and recursively called itself. The producer-owned/direct-reuse doctrine remained semantically correct while ordinary implementation wiring violated it.

### 4. Typed lifecycle law did not generate driver sequencing

R6W had a correct verifier contract and an incorrect driver transition order. The semantics of S17 were documented/adopted; the state machine was not mechanically derived from them.

### 5. Living-ledger law did not prevent wrong-scope terminalization

R6X exists because infrastructure failures were serialized into terminal history at the wrong scope and therefore needed governed reconciliation before lawful retry. The project preserved history, but execution-state semantics were not fully aligned with repair/retry semantics.

## The mechanization gap

The supported gap is not “more documentation was needed.”

It is:

`PRESERVATION/CURRENTNESS/OWNER LAW WAS EXTERNAL TO SOME EXECUTABLE COMPOSITION DECISIONS`.

A worker could possess the right authority document, exact artifact identities, and accepted producer semantics while still building a runtime that omitted, misaddressed, shadowed, misordered, or mis-serialized them.

This return does **not** authorize a redesign. It records the gap for the ten-worker fan-in court.
