# Generic Failure-Class Applicability — Wave 2 Late GSS

## Scope

This file generalizes the **question**, not another source's answer. The five late-GSS releases have no banked source-specific realization/runtime package at the R3 fan-in, so runtime-only failures are not mislabeled as present source defects.

Applicability vocabulary used here:

- `APPLICABLE_NOW` — the failure question already constrains the governed source/documentary boundary.
- `APPLICABLE_AFTER_REALIZATION_AND_RUNTIME_PACKAGING` — it becomes executable only after a bounded source realization and current PRE553 package exist.
- `APPLICABLE_AFTER_RUNTIME_PACKAGING` — it is a runtime/catalog/I05 consumer question.
- `UNKNOWN_REQUIRED_AUTHORITY_ABSENT` — the exact source relation needed to construct the object is not presently authorized.
- `NOT_APPLICABLE` — the release topology does not invoke the question at this grain.

## 1. DECODER_RUNTIME_TYPE__GOVERNED_KEY_NONINTERSECTION

PREP71 freezes reader configuration, exact witnesses and physical states, but this browser lane does not possess the complete qualified decoder-host representation table needed for exact R5-style typed physical keys. A later package must construct keys from the authorized decoder representation, never from an equal-looking numeric/string spelling.

**Required hostile:** mutate only host representation while preserving displayed magnitude; exact rule lookup must not silently coerce.

## 2. LAWFUL_AUTHORITY_REPRESENTATION__CONSUMER_IGNORES_FORM

GSS itself contains materially different forms: physical missing representation, questionnaire/form/version topology, release-specific weight domains and documentary layers. A later runtime consumer must read the exact representation-form field that makes an authority claim lawful rather than merely retaining an authority hash/ref.

**Required hostile:** hold authority identity constant while changing/omitting the representation-form input; reject.

## 3. DYNAMIC_QUERY_REF__STATIC_CATALOG_ONLY_RESOLUTION

No late-GSS runtime query producer exists yet. When packaged, dynamically generated query/predicate/fact refs must retain construction preimages or deterministic reconstruction material. A post-consumer may not resolve only the pre-search static catalog.

## 4. I05_FACT_EXISTS__POSTCONSUMER_PREIMAGE_MISSING

No real I05 was run. A later valid fact ref is insufficient if the actual fact preimage—typed state, source/release refs, authority refs, dependencies and replay root—is absent at the consumer seam.

## 5. HISTORICAL_FILE__AMBIENT_CURRENT_DEPENDENCY

Applicable now to every exact release snapshot. PREP71's evidence method expressly makes the exact release/source layer outrank ambient current or cumulative documentation. Later/current material may support a delimited historical relation; it cannot silently become the source authority.

For 2024 this includes the exact March-2026 Release-3 documentary binding: later GSS materials must not rewrite that snapshot.

## 6. HISTORICAL_SUCCESSOR__RUNTIME_CATALOG_SCOPE_NOT_ENFORCED

A valid later/successor authority may be lawful only for a named source/release/operation. The eventual package must freeze exact runtime-catalog identity, historical parent operation, successor operation and negative scope. Newer is not automatically admissible.

## 7. SOURCE_SPECIFIC_TERMINAL_DOMAIN__GENERIC_FIELD_SUBSTITUTION

Applicable now as a realization-authoring constraint. The source preparation preserves distinct physical/source states—ordinary observed values, format/user missing, IAP, no-answer, release/year-unavailable states, routing coordinates, weight-domain exclusions and bounded UNKNOWNs. A generic runtime status field may not erase these distinctions.

2024 makes the danger especially visible: `WTSSPS_AS=-70` is a real source state documented as unavailable in that year, while the exact Release-3 combined single-year weight is `WTSSNRPS_AS`. That relationship is not repairable by generic "missing weight" substitution.

## 8. RISK_SET_DECLARED__MEMBERSHIP_PREIMAGE_UNAVAILABLE

`UNKNOWN_REQUIRED_AUTHORITY_ABSENT` for all five at exhaustive scope. PREP71 explicitly leaves variable×instrument/form/version×route/universe binding incomplete. Therefore a complete exact risk set cannot lawfully be manufactured from IAP/missingness incidence, neighboring variables, or current questionnaire shape.

A bounded realization may omit/unproject the unclosed risk-set grain.

## 9. QUESTION_VALUE_BINDING__EXACT_RESPONSE_REF_UNAVAILABLE

For exact authority-admitted question/value grains this is a future realization/runtime packaging problem: current late-GSS has no PRE553 response-ref package. Packaging must create exact question-scoped refs from admitted source law; unclosed routing or semantics remain absent/UNKNOWN rather than receiving fabricated refs.

## 10. CURRENT_PRODUCT_SHAPE_MATCHES__SUBSTANTIVE_PRIOR_TRUTH_NOT_PROVED

Applicable now across all five.

- 1993 ballot structure does not prove 2002 version structure.
- 2002 manual-map/version structure does not prove 2010/2016 two-phase routing.
- 2010/2016 similarity licenses only the explicitly frozen structural subset, not ordinal/dictionary/routing/weight continuity.
- 2024 is an explicit hard break from 2010/2016.
- Recurring variable names and weight names do not prove cross-release substantive equivalence.

## Holding

The transferable law is the audit question:

> Does the source/runtime path preserve the exact representation, provenance, applicability, response binding, catalog scope, generated preimage and terminal domain required by **this release's own authority**?

Where the answer requires missing documentary authority, remain `AUTHORITY_BLOCKED`. Where it requires absent runtime plumbing, remain `REQUIRES_RUNTIME_PACKAGE`. Neither condition is a license to infer continuity.
