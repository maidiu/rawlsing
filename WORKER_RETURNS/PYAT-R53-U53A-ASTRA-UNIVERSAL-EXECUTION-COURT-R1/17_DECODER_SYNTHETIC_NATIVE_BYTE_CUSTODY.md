## Mechanism and narrow conclusion

_decode hashes before metadata reading (lines451–465). Native no-encoding incidences retain a pathname instead of a frame (467–519). iter_batches reopens that pathname through read_file_in_chunks and emits cells under previously retained variables/declarations (108–148), without revalidating the pinned bytes. The metadata digest deliberately describes metadata; it is not cell replay proof. These identities can therefore remain stable while the reopened content changes.

Classification: REPAIR_FUNCTIONAL_BUG at the direct decoder custody boundary when a mutable pathname is accepted. The demonstration changes bytes between calls, not via a speculative concurrent race. It does not show mutation in a real deployment or propagation into C11/Batch/scientific output. A verified immutable snapshot supplied by a caller can prevent this scenario; that precondition must be explicit and checked if it is the chosen ownership contract. A one-time hash before returning a lazy incidence is insufficient on its own. The full-read compatibility path and mutation during an active stream were not tested.

Selected P2X caller lines708–727 hash before decode and compare the returned incidence digest; they do not by themselves establish future path immutability. The physical bridge lines39–42 compares candidate hashes to the stored incidence hash. These static observations motivate caller/custody inspection, not a claim that the complete P2X/C11 graph is compromised. Preserve reuse of the format-neutral decoder and bounded streaming; no replacement engine or unconditional full-memory load is justified.
