# PYAT HQ117 — M2 Constitution

## 1. Jurisdiction

M2 owns one bounded semantic act:

make an already producer-owned learned semantic product, learned service contract, or typed disposition durably citable and lawfully resolvable under exact authority/dependency/replay/explanation closure.

M2 does not own:
- the semantic truth or disposition being released;
- the producer's family-specific validation/adjudication law;
- lifecycle/current-selection events;
- downstream consumer permission;
- Field Forge structural admission;
- PRE-V3 target-use permission;
- source-universe composition, comparability, measurement portability or positioned-subject authority;
- physical architecture selection.

Freeze:

PRODUCER_SEMANTICS -> M2_RELEASE_BINDING -> M3_LIFECYCLE_OPTIONALLY

is a jurisdiction graph, not a required physical conveyor.

## 2. Five identities

M2 requires the machine to keep five identities separately nameable even when an implementation co-locates them:

1. Semantic subject identity
   The exact producer-owned product, service contract or typed disposition.

2. Release identity
   The immutable content-addressed binding of that subject to the exact authority, dependency, determinant, replay and explanation closure under which the release claim is made.

3. Publication-binding identity
   The immutable statement that one exact release can be resolved by one exact producer-preserving resolver/locator representation.

4. Lifecycle/current-selection identity
   A separate M3 event/selection over exact release ids.

5. Consumer-permission identity
   A separate downstream authority for a named use.

Nonimplications:

SEMANTIC_SUBJECT_EXISTS != RELEASE_EXISTS
RELEASE_EXISTS != PUBLICATION_BINDING_EXISTS
PUBLICATION_BINDING_EXISTS != CURRENT_SELECTED
CURRENT_SELECTED != CONSUMER_PERMISSION
RELEASE_RESOLVABLE != SEMANTICALLY_POSITIVE
RELEASE_RESOLVABLE != STRUCTURALLY_ADMITTED
RELEASE_RESOLVABLE != PREV3_USE_AUTHORIZED

## 3. M2 constitutional objects

### A. Release subject

An exact reference to an already producer-owned semantic object/disposition/service contract.

Requirements:
- exact identity; no latest/default/fuzzy alias;
- producer contract/owner is recoverable exactly;
- complete semantic anatomy is recoverable at the producer's grain;
- any typed negative/uncertainty ceiling remains part of the producer-owned subject;
- M2 cannot manufacture omitted semantic dimensions.

### B. Release core

An immutable, canonical, content-addressed manifest that binds:
- release contract identity;
- release subject exact ref;
- subject kind;
- producer/semantic-owner exact contract ref;
- authority closure;
- direct dependency closure;
- semantic determinant closure;
- replay/reconstruction closure;
- explanation lineage.

The release core does not contain currentness or consumer permission.

### C. Publication binding

An immutable exact binding from a release id to one resolution mode and its exact resolver/locator integrity material.

Examples of lawful resolution mode:
- DIRECT_PRODUCER_REF
- CONTENT_ADDRESSED_MATERIALIZATION
- IMMUTABLE_REPOSITORY_LOCATOR
- GOVERNED_VIRTUAL_REBUILDER
- GOVERNED_SERVICE_RESOLVER

A binding is a serving fact, not semantic ownership.

### D. Resolution receipt

A per-resolution audit fact proving that:
- the requested exact release id was used;
- the exact publication binding was used;
- the resolved release core matched;
- the resolved producer subject matched;
- no current/latest/default substitution occurred;
- representation integrity checks passed or failed with typed failure.

A resolution receipt does not create a new release unless its result is itself separately produced and released as semantic content.

## 4. Release validity

A release is valid only if all constitutively required exact refs resolve and the release subject's producer contract confirms the referenced subject is complete at its own semantic grain.

Fail closed for:
- missing producer identity;
- mutable or fuzzy product alias;
- authority closure gap;
- missing constitutive dependency;
- missing determinant needed for historical reconstruction;
- replay contract unable to recover the promised semantics;
- explanation lineage that cannot walk back to exact producer/evidence roots;
- typed negative collapsed into an empty positive;
- subject-kind mismatch;
- hash/preimage mismatch.

M2 may publish a typed blocked/unresolved disposition where that disposition is itself producer-owned and complete. "Blocked" is not a release-construction failure unless the release falsely claims a positive subject.

## 5. Producer ownership firewall

Authority31 governs the central rule:

publication does not re-own semantics.

M2 MUST preserve:
- exact producer identity;
- direct producer dereference;
- producer-defined type/cardinality/order/multiplicity;
- producer-defined semantic state;
- producer-defined support/uncertainty/negative ceilings.

M2 MUST NOT:
- rewrite a producer object into a generic JSON "meaning";
- copy fields and declare the copy authoritative;
- flatten n-ary structure into pairs;
- promote provenance into truth;
- promote physical presence into permission;
- infer positive state from publication success.

If the release subject is a mixed-producer product, the product's own producer contract must already lawfully own the new composed meaning and preserve its direct upstream refs. M2 does not create that composition authority.

## 6. Product versus service release

### Learned product

An immutable semantic subject whose exact content/identity can be dereferenced or reconstructed.

### Typed disposition

An immutable semantic/adjudicative subject whose state may be nonpositive, unresolved, valid-empty or blocked.

### Learned service contract

A governed callable learned-world capability whose semantic contract, authority inputs, algorithm/model/configuration determinants and output contract are exact.

For a service release:
- the logical service contract belongs to the release subject;
- a network address/process/container does not;
- physical endpoint movement changes publication binding, not release identity;
- historical invocation replay additionally requires exact invocation input and execution receipt;
- nondeterminism requires governed named random streams/subsampling/search budget/tie/stop determinants where applicable.

## 7. Virtual release law

M2 expressly permits:

DURABLE_RELEASE_ID + NO_DURABLE_PAYLOAD_BYTES

when:
- the producer subject remains exactly identifiable;
- all non-source-derivable semantics are retained;
- exact reconstruction dependencies/determinants survive;
- replay/reconstruction is executable or otherwise governed at the promised level;
- historical authority versions are pinned;
- reconstruction failure is typed and cannot silently fall back.

A virtual release is not permission to discard source/authority roots, manual semantic authority, replay receipts, or historical epistemic state.

## 8. Direct dereference law

No M2 wrapper is universally mandatory.

A downstream producer/consumer may directly dereference an exact upstream semantic object where:
- its own contract permits direct use;
- the exact upstream ref is sufficient;
- no required publication/currentness claim is being made;
- no constitutive validation/comparability/composition premise is bypassed.

Direct reuse may coexist with an M2 release of the same subject.

Therefore:
DIRECT_EXACT_USE != UNRELEASED_INVALIDITY
and
DIRECT_EXACT_USE != IMPLIED_RELEASE

M2 exists where durable publication, cross-session reference, generic service resolution, historical citation, or M3 lifecycle over a learned product is required.

## 9. M3 handoff

M2 exposes to M3:
- immutable release_id;
- release subject exact ref and subject kind;
- exact release scope already owned by the subject;
- exact authority/dependency/determinant closure;
- replay/explanation roots;
- immutable publication-binding ids.

M2 does not expose a "latest" release.

M3 alone may create typed lifecycle events and an explicit current selection at exact jurisdiction/scope/purpose.

Dependency changes may tell M3 which releases are affected. They do not tell M3 whether the semantic event is CORRECTS, RECERTIFIES, WITHDRAWS, ONTOLOGY_EXPANDS, SUPERSEDES_COMPLETENESS_ONLY or another P2 event.

## 10. Downstream handoff

Downstream services may ask M2 to:
- resolve an exact release id;
- verify release core integrity;
- return exact producer subject ref;
- resolve/verify a named publication binding;
- return replay/explanation closure.

They may not ask M2 to:
- authorize their use;
- select a current release;
- reinterpret negative state;
- manufacture source/measurement/comparability authority;
- admit a structural relation;
- infer actor state.

## 11. Physical-neutrality law

The following normally remain outside release identity:
- file/table/database layout;
- serializer;
- compression;
- column order;
- chunking;
- materialized versus virtual payload;
- storage backend;
- cache/index representation;
- filesystem path;
- network endpoint;
- process topology;
- replica/mirror count;
- warm/cold retention tier.

A physical choice enters semantic identity only if a competent semantic producer explicitly makes that property constitutive of the product meaning. M2 cannot make that determination itself.
