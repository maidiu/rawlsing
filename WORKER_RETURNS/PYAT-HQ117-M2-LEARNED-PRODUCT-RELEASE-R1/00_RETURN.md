## Holding

M2 is separable and can be constituted without taking semantic ownership, current-selection ownership, or consumer-permission ownership.

Freeze:

SEMANTIC_PRODUCT != PRODUCT_RELEASE != PUBLICATION_BINDING != CURRENT_SELECTION != CONSUMER_PERMISSION

The smallest lawful M2 jurisdiction has two immutable identities:

1. a content-addressed learned-product release identity over an already producer-owned semantic product or typed disposition plus its exact authority/dependency/determinant/replay/explanation closure; and
2. one or more content-addressed publication bindings that make that exact release resolvable through exact producer dereference, materialized representation, repository locator, or governed service resolver without changing release identity.

2. Exact semantic producer/product ref:
   M2 MUST point to an already complete producer-owned semantic object/disposition/service contract. M2 may not restate, reinterpret, flatten, or re-own its semantic anatomy.

3. Authority/dependency/determinant closure:
   Each closure is immutable, exact, content-addressed or otherwise exact-ref resolvable, and historically pinned. Missing required closure fails release publication closed.

4. Replay/reconstruction and explanation lineage:
   A release must preserve the exact evidence/authority roots, operation/model/configuration determinants, replay receipts, and reverse explanation path needed to reconstruct or explain what was released. Rebuildability is lawful; unprovable rebuildability is not.

5. Product/service kind and resolution:
   Logical kind belongs in the release preimage because it constrains lawful dereference semantics. Physical resolver/locator data belongs in separate publication-binding identity. Exact resolution may never use latest/default/fuzzy/nearest selection.

6. Negative/nonpositive products:
   Publish the exact producer-owned typed disposition, never an invented empty positive object. VALID_EMPTY, OBSERVED_ZERO, ZERO_SUPPORT, REJECT, BLOCKED, NONCOMPARABLE, NO_TRANSPORT, OUT_OF_SCOPE, NOT_APPLICABLE, coverage-limited, missing-authority and integrity-failure states remain distinct.

7. Virtual/rebuildable release:
   YES. Durable semantic release identity does not require durable bytes for one payload representation. The release remains durable through exact subject identity plus exact reconstruction/replay closure.

8. Non-semantic physical choices:
   serialization, compression, table/file layout, database choice, materialized versus virtual payload, cache/index shape, mirror count, physical path, endpoint address and warm-retention strategy remain non-semantic unless separately governed as semantic content.

9. Direct producer dereference:
   Direct exact producer reuse remains lawful and preferred where a consumer already has the exact governed subject and its own authority makes a generic published release unnecessary. M2 does not force a universal wrapper. Direct reuse is not evidence that a generic M2 release exists.

## New constitutional split

A single "release object" that embeds a mutable path, mutable current pointer, or consumer permission would collapse jurisdictions.

M2 therefore freezes:

RELEASE_CORE_IDENTITY != PUBLICATION_BINDING_IDENTITY

The release core survives relayout, rematerialization, mirror changes, cache loss and endpoint relocation.

A publication binding changes whenever its exact resolver/locator representation changes, without changing the release core.

Multiple publication bindings may lawfully expose the same release.
