# Proposed independent custody protocol — NOT ISSUED

This packet proposes an operational protocol. It does not certify its own scenario independence, lawful-set authority, a trusted signature, or a model-use grant. The 28 new surface-context cases are frozen implementation-visible template holdouts; their semantic prototypes and answer sets are known to this author. They provide prospective regression checks, not an independently held-out population.

1. **Name competent, distinct people/roles before authoring the confirmatory bank.** HQ records the candidate implementer, scenario custodian, competent K3/K5/K6 semantic approvers, key adjudicator and independent I2 acceptance reviewer with relevant competence and conflicts. The independent custodian cannot be the candidate author or their delegated answer compiler. Prefer distinct scenario authors and a key adjudicator; two functions/files from one author are correlated cross-validation. Candidate-suggested cases must retain that provenance and remain a separate development/exploratory stratum. No names or competence certificates are invented by this return.

2. **Agree on constructs and lawful sets before policy/model output.** A semantic owner approves the event admission and access rules, independent public standing/private belief, true practice plus current capacity, and accessible trace without inaccessible origin. Keys encode sets, not a single mandatory action. Preserve APPEAL, REMAIN_DOUBTFUL and NO_SANCTION. A choice between lawful options is not automatically a quality improvement. Typed schema validity, in-menu action, joint reports, protected-origin violations and unscorable outcomes remain separately auditable. A statistical scorer cannot issue world-owner facts or psychological truth.

3. **Seal a versioned capsule with role- and purpose-bound signatures.** The proposed capsule includes schema/version, commission/purpose, source/law refs, scenario frame and sampling algorithm, family/duplicate graph, exact case bytes and hidden/public projection split, lawful sets and reasons, coder rubric, split assignments, generation/contribution history, rejected alternatives, freeze timestamp and hashes. Use a competent registry of externally controlled public keys and context-bound signatures (for example Ed25519) over a canonical manifest and content hashes. Verify signer identity, role, scope, version, expiry and revocation against that registry. A hash proves byte identity, not authorship, independence, competence or permission; a signature by an untrusted or candidate-controlled key does not cure that. The R3 mock MAC is a local test mechanism only. This return contains no operative external signature verifier or trusted registry, so `custody_status` returns HOLD even when fields look complete.

4. **Keep the genuine holdout inaccessible until the candidate is fixed.** The custodian keeps holdout scenarios/keys in a separate access-controlled environment. Candidate development receives only approved development cases and the public schema. Commitments alone do not hide a JSON file readable by the implementer. After candidate source, renderer, policy/model configuration, endpoints, scoring code and sampling plan are locked, the custodian releases the approved public projections to an independently controlled execution process. Keep custody/access logs, record every exposure and development use, and retire exposed cases from confirmatory holdout status. Freeze violations produce a new version with old outputs retained, not an edited certificate.

5. **Generate allocation and opaque identifiers independently of outcomes.** The custodian seals the outcome-independent randomization seed/algorithm after the bank is fixed. Each case crosses all menu rotations and all six arm orders. Trial IDs stay evaluator-side; a random opaque public nonce is shared within each matched A/B/C block so an ID-only responder cannot recover arm. Each request receives an isolated stateless session in a future provider study; reused nonce must not imply provider cache/session reuse. Independently rerandomized nonce blocks diagnose metadata dependence. Metadata fields, prompt length, context truncation, generation settings and serial/batch position are audited before unblinding.

6. **Blind the channels and freeze the joins.** Providers receive equal lawful facts and only the assigned lawful representation; no K, contrast, case/family/arm tag, hidden origin, evaluator grant, oracle or score. C is a replay-verified derived index, not a new cause; B supplies descriptive grouping, not a recommended action. Record exact raw request/response bytes before coding. Coders see response and schema/rubric, not arm, provider, expected answer or desired result. Typed coding is deterministic. Arbitrary prose requires a separately reviewed, key-blind rubric and competent adjudicators; ambiguous output is OTHER_UNSCORABLE, never a guessed canonical action. Lock coding/adjudication and reasons before matching to the sealed lawful sets and arm labels.

7. **Keep all planned denominators and resolve disagreement openly.** Missing responses, refusals, budget/transport failures, malformed output and OTHER_UNSCORABLE remain planned units. No deleting disagreements, rekeying cases from observed outputs, or semantic redraw. Record separate technical failure, lawful uncertainty and true rule violation. A disputed key goes to its competent semantic owner with blinded alternatives and provenance, not to the model or implementer. Confirmatory treatment analyses stay HOLD for an unresolved key; any revision is prospective and versioned.

8. **Separate custody, experiment permission and provider implementation.** Semantic approval and custody signatures grant no network/model access. A later, separately commissioned provider adapter must be independently validated under the actual issued model-use/privacy/spend/retention grant. The inherited eight required fields are: `named_provider_exact_endpoint`, `exact_model_and_version_pin`, `privacy_permission_for_synthetic_lab_packets`, `experiment_use_grant_behavioral_actor_trials`, `explicit_monetary_cap`, `price_class_and_quota_observed`, `raw_request_response_retention_permission`, and `per_trial_call_budget`. Mere nonempty strings are insufficient: the competent issuer must actually authorize exact purpose, packet disclosure, retention, maximum attempts/retries and cost under a current pin/expiry/revocation policy. Provider credentials or authoring-model access imply none of these. Current values remain UNISSUED, adapter NOT_IMPLEMENTED, external experiment calls permitted ZERO.
