## Actual fact custody is not immutable

WG0P3 `FactCustody` lines 892–924:
- `store(key, fact_data)` computes `_h(json.dumps(...))` but stores `self._facts[key]=fact_data` **without copying**. Caller's original dict/nested list remains the archived object.
- `read(key)` checks hash against current aliased content, then **returns the internal mutable dict**. A consumer can corrupt a previously verified value and its later re-read will refuse. Detecting corruption is useful, but does not make the stored historical value immutable nor preserve a truthful accepted read.
- `snapshot()` uses `dict(self._facts)`, a **shallow copy**, retaining the nested dict aliases. `restore()` also shallow copies and performs **no immediate hash verification**.
- `store()` with same key replaces existing content and hash without rejecting a conflict. If the key represents exact `EmpiricalFact.ref.key`, this is a collision/overwrite channel for a purported immutable value-bearing fact. No content-hash check to independently verified original `EmpiricalFact.ref` is performed in this small custody store; the self-calculated adapter hash verifies local consistency alone.

Isolated executable Python acceptance court ran the above method bodies with synthetic counted facts: mutating a caller-owned fact, returned read dict or snapshot's nested cell changes internal archival state; subsequent read raises `IdentityError` instead of returning the original fact. Registering another value under the same key is accepted. Restoring a snapshot retains aliases and can similarly be corrupted. **These are method-level REDs on the source behavior; no full candidate/owner import is claimed.** Smallest repair: canonicalize and deep-freeze or deeply copy on `store`, deep copy/immutable view on `read` and `snapshot`, validate all source-meaningful primitives + original accepted EmpiricalFact ref projection, reject same-key conflicting bytes and independently reconcile source release/query/semantic readset at read. Do not simply silence the hash-drift detector.
