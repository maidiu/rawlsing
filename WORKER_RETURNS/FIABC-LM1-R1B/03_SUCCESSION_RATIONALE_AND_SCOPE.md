# Succession rationale and scope

The predecessor no-repeat rule remains generally valid. The sole exception exists because the earlier completed LiTS-A R5 became inadmissible for current source-free use after generic R35 parentage became mandatory, while LM1-R1A established that its historical first-build receipt cannot lawfully be recovered. Keeping both laws without succession would permanently deadlock LiTS-A.

The successor therefore authorizes one outcome, not one process start: one successfully sealed LITS_I × CANDIDATE_A × R5 replacement. A crash or incomplete attempt does not consume the authority, cannot yield an admitted derivative, and is retryable only through existing interruption/recovery law. A second successful replacement requires a new authority event.

The successor changes no source, Candidate-A, projection, product, replay, runtime, workload, comparison, I05, I08, population, or weight meaning. It does not authorize Candidate B, WVS, arbitrary caches, historical stage reruns, measured P2X, old telemetry credit, or mutation of T2 evidence.

The old carrier remains historical semantic/equality-replay evidence only where otherwise lawful. It is not current source-free parentage evidence and contributes zero numeric credit. The new build is current EXECUTED_NOW work and cannot be double-counted with the old carrier.
