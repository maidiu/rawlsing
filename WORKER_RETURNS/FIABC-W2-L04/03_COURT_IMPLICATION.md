# FIABC-W2-L04 — Court Implication

## 1. Exact contract proved

Route C has two distinct layers that must not be collapsed.

First is the mandatory semantic spine: exact source -> governed source-specific projection -> source-backed C11 -> unchanged exact I03/I05 -> exact replay/provenance.

Second is candidate-owned physical acceleration. The accepted concrete C implementation contains exactly CACC1 and CACC2. They are nonauthoritative, deletable, regenerable, and LiTS-specific. Their absence or inapplicability cannot create a new semantic negative state because the accepted owner explicitly denies them authority over semantic truth, candidate reachability, terminal state, or learned product identity.

That separation answers both ownership questions:

- truth owner: candidate-neutral source/semantic/PRE553 authorities;
- realization-cost owner: Candidate C for whatever exact-source access, accelerator build/read/delete/regeneration, and common-engine execution its frozen policy actually performs.

A source-backed fallback therefore does not give C semantically pre-solved work. It is the base physical path of the hybrid policy.

## 2. Why zero-accelerator execution is already lawful Candidate C

The original AS3R2/AS4 authorization is stronger than a mere statement that caches are optional. Route C was required to execute an accelerator-present state, then delete all accelerators, start fresh, execute exact cacheless, regenerate, and execute again while preserving exact truth/capability/replay identity.

Thus exact cacheless source-backed execution is already inside the accepted Route-C state machine. It is not a new Route B substitution.

The later owner registry preserves the same distinction: C's mandatory semantic core is exact source plus governed projection into source-backed C11 and unchanged I03/I05; its CACC artifacts have no authority role.

## 3. LiTS-C q310/q311

The frozen CACC implementation was designed for the older LiTS q301 surface. CACC1 stores q301_2, q301_7, five frozen coordinate values and q301 risk membership. CACC2 binds 19 frozen q301 roles.

The current LiTS runtime expands the empirical grammar with F02 q310/q311 predicates. P2X currently stops Candidate C at S02 because the CACC1 stream cannot reach those fields.

That stop is mechanically truthful about the current implementation, but its interpretation must be narrower:

- the CACC physical representation does not cover q310/q311;
- the current backend has not bound the lawful zero-accelerator/source-backed Route-C state to the expanded workload;
- no evidence authorizes dropping q310/q311, synthesizing new CACC fields, creating CACC3, or changing shared I03/I05;
- therefore the candidate-level nonqualification is AUTHORITY_EXISTS_RUNTIME_INTEGRATION_MISSING, while the accelerator itself has a lawful scope ceiling.

The repair shape is deliberately not specified here. L04 proves the contract boundary only.

## 4. WVS-C

WVS makes the distinction even sharper.

The current P2 constitution deliberately requires WVS7 as a proving source while freezing the CACC implementation as LiTS-only. It forbids a WVS-specific accelerator and says the WVS C cell must resolve without redesign.

Joining that law to the older AS4 cacheless requirement resolves the fork: Candidate C can lawfully execute with zero applicable accelerators through the common exact-source semantic core, provided the WVS source/projection/runtime authority is otherwise closed.

R6S has since closed the common WVS projection/runtime path for A/B, but the current backend still has no Candidate-C binding and simply stops WVS-C. That is runtime integration debt. It is not evidence that WVS lies outside Candidate C's policy scope.

No WVS CACC should be created.

## 5. Does this make A/B/C ill-posed?

No at the constitutional level.

The independent variable is the physical persistence/reuse policy under invariant semantic work. A hybrid policy can lawfully degenerate to its source-backed base path where none of its optional accelerators apply. On WVS, and potentially on portions of the expanded LiTS workload, C may therefore perform the same physical work as B. That means the cell has little or no B-v-C treatment contrast; it does not make the semantic court invalid. It is itself portability evidence about the frozen C policy.

What is invalid today is treating the current executable P2X state as a completed three-way equal-work result. C never reaches the common output on LiTS-current or WVS, so no current C performance or parity result exists.

Before a measured result can be dispositive, the court must execute the already-lawful Candidate-C fallback as Candidate C, preserve the full source-local workload, and account its candidate-local work symmetrically. That implementation task belongs to later HQ fan-in, not this worker.
