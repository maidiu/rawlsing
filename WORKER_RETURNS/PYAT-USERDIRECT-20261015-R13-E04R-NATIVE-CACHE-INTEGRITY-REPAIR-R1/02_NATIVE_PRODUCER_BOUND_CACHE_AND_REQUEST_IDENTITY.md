# Native owner record and cache request identity

E04N's original cache-hit return deep-copied an unchecked dictionary. E04R retains the interface while treating that dictionary as an untrusted projection. It changes one product file inside this new return and leaves accepted owners untouched.

`_AcceptedOwnerEntry` is a frozen dataclass whose descendants are immutable strings, tuples, integers and bytes. It is created only after actual owner production and F8 evaluation. Its `projection` stores the complete original result, including all numerator/denominator/minority cells, fractions, geometry, typed state, exact source/release/risk/target and ordered conditioners, permission root, witness/query/fact/evidence refs, model, authority/provenance refs and content hash. Its `native_owner_material` independently retains the original composition identity, full I03 facts, complete evidence fields, full producer query, condition-witness ref, source/request identity and actual F8 material. These bytes are captured from the actual Python owner results, never read from the public cache or accepted from a request.

At each hit, the current source/role/permission binding must equal its initial identity. The actual repository must still resolve the same immutable accepted C11 release object. The entry must have a private native-produced record for this exact target and ordered value bindings. Canonical serialization of the entire public projection must equal the stored original bytes; comparing a locally recomputed hash with another attacker-controlled hash is insufficient and is never the certification check. The provider then returns a fresh JSON reconstruction of trusted bytes, avoiding both cached and returned mutable descendants. All keys, including unsupported extra keys, participate in equality.

No new estimator, smoothing rule, probability channel, issuer or accepted-owner implementation is added. N10E still handles a single conditioner; existing C1 handles multiple bindings; the same concrete C1 evidence enters actual F8. Genuine ZERO_SUPPORT remains uncached and typed as before, so fabricated supported or empty projections cannot acquire an attestation. State flips to ZERO_SUPPORT from a supported original refuse.

The private record is process-local trust state under the native immutable-owner contract. It is not a cryptographic defense against arbitrary Python code replacing private attributes, monkeypatching code or using `object.__setattr__` on trusted native objects. No persisted cache loader or cross-process cache authorization is introduced. Cold services must run real owners; copying even a valid projection from another service is insufficient. Native C11 release objects and their exact records retain the accepted immutability contract.

## Selectivity and history

Corruption fails before `service.possibilities` appends any empirical read. The unchanged nonparent client may already have read legitimate structural premises; this is recorded explicitly in closure probes. Neither client records an empirical value nor emits a new product receipt after a corrupt step. A later progressive step failure cannot commit earlier empirical reads because the whole progressive list is obtained before the service read loop.

Dropping a corrupt projection regenerates that exact query via actual owners. The dedicated hostile preserves earlier immutable accepted entries by object identity, preserves the independent structural-only product and historical receipt, and verifies repaired deep-step equality. Legitimate source release intervention uses a new provider: all empirical descendants change to19/32,11/16,7/8 while native M4/M5 field products, civil feasibility and other structural alternatives stay equal. No in-place source-update or global cache flush API is added. Existing scoped permission revocation still blocks fresh reads and retains historical receipts as archival-only.
