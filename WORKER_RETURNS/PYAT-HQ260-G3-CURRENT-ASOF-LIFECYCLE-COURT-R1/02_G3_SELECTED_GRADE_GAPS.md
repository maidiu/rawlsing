# HQ260 G03 — selected grade and remaining gaps

## 1. What G3 now holds (source-free, fixture grain)

The accepted B5/C1-03R owner lifecycle is **positively confirmed** for the exact G3 demand:

- a **fixture-only** release/product can be registered, published and **selected current** through
  the owner, and currentness is reported **only** as the owner's own exact selection receipt;
- **current/as-of** answers correctly by `as_of_event_ref` **and** by `as_of_checkpoint`;
- a **fresh interpreter process** reconstructs the checkpoint and resolves the same selected current
  release and receipt;
- after a governed supersession, **historical as-of still resolves the prior exact product**, while
  the present resolves the successor;
- a determinant change produces the **exact affected set (direct + transitive) and the unchanged
  unaffected sibling**, and the invalidated product becomes `NO_CURRENT` and can never be served or
  re-selected as current;
- unknown selection, fabricated "current" receipts and staged-but-unselected releases are all typed
  fail-closed refusals, never inferred currentness.

No production code was changed and no new adapter was manufactured, because the accepted owner
already provides the route.

### Grade language

- The competent grade this court can support is **`LOCAL_SELECTED_CURRENT_ASOF_LIFECYCLE_CAPABILITY_CONFIRMED`**
  at a source-free fixture grain.
- It does **not** support `CURRENT_AS_OF_SELECTED_FIXTURE_SERVICE` as a *service* claim, because the
  service join is absent; that grade remains the **intended** target of the eventual full T1.
- It is emphatically **not** EE14 model use, source permission, issuer authority, native F7, actor/V3,
  pair authority or a temporal sign.

## 3. What must not be done next (hostile-anticipation)

- Do not present this fixture selected-current as evidence that a service consumes it.
- Do not let the fresh-process reconstruction be cited as a production restart guarantee: it proves
  the **owner's checkpoint round-trip**, not a deployed serving process.
- Do not extend this court to manufacture a second "current" by timestamp, cache residency, file
  order, semver, "latest" or a caller tag; the owner has no such API and the court asserts that.
- Do not treat the `urn:hq260:g3:fixture:` refs as authority. They are identities for a state
  machine.

## 4. Smallest next edge

1. **G1** — produce the owner-authenticated C1 producer identity/ingress (source-free), so a
   selected release/product can be bound to a *real* producer receipt rather than a fixture
   identity.
2. **Join** — a bounded court where the EE14 selected service consumes the selected current product
   through the existing serving owner, with the same current/as-of, historical replay and
   affected/unaffected invalidation behaviour proved here, and with the G4 native negatives.
3. Only then can a specific `CURRENT_AS_OF_SELECTED_FIXTURE_SERVICE` grant act be drafted, reviewed
   and (separately) adopted.
