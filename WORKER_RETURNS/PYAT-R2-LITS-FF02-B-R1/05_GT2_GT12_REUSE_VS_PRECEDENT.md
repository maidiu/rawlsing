# GT2 / GT12 reuse versus precedent classification

## Reusable current implementation

### Exact empirical-object consumption

Current code can consume exact `EmpiricalFact`, `EmpiricalQuerySpec`, `EmpiricalPredicate` and authority refs directly. GT12's repo-native current-payload bridge proves direct reconstruction/validation from exact committed material, and the final LiTS checkpoint v3 now preserves complete exact current object preimages source-free.

This is reusable implementation law:

- identity is exact-ref/content-hash based;
- query/fact/predicate substitution fails;
- risk/universe/provenance/authority/replay closure must be exact;
- no compact historical ASTRA product is required.

### Actor-independent semantic ownership

The current GT2 relation object keeps:

`FIELD_FORGE_ACTOR_INDEPENDENT_RELATION_OWNER`

separate from:

`PREV3_FIELD_FORGE_RELATION_ADMISSION_OWNER`.

That separation is reusable and required by adopted R2 producer-ownership law.

### Relation/admission conservation envelope

The following fields are reusable implementation capital:

- exact relation ref + content hash;
- relation rule identity;
- participant role/order/cardinality identities;
- native scope;
- source universe;
- risk set;
- relation authority/current-selection refs;
- producer dependency/provenance/replay refs;
- target-use permission ceiling;
- estimand/weight/comparability authority refs where required;
- typed negative/denial/noncomparability refs;
- reference-preserving information-loss declaration;
- deterministic replay.

### Typed refusal conservation

Nonpositive upstream state does not acquire positive permissions. This is reusable.

### Admitted-relation M1 preparation envelope

`m1_admitted_field_forge_relation_v554_ingress.py` accepts exact PRE553 `ExactRef` and `AuthorityRef` objects losslessly and is not relation-family locked in its projection schema. The physically present F07 second-canary code demonstrates a second relation family can be shaped into this envelope without reusing the GT2 relation family or GT2 admission authority.

Under HQD-112 this is **compatibility/current implementation capital**, not a mandate to restore numbered V554/V557/V558 topology.

## Canary-specific implementation — do not reuse semantically

### `field_forge_conditional_support.py`

Frozen to:

- Afrobarometer R5;
- Q86B CONDITIONER;
- Q86A TARGET;
- two-target exact conditional support;
- one exact universe;
- RAW/unweighted;
- complete Q86B x Q86A state domain;
- identity-only state ordering;
- no causal/pressure/mechanism semantics.

LiTS facts cannot be passed into this module merely because they are EmpiricalFacts.

### `wave1_ff_prev3_relation_admission.py`

Frozen to:

- GT2 relation family;
- Afrobarometer R5 source hash;
- exact 19,210 risk set;
- exact Q86 participant identities;
- `STRUCTURAL_MEDIATION_INPUT`;
- exact GT2 admission authority/current selection.

Its receipt shape is useful. Its rule/evaluator is not a generic LiTS admission service.

### `gt12_c_to_d_relation_bridge.py`

Accepts only the actual `ExactConditionalSupportProfile` class. It explicitly rejects EmpiricalFact/I04/duck coercion. This is an exact GT12 bridge, not a general Field Forge adapter.

### `gt12_permission_translation_authority.py`

Explicitly says it does not generalize beyond the frozen GT2 relation-specific V554 seam. It requires exact GT2 family/source/risk/participants and translates only to CONTEXT. It is proof precedent, not LiTS authority.

### GT12 downstream V554 -> V557 -> V558 -> V3

The real 19,210 vertical proves the firewall and reference-preserving downstream path at its exact adopted grain. HQD-112 means this numbered topology must not be resurrected as a mandatory FF02 output route.

## Proof precedent only

The current adopted GT12 result proves that a real populated actor-independent Field Forge relation can:

- retain exact empirical ancestry;
- receive separate PREV3 admission;
- be constrained to a narrow permission;
- reach structural context;
- produce V3 `DENY_ZERO_EFFECT`.

It does **not** prove that every LiTS relation may be interpreted as conditional support, mediation, context, or a particular PREV3 product family.

The F07 second-canary module is also precedent rather than a current live service because its hard-coded E10/D09 source-record paths are absent at the live base. It is useful evidence that the admitted-relation compatibility envelope can accept a second family, but it cannot govern FF02.
