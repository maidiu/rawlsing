# Zero-change path

## Zero-change path A — semantic refusal

If FF02-A determines that a LiTS candidate does not lawfully support a positive actor-independent relation at the requested grain, HQ may bank the exact typed refusal/negative authority result without changing production code.

The current system already has the vocabulary and downstream conservation law to keep such a result nonpositive:

- VALID_EMPTY;
- OUT_OF_SCOPE / UNDEFINED_FOR_OBJECT;
- DENIED;
- MISSING_AUTHORITY / UNRESOLVED;
- NONCOMPARABLE / NO_TRANSPORT;
- BLOCKED_EXPLICIT_AUTHORITY;
- OBSERVABILITY_LIMIT;
- INTEGRITY_FAILURE;
- NO_GEOMETRY_REQUIRED;
- MISSING_ROLE_AUTHORITY;
- exact negative/refusal refs.

No positive relation object, positive PREV3 admission, mediation token or downstream structural object is required.

## Zero-change path B — empirical inspection/replay

FF02 can source-free inspect and exact-reinstantiate current LiTS:

- facts;
- query specs;
- predicates;
- authority snapshots;
- discovery receipts/authority;
- universe;
- risk/provenance/replay closure.

This requires no raw source and no code changes.

## Zero-change path C — existing GT2 canary replay

Existing GT2/GT12 relation/admission artifacts may be replayed under their frozen exact authority with current code. This is not a LiTS path.

## No zero-change positive LiTS relation path

If FF02-A admits a **new positive LiTS relation family**, current code cannot lawfully produce and admit it unchanged:

- the only live positive relation producer is GT2-specific;
- the only live generic-looking PREV3 relation evaluator is GT2-specific;
- the F07 second-family implementation is claim-specific and its live data dependencies are absent;
- the M1 relation compatibility seam hardcodes a mediation-named target use.

Therefore:

`NEW_POSITIVE_LITS_RELATION != ZERO_CHANGE_PATH`

The minimum next implementation, if authorized after HQ join, is the bounded claim-specific relation/admission adapter documented in `07_IMPLEMENTATION_RESIDUALS.md`.
