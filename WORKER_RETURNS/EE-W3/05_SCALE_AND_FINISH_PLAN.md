## Response-category closure in finite batches

1. Partition the 18,012 exact selected IDs by immutable source identity coordinates already carried in the current ledger (source family, release/wave, source variable identity and source-documentary root). Partitioning is organizational only; it creates no semantics.
2. For each source-documentary authority unit, perform one competent batch court over the source's explicit category/scale definitions. Reuse an existing certified response contract only when the source court explicitly establishes the exact binding.
3. Publish a governed exact binding manifest whose coverage is itself explicit: implementation ref -> response-semantics contract ref + binding ref + semantic authority ref + currentness ref + source provenance ref. No implicit expansion by label, code range, adjacency, family resemblance or frequency is allowed.
4. Feed every positive row through the EE-W3 objectizer. Rows with absent/conflicting documentary meaning remain typed class D; rows that receive exact accepted bindings become objectizable without further semantic judgment.
5. Replay and hash every emitted object/ref; join the resulting exact refs back to the current implementation ledger.

This separates two operations that R4A correctly kept distinct: **semantic adjudication/binding** and **canonical object materialization**. The latter is now generic; only the former remains.

## Routing closure in finite batches

1. Start from the exact 159-ID R4B selection, not from question numbering or text.
2. Group only by exact source routing document/rule identity where the source itself declares common coverage.
3. Issue a competent current routing ruling that resolves each covered implementation to a supported N02-style state and exact basis/binding refs.
4. Preserve genuinely unresolved/conflicted implementations as typed D; do not coerce them to applicable, inapplicable, or outside-jurisdiction.
5. Feed positive/known states through the same content-addressed objectizer and replay.

## Finish conditions

Response semantic-capital closure for a row is complete only when its exact implementation-to-response-contract binding is current and objectized. Routing closure for a row is complete only when its accepted routing/applicability authority is no longer unresolved and the exact basis/binding is objectized. Corpus completion does not require converting relation/subjective evidence into T03 structural positions.
