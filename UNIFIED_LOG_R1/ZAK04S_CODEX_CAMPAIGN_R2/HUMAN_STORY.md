# HUMAN STORY — the real N9/N10W world path, and where F6 bounds cannot enter

The protected code has a real N9/N10W-shaped path, but it is not a national world model. It is a carefully guarded **test-only selected-world service**.

The path begins at `pre553_evidence_world_consumer.configure_evidence_world_context`. A host supplies an `EvidenceConsumerReader` for each empirical prefix. That reader is not a loose dictionary: it is bound to a signed `EvidenceRequest`/`EvidenceResult` pair with source, dataset, wave, edition, byte digest, instrument, sampled/reporting unit, risk set, predicate, target, conditions, estimand, weight/design/uncertainty, clocks, permission, model-rule hash and producer/consumer query identities. The adapter replays the reader and refuses if any of those differ from the prefix. This is the strongest positive finding: R08-style evidence is not merely named; it is checked against the actual consumer determinants.

The adapter then calls `configure_progressive_world_context`. That function requires exact N10E/C1 extensions for every prefix and a `world_empirical` envelope whose source, release, risk set, row identity and repository all match. It builds a `SelectedWorldCatalog` and two snapshots, T0 (historical) and T1 (as-of). `progressive_world_view` then composes a P41 progressive receipt and calls `consume_world_conditioned_prefixes`, which invokes the nonparent consumer. The result carries a modeled N9 world, exact N10E step cells, N10W positioned consumptions, structural routes (`training`, `civil`, `exit_constraint`) and `actor_state=NOT_TOUCHED`.

But the “world” is modeled, not observed. `SelectedWorldCatalog` publishes five fixed E04 fields (`training_access`, `training_fee`, `exit_cost`, `civil_open`, `civil_sanction`) with `epistemic_class='MODELED_NOT_OBSERVED'`, `source_root='TEST_ONLY_E04_SOURCE_ROOT'`, and `empirical_identity()` hardcodes `grade='SYNTHETIC_NOT_OBSERVED'`. The accepted test fixture calls itself `L01_SYNTHETIC`/`L01_TEST_ROWS` and explicitly says “never an original-source grant.” So the code is protected and coherent, but the actual selected source world is not there.

The F6 boundary is sharper. F6P speaks in **covered subprobability**, **uncovered target mass**, disagreement/bias bounds and `PARTIAL_IDENTIFICATION_ONLY`. The world path speaks in **integer denominator**, **raw numerator cells**, and `EXACT_SUPPORTED`. P41 requires an integer denominator greater than zero and non-empty exact cells; N112 refuses a prefix whose state is not exact. There is no field in `EvidenceResult` or `world_empirical` for F6’s uncovered mass. The old PDEV01 WP2 port speaks a third language — `native_bundle` and `native_conditional_consumer` — and holds its join. Three shapes, no bridge.

So where could F6 legitimately enter? Only through a future owner-issued world-field or evidence adapter that translates F6 covered/uncovered partial bounds into an exact-denominator/typed-field form with estimand, permission, uncertainty and as-of scope. That is not present at the protected cut. Building it here would be new architecture, which this commission forbids. An IF/OR direct route is legitimate only when a real owner defines the field; there is no compulsory serial F6→N9 chain.

The roadmap says the L01/R118 sourcefree world service is protected. That is true at the code level. It also says the native N9 producer/reader remains missing. That is also true. The two statements are compatible only when “protected” means **protected test-only sourcefree code**, not an operative selected N9 world.
