# HUMAN STORY — what the F6M machine knew, and what survives

Imagine two national surveys that each measured the same two things — say, material security and employment position — but sampled different people. No respondent appears in both. A planner wants a target-country joint distribution, not a pooled average that pretends the surveys are one sample.

The **F6M** candidate is the old computational answer to that problem. It takes each survey's own joint table, keeps the source-native table intact, and tries to build a target mixture. If some target stratum cannot be covered by an eligible source, it does not fill the hole with a zero or quietly rescale the remaining sources. It records an **uncovered target mass** and returns a **partial identification**: a covered subprobability plus lower and upper sensitivity envelopes. Only when coverage is complete does it emit a full target distribution. Its own code says the result is sourcefree/experimental and that no real-use authority has been admitted.

The first downstream reader is **F6P**. It does not recompute the mixture. It verifies the bundle hash, checks that covered plus uncovered mass equals one, refuses a “complete” distribution that still has uncovered mass, refuses a complete distribution with zero uncovered mass when the producer says there is none, detects excluded-source false-full, and returns typed states such as `PARTIAL_IDENTIFICATION`, `FALSE_FULL_COVERAGE`, `PROHIBITED_MODEL_USE`, `WEIGHT_OR_DESIGN_UNKNOWN` or `REVOKED_EVIDENCE`. That is a genuine second mind reading the first mind's numerical product. But F6P is itself a sourcefree test-only consumer; it grants no source rights, no transport permission and no actor psychology.

The **alternative producer cut** matters. An earlier copy of the same module, at `1428c2e9...`, handled an ineligible source by adding its whole target share to uncovered (`uncovered += share`). The repaired candidate at `1f1c72f8...` computes the planned source set, the eligible weight, and a proportional `missing_share`; only the truly missing planned contribution becomes uncovered. That is not cosmetic: it changes the denominator story and prevents silent renormalization onto survivors. This return pins the difference but does not declare which copy was ever the real historical runner.

Today, a protected module called `pre553_source_relations.py` contains an operation named `guard_estimand_composition`. It sounds related, and it is — but it only asks whether the semantic-equivalence, overlap and composition authorities are present and exactly bound. It returns a permission receipt. It does **not** calculate a mixture, a covered subprobability or an uncovered mass. Confusing the guard with the producer would be like confusing a signed permit with the building.

A later branch, PDEV01, tried to carry the F6M bundle into a test WP2 world port. It can construct the bundle and put its hash and conditional sidecar into a read-only envelope, but it explicitly marks the join `NO_AUTHORIZED_COMMON_WORLD_OR_RESPONDENT_JOIN` and does not install an F6M→E04 consumer. When an F6P product is substituted where the port expects a raw `native_bundle`, it fails with `KeyError: 'native_bundle'`. The branch's N9/N10W candidate imports no F6 material at all.

So the plain answer is: **the numerical partial-identification knowledge survives at the F6M source and reaches F6P as a static consumer; the protected current I07 guard preserves only permission semantics; and no selected current N9/SOROK reader is proved.** This is a scoped documentary result, not a claim that the capability is lost everywhere, and not a licence to rebuild it.
