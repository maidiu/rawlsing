## 1. Identity and reason

The historical capability built a **partial, greedy, entropy-selected tree** over one question's respondent response and a list of position indicators. It produced a diagnostic node table that recorded a root, recursively chosen split indicators and values, depth, node entropy, entropy gain, dominant answer and stop reason. It mattered because it gave the old machine a bounded answer to “which observed position categories most reduce uncertainty about this response, and what does each resulting subgroup look like?” It did **not** produce an exhaustive respondent partition, a causal model, a canonical empirical memory, or a permanent empirical ontology.

The original `T0024` case in the predecessor return established the source function, writers and bridge identity loss. This bounded tranche adds the previously uninspected **Trii/Chetiri treatment** and the **current exact/adaptive discovery** comparison. It preserves the original positive and the original boundedness negative.

## 2. Old inbound data

- **Grain:** one row per question × respondent response frame in a source/wave/country shard, before tree construction; output grain is one row per emitted tree node.
- **Inputs:** `df` with a normalized response column `response_value_normalized`, candidate position-indicator columns from `INDICATOR_FIELDS`, `question_meta` containing `question_id`, `n_respondents`, source/wave/country metadata, `max_depth` (default `3`), and `min_branch_n` (default `DEFAULT_SUPPORT_CAP`).
- **Support rule:** the effective minimum branch n is `support_threshold_from_total(question_meta["n_respondents"], support_cap=min_branch_n)`, so the nominal cap is adjusted to the question's respondent total. This is a **source-relative support gate**, not a fixed national threshold.
- **Eligibility:** an indicator is skipped if its observed (nonblank) count in the current subset is below the effective minimum; a child is skipped if its n is below the same gate. Blank indicator values are excluded from the entropy calculation by the `mask`.
- **Worked illustrative field example (not observed data):** question `Q7` has 1,000 respondents; effective minimum support 50; indicator `sex` has `female` n=520 and `male` n=480; only these two values are eligible for child recursion because the code expands `value_counts().index[:2]`; a third category `other` n=60 is observed but not expanded.

## 4. Old output and consumption

- **Output schema:** `node_id`, `parent_node_id`, `branch_depth`, `split_indicator`, `split_value`, `node_entropy`, `entropy_gain_from_parent`, `stop_reason`, `branch_type`, `dominant_response`, `dominant_response_pct`, plus question/source metadata.
- **Knowledge produced:** a bounded diagnostic description of the strongest observed entropy-reducing position splits and subgroup dominant answers. It does **not** establish that the split is the only or best partition; it does **not** enumerate minority categories beyond the top two; it does **not** preserve exact respondent membership in the node rows.
- **Historical first reader:** the V550 wave/repository writers write the table; the V550 bridge is the first static code adapter. No qualified scientific first reader was demonstrated. The predecessor correctly left the first reader `UNKNOWN/NOT_PROVED`.
- **Bridge fate:** the table is admitted to the bridge under `derived_determinicity`, but the canonical V551 v3 atom compiler admits only `answer_distribution` and `country_answer_distribution`. Therefore bridge presence is not canonical V551 consumption. The original row/category identity was already lossy at the bridge (R9 anti-join).

## 10. Plain-English summary

Old V550 took one survey question and its position indicators and grew a small greedy tree: at each node it picked the indicator with the largest entropy reduction, then followed only the two most common values, stopping at depth three or when support ran out. The resulting `recursive_branch_nodes` table described a few strong splits and dominant answers. Trii later found that this table entered only the broad `derived_determinicity` bridge lane and was excluded from canonical V551 v3, so it ruled the historical branch-cohort meaning `STRANDED`; its capability closure nonetheless kept branch-conditioned distributions, recursive forks and exact branch membership as terminal requirements, while calling the old table `LOSSY_INSUFFICIENT`/`SUPERSEDED_IMPLEMENTATION`. The Chetiri-corpus conditional-meaning synthesis went further and graded the tree `DIAGNOSTIC_ON_DEMAND`, not empirical ontology, and called for retiring the derived lane after a governed replacement. Today the closest machinery is the PRE553 exact I05 discovery plus the MX01 R2 recursive handoff: exact declared-frontier enumeration, receipt-bound child/parent persistence, and exact same-respondent membership replay. That is a real analogue of the capability class, but it is not the old entropy-selected top-two tree, and no current code reads the old table. The open question is therefore not “build the old tree again”; it is whether any actual old tree population survives and whether its exact produced topology can falsify or confirm the source-level account.
