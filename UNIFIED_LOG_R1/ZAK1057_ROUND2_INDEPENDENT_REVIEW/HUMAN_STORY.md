# HUMAN_STORY — what survived review, and the one claim that must change

This review is deliberately narrow. Three frozen round-1 returns made specific documentary claims about old and current source. I did not try to finish their historical territories. I checked the claims they actually made, against the exact commits, blobs, and lines they cited, and I ran one bounded omitted-producer/reader challenge per tract.

## 02 — the old tree was retired; the capability was not

The old V550 code really did grow a small greedy tree. At each node it measured response entropy, picked the position indicator with the largest positive entropy reduction, expanded only the two most frequent values, and stopped on depth, support, purity, no indicators, or no gain. The node identity was a descriptive path, not a replayable respondent-membership key.

The later records are equally clear. Trii D11 called the old V548 branch-cohort meaning `STRANDED` at the canonical V551 v3 seam because the table entered only the broad `derived_determinicity` lane. Trii D12 called the current artifact `LOSSY_INSUFFICIENT` but kept branch-conditioned distributions, recursive subgroup forks, and exact branch membership as terminal requirements. Trii D15 called the artifact `SUPERSEDED_IMPLEMENTATION` while selecting bounded exact plus adaptive discovery. Chetiri-corpus N011 called it `DIAGNOSTIC_ON_DEMAND` and told the broad derived lane to retire from canonical production. The Chetiri C08 crosswalk added that governed changes must trigger the smallest lawful recomputation, including recursive branch discoveries, and that retaining some compiled intermediates may be justified.

That is not a contradiction between “diagnostic” and “invalidation.” A diagnostic-on-demand artifact can still need recomputation when its inputs change; retention for replay is not promotion to canonical truth. The return already says “lifecycle/retention requirement, not canonical meaning,” but then calls it a “real tension.” The better wording is a separate lifecycle duty. This is a clarity issue, not a factual failure.

Today the exact I05 mode enumerates a declared frontier and explicitly refuses entropy/MI/Cramér's V as validation truth. The adaptive mode is order-only and marks unvisited territory as unknown, never as a global negative. The recursive handoff persists a receipt-bound branch and replays exact same-respondent membership. None of them reads the old `recursive_branch_nodes` table. One omitted current consumer, `pre553_learned_world_composition.py`, does feed a `RecursiveBranchHandoff` into C1 composition, so the handoff capability has another non-test reader; it still does not revive the old artifact. The retained historical V550 bridge still reads the table as a historical adapter, so the return’s “no current code reads the old table” should be read as “no current operational/`rawlsing_next` reader.” The 02 verdict is **ACCEPT_SCOPED_S1**.

## 03 — a real structural-admission engine, but no protected selected-QSM rule producer

The protected I04 module is real and specific. `StructuralAdmissionRule` binds the exact structural target, semantic identity, directionality/role meaning, predicate/target semantics, native scope, estimand/measure, uncertainty, negatives, and a required `TARGET_USE_PERMISSION` authority. It is not a generic target-use flag.

But the rule is caller-supplied. The only direct constructor found at the protected cut is a test fixture. No non-test protected code derives a rule from a selected F03/QSM row or version. The candidate `pre553_inherited_source_rules.py` selects and compiles source rules; it does not construct `StructuralAdmissionRule`. Candidate R157 builds a C11 projection from a configuration; it likewise does not construct the I04 rule.

The receipt side is stronger than a type-only story. `RouteObligation.from_structural_admission` is a real non-test static consumer. It requires the exact `AdmissionEvaluation` and canonical `StructuralEmpiricalAdmission` receipt, reads every authoritative route fact from the receipt, and rejects a hand-built evaluation that disagrees. Its own callers at the frozen cut are tests only. The actual issued-workload path runs I03/I05/Batch and never imports I04. Protected B49 and the source-native adapter remain test-only.

One field-name trap: `target_use_permission_refs` also appears in F07 second-canary, EE14 C1 owner-authenticated ingress, and GT12-to-M4 typed bridge. Those are parallel admission/materialization paths, not evidence that a QSM row produced an I04 rule. The 03 verdict is **ACCEPT_SCOPED_S1**, with the author’s next question correctly aimed at the exact rule constructor and selected-row provenance.

## 04 — the numbers are real; one comparison sentence is wrong

The repaired F6M candidate is a genuine partial-identification producer. It retains a covered subprobability and an explicit uncovered target mass, emits a full distribution only when coverage is complete, and otherwise refuses a false point with `PARTIAL_IDENTIFICATION_ONLY` and `NO_COMPLETE_TARGET_JOINT`. F6P really imports that producer, verifies the replay hash and conservation identity, and refuses complete-with-uncovered, null-with-zero-uncovered, excluded-source-with-zero-uncovered, and prohibited model use. That is the strongest positive edge in the tract.

The protected I07 `guard_estimand_composition` is a different thing. It checks semantic equivalence, overlap, and estimand-composition authority and returns a permission receipt. It does not calculate a mixture, a covered mass, or an uncovered mass. Calling it the numeric successor would be wrong; the return correctly does not.

The protected N9 candidate exists, but it is a synthetic 58-respondent A/B/C/Y progressive chain over N10E/C1/F8. It has no F6M import and no partial-bound shape. The current world-serving alternative — R08 signed evidence, N10E slices, P41/sourcefree-world execution, progressive conditioner prefixes — also has a different input contract and no F6 token. So a selected current F6 numeric receiver remains `NOT_PROVED`, not globally absent.

The defect is in the alternative-cut comparison. The return says the predecessor adds the whole target-stratum share to `uncovered` when a present source is ineligible. The code says something else. The predecessor computes `denom` over **eligible** sources and adds the whole share only inside `if not denom` — that is, only when **no** source is eligible. If one planned source is ineligible but another is eligible, the predecessor renormalizes the surviving weights and emits a complete distribution with zero uncovered mass. It does not charge the whole target share for the missing source.

The repair is still materially different: it computes `denom` over all **planned** sources, retains `missing_share = share * (1 - eligible_weight/denom)`, and adds that mass to `uncovered` instead of renormalizing it away. That can avoid a false-full output that F6P would reject. But the return’s trigger and mechanism sentence must be corrected in both the 00_RETURN and the case. One secondary clarification is worth making: a source with no table for a stratum is listed as excluded but does not contribute missing mass, while F6P’s false-full check treats every excluded source as a candidate for refusal. Distinguish `NO_SOURCE_STRATUM` from support-failure missing mass.

The 04 verdict is **REVISE_EXACT_DOCUMENTARY_DEFECT**, with the smallest revision confined to that comparison. The accepted F6P, I07, N9, and world-path findings stand.
