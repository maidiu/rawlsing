## 2. Dynamic task-level decision and escalation

Before each substantial task and at each return:

1. **Determine decision sensitivity:** what would break if the conclusion were wrong? Is meaning/authority/causality involved? Is this reversible and independently checkable?
2. **Estimate cognitive requirement**: mechanical deterministic, bounded technical reasoning, expert interpretation, architecture/scientific synthesis. Choose minimum safe capability; escalate when there is ambiguity or evidence contradicts the schema. This is a *risk-specific allocation*, not a boast about "intelligence."
3. **Check observability** of selected Astra model/effort, usage remaining, context pressure and next reset, session clock, native host/credential/lease. Log concrete values and their source **or `UNKNOWN`**; never fabricate a percentage or claim automatic switching.
4. **Check authorization and dispatch safety:** principal-provided model specified, existing Codex HQ route and writer lease available, immutable source cut pinned, allowed read/write paths, no protected merge, no source/rights violations, independent review path, commands, success/failure and stop conditions. Without these, **prepare a commission without claiming launch**, or do a bounded read-only task.
5. **Partition** only when the delegated slice is genuinely separable and does not hide a scientific decision. Preserve a frozen high-intelligence acceptance oracle before allowing worker to implement it.
6. **Return handling:** verify exact branch/commit, complete output, negative cases, tests, tool origin and independence; review meaning at the grade appropriate to it. Change intelligence effort upward if the return exposes hidden semantics, contradictory sources or architectural alternatives.
7. **Commit and checkpoint** the verified state, preserving partial/HOLD work. No uncommitted knowledge or unsaved handoff should survive only in context memory.

**Minimum safe commission packet:** `ROLE/OWNER; TASK_ID; MODEL=Deepseek V4.1-Flash 1017 MAX; MODE=read-only or isolated-write; EXACT_REPOSITORY; BASE_SHA; BRANCH; ALLOWED_PATHS; INPUT_SHA/HASHES; EXACT_OUTPUTS; FREEZE_ORACLE; PERMITTED_TOOLS; PROHIBITIONS; TESTS+NEGATIVES; INDEPENDENT_REVIEWER; RESOURCE_LIMIT; RETURN_SHA; EXPIRY/CHECKPOINT RULE; FAIL_CLOSED_RESULT`. ## 4. Five-hour continuity discipline — GitHub first, not a last-minute archive

Time thresholds are **relative to a *verified* local session start** (or conservative earliest credible start if not verifiable), not a claim the current conversation has a known five-hour host expiry.

1. **At start / first useful result:** verify current branch SHA and write lease. Create/retain isolated documentary work branch. Commit a durable initial plan/issue matrix immediately. Do not spend the first hours drafting one massive unsaved document.
2. **After each coherent artifact:** commit source and findings immediately, independently of estimated token usage. Target **every 20–30 minutes at maximum** of genuine work without a saved state; sooner for decision-changing evidence. Use immutable SHA and readback.
3. **At nominal T+3 hours:** begin final synthesis and currentness audit; avoid launching new long unbounded investigations. Commit hypotheses, code maps, empirical holds and dissenting alternatives so a successor can recover them even if the model vanishes.
4. **At nominal T+4 hours:** freeze all main content that is already defensible; open/update draft PR and prepare exact handoff, even if answer incomplete. Stop adding new dependency chains without conservative finish evidence.
5. **By nominal T+4h15m:** publish final progress, review/test/source-grade matrix and current HEAD; ensure handoff and commission returns are GitHub-resident. Protect a **45-minute or greater reserve** before the stated nominal five-hour limit.
6. **At T+4h30m or earlier if host signals expiry/quota pressure:** do no new research or nonessential tool work. Verify branch/PR/current file readback and record `INCOMPLETE/HELD` accurately, preserving independent returns and obligations. The reserve exists because uploads and GitHub commits can fail or require CAS recheck.
7. **If session began earlier, remaining duration is unknown or a quota interrupt is imminent:** skip to immediate checkpoint and handoff; never sacrifice a committed partial result for an ideal final answer. A commit may take longer than expected; keep an additional local file copy when GitHub unavailable, label GitHub persistence **UNVERIFIED**, and never fabricate a commit.
8. **If no native switching/commission tools or no remaining credits:** do only the work possible with available capability, make the GitHub state exact, issue a bounded continuation packet. No unattended continuation claim.

**The 5-hour rule is a hard *operational persistence target*, not permission for unsafe autonomous account/model changes or premature merges.** The only acceptable completed handoff names exact GitHub branch, HEAD, PR, files, test grades, source/science/actor holds, current budget observations and next owned work.
