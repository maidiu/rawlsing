# 06 — MULCH AS METHOD, THEORY, CODE, RECIPROCAL LIFE

**MULCH is not "summarize and connect", UI polish, an endless historical inventory, a toy runnable proof, a single synthesis document, an abstract process of finding better metaphors, or a cycle of committee approvals.** It is an immanent transformation: contradictory historically developed conceptual and computational arrangements become a more adequate operative causal process through material code, and the code's failures change the theory in return.

### Theory-MULCH

Start with the actual social-material phenomenon: persons historically formed by body, need, institutions, class, care, labor, objects, projects, culture, Other people and differing practical possibilities. Reconstruct contending source arguments in their strongest form; identify what each already explains, what it cannot explain, whose experience remains invisible and what social structure produces its limits. Trace original user design intention and later correction, do not mistake dated conceptual "law" for protected status. Name an irreducible positive contradiction rather than a list of recommended APIs.

Examples: care can become a means of cruelty without having ceased to be care; repression can form an indirect historically operative source; actor belief and material harm diverge; two icebergs do not negotiate with full self-conscious control; "time offscreen" can be real developmental material, not compressed narration; one past event can be reinterpreted without being rewritten; person and relation co-constitute without exhaustively defining each other.

Theory return is **a transformed positive causal conception** and a specific falsifier, not a long pile of philosophy with no construction.

### Code-MULCH

Locate **exact existing producer/consumer and historical variant** before claiming absence. Read SOROKUDA, functional inventory, original owner/test. Reuse, extend, selectively transplant legitimate old functions. Preserve old negative examples. Build connected capability into existing organism owners: actual world/input → lived sign → recruitment and compose → world-owned consequence → personal afterlife → future activity. Temporary sourcefree models may be provisional and imperfect, but do not pretend they're empirically authorized. A new Python module only reporting an interpretation is insufficient if that interpretation should condition later action.

Code return is **substantial source diff** + genuine end-to-end first consumer + source SHA and executed tests, along with actual inherited no-drop constraints. New LLM outputs must enter original qualified developmental owner, not narrator-only scratch text.

### FUSED MULCH (the essential third motion)

Theory **causes new operations to be built**; running those operations reveals what theory got wrong; a stronger positive theory arises; original code changes again. Each pass should preserve actual improved prior functionality, not conclude at a test counter. Record the "code challenged theory" result, not merely "we added cases."

R23 materialized a conceptual relational topology into operative APPROACH/WITHHOLD under a lived Other and acquired operation. Code still required an already acquired relation and specific cues → forced R24 to address qualified historically different institutional experiences → R25 recurrent labor across episodes; new code exposed how shallow a three-event proxy remains against years of class/social reproduction. **This is the proper momentum.** Unexecuted R23–R25 still need their actual source-local court; a conceptual advance is not test pass.

### RED/first faults and REMONT

The builder owns first execution faults, direct fixture errors and source repair. Qualified independent REMONT investigates independent consequential defects only after actual first-consumer evidence. The previous policy of broadly "send to REMONT" caused parallel repair projects to displace the growth of the organism. Do NOT revert to that. Independent review is later and scoped; paired PROGRAMMA receiving remains required. A few narrowly verified errors do not justify freezing the entire construction until everything is scientifically calibrated.

### Every serious return must say

What changed in the **positive conception**? What actual original source and function were reused? Which previous limitation/contradiction was transformed? What did the new code **actually run and prove**? What did code force theory to revise? Which previous valid function is preserved? What still fails? What is the next richer function to build now? Does it advance the whole embodied person, not only one psychometric category?

### What to avoid

No universal emotion scale, work ethic/class/religious destiny, ideology trope, LLM puppet, omniscient narrator, prompted Nadia substituted for actual psyche, deterministic relationship score, attrition to "validated mini-modules" without integration, science-first perfectionism, grand theories without code, whole-repository forensic archaeology without G4/SOROKUDA source-local need, or permanent competing implementations. **The full organism is the program.** No isolated demonstration constitutes a human person; equally no perfect science should be demanded before building a functioning approximation.
