# Architecture Pass Law — Whole Picture, Bounded Jurisdiction

**Authority:** Vozhd Dva whole-system architecture method  
**Applies to:** every maximal architecture or terminal-demand recalibration pass from V553 through V2/app.

## Core law

Every architecture worker designs **one bounded organ of the complete Rawlsing system**.

The worker must see the whole finished system deeply enough to prevent local architecture from starving later capabilities. That whole-system visibility does **not** authorize the worker to move later semantics into the current stage.

The governing equation is:

`WHOLE TERMINAL DEMAND`
`+ CUMULATIVE LAWFUL UPSTREAM MATERIAL`
`- WHAT LATER STAGES CAN REUSE DIRECTLY FROM EARLIER AUTHORITY`
`- WHAT DOWNSTREAM STAGES THEMSELVES OWN`
`= CURRENT STAGE'S BOUNDED ARCHITECTURAL OBLIGATION`

Then:

`BOUNDED STAGE OBLIGATION`
`→ minimum sufficient internal architecture`
`→ exact new semantic outputs + preserved references + negative authority + boundary objects`
`→ proof that immediate and terminal downstream capabilities are not starved`

## Four simultaneous views

Every worker must reason with all four views at once:

1. **Whole-system destination** — the complete Rawlsing terminal demand described in `TERMINAL_DEMAND_ENVELOPE.md`.
2. **Cumulative upstream reality** — every lawful authoritative object available before this stage, not merely the immediate predecessor.
3. **Current-stage jurisdiction** — the exact new meaning this stage is allowed and required to create.
4. **All downstream consequences** — the next stage plus V556 pressure-flow, V3 developmental causality/orientation/attractors, genealogy, V2 phenomenology, and the app path as applicable.

## Mandatory disposition taxonomy

For every terminal capability, the worker must classify this stage's relationship to it as exactly one or more of:

- `OWN_AND_DERIVE_HERE` — this stage uniquely creates the required meaning.
- `PRESERVE_BY_REFERENCE` — this stage must carry an exact reference/identity/lineage because later use would otherwise be starved.
- `PROVIDE_PREREQUISITE_ONLY` — this stage creates a bounded precursor, while downstream owns the completed semantic operation.
- `DIRECT_UPSTREAM_REUSE_SUFFICIENT` — later stages should reach the earlier authoritative object directly; this stage should not duplicate it.
- `DOWNSTREAM_OWNS` — the capability belongs wholly to a later stage; current architecture must avoid pre-instantiating it.
- `MISSING_AUTHORITY` — the terminal need is real, but available governed material cannot lawfully support it.
- `IRRELEVANT_TO_THIS_STAGE` — no current-stage contribution or preservation obligation exists.

No terminal capability may remain implicit or unclassified in a maximal architecture return.

## No-starvation and no-bloat tests

For every proposed primary semantic family, component, or boundary family:

1. identify at least one immediate or terminal capability that would fail, become ambiguous, or require illicit invention if the object were absent;
2. state why lawful direct reuse of an earlier authoritative object cannot satisfy the same need;
3. state why the meaning does not belong to a later stage instead.

If the worker cannot answer all three, the object should normally be removed, demoted, or left as diagnostic/compatibility rather than promoted into canonical architecture.

Conversely, for every terminal capability assigned `PRESERVE_BY_REFERENCE` or `PROVIDE_PREREQUISITE_ONLY`, identify the exact current-stage object/reference slot that prevents starvation.

## Whole-picture awareness must not become semantic leakage

The worker may understand later actor dynamics in detail in order to design the correct precursor. It may not use that knowledge to assert later facts early.

Examples:

- V554 may know V3 eventually forms orientation-to-strata, but V554 may only preserve the structural positions/relations and create its own bounded eligibility/constraint meaning.
- V555 may know a child's actual household history will matter, but V555 may create only structural mediation possibilities/conditions, not an actual parent belief or childhood event.
- V556 may know Enneagram-like attractors will form, but it may create only structural pressure-flow topology and attractor prerequisites, not a final actor type.
- V557/V558 may know V2 will render dialogue, but they may expose only governed runtime priors/boundaries, not source-derived dialogue.

## Direct DAG reuse remains first-class

A later stage may directly consume an earlier object when that earlier producer remains authoritative for the meaning used.

Architecture workers must never solve terminal-demand preservation by forcing all earlier material through the current stage. The preferred solution is:

- current stage creates only its unique new meaning;
- exact authoritative earlier objects remain reusable;
- current-stage outputs reference those objects where needed;
- downstream composed intake selects the right mixture.

## Required final architecture statement

Every maximal architecture result must end with a finite statement of the form:

`THIS STAGE IS RESPONSIBLE FOR:`
- exact list of meanings it uniquely derives;
- exact references/identity classes it must preserve;
- exact negative authority it must preserve/create;
- exact governed boundary objects it must publish.

`THIS STAGE IS NOT RESPONSIBLE FOR:`
- exact list of downstream meanings deliberately excluded.

`TERMINAL CAPABILITIES PROTECTED:`
- exact list and how they remain possible.

`OPEN MISSING AUTHORITY:`
- exact list of terminal needs that cannot yet be lawfully satisfied.

A maximal architecture cannot pass while any material terminal capability is left as an unstated assumption.
