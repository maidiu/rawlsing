# Strategy and Gates

## Execution model

Rawlsing will not be completed by serially perfecting V553, then V554, then V555. The execution model is **bounded verticalization**:

1. identify the minimum cross-stage semantic capabilities required by the final runtime;
2. state what each stage must preserve or add for those capabilities;
3. carry representative fixtures through V553→V558;
4. repair the chain wherever information is lost or semantics are underspecified;
5. qualify the resulting path horizontally across source families/waves;
6. rebuild V3/V2 against the proven V558 boundary;
7. wire the app/demo path.

The architecture pass ends once implementation can proceed safely. It is not an independent deliverable to elaborate indefinitely.

## Phase A — Cross-stage contract pass

Goal: remove downstream blindness before deep implementation.

Required outputs:
- compact capability matrix;
- stage responsibility assignments;
- five representative vertical acceptance slices;
- explicit V558→V3 information contract;
- explicit V3→V2 boundary contract;
- known-loss rules for stage transformations.

Gate A passes when these are precise enough for workers to implement without inventing downstream semantics independently.

## Phase B — Vertical semantic implementation

Goal: make representative hard cases work end-to-end through V553→V558.

Initial slices:
1. temporal persistence / drift / rupture;
2. inter-strata pressure, counter-pressure, and contradiction;
3. mediation with buffering / amplification;
4. pressure-flow and Enneagram-like attractor formation prerequisites;
5. uncertainty, absence, noncomparability, provenance, and forbidden inference.

Workers may operate concurrently, but shared schema/interface changes must be coordinated through the control room.

Gate B passes when all slices survive V553→V558 with no silent semantic loss and V558 exposes all information required by the runtime contract.

## Phase C — Horizontal qualification

Goal: prove the common semantic path generalizes beyond the reference fixtures.

Method:
- representative multi-wave families first;
- adversarial source structures next;
- full available corpus only after common defects are repaired.

Failures become concrete issues. Source-specific branching is allowed only where governed source differences genuinely require it.

Gate C passes when the downstream chain is production-worthy for the available 35-wave/9-source authority scope, with explicit BLOCKED/DEGRADED states where evidence does not permit stronger claims.

## Phase D — V3 rebuild

Goal: realize individual developmental dynamics from V558-approved structural priors.

V3 owns actor-specific temporal metabolism: orientation-to-strata, exposure, absorption/resistance, pressure-flow routing, developmental feedback, household/relationship effects, and Enneagram-like attractor formation over lived time.

V3 must not treat raw survey evidence as psyche and must not allow LLM rendering to decide causal state transitions.

Gate D passes when an actor can be instantiated and developed through a deterministic/auditable event history with attributable causal updates.

## Phase E — genealogy / household integration

Goal: implement Parent 1 → encounter → Parent 2 → relationship/household → child generation as historically and structurally constrained runtime processes, interleaved with V3 development.

Gate E passes when a child is generated from intersecting parental histories and household fields rather than demographic averaging or unconstrained narrative invention.

## Phase F — V2 rebuild and app path

Goal: make V2 the phenomenological/conversational membrane over V3 state and expose a demonstrable app path.

V2 owns expression, memory presentation, register, self-narration, voice, conversational realization, concealment/misrecognition, and symbolic language. It does not directly rewrite causal state.

Gate F passes when the app can demonstrate a coherent generated person with visible provenance/debug trace, stable runtime state, and bounded conversational rendering.

## Gate discipline

- A phase may overlap the next when interfaces are stable enough, but later work must not silently redefine earlier semantics.
- No gate passes from artifact existence or process exit code alone.
- Cross-stage consumer needs must be tested before calling a producer complete.
- Any architectural expansion must identify the concrete gate or vertical slice it unblocks.
