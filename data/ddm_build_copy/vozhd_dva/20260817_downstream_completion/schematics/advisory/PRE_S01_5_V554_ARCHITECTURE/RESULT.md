# 1. Architecture conclusion

**[PROVISIONAL_FROM_PRE_S01_V554] [SAFE_TO_SPECIFY_NOW]**

The provisional peak V554 is a **narrow, reference-composed structural-affordance compiler**. It should not become a second structural-pressure stage, a temporal summarizer, a mediation-route engine, or a proto-persona generator. Its unique semantic operation is to decide, under an explicit V554 rule and fail-closed authority precedence, whether a lawfully identified upstream structural condition may enter V555 as a **bounded structural mediation input**, with exact source references, explicit unresolved structural requirements, typed negative authority, and no actor instantiation.

The completed DAG should therefore read:

`original governed upstream meanings`
`+ exact V553 temporal meanings only when temporal reasoning is required`
`+ V554 rule authority`
`→ bounded downstream-use affordance / requirement / limit objects`
`→ thin exact-reference V555 handoff`

V554 does **not** need V553 to republish V552 pressure values, V552J permission, or earlier semantic/directionality/position authority. Those remain directly reusable under their original ownership. Conversely, V554 may not reconstruct temporal identity from an aggregate or infer a temporal contradiction because multiple waves exist.

**[STABLE_FROM_ACCEPTED_UPSTREAM_LAW] [SAFE_TO_SPECIFY_NOW]** V552 remains the owner of empirical structural-pressure value, measurement status, observed-zero state, decomposition and factual provenance. V552J remains the owner of packet↔fact association, admission/use permission, blockers and lineage. Earlier governed surfaces retain semantic/directionality/position/use authority. V553 owns exact governed multi-wave temporal identity and relations. V554 can reference all of them but cannot overwrite their meanings.

**[REQUIRES_BINDING_S01_ADJUDICATION] [SAFE_TO_SPECIFY_NOW]** The recommended canonical name for the stage's positive object is `BOUNDED_STRUCTURAL_AFFORDANCE`, retiring “persona seed” from primary semantic vocabulary. A compatibility alias may survive temporarily, but the primary contract should say what the object actually is.

## 1.1 Delta from PRE-S01

This build-out **strengthens** PRE-S01 by specifying seven internal components, five semantic object families, exact row-grain principles, state precedence, a seven-artifact publication target, an eighteen-gate completion court and five finite implementation packets.

It **narrows** PRE-S01 in three places. First, “reviewable” is treated as metadata or an unresolved authority condition, not as an affirmative permission state. Second, contradiction/competition is an optional, explicitly governed relation family and defaults to valid-empty/disabled if no rule exists. Third, no V554-specific numeric seed strength/confidence/certifiability score is part of the canonical semantic contract absent a separately governed formula with a named interpretation.

It **rejects** the current architecture's hardcoded demographic/regional slices, universal mediation slots, country-year synthetic identities, aggregate-first temporal construction, interpolation dependency, fixed low blocker scores and wave-pair-equals-contradiction logic as primary V554 semantics.

# 2. Exact semantic jurisdiction

## 2.1 Formal responsibility

**[PROVISIONAL_FROM_PRE_S01_V554] [SAFE_TO_SPECIFY_NOW]**

Let:

- `F` = an exact V552 structural fact and its producer-owned factual meaning;
- `A` = the exact V552J association/admission/use-permission envelope authorizing downstream use of `F` for the relevant scope;
- `U` = whichever earlier governed semantic/directionality/position/use authority the selected V554 rule actually requires;
- `T` = zero or more exact V553 temporal objects when the V554 rule requires temporal meaning;
- `R554` = an explicit, versioned V554 affordance-derivation rule;
- `Q` = structural requirements whose resolution is necessary either before V554 can authorize the affordance or before V555 can lawfully mediate it;
- `L` = inherited or V554-derived limits/negative authority.

Then the semantic transformation is provisionally:

`R554(F, A, U, T) → (Affordance, Requirements, Limits [, ExplicitRelation])`

subject to fail-closed precedence and exact reference integrity.

The output answers only:

> “May this exact governed structural condition serve as a V555 structural mediation input, under what structural constraints, with what unresolved requirements and what explicit limits?”

It does not answer:

- which mediation route V555 should choose;
- whether a household, parent, co-parent, child, institution or locality exists for a generated actor;
- whether an actor encountered, absorbed, resisted, transmitted or transformed a pressure;
- any memory, motive, biography, psyche, voice or attractor fact.

## 2.2 Stage ownership boundary

| Meaning | Owner | V554 action |
|---|---|---|
| measured structural pressure/value | V552 | reference; never recompute |
| structural decomposition/rollups | V552 | reference when needed |
| packet↔fact admission/use permission | V552J | enforce and preserve |
| semantic/directionality/position/use authority | earlier governed authority | reference exact authority |
| exact cross-wave key/order/change/gap/noncomparability | V553 | reference exact temporal objects |
| bounded downstream mediation-input eligibility | **V554** | create |
| unresolved structural requirement attached to that eligibility | **V554** | create when rule-grounded |
| typed V554 use limitation/prohibition | **V554** or inherited | create/preserve |
| mediation route/channel candidate | V555/S02 | must not pre-create |
| pressure-flow interaction/topology | V556/S03 | must not pre-create |
| actor/history realization | V3/later | forbidden in V554 |

**[STABLE_FROM_ACCEPTED_UPSTREAM_LAW] [SAFE_TO_SPECIFY_NOW]** A V553 temporal limit may disable one temporal use without erasing the underlying V552 fact. `TEMPORAL_NONCOMPARABLE` therefore cannot be translated into “no structural fact exists.” A separate non-temporal V554 rule may still lawfully use the original V552 fact if V552J and the applicable upstream authority allow it.

# 4. Target internal architecture — 7 components

## C1. `CanonicalInputAdmissionAndReferenceResolver`

**Status:** `STABLE_FROM_ACCEPTED_UPSTREAM_LAW` + `PROVISIONAL_ON_INTENDED_V553_TARGET`  
**Detail:** `SAFE_TO_SPECIFY_NOW`; concrete V553 field/path bindings `FINALIZE_AFTER_V553_COMPLETION`

Responsibilities:

1. verify producer manifests/schema/integrity before semantic use;
2. distinguish valid-empty publication from missing/corrupt transport;
3. resolve exact V552J association to the exact V552 fact/scope;
4. reject substitute/rematched facts;
5. resolve final SWID/source/wave/country identity;
6. resolve exact V553 handoff refs when temporal semantics are requested;
7. reject aggregate-only temporal identity;
8. return typed immutable internal object references rather than copied semantic values where possible.

Output is an internal `V554InputBundle`; it is not a public semantic family.

## C2. `SemanticInputSelectorAndAuthorityResolver`

**Status:** `PROVISIONAL_FROM_PRE_S01_V554`  
**Detail:** `SAFE_TO_SPECIFY_NOW`

Given an explicit V554 rule, select only the producer-owned meanings that rule requires. It must support two lawful modes:

- `NON_TEMPORAL_STRUCTURAL`: exact V552 fact + V552J permission + required earlier authority; no V553 object is required merely for serialization convenience.
- `TEMPORAL_STRUCTURAL`: the same original structural/permission basis plus exact V553 temporal key/observation/relation/limit refs required by the rule.

The selector applies authority precedence before derivation. It never upgrades reviewability, confidence, harmonization or file presence into authority.

## C3. `BoundedAffordanceDerivationEngine`

**Status:** `REQUIRES_BINDING_S01_ADJUDICATION`  
**Detail:** architecture slot `SAFE_TO_SPECIFY_NOW`; exact rule registry/taxonomy binding waits for S01

This is the only component that creates positive V554 semantic meaning. It applies an explicit `rule_id` + `rule_version` to an admitted input bundle and emits a `BOUNDED_STRUCTURAL_AFFORDANCE` only when the rule's applicability conditions are met.

The recommended first-tranche affordance target is deliberately narrow: `structural_mediation_input`. V554 need not invent multiple colorful seed types to be useful. If S01 later recognizes multiple lawful affordance kinds, each must have its own governed rule and required input signature.

No numeric score is emitted unless a separate governed formula is named and its interpretation is explicit. The default canonical schema contains no V554-derived strength/confidence/certifiability score.

## C4. `StructuralRequirementAndPositionConstraintResolver`

**Status:** `PROVISIONAL_FROM_PRE_S01_V554`  
**Detail:** `SAFE_TO_SPECIFY_NOW`

This component converts genuinely required but unresolved structural conditions into `STRUCTURAL_MEDIATION_REQUIREMENT` rows. It may point to an existing governed receiving-position authority; it may also state that a governed position/locality/context reference is required and unresolved.

It may never fill an unresolved slot with an actor fact. `parent`, `household`, `child`, `carrier member`, `local resident`, or similar is not a permissible generated value here. A requirement says what **kind of structural resolution** is needed, who owns that resolution, and whether its absence blocks V554 or merely makes the V555 handoff conditional.

## C5. `NegativeAuthorityAndOptionalRelationResolver`

**Status:** negative-state part `STABLE_FROM_ACCEPTED_UPSTREAM_LAW` / `PROVISIONAL_FROM_PRE_S01_V554`; relation part `REQUIRES_BINDING_S01_ADJUDICATION`  
**Detail:** `SAFE_TO_SPECIFY_NOW`

This component merges current absence, blocker and prohibition semantics into one typed `V554_LIMIT` family. It also owns the optional `AFFORDANCE_RELATION` family, but that family is **disabled/valid-empty by default** unless a governed relation rule exists.

Mere opposing values, two wave-pair records, low confidence or two distinct affordances do not create contradiction. V553 same-key temporal change also does not by itself create cross-key competition.

## C6. `V555CompositionHandoffPublisher`

**Status:** `PROVISIONAL_FROM_PRE_S01_V554`  
**Detail:** `SAFE_TO_SPECIFY_NOW`; exact V553 locator fields `FINALIZE_AFTER_V553_COMPLETION`

Publish one thin handoff row per V554 affordance that has a consumer-visible state. Handoff rows do not duplicate upstream measurements or manufacture a mediation channel. They expose:

- the V554 affordance ID/state;
- exact upstream object references needed by V555;
- requirement IDs and resolution-owner information;
- limit IDs and affected-use scope;
- optional relation IDs;
- a derived V555 use state.

V555 then composes the original referenced V552/V552J/authority/V553 objects with the V554 affordance. This prevents V554 from becoming a universal serializer.

## C7. `PublicationManifestAndCompletionCourt`

**Status:** `PROVISIONAL_FROM_PRE_S01_V554`  
**Detail:** `SAFE_TO_SPECIFY_NOW`

This component writes only the canonical artifact allowlist, schema sidecars, content/row-count/hash metadata, readiness state, and finite `V554_COMPLETE_FOR_V555` gate results. Readiness is a verdict over semantic invariants, not a score.

Valid-empty can be complete. A valid scope with zero lawful affordances should publish canonical empty tables and pass as `COMPLETE_VALID_EMPTY` if all gates succeed; it must not invent a positive row merely so downstream has data.

## 5.2 Candidate discovery

**[REQUIRES_BINDING_S01_ADJUDICATION] [SAFE_TO_SPECIFY_NOW]** V554 must not iterate “whatever files are present” and treat every row as an affordance candidate. Candidate discovery is rule-driven. A rule declares:

- eligible producer object family/families;
- exact source grain;
- target downstream use;
- required authority classes;
- whether temporal meaning is required;
- applicability predicate;
- required structural-position information;
- allowed negative-state behavior;
- any valid-empty behavior.

This makes the absence of an affordance explainable: rule non-applicability, explicit block, unresolved authority, or valid-empty input are distinct outcomes.

## 5.3 Final V553 ingress

**[PROVISIONAL_ON_INTENDED_V553_TARGET] [FINALIZE_AFTER_V553_COMPLETION]** The exact canonical V553 ingress should be the frozen `v553_v554_handoff_index` plus referenced sparse `TEMPORAL_KEY`, `TEMPORAL_OBSERVATION`, `TEMPORAL_RELATION` and `TEMPORAL_LIMIT` artifacts. The final SWID UID columns, row keys, manifest linkage, schema versions and valid-empty representation must be bound after V553 completion. The semantic rule is already fixed: temporal identity must remain exact and sparse, and the aggregate projection is never sufficient by itself.

# 6. Canonical semantic object model — 5 families

All families share these common principles:

- semantic IDs are stable across runs and do **not** include `run_id` merely for uniqueness;
- `run_id` is provenance, not semantic identity;
- IDs derive from a canonical identity payload containing exact producer refs, governed scope, semantic kind and rule version;
- source refs never point to synthetic country/year fallback IDs when exact producer IDs exist;
- list-valued refs are canonicalized in deterministic order before ID derivation;
- `created_at`, schema/compiler versions and manifest refs are provenance fields and do not define semantic identity unless the underlying referenced semantic object itself changed;
- every family carries an explicit `epistemic_class`.

**Status:** `PROVISIONAL_FROM_PRE_S01_V554`  
**Detail:** `SAFE_TO_SPECIFY_NOW`

# 7. Stable ID, lineage and provenance architecture

## 7.1 Stable semantic IDs

**[PROVISIONAL_FROM_PRE_S01_V554] [SAFE_TO_SPECIFY_NOW]**

Use a deterministic digest of a canonical identity payload. The exact helper/hash implementation can follow repository convention, but the payload law is fixed now:

`semantic_id = digest(canonical_json(identity_payload))`

where canonical JSON has stable field ordering, normalized nulls and deterministic ordering of unordered ref sets.

`run_id` must not be the identity key. Re-running the same governed semantic inputs under the same rule/version should reproduce the same semantic IDs.

### Identity payloads

- Affordance: family + affordance kind + target use + exact source fact/association refs + exact governed scope + temporal mode + exact temporal identity refs required by the rule + rule ID/version.
- Requirement: affordance ID + requirement kind + required structural dimension/scope + resolution owner + rule ID/version.
- Limit: subject ID + limit type + affected use + exact authority ref(s) + rule/version where V554-derived.
- Relation: canonical ordered member-ID set + relation type + exact scope + authority/rule refs.
- Handoff: affordance ID + target consumer/use + handoff contract version; upstream semantic values do not get copied into identity again.

## 7.2 Typed reference envelope

Every cross-stage reference should resolve conceptually to:

- `producer_layer`
- `object_family`
- `object_id`
- `producer_run_id`
- `artifact_path`
- `producer_manifest_ref/hash`
- `schema_version`

Central refs such as `source_v552_fact_id` remain first-class columns for joins. Multiplicity can be represented in canonical JSON/list columns so long as ordering is deterministic and schema validation is strict.

## 7.3 Provenance invariants

1. V554 provenance points back to original meaning owners; it does not replace them with `source_authority_lanes = ["v553_readiness"]`.
2. A V553 temporal observation ref must still lead to the exact V552 fact and V552J association that authorized it.
3. V554 may denormalize producer IDs for join efficiency, but denormalized values must be equality-checked against the canonical referenced object.
4. Aggregate projection membership may be logged diagnostically but cannot stand in for exact sparse temporal refs.
5. Every V554-derived semantic row names the exact `rule_id` and `rule_version` that created it.
6. Manifest hashes and schema versions are completion-court evidence, not semantic authority.

# 8. Affordance state model and lifecycle

## 8.1 Canonical states

**[PROVISIONAL_FROM_PRE_S01_V554] [SAFE_TO_SPECIFY_NOW]**

- `ELIGIBLE`: all V554-owned authority/preconditions for the target use are satisfied; no blocking limit applies.
- `CONDITIONAL`: V554 may lawfully expose the affordance to V555, but one or more explicitly named V555-owned structural requirements remain unresolved.
- `UNRESOLVED`: V554 itself lacks authority required to decide eligibility; V555 may receive the row only as non-positive context if the handoff contract permits, never as an allowed route source.
- `BLOCKED`: explicit negative authority forbids the target V555 use.

`REVIEWABLE` is not a state. Review metadata may explain why authority is unresolved, but reviewability does not create permission.

`NOT_APPLICABLE` is an evaluation outcome before semantic-object materialization. It should be recorded in a diagnostic decision audit if useful, rather than generating a fake affordance row.

## 8.2 State lifecycle

1. Rule identifies a candidate exact input bundle.
2. C1 verifies object/manifest/ref integrity.
3. C2 evaluates original producer permissions and required authority.
4. If the rule is temporal, exact V553 refs are resolved and temporal limits applied.
5. C3 evaluates rule applicability without numeric heuristic substitution.
6. C4 creates rule-grounded requirements and classifies their resolution owner.
7. C5 attaches inherited and V554-derived limits.
8. State is derived under precedence.
9. C6 derives the V555 handoff state.
10. C7 validates publication invariants.

A later run does not mutate an old row in place. New upstream semantic objects, authority decisions or rule versions produce a new publication with deterministic IDs appropriate to the changed identity payload.

## 8.3 State-to-handoff mapping

| Affordance state | V555 handoff | Allowed structural use? |
|---|---|---:|
| `ELIGIBLE` | `AVAILABLE` | yes |
| `CONDITIONAL` | `AVAILABLE_WITH_REQUIREMENTS` | yes, only as conditional structural input |
| `UNRESOLVED` | `UNRESOLVED` | no positive use |
| `BLOCKED` | `BLOCKED` | no |

V555 must still read the attached requirement/limit objects. `allowed_v555_structural_use = true` never means a route occurred or an actor occupies any position.

# 9. Structural source, receiving position and unresolved requirements

**[PROVISIONAL_FROM_PRE_S01_V554] [SAFE_TO_SPECIFY_NOW]**

The architecture distinguishes three things that current V554 tends to blur:

1. **structural source anchor** — the exact V552 fact/scope and any governed source-position refs;
2. **receiving-position constraint** — an existing governed structural position/conditioning object that bounds later mediation;
3. **unresolved receiving-position requirement** — a statement that such authority is required but unavailable at V554.

A receiving-position constraint is not a person. For example, a governed upstream position authority might establish an age stratum, locality scope, institutionally exposed class or other structural category. V554 may reference that category. It cannot say that a generated person is a member of it.

If a rule requires household context but no governed household-position authority exists, V554 creates a requirement with `required_dimension_kind = HOUSEHOLD_CONTEXT`, `requirement_state = REQUIRED_UNRESOLVED`, and a resolution owner. It does not synthesize `household_pending`, a weak household seed, or an actor household.

S01 must decide the exact allowed requirement taxonomy and which upstream position-authority families are canonical for each requirement kind. Until then, the architecture reserves the typed slot without creating universal demographic/household requirements.
