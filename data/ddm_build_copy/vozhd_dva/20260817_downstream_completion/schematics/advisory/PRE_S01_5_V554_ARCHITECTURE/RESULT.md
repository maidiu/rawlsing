# 1. Architecture conclusion

**[PROVISIONAL_FROM_PRE_S01_V554] [SAFE_TO_SPECIFY_NOW]**

The provisional peak V554 is a **narrow, reference-composed structural-affordance compiler**. It should not become a second structural-pressure stage, a temporal summarizer, a mediation-route engine, or a proto-persona generator. Its unique semantic operation is to decide, under an explicit V554 rule and fail-closed authority precedence, whether a lawfully identified upstream structural condition may enter V555 as a **bounded structural mediation input**, with exact source references, explicit unresolved structural requirements, typed semantic/use limits, and no actor instantiation.

The completed DAG should therefore read:

`original governed upstream meanings`
`+ exact V553 temporal meanings only when temporal reasoning is required`
`+ V554 rule authority`
`→ bounded downstream-use affordance / requirement / semantic-limit objects`
`→ governed thin exact-reference V554→V555 boundary handoff`

V554 does **not** need V553 to republish V552 pressure values, V552J permission, or earlier semantic/directionality/position authority. Those remain directly reusable under their original ownership. Conversely, V554 may not reconstruct temporal identity from an aggregate or infer a temporal contradiction because multiple waves exist.

**[STABLE_FROM_ACCEPTED_UPSTREAM_LAW] [SAFE_TO_SPECIFY_NOW]** V552 remains the owner of empirical structural-pressure value, measurement status, observed-zero state, decomposition and factual provenance. V552J remains the owner of packet↔fact association, admission/use permission, blockers and lineage. Earlier governed surfaces retain semantic/directionality/position/use authority. V553 owns exact governed multi-wave temporal identity and relations. V554 can reference all of them but cannot overwrite their meanings.

**[REQUIRES_BINDING_S01_ADJUDICATION] [SAFE_TO_SPECIFY_NOW]** The recommended canonical name for the stage's positive semantic object is `BOUNDED_STRUCTURAL_AFFORDANCE`, retiring “persona seed” from primary semantic vocabulary. A compatibility alias may survive temporarily, but the primary contract should say what the object actually is.

## 1.1 Delta from PRE-S01

This build-out **strengthens** PRE-S01 by specifying seven internal components, four semantic object families plus one governed V554→V555 boundary family, exact row-grain principles, state precedence, a seven-artifact publication target, an eighteen-gate completion court and five finite implementation packets.

It **narrows** PRE-S01 in six places. First, “reviewable” is metadata or an unresolved authority condition, not an affirmative permission state. Second, contradiction/competition is an optional, explicitly governed relation family and defaults to valid-empty/disabled if no rule exists. Third, no V554-specific numeric seed strength/confidence/certifiability score is part of the canonical semantic contract absent a separately governed formula with a named interpretation. Fourth, `V554_LIMIT` contains only downstream-meaningful semantic/use limits that may lawfully exist in a valid publication; admission, integrity and forbidden-construction failures are completion-court/audit codes and never canonical semantic rows. Fifth, the V554→V555 handoff is a governed interface/boundary family rather than a V554 semantic meaning family. Sixth, `BOUNDED_STRUCTURAL_AFFORDANCE` is genuinely positive/conditional: only `ELIGIBLE` and `CONDITIONAL` materialize as F1 rows.

It **rejects** the current architecture's hardcoded demographic/regional slices, universal mediation slots, country-year synthetic identities, aggregate-first temporal construction, interpolation dependency, fixed low blocker scores and wave-pair-equals-contradiction logic as primary V554 semantics.

# 2. Exact semantic jurisdiction

## 2.1 Formal responsibility

**[PROVISIONAL_FROM_PRE_S01_V554] [SAFE_TO_SPECIFY_NOW]**

Let:

- `F` = an exact V552 structural fact and its producer-owned factual meaning;
- `A` = the exact V552J association/admission/use-permission envelope authorizing downstream use of `F` for the relevant scope;
- `U` = whichever earlier governed semantic/directionality/position/use authority the selected V554 rule actually requires;
- `T` = zero or more exact V553 temporal objects when the V554 rule requires temporal meaning;
- `R554` = an explicit, versioned V554 affordance-derivation rule;
- `Q` = rule-grounded structural requirements whose resolution is necessary either before V554 can materialize an affordance or before V555 can lawfully mediate it;
- `L` = inherited or V554-derived **semantic/use limits** that are valid meaning-bearing negative authority rather than build/integrity failures.

Then the semantic transformation is provisionally:

`R554(F, A, U, T) → [Positive/Conditional Affordance] + Requirements + Semantic Limits [+ ExplicitRelation]`

subject to fail-closed admission, exact reference integrity and a nonsemantic validation/completion court.

The output answers only:

> “May this exact governed structural condition serve as a V555 structural mediation input, under what structural constraints, with what unresolved requirements and what explicit semantic/use limits?”

It does not answer:

- which mediation route V555 should choose;
- whether a household, parent, co-parent, child, institution or locality exists for a generated actor;
- whether an actor encountered, absorbed, resisted, transmitted or transformed a pressure;
- any memory, motive, biography, psyche, voice or attractor fact.

A failed transport/schema/ref/integrity check does not answer this semantic question at all. It rejects construction and records a nonsemantic admission/completion failure code; it must not be converted into an authoritative F1–F4 row.

# 4. Target internal architecture — 7 components

## C1. `CanonicalInputAdmissionAndReferenceResolver`

**Status:** `STABLE_FROM_ACCEPTED_UPSTREAM_LAW` + `PROVISIONAL_ON_INTENDED_V553_TARGET`  
**Detail:** `SAFE_TO_SPECIFY_NOW`; concrete V553 field/path bindings `FINALIZE_AFTER_V553_COMPLETION`

Responsibilities:

1. verify producer manifests/schema/integrity before semantic use;
2. distinguish valid-empty publication from missing/corrupt transport;
3. resolve exact V552J association to the exact V552 fact/scope;
4. reject substitute/rematched facts;
5. resolve final SWID/source/wave/country identity;
6. resolve exact V553 handoff refs when temporal semantics are requested;
7. reject aggregate-only temporal identity;
8. return typed immutable internal object references rather than copied semantic values where possible;
9. emit only nonsemantic admission/completion failure codes when any integrity condition fails.

Output is an internal `V554InputBundle`; it is not a public semantic family. A bundle that fails integrity/admission is rejected before F1–F4 derivation. Its failure code may appear in diagnostics/readiness evidence but never as a canonical semantic row.

## C2. `SemanticInputSelectorAndAuthorityResolver`

**Status:** `PROVISIONAL_FROM_PRE_S01_V554`  
**Detail:** `SAFE_TO_SPECIFY_NOW`

Given an explicit V554 rule, select only the producer-owned meanings that rule requires. It must support two lawful modes:

- `NON_TEMPORAL_STRUCTURAL`: exact V552 fact + V552J permission + required earlier authority; no V553 object is required merely for serialization convenience.
- `TEMPORAL_STRUCTURAL`: the same original structural/permission basis plus exact V553 temporal key/observation/relation/limit refs required by the rule.

The selector applies authority precedence before derivation. It never upgrades reviewability, confidence, harmonization or file presence into authority.

A **valid negative authority state** such as V552J use denial, V553 noncomparability, or an explicit governed unresolved-authority condition may be preserved into F2/F3. A **failed validation** such as fact-association mismatch or malformed transport is not negative semantic authority and terminates semantic construction for that candidate.

## C3. `BoundedAffordanceDerivationEngine`

**Status:** `REQUIRES_BINDING_S01_ADJUDICATION`  
**Detail:** architecture slot `SAFE_TO_SPECIFY_NOW`; exact rule registry/taxonomy binding waits for S01

This is the only component that creates positive V554 semantic meaning. It applies an explicit `rule_id` + `rule_version` to an admitted input bundle and emits a `BOUNDED_STRUCTURAL_AFFORDANCE` **only** when the result is `ELIGIBLE` or lawfully `CONDITIONAL`.

`UNRESOLVED` and `BLOCKED` are candidate-decision outcomes, not F1 affordance states. Their downstream-meaningful content may be represented by F2 requirements, F3 limits and a nonpositive B1 handoff boundary row, while the evaluation itself is retained in a non-authoritative decision audit. Pure validation/integrity failures produce neither semantic rows nor a B1 consumer handoff.

`CONDITIONAL` is permitted only when every unresolved requirement that remains after V554 evaluation is explicitly owned by V555 and does not represent missing upstream/V554 authority. Missing required V554 or upstream authority can never be converted into positive permission.

The recommended first-tranche affordance target is deliberately narrow: `structural_mediation_input`. V554 need not invent multiple colorful seed types to be useful. If S01 later recognizes multiple lawful affordance kinds, each must have its own governed rule and required input signature.

No numeric score is emitted unless a separate governed formula is named and its interpretation is explicit. The default canonical schema contains no V554-derived strength/confidence/certifiability score. An attempt to emit one without authority is a completion-court failure code, not an F3 semantic limit.

## C4. `StructuralRequirementAndPositionConstraintResolver`

**Status:** `PROVISIONAL_FROM_PRE_S01_V554`  
**Detail:** `SAFE_TO_SPECIFY_NOW`

This component converts genuinely required but unresolved structural conditions into `STRUCTURAL_MEDIATION_REQUIREMENT` rows. It may point to an existing governed receiving-position authority; it may also state that a governed position/locality/context reference is required and unresolved.

It may never fill an unresolved slot with an actor fact. `parent`, `household`, `child`, `carrier member`, `local resident`, or similar is not a permissible generated value here. A requirement says what **kind of structural resolution** is needed, who owns that resolution, and whether its absence blocks V554 materialization or merely makes an otherwise lawful V555 handoff conditional.

If `resolution_owner = V555` and all V554/upstream authority needed to establish the affordance is satisfied, the requirement may support an F1 `CONDITIONAL` row. If the missing authority belongs to V554 or upstream, no positive F1 row materializes. The valid unresolved requirement and any associated F3 semantic limit may still be published when the absence itself is governed and downstream-meaningful.

# 6. Canonical object model — 4 semantic families + 1 governed boundary family

The four V554 semantic families share these common principles:

- semantic IDs are stable across runs and do **not** include `run_id` merely for uniqueness;
- `run_id` is provenance, not semantic identity;
- IDs derive from a canonical identity payload containing exact producer refs, governed scope, semantic kind and rule version;
- source refs never point to synthetic country/year fallback IDs when exact producer IDs exist;
- list-valued refs are canonicalized in deterministic order before ID derivation;
- `created_at`, schema/compiler versions and manifest refs are provenance fields and do not define semantic identity unless the underlying referenced semantic object itself changed;
- every semantic family carries an explicit `epistemic_class`;
- no validation/admission failure is promoted into a semantic family merely because the build needs to explain why construction stopped.

The B1 V554→V555 handoff is governed and canonical, but it is a boundary/interface family rather than a V554 semantic meaning family.

## F1. `BOUNDED_STRUCTURAL_AFFORDANCE`

**Status:** `PROVISIONAL_FROM_PRE_S01_V554`  
**Detail:** `SAFE_TO_SPECIFY_NOW`

### Row grain

One row per:

`V554 rule/version × exact source structural anchor × exact governed scope × target downstream use`

with exact temporal support included in the identity payload when the rule's meaning is temporal.

A row means: **this exact structural condition is positively eligible or lawfully conditionally eligible for a named downstream structural-mediation use under the attached requirements and limits.** It does not assert that any actor occupies the receiving position or traverses a mediation route.

Only two states materialize:

- `ELIGIBLE`
- `CONDITIONAL`

`UNRESOLVED` and `BLOCKED` are candidate-decision/boundary outcomes and never F1 row values.

### `CONDITIONAL` law

`CONDITIONAL` is legal only if:

# 7. Stable ID, lineage and provenance architecture

## 7.1 Stable semantic IDs

**[PROVISIONAL_FROM_PRE_S01_V554] [SAFE_TO_SPECIFY_NOW]**

Use a deterministic digest of a canonical identity payload. The exact helper/hash implementation can follow repository convention, but the payload law is fixed now:

`semantic_id = digest(canonical_json(identity_payload))`

where canonical JSON has stable field ordering, normalized nulls and deterministic ordering of unordered ref sets.

`run_id` must not be the identity key. Re-running the same governed semantic inputs under the same rule/version should reproduce the same semantic IDs.

### Identity payloads

- Affordance F1: family + affordance kind + target use + exact source fact/association refs + exact governed scope + temporal mode + exact temporal identity refs required by the rule + rule ID/version. Only positive/conditional materialized objects receive F1 IDs.
- Requirement F2: exact structural anchor/use + optional affordance ID + requirement kind + required structural dimension/scope + resolution owner + rule ID/version.
- Limit F3: exact semantic subject/use + limit type + affected use + exact negative-authority ref(s) + rule/version where V554-derived.
- Relation F4: canonical ordered F1 member-ID set + relation type + exact scope + authority/rule refs.
- Boundary B1: exact candidate/use + optional affordance ID + target consumer/use + boundary contract version.

Validation/completion failure codes are not semantic IDs and must not be hashed into F3 identities merely to make failed construction look complete.

## 7.2 Typed reference envelope

Every cross-stage reference should resolve conceptually to:

- `producer_layer`
- `object_family`
- `object_id`
- `producer_run_id`
- `artifact_path`
- `producer_manifest_ref/hash`
- `schema_version`

Central refs such as `source_v552_fact_id` remain first-class columns for joins. Multiplicity can be represented in canonical JSON/list columns so long as ordering is deterministic and schema validation is strict.

## 7.3 Provenance invariants

1. V554 provenance points back to original meaning owners; it does not replace them with `source_authority_lanes = ["v553_readiness"]`.
2. A V553 temporal observation ref must still lead to the exact V552 fact and V552J association that authorized it.
3. V554 may denormalize producer IDs for join efficiency, but denormalized values must be equality-checked against the canonical referenced object.
4. Aggregate projection membership may be logged diagnostically but cannot stand in for exact sparse temporal refs.
5. Every V554-derived semantic row names the exact `rule_id` and `rule_version` that created it.
6. Manifest hashes and schema versions are completion-court evidence, not semantic authority.
7. Failed integrity/admission attempts remain diagnostic/court evidence and do not create semantic provenance chains.

# 8. Affordance state model and lifecycle

## 8.1 F1 materialized states

**[PROVISIONAL_FROM_PRE_S01_V554] [SAFE_TO_SPECIFY_NOW]**

F1 has exactly two materialized states:

- `ELIGIBLE`: all upstream and V554-owned authority/preconditions for the target use are satisfied; no blocking semantic limit applies.
- `CONDITIONAL`: all upstream and V554-owned authority/preconditions needed to establish the affordance are satisfied, no blocking semantic limit applies, and one or more explicitly named **V555-owned** structural requirements remain unresolved under a rule that permits conditional handoff.

`REVIEWABLE` is not a state. Review metadata may explain why authority is unresolved, but reviewability does not create permission.

`UNRESOLVED`, `BLOCKED`, `NOT_APPLICABLE`, and `VALIDATION_FAILURE` are **candidate decision outcomes**, not F1 states.

## 8.2 Candidate decision outcomes

A non-authoritative decision audit may record:

- `MATERIALIZE_ELIGIBLE`
- `MATERIALIZE_CONDITIONAL`
- `REJECT_NOT_APPLICABLE`
- `REJECT_UNRESOLVED_V554_OR_UPSTREAM_AUTHORITY`
- `REJECT_BLOCKED_BY_VALID_NEGATIVE_AUTHORITY`
- `REJECT_VALIDATION_FAILURE`

Downstream-meaningful content from a valid unresolved/blocked decision may be represented semantically through F2/F3 and, if lawful for V555 to see, through a nonpositive B1 boundary row. Validation failures never become F2/F3/B1 merely for observability; they remain diagnostics/completion evidence.

## 8.3 Lifecycle

1. Rule identifies a candidate exact input bundle.
2. C1 verifies object/manifest/ref integrity. Failure → `REJECT_VALIDATION_FAILURE`; no F1–F4 or B1 rows derived from that invalid bundle.
3. C2 evaluates original producer permissions and required authority.
4. If the rule is temporal, exact V553 refs are resolved and semantic temporal limits are recognized.
5. C3 evaluates rule applicability without numeric heuristic substitution.
6. C4 creates rule-grounded requirements and classifies their resolution owner.
7. C5 attaches only semantically valid inherited/V554-derived use limits.
8. Candidate decision outcome is derived under precedence.
9. If and only if outcome is `MATERIALIZE_ELIGIBLE` or `MATERIALIZE_CONDITIONAL`, C3 materializes F1.
10. C6 derives B1 boundary state for positive/conditional F1 and any lawfully exposable valid negative context.
11. C7 validates publication invariants and writes court/audit evidence.

A later run does not mutate an old row in place. New upstream semantic objects, authority decisions or rule versions produce a new publication with deterministic IDs appropriate to the changed identity payload.

## 8.4 State-to-boundary mapping

| Candidate/F1 outcome | F1 row? | B1 handoff | Allowed structural use? |
|---|---:|---|---:|
| `ELIGIBLE` | yes | `AVAILABLE` | yes |
| `CONDITIONAL` | yes | `AVAILABLE_WITH_REQUIREMENTS` | yes, only as conditional structural input |
| valid semantic unresolved authority | no | `UNAVAILABLE_UNRESOLVED` if negative context is lawfully exposed | no |
| valid semantic use denial/block | no | `UNAVAILABLE_BLOCKED` if negative context is lawfully exposed | no |
| `NOT_APPLICABLE` | no | none | no |
| validation/integrity failure | no | none | no; completion fails as applicable |

V555 must still read the attached requirement/limit objects for B1 rows. `allowed_v555_structural_use = true` never means a route occurred or an actor occupies any position.

# 9. Structural source, receiving position and unresolved requirements

**[PROVISIONAL_FROM_PRE_S01_V554] [SAFE_TO_SPECIFY_NOW]**

The architecture distinguishes three things that current V554 tends to blur:

1. **structural source anchor** — the exact V552 fact/scope and any governed source-position refs;
2. **receiving-position constraint** — an existing governed structural position/conditioning object that bounds later mediation;
3. **unresolved receiving-position requirement** — a statement that such authority is required but unavailable at V554.

A receiving-position constraint is not a person. For example, a governed upstream position authority might establish an age stratum, locality scope, institutionally exposed class or other structural category. V554 may reference that category. It cannot say that a generated person is a member of it.

If a rule requires household context but no governed household-position authority exists, V554 may create a valid F2 requirement with `required_dimension_kind = HOUSEHOLD_CONTEXT`, `requirement_state = REQUIRED_UNRESOLVED`, and a resolution owner **only if the rule itself lawfully establishes that requirement**. It does not synthesize `household_pending`, a weak household seed, or an actor household.

If `resolution_owner = V555`, and every upstream/V554 prerequisite for positive eligibility is already satisfied, F1 may be `CONDITIONAL`. If `resolution_owner = V554` or `UPSTREAM_REPAIR`, no F1 row materializes; F2 plus any rule-grounded F3 unresolved-authority limit and nonpositive B1 boundary context carry the valid negative meaning.

S01 must decide the exact allowed requirement taxonomy and which upstream position-authority families are canonical for each requirement kind. Until then, the architecture reserves the typed slot without creating universal demographic/household requirements.

# 13. Canonical production dataflow

**[PROVISIONAL_FROM_PRE_S01_V554] [SAFE_TO_SPECIFY_NOW]**

A complete V554 run should execute the following deterministic sequence:

1. **Open run and load rule registry.** Unknown/ungoverned rule → validation failure; no semantic derivation for that candidate.
2. **Verify upstream publication manifests.** Recognize valid-empty separately from missing/corrupt. Invalid transport → admission failure, not F3.
3. **Resolve exact V552J association/admission objects.** Preserve explicit permission/semantic blocker state.
4. **Resolve exact V552 facts.** Equality-check fact/scope against V552J authorization; mismatch → validation failure, no rematch/substitution and no semantic row from the invalid bundle.
5. **Resolve rule-required earlier authority.** Semantic/directionality/position/use authority must be governed/certified for the exact scope.
6. **Resolve final SWID identity.** Use canonical source/family/wave/country IDs; fallback attempt → validation failure.
7. **If temporal rule, resolve V553 exact handoff and sparse objects.** Aggregate may be loaded only as optional diagnostic/secondary context; aggregate substitution attempt → validation failure.
8. **Recognize semantic temporal negative authority.** Preserve V553 gap/noncomparability/insufficient-authority meaning; never reconstruct interpolation.
9. **Build internal candidate input bundle.** Bundle contains typed refs and inherited statuses, not copied authority guesses.
10. **Evaluate rule applicability.** Non-applicable candidates remain diagnostic decisions, not semantic affordance rows.
11. **Resolve F2 structural requirements and their owner.** Valid governed unresolved requirements may be semantic even when F1 will not materialize.
12. **Derive/preserve F3 semantic limits only.** Admission/integrity/audit failures remain outside F3.
13. **Derive candidate decision outcome under precedence.** Distinguish positive/conditional, valid unresolved/block, not applicable, and validation failure.
14. **Materialize F1 only for `ELIGIBLE` or lawful `CONDITIONAL`.** No blocked/unresolved F1 rows; no numeric score.
15. **Optionally derive F4 relation among materialized F1 rows.** Only if governed rule enabled; otherwise valid-empty.
16. **Build B1 V555 boundary rows.** Positive/conditional rows point to F1; valid semantic blocked/unresolved context may be exposed nonpositively; validation failures produce no handoff.
17. **Write canonical allowlist + schema sidecars + run manifest.** Hash/count/version every artifact; diagnostics remain non-authoritative.
18. **Run completion court and write readiness report.** Publication is authoritative only if all required gates pass.

The semantic builder should remain in `ddm_v554_seed_contract.py` initially to minimize churn. Existing helper functions can be replaced/refactored internally around these components. `compile_v554_thin_layer.py` can remain the sole CLI but should call the canonical V554 compiler rather than maintain an independent generic thin semantic contract. `ddm_v5_thin_end_to_end.py` should eventually treat V554 as a compatibility/orchestration consumer of the canonical publication, not an alternate producer.
