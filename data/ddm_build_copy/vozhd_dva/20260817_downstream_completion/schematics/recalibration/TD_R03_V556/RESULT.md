## 4. Pressure-flow edge verdict

The V556 base graph is logically:

`G556_BASE = { r | r is a V555 STRUCTURAL_MEDIATION_ROUTE_CANDIDATE and V555_V556_HANDOFF allows structural V556 use }`.

A conditional route may enter this graph while retaining unresolved runtime-owned predicates. “Structurally usable by V556” is not “realized by an actor.”

### 4.2 No second edge identity

A canonical V556 `PressureFlowEdge` would create two semantic IDs for one route, invite divergence from V555 producer facts, pressure V556 to duplicate V554/V555 conditions and temporal lineage, and add no capability that direct reuse cannot supply. It therefore fails `ARCHITECTURE_PASS_LAW`.

A future implementation MAY materialize a non-authoritative edge projection for query performance, but it must be one-to-one keyed to the V555 route ID, reconstructible from V555, semantically removable, and forbidden from acquiring V556-created meaning.

### 4.3 Multi-hop composition requires authority

Additional hops are additional V555 routes. V556 may compose them, but endpoint adjacency/common time does not itself prove a lawful multi-hop flow. A `FLOW_CONTINUATION` assertion is a V556 F1 relation and requires an explicit rule that proves participant compatibility, roles/order, authority and condition compatibility.

**Pressure-flow edge verdict: `DIRECT_UPSTREAM_REUSE_SUFFICIENT`.**
