# Binding terminal-consumer law

## A. Repository, not one giant stage payload

The completed offline product is a stage-agnostic **StructuralPriorRepository** that retains producer-owned identity/meaning rather than collapsing everything into one synthetic semantic layer.

At minimum the repository must be capable of linking/indexing, where authorized:
- structural pressure priors / source structural facts required by runtime;
- structural-position / finite-stratum references;
- V553 temporal keys/observations/relations/limits;
- V554 affordances/applicability conditions;
- V555 routes/route conditions;
- V556 interaction relations/attractor-prerequisite topologies;
- explicit Horizon / Absolute-Horizon refs where governed;
- typed negative/missing/unresolved/denied/noncomparable authority;
- item-level epistemic class, causal-use permission, uncertainty/completeness and provenance;
- producer lineage/content hashes/version contracts;
- temporal/geographic/stratal/position indexes.

V3 must not know that an applicable prior originated in “V553” or “V556” in order to use the context contract.

## B. ContextQuery

Re-adjudicate the minimum deterministic query contract. It must support at least the equivalent of:
- repository/bundle ID;
- query time;
- location/geographic path;
- generated structural-position bindings;
- actor generation phase;
- optional household/family/relationship bindings where already generated;
- deterministic resolution-policy version.

Location may make higher-stratum priors applicable at their native stratum; it may not infer actor class/sect/party/family/household/etc.

## C. Progressive position binding

Before a generated position exists, conditioned priors remain explicitly unbound, e.g. `UNBOUND_REQUIRES_RUNTIME_POSITION` or equivalent.

After V3/genealogy generates the position, the same repository may be re-resolved and those priors may become applicable.

The repository/resolver does not invent the position.

## D. Two-phase initialization

Preserve the distinction:

**Phase A:** time/geography/generation-role/already-known environmental context, including broad structural priors and only lawfully authorized position-generation constraints if such authority exists.

**Phase B:** re-query after runtime positions exist, yielding position-specific pressures, mediation possibilities, pressure-flow topology, Horizon context and typed limits/unknowns.

Do not invent population distributions merely because Phase A would benefit from them. Missing position-generation authority remains `MISSING_AUTHORITY` outside V557/V558 unless a governed producer exists.

## E. Temporal resolution

V553 says what was actually observed/comparable and which temporal relations/limits are lawful.

The runtime resolver may select an authoritative prior object as a marked generation proxy for an unobserved query time without rewriting producer evidence time.

Re-adjudicate at least these conceptual modes:
- `DIRECT_TEMPORAL_SUPPORT`;
- `LATEST_PRIOR_OBSERVATION_PROXY`;
- `EARLIEST_POST_QUERY_PROXY`;
- `EARLIEST_POST_BIRTH_ANCHOR` as a birth-context specialization if retained;
- `NO_LAWFUL_TEMPORAL_ANCHOR`.

No interpolation by default.

Critical law:
- evidence time != runtime proxy time;
- forward proxy is generation policy, not V553 temporal authority;
- a future observation selected as a proxy remains evidence about its real period;
- resolver proxy metadata never becomes actor exposure/repetition/reinforcement history.

Adjudicate exact **proxy eligibility authority**: not every observed prior may automatically be usable as a backward/forward runtime proxy merely because it exists. Define what explicit producer/use-permission/rule state must make an object lawfully proxyable.

Adjudicate **direct temporal support** carefully: do not silently create a validity interval around a point observation. Direct support exists only where governed temporal support/validity actually includes the query time.

Adjudicate **collision/tie law**: if multiple equally authoritative candidate anchors are eligible at the same temporal rank, resolution must be deterministic without arbitrary winner selection; preserve lawful multiplicity where needed.

Adjudicate **future-derived metadata separation**: a forward proxy may be selected for generation, but later temporal relation information must not be exposed as if it were causally available to the actor at the earlier simulated time. Distinguish active resolved prior from provenance/explanatory metadata.

## F. Spatial resolution

Hierarchical applicability is not geographic imputation.

A Lebanon Nation-State prior may bear upon an actor located in Tyre as a Nation-State influence. It never becomes a Tyre-local prior.

Missing lower-level coverage remains missing.

Cross-scope relation/topology applicability must respect producer/V556 rule authority.

- query time;
- geographic path;
- generated position bindings;
- selected structural priors;
- selected structural pressures;
- temporal relations/limits needed for context;

- Horizon/AH context where governed;
- typed negative authority/unresolved states;
- selection ledger;

- next context-change time/schedule if lawfully derivable;
- resolver policy/version.

Do not make context snapshot identity depend on prose rendering.

## H. SelectionRecord / replay ledger

Every candidate prior considered for selection must be auditable through a deterministic ledger containing the equivalent of:
- semantic/prior key;
- prior ID / producer locator;
- selected/rejected/deferred decision;
- resolution mode;
- anchor/query time;
- temporal lag/proxy metadata;
- native geographic scope;
- generated-position bindings relevant to decision;
- authority/permission state;
- rejection/limit reason;
- resolver policy version.

This is required to replay context resolution and prevent “convenient row” selection.

## I. Coverage/fidelity profile

No hardcoded “1980s good / 1960s bad” cutoff.

Coverage/fidelity must derive from objective facts such as:
- counts/fractions by temporal-resolution mode;
- proxy lag distributions;
- strata/scope coverage;
- mediation/interaction/topology coverage;
- missing/noncomparable/blocked counts;
- observation density;
- unresolved runtime-position requirements.

## J. Refresh / lifecycle

A generated life is not initialized once and frozen.

Adjudicate deterministic re-resolution triggers, including where applicable:
- query time crossing an observation/support/change boundary;
- migration/location change;
- generated structural-position change;
- household/family/relationship binding change;
- other governed applicability changes.

The resolver may expose `next_context_change_time` or an equivalent deterministic schedule when derivable.
