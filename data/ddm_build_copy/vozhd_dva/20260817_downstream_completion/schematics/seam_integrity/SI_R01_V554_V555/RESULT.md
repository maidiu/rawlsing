## 5. Hostile questions — explicit rulings

### HQ1 — Did F1 + F2 + B1 lose a V555 prerequisite?

**No.** Every lawful prerequisite is either (a) V554-owned positive eligibility, (b) a V554-owned applicability/use/deferred condition, (c) exact producer-owned upstream authority reachable by reference, or (d) V555-owned route authority/route-born condition. Restoring a broader V554 family would duplicate one of those jurisdictions.

### HQ2 — Can V555 build one lawful atomic route without inventing identity/support/eligibility/position/negative authority/premise/provenance?

**Architecturally yes; present production no.** A route can be built only when exact F1/B1, inherited F2/upstream refs and an authorized V555 route rule are present. The route-rule registry is still a declared implementation blocker, so absence of that authority must produce valid-empty/denied/missing state rather than a guessed route. Present universal slots are not a lawful substitute.

### HQ3 — Is route-born condition meaning duplicated V554 F2?

**Not in the accepted architecture.** If a condition means the same thing before route creation, V555 must reference the V554 F2 ID only. V555 F2 is lawful only when mediator/channel/receiver selection creates a genuinely new route-specific predicate.

### HQ4 — Does V554 retain post-route meaning that belongs in V555?

**Accepted architecture: no. Present implementation: yes, as legacy structure.** Fixed required-mediation slots and mediation-facing score semantics prefigure route topology. They must be removed from canonical authority or quarantined as non-authoritative compatibility views.

### HQ5 — Does progressive runtime-position binding survive?

**Yes architecturally.** V554 F2 carries exact deferred runtime-position requirement identity; V555 references it and may add a route-specific requirement only if the route creates that predicate. V3 generates actor positions/relationships and causes repository re-resolution. Present legacy code needs hardening to expose this exact chain.

### HQ6 — Can family/household/parent structural requirements cross without biography?

**Yes.** They cross only as governed structural-role refs and/or deferred runtime-position/relationship requirement IDs. `parent` as a structural mediation role is not `this actor has parent X` or `father believed Y`. Actual relationship membership/history remains V3/genealogy jurisdiction.

### HQ7 — Do simultaneous affordances remain distinct?

**Accepted architecture: yes. Present implementation: no guarantee.** One F1 per V555 route and prohibition on V555 cross-pressure combination preserve distinction. Current all-seeds-to-every-slot fanout and scalar seed/readiness semantics must not survive as authority.

### HQ8 — Can later stages reach original V552/V553 authority directly?

**Yes, and they should.** Exact DAG/reference-contract reuse is preferable to copying producer meanings into each handoff. The seam must carry deterministic locators/refs sufficient for resolution; it need not carry duplicated semantic payloads.

### HQ9 — Does accepted V3 require a dropped mediation prerequisite?

**No.** V3 requires the exact V553 temporal/negative basis, V554 F1/F2, V555 route/condition identity, unresolved generated-position requirements and provenance. The accepted reference/repository architecture preserves all of these without adding a V554 semantic family.

### HQ10 — Does present V554 still emit illicit legacy seed/score/interpolation structure?

**Yes.** This is a concrete hardening requirement. Numeric seed/readiness semantics, interpolation-derived mediation authority, hardcoded slot/slice structures and related legacy views may not constrain canonical V555.

### HQ11 — Does present V555 consume one affordance per route?

**No.** It attaches all seed IDs to generic slots and truncates several register constructions to the first five seed rows. This is a concrete present producer-consumer defect and information-loss hazard.

### HQ12 — Can exact V554 applicability conditions be referenced rather than re-owned?

**Yes architecturally; present canonical implementation is absent.** Canonical V555 must carry exact inherited F2 IDs/reference contract and create no semantic duplicate.

### HQ13 — Are missing authority, denied use, unresolved generated position, noncomparability and valid eligibility distinct?

**Accepted architecture: yes. Present implementation: insufficiently.** Required distinctions are: positive F1 `ELIGIBLE`; V554/V555 typed denied use; typed missing static authority; deferred runtime/context/genealogy requirement; inherited `NONCOMPARABLE`; and construction/validation failure outside semantic negative state. Generic readiness/unresolved scores cannot substitute.

### HQ14 — Is a terminally necessary semantic family missing?

**No.** No candidate survives the ownership test. Upstream facts/temporal/negative meaning remain upstream; V554 owns eligibility and pre-route applicability; V555 owns atomic route identity and route-born conditions; V556 owns new cross-route/cross-pressure interaction; V3 owns actual actor position, relationship, traversal and developmental history. Adding another V554↔V555 family would create duplication or jurisdiction bleed.
