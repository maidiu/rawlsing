# Boundary Transformation Method

Rawlsing downstream dataflow is a governed dependency DAG. For current stage `B` and downstream stage `C`, do not assume that C receives all useful information through B.

Use this sequence:

`CUMULATIVE UPSTREAM MAP`
`→ C TOTAL NEED`
`→ C DIRECT LAWFUL REUSE OF EARLIER OUTPUTS`
`→ RESIDUAL NEED REQUIRING B`
`→ B SELECTED INPUTS`
`→ B UNIQUE TRANSFORMATION`
`→ B NEW OUTPUTS`
`→ C COMPOSED INTAKE`
`→ UPDATED CUMULATIVE MAP`

The central question is:

> Given everything already available upstream, what can C already use lawfully, what new meaning must B uniquely create, and does the union satisfy C without invention or unnecessary duplication?

## 1. Cumulative map

Every session inherits `schematics/CUMULATIVE_UPSTREAM_MAP.md`.

Earlier outputs remain reusable when their producer still owns the meaning needed for the intended use. Stage distance is not a prohibition.

Direct reuse is defective only when it:
- bypasses a transformation actually required for the claimed meaning;
- creates competing authorities without precedence;
- strips provenance, epistemic/permission state, absence/noncomparability or uncertainty;
- silently reinterprets what the earlier producer established.

An object may be superseded for one semantic use while remaining authoritative for another.

## 2. Downstream demand

Start with C's actual operation and list only information classes necessary to perform it.

Partition:

`C_NEED = EARLIER_REUSABLE + RESIDUAL_NEED_FOR_B + C_OWN_DERIVATION`

Do not make B republish earlier information merely for serial neatness.

## 3. B selected inputs and unique obligation

For the residual need, identify which adjudicated upstream objects B must use.

For each selected input record only:
- producer/object;
- meaning owned;
- why B needs it;
- governing restriction or authority precedence.

Then state one transformation equation:

`SELECTED INPUT GRAINS → B-AUTHORIZED OPERATION → B-DERIVED OBJECT GRAINS`

Every B-derived meaning needs lawful basis, retained lineage and an explicit epistemic/permission state.

## 4. B new-output envelope

Separate:
- genuinely B-derived meaning;
- useful lossless reformats;
- aggregates with lineage;
- B-created negative/uncertainty states;
- earlier meaning B merely references;
- meanings B cannot lawfully create.

B's required contract is the minimum new/reshaped contribution needed by C or a named later capability.

## 5. C composed-intake test

Test:

`selected earlier reusable outputs + accepted B outputs + C-own derivations`

against C's total need.

Use only these outcomes unless a new category is materially necessary:
- `MEETS_BY_UPSTREAM_REUSE`
- `MEETS_BY_B_DERIVATION`
- `MEETS_BY_COMPOSITION`
- `CONTRACT_GAP`
- `REPRESENTATION_GAP`
- `AMBIGUOUS_AUTHORITY`
- `MISSING_AUTHORITY`
- `MISPLACED_RESPONSIBILITY`
- `ILLICIT_BYPASS`
- `UNNECESSARY_DUPLICATION`

## 6. Negative-state law

Where relevant, explicitly test:
- observed zero vs absence;
- unknown vs low confidence;
- noncomparability;
- blocker/permission denial;
- contradiction/competing evidence;
- temporal gap/rupture uncertainty;
- duplicate authority;
- direct structure-to-person/personality inference.

Unknown remains unknown until a governed transformation resolves it.

## 7. Reporting economy law

Workers may investigate at whatever granularity is necessary internally. **Returned artifacts must be compact and decision-bearing.**

A normal breakout return should contain only:

1. **Conclusion** — 1–3 short paragraphs.
2. **Need/reuse map** — normally no more than 12 rows; group equivalent physical artifacts by semantic role.
3. **Residual stage obligation** — normally no more than 8 bullets.
4. **Selected input set** — only inputs that materially affect the stage transformation.
5. **Transformation equation** — one canonical statement.
6. **Proposed new-output contract** — normally no more than 6 object families.
7. **Defects** — only concrete defects that change implementation or authority; normally no more than 5.
8. **Unresolved Vozhd forks** — only choices that genuinely require adjudication; normally no more than 3.
9. **Worked cases** — one ordinary and one adversarial example unless a third case reveals a distinct authority problem.
10. **Machine result** — concise JSON carrying the same conclusions plus source/provenance metadata.

Do **not** repeat a table in prose, enumerate every file read in Markdown, or expand every field into a separate ontology entry when several fields share one semantic role. File-read provenance may live in JSON if useful.

Exceed these norms only when compression would hide a real semantic distinction or implementation obligation. The worker should say why the extra granularity is necessary.

## 8. Vozhd synthesis

Vozhd Dva reconvenes independent perspectives and records only:
- accepted dependency/reuse law;
- accepted stage transformation;
- accepted new-output contract;
- authority precedence and negative-state rules;
- implementation/test obligations;
- unresolved blockers that survive adjudication;
- cumulative-map additions needed by the next session.

Worker proposals are advisory. Only the synthesis ruling changes Rawlsing law.

## 9. Termination

A schematic session ends when the next stage can be launched from a finite accepted contract. Do not continue architecture work because further descriptive detail is possible.
