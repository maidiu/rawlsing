# CANONICAL INDEX REQUIREMENTS

Status: `REQUIRED_FOR_LOSSLESS_PRE_MAIN_KNOWLEDGE_REACHABILITY`

## Purpose

The canonical index exists so a fresh agent can identify current governing knowledge without searching branch names, chronology, chat history, or historical worker commands.

It is **not** a replacement for exact authority artifacts. It is the canonical routing layer to them.

## Minimum records

The index must contain one explicit current record for each of these authority families:

1. Job3-R3 typed relation authority: positive topology, exact REJECT ledger, BLOCKED ledger, blocker obligations, O12 successor obligations, O12_R3 denominator, O11_R2 capability, O10 grammar, current T06/T15, source-native substrate pointer.
2. P1 semantic identity law.
3. P2 typed succession/current-selection law plus P3/P4 jurisdiction/completeness nonimplications.
4. P10/G1A preservation closure and exact preservation census/ref.
5. PRE-V3 Authority31 architecture theorem and `NO_ARCHITECTURE_WINNER_SELECTED` state.
6. Long Memory Authority39 inherited baseline / living succession law.
7. Current J01-A frozen current-only source/candidate denominator and exact carrier hashes.
8. Current routing ledger contract/current carrier and typed unresolved state.
9. Current open architecture/function/proof forks.
10. Field Forge corpus and induction, explicitly `EXPLORATORY_NONBINDING`.
11. Historical reservoirs whose functions remain relevant but whose machinery/authority role is superseded.

## Required fields per index row

Every row must expose:

- `authority_or_proposition_id`
- `human_name`
- `authority_class`
- `jurisdiction`
- `current_status`
- `source_path`
- `immutable_ref_sha`
- `carrier_hash_or_exact_pointer` when applicable
- `current_selected_by` or exact successor relation
- `supersedes` / `superseded_by`
- `downstream_consumers`
- `typed_unresolved_or_negative_ceiling`
- `canonical_representation_disposition`
- `do_not_infer`

The index must be mechanically sortable by jurisdiction and current status.

## Physical-vs-exact-ref rule

### Must be physically discoverable on canonical ancestry

- current constitutional laws: P1, P2/P3/P4;
- current semantic relation authority/index and its exact negative/open-world interpretation law;
- current PRE-V3 architecture theorem;
- current conservation/succession law;
- current open-fork ledger;
- current index itself;
- Field Forge exploratory entrypoint/status fence.

### May remain exact-ref/hash backed if canonically indexed

- bulky frozen evidence carriers and source-native archives;
- historical proof corpora not used directly as current runtime law;
- accepted non-serving physical implementation capital;
- superseded machinery retained for regression/replay/history;
- P10's bulky preservation substrate, provided its accepted holding, exact census identity, unresolved-state semantics, and immutable refs are on canonical ancestry.

### Must not surface as current

- superseded denominators/mechanisms/backends;
- rejected/nonselected implementation candidates;
- command-only or dispatch-only branches;
- blocked courts as if they were either rejection or acceptance;
- Field Forge prospective architecture as if HQ had selected it.

## Currentness rule

The index may not calculate currentness from:

- timestamp;
- lexical version ordering;
- branch recency;
- names such as `final`, `freeze`, `integration`, `accepted`, or high revision numbers;
- passing tests alone;
- Git topological maximality;
- absence from a later lineage.

Currentness must be backed by explicit governed selection / typed succession / acceptance evidence.

## Anti-recovery-of-recovery invariant

A future authority must be able to answer these questions from canonical ancestry alone:

1. What is current?
2. Why is it current?
3. What exact object/ref carries it?
4. What did it supersede, and at what grain?
5. What unresolved/blocked/negative ceiling survives?
6. What consumer depends on it?
7. What exploratory or historical capital is nearby but nonbinding?

If any answer requires searching hundreds of branches, the canonical index has failed its purpose.

Terminal invariant:

`CANONICAL_DISCOVERABILITY != COUNTERFEIT_PROMOTION`

`EXACT_REF_PRESERVATION != ORAL_HISTORY`

`CURRENT_INDEX = AUTHORITY_ROUTING_SURFACE__NOT_AUTHORITY_BY_BRANCH_NAME`.
