# Decision-domain laundering

Ruling: BYPASS.

`decision_domain` selects grounding requirements, but the validator never derives or verifies domain from the packet's actual task/result/authority/closure subject. `GENERAL_PROJECT_DECISION` is adoption-eligible and intentionally sparse. Therefore a decision that should require PHYSICAL_ARCHITECTURE, FIELD_FORGE, PHYSICAL_PERSISTENCE, etc. can be relabeled GENERAL_PROJECT_DECISION unless some independent structured target happens to catch it. `task_scope` is free text and does not close this seam.

This independently fails R2A-G4 and R2A-G5.
