# CANONICAL PROJECT ANCESTRY LAW R1

After competent global adoption, the canonical project branch must again become the cumulative project ancestry.

It should inherit:

- operative runtime and implementation;
- current authority/governance;
- central project cognition/state;
- conceptual inheritance;
- unfinished/return-required obligations;
- historical/intellectual preservation;
- exploratory/nonbinding capital;
- the protocols that prevent detached decision and silent stranding.

Do not define a permanent architecture in which `main` is only runtime/body while PRE-MAIN or another side branch is the permanent project brain.

Runtime-currentness remains a typed/indexed property inside cumulative ancestry. Authority-currentness remains separately typed. Historical/exploratory presence remains separately typed.

Git ancestry answers what future Rawlsing must inherit. It does not by itself answer what executes or what governs.
