# WORK RETURN / REINTEGRATION PROTOCOL R1

A significant return is incomplete unless it explains both local result and project-state effect.

Every return must answer:

1. What was accomplished?
2. What was not accomplished?
3. What remains open?
4. Why does it remain open?
5. What exact dependency/blocker exists?
6. What new question/obligation was discovered?
7. What successor was spawned?
8. What must that successor return?
9. What parent must later be revisited?
10. Which central state rows change?
11. Which relevant central state rows explicitly do not change?
12. What authority was actually obtained?
13. What authority was explicitly not obtained?
14. What is locally complete?
15. What remains project-incomplete?
16. What campaign/HQ/canonical banking action remains?

Every touched obligation receives an explicit disposition. New obligations receive IDs before adoption. Every successor receives a return destination.

Allowed reintegration statuses include `ACTIVE_GROUNDED`, `LOCAL_COMPLETE_UNRECONCILED`, `BLOCKED_ON_DEPENDENCY`, `SPAWNED_SUCCESSOR_RETURN_REQUIRED`, `CAMPAIGN_ACCEPTED_UNBANKED`, `HQ_BANKED_NOT_CANONICALLY_INHERITED`, `PRESERVED_NONCURRENT`, `DELIBERATELY_NOT_ADOPTED`, `CANONICALLY_INHERITED`, `SUPERSEDED_AT_EXACT_GRAIN`, `INTERRUPTED_STRANDED`, and `UNKNOWN_REQUIRES_SYNTHESIS`.

`LOCAL_COMPLETE_UNRECONCILED` remains centrally open. A worker return does not self-bank.
