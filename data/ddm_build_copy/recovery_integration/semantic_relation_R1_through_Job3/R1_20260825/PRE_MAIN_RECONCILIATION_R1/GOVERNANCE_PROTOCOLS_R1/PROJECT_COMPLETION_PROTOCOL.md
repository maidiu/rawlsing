# PROJECT COMPLETION PROTOCOL R1

## Local success

Tests may pass; an artifact may exist; a court may rule; a worker may return. Those facts can establish local success.

## Project completion

Project-level closure additionally requires central-state reconciliation.

A significant work unit may not claim project-level `CLOSED` unless every touched obligation has a central disposition, every new obligation is registered, every successor has a return path, the authority ceiling is recorded, and the governing outcome is canonically inherited or a competent deliberate non-adoption/preservation disposition is centrally recorded.

If the governing result is accepted by a campaign but not banked, use `CAMPAIGN_ACCEPTED_UNBANKED`.

If banked by HQ but not inherited by the cumulative canonical project head, use `HQ_BANKED_NOT_CANONICALLY_INHERITED`.

If locally done but not reconciled, use `LOCAL_COMPLETE_UNRECONCILED`.

If blocked, the project state remains open/blocked and must name the dependency.

If work spawns a successor, the parent remains open/return-required unless exact competent authority says otherwise.

`ABSENCE_OF_LATER_WORK != CLOSURE`.
