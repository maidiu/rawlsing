# WORK LAUNCH PROTOCOL R1

Every significant governed Rawlsing work unit must be centrally addressable before launch.

Required launch declaration:

- `work_unit_id`;
- parent campaign / commissioning authority;
- exact canonical launch head;
- Ground version;
- grounding receipt ID, or exact authorized grounded parent for bounded execution;
- agent mode;
- jurisdiction and write scope;
- authority ceiling;
- state IDs touched;
- obligation IDs touched;
- exact question being answered;
- local success condition;
- project-closure condition;
- dependencies/blockers;
- return destination;
- successor-spawn policy;
- forbidden assumptions.

No significant work launches with an unspecified return destination.

A worker's local success condition must not be written as though it were automatically project closure. If a new prerequisite/successor is discovered, the return must register a new obligation plus explicit `SPAWNED_SUCCESSOR` and `RETURN_TO` relations. The parent remains open unless competent authority explicitly disposes it.

A mechanical worker operating under `GROUNDED_BOUNDED_EXECUTION` may use narrow context but may not reinterpret the governing adjudication. If execution exposes a conceptual ambiguity, stop at the ambiguity and return it to a grounded decision authority.
