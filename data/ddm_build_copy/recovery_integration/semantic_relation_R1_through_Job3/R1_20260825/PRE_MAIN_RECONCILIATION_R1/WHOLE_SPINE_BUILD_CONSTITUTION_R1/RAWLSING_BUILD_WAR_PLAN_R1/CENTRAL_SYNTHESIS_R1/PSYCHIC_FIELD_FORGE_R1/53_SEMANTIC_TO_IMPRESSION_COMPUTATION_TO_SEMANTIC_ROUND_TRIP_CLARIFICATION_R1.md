# PSYCHIC FIELD FORGE R1 — SEMANTIC → IMPRESSION-COMPUTATION → SEMANTIC ROUND-TRIP CLARIFICATION R1

**Status:** `PRE_ARCHITECTURE_ZERO_LOSS_CLARIFICATION__MUST_FACTOR__NO_ARCHITECTURE_ADOPTION__NO_RUNTIME_AUTHORITY`

## 0. Purpose

This file makes explicit a core interaction model that was already present in the originating PFF zero-loss vision but could be obscured by later shorthand such as `machine candidate reading -> actor uptake -> response`.

The intended model is not ordinary semantic question-answering with personality modulation.

The intended model is a **round-trip transduction**:

1. actual user discourse is semantically/pragmatically interpreted only far enough to translate it into a pre-derived, machine-bounded interaction/impression representation;
2. that representation is not itself the actor's psychology and cannot mutate person state;
3. the input is recomputed through the developed V3/PFF person so that the system determines what this event becomes for this person and what of the person is recruited now;
4. the resulting person-side computation is transformed into bounded action/expression consequences under actor-access, perspective, defense, effort, relationship, and other constraints;
5. the original discourse semantics then re-enter at final realization so the response can address the actual semantic particulars of the user message;
6. that re-entry may not bypass or repair away the actor-specific mediation that occurred in the middle.

This clarification does not adopt an exact schema, numeric ontology, module graph, LLM count, prompt contract, or runtime topology.

## 1. The central round-trip

Conceptually:

```text
USER'S ACTUAL DISCOURSE
  lexical / semantic / pragmatic / contextual particulars
        |
        v
LLM-FACING DISCOURSE TRANSDUCTION
  semantics used as evidence
  -> pre-derived legal interaction/impression coordinates
  -> preserve ambiguity / scope / target / intensity / confidence / multiplicity
        |
        v
BOUNDED MACHINE-SIDE INTERACTION REPRESENTATION
  != user hidden intention
  != persona perception
  != persona psyche
        |
        v
PERSON × EVENT COUPLING
  durable V3 person
  + relationship history
  + live PFF residue/current condition
  + actor-specific uptake/appraisal
  + situated recruitment
        |
        v
PERSON-SPECIFIC PSYCHIC COMPUTATION
  conflict / amplification / inhibition / defense / regulation
  memory resonance / causal trace
  self-model pressure
  anticipation / metaperception
  current awareness
  effort/capacity
        |
        v
BOUNDED ACTION / COMMUNICATIVE CONSEQUENCES
  current intention/tendency
  content actor may use
  pressures
  prohibitions
  disclosure/concealment constraints
  actor-access ceilings
        |
        v
EXISTING V2 EXPRESSION JURISDICTIONS
        |
        +-------------------------------+
        |                               |
        |                     ORIGINAL DISCOURSE RE-ENTERS
        |                     for exact semantic grounding
        |                               |
        +---------------+---------------+
                        v
FINAL LLM SURFACE REALIZATION
  answer the actual semantic particulars
  THROUGH the actor-bounded recomputed result
  without restoring machine-level omniscience
                        |
                        v
ACTUAL OCCURRED RESPONSE
  -> user next move
  -> actor self-observation
  -> next fast recursion
  -> possible durable V3 return only under exact authority
```

This is the conceptual model to preserve.

## 2. “Not for its semantics, but from its semantics”

The project lead's formulation is important and should be read precisely.

The first LLM **does use semantics**. It cannot translate a user utterance into interaction coordinates without understanding enough of:

- literal content;
- pragmatic move;
- target;
- discourse history;
- implication;
- ambiguity;
- relational positioning;
- teasing/criticism;
- intimacy/distance;
- status move;
- vulnerability bid;
- quotation/reporting;
- scope.

But it is **not using semantics to answer the user**.

It is using semantics as evidence **from which to derive a bounded computational description of the presented interaction**.

Thus:

```text
FIRST_LLM_SEMANTIC_COMPETENCE
!=
FIRST_LLM_RESPONSE_AUTHORITY
```

and:

```text
SEMANTICS_AS_EVIDENCE_FOR_TRANSDUCTION
!=
SEMANTICS_AS_DIRECT_PERSONA_RESPONSE
```

The first stage should therefore be thought of as semantic/pragmatic **measurement/translation into a preconstituted interaction space**, not as hidden conversational reasoning whose answer is later stylized.

## 3. The impression-computational schema is pre-derived, not invented turn by turn

The original zero-loss appendix requires the legal interaction categories/dimensions to be established by Rawlsing rather than freely improvised by the LLM.

The first LLM may nominate/measure only inside that lawful representational vocabulary or its eventual equivalent.

Candidate non-collapse dimensions already preserved as requirements include:

- magnitude/intensity;
- direction/polarity;
- confidence;
- interpretive weight/probability;
- target binding;
- participant role;
- discourse scope;
- temporal scope;
- relational scope;
- ambiguity;
- multiplicity.

The exact dimensions, scales, numeric representation, calibration and equations remain architecture work.

Important law:

```text
PRE_DERIVED_INTERACTION_SCHEMA
!=
FREE_FORM_LLM_PSYCHOLOGY
```

The LLM must not invent `shame = .83`, `attraction = .61`, or a new psychological construct because the prose suggests it.

It describes the observable/candidate **interactional stimulus**; the developed person determines the psychic impact.

---

## 4. The first translation is not the persona's perception

The pre-derived interaction representation is a machine-side bounded account of what the discourse can support.

It may preserve multiple candidate readings.

Therefore:

```text
USER_UTTERANCE
!=
MACHINE_INTERACTION_ENCODING
!=
USER_TRUE_INTENTION
!=
PERSONA_UPTAKE
!=
PERSONA_CONSCIOUS_INTERPRETATION
!=
PSYCHIC_EFFECT
```

This matters because a highly capable LLM may recognize ten nuances while the persona lawfully receives only three strongly, one faintly, and perhaps transforms another through an expectation or defense.

The machine-side encoder is allowed to be **better at discourse comprehension than the actor**.

The actor is not thereby made omniscient.

---

## 5. The middle computation must leave ordinary semantic paraphrase-space

The original vision's `friction charge / psyche-substance` language was metaphorical, but the semantic requirement remains strong:

> The middle computation must not merely keep paraphrasing the conversation in increasingly psychological English.

A weak implementation would be:

```text
user prose
-> LLM prose analysis of what user means
-> LLM prose analysis of what persona feels
-> LLM prose instruction for response
-> reply
```

That risks collapsing the entire machine into one long roleplay prompt spread across several calls.

The intended middle instead operates over Rawlsing-native, preconstituted person and interaction relations:

```text
interaction coordinates
× developed V3 organization
× relationship/history
× current live configuration
-> person-specific state transition / current configuration
```

The exact mathematical or symbolic form is not yet adopted.

But the semantic burden is:

```text
MIDDLE_COMPUTATION != PARAPHRASED_CONVERSATION
```

and:

```text
PSYCHIC_TRANSITION_MUST_BE_CONSTRAINED_BY_RAWLSING_NATIVE_PERSON_STATE_AND_RELATIONS
```

## 6. Input impact is recomputed, not merely looked up

The same interaction representation can have different impacts because the generated person differs.

Likewise the same person can receive the same literal message differently after relationship history or current live state changes.

Thus:

```text
INPUT_COORDINATES
!=
PSYCHIC_EFFECT
```

The effect arises through coupling with:

- durable expectations;
- strivings;
- mediators;
- tensions;
- practices;
- memory / causal traces;
- self-model;
- attractor/developmental organization;
- relationship history;
- current condition;
- live residue/hysteresis;
- anticipation;
- actor model/metaperception;
- defenses;
- organismic/capacity conditions where lawful.

This is where the **one actual generated person** becomes causally necessary rather than decorative.

## 7. Actor uptake is the event-side result; situated recruitment is the person-side result

The current campaign's stronger formulation fits the old transduction intuition.

### Event-side

`ACTOR_UPTAKE` asks:

> What did the encoded/presented event become for this person?

### Person-side

`SITUATED_RECRUITMENT` asks:

> What of this developed person became operative because of the event here and now?

They are paired views of one person-event coupling, not necessarily two serial modules.

This means the impression-computational schema does not itself contain the finished actor uptake. It supplies the lawful event-side material that the person then transforms.

---

## 8. The recomputed output is not yet semantics

After person-specific mediation, Rawlsing should not immediately jump to prose.

The current strongest conceptual remainder is a bounded current action/communicative direction with actor-lawful positive and negative constraints.

Possible consequences include:

- remain engaged;
- withdraw;
- test;
- repair;
- tease;
- preserve deniability;
- answer only one thread;
- permit warmth;
- inhibit explicit disclosure;
- challenge status;
- ask for reassurance;
- avoid claiming certainty about the user's intent;
- leave some active material unsaid;
- allow leakage pressure without explicit self-knowledge.

These are not required as one universal enum or object.

The key law is:

```text
PSYCHIC_OUTPUT
-> BOUNDED_ACTION_EXPRESSION_CONSEQUENCES
!=
PSYCHIC_OUTPUT -> DIRECT_PROSE_TRANSLATION
```

---

## 9. The original semantic particulars must re-enter

After the non-semantic/person-computational middle has determined the actor-bounded current action/expression direction, the final language model must again receive the actual conversational substance.

Without this re-entry, the final model would be asked to generate language from abstract coordinates and would lose:

- exact propositions;
- referents;
- names;
- quoted phrases;
- jokes;
- local wording;
- discourse dependencies;
- question particulars;
- semantic entailments;
- linguistic repair context.

Thus:

```text
FINAL_RENDERER_REQUIRES_ORIGINAL_DISCOURSE_GROUNDING
```

The original semantic message is **not consumed and discarded** after first translation.

It is held as surface evidence/context and reintroduced at realization.

---

## 10. But semantic re-entry is subordinate to actor mediation

This is the critical complement.

Suppose:

```text
SYSTEM INTERPRETATION:
A + B + C + D

PERSON-SPECIFIC UPTAKE / RECRUITMENT:
B strongly
C transformed
A barely operative
D defensively excluded from current response

LAWFUL COMMUNICATIVE DIRECTION:
respond around B + transformed C
```

The final renderer may consult the actual message so it knows exactly what B and C referred to and how the user phrased them.

It may **not** say:

> And to address A and D as well...

merely because those threads remain visible in the original user text.

Therefore:

```text
SEMANTIC_REENTRY
!=
SEMANTIC_RESCUE
```

```text
RENDERER_ACCESS_TO_ORIGINAL_MESSAGE
!=
RENDERER_AUTHORITY_TO_WIDEN_ACTOR_RESPONSE
```

The renderer's task is to realize the recomputed actor response **with semantic fidelity to the parts the actor is lawfully responding to**, not to maximize service completion.

---

## 11. The round trip is not symmetric translation

Do not assume:

```text
semantic input -> coordinates -> semantic output
```

is an information-preserving codec.

The point is precisely that the person changes the information that matters.

The middle may lawfully produce:

- selective uptake;
- altered significance;
- uncertainty;
- omission;
- conflict;
- defensively transformed meaning;
- partial awareness;
- effort-limited response;
- new action intention;
- no significant response at all.

So the output side is **not the inverse transform of the input side**.

It is:

```text
INPUT SEMANTICS
-> INTERACTION REPRESENTATION
-> PERSON-SPECIFIC CAUSAL TRANSFORMATION
-> ACTOR-BOUNDED RESPONSE COMPUTATION
-> NEW SEMANTIC ACT GROUNDED AGAINST ORIGINAL INPUT
```

---

## 12. Two LLM-facing functions remain conceptually distinct without freezing call count

The present design repeatedly points to two language-facing functions:

1. discourse-to-bounded-interaction translation;
2. bounded-expression-to-surface-language realization.

Historical V3 also contained separated proposal/render functions.

But this file does not freeze `exactly two LLM calls` as architecture.

Hard laws are functional/authority laws:

```text
INPUT_LLM_FUNCTION != PSYCHIC_TRANSITION_AUTHORITY
```

```text
OUTPUT_LLM_FUNCTION != PSYCHIC_TRANSITION_AUTHORITY
```

```text
INPUT_INTERPRETATION_AUTHORITY != OUTPUT_RENDER_AUTHORITY
```

The same underlying provider/model may perform both calls if later architecture permits, but the information/authority boundaries must remain distinct.

## 13. Periodic V3 homology

The exact discourse transduction is interaction-specific.

Periodic V3 does not need a natural-language conversation parser for every generated life event.

But the general principle survives:

```text
OBJECTIVE EVENT DESCRIPTION
!=
ACTOR-SPECIFIC PSYCHOLOGICAL INPUT
```

Where a developmental event's effect depends on how the actor perceives/appraises/metabolizes it, the event must be translated/bound into whatever lawful event-side representation the shared person psychology consumes and then recomputed through this actor.

Thus:

```text
SHARED_PERSON_EVENT_MEDIATION
!=
SHARED_CHAT_DISCOURSE_ENCODER
```

The chat encoder is a specialized ingress adapter to a more general person-event metabolism.

## 14. Anti-collapse tests

Reject future architecture if it effectively becomes any of:

### A. Direct semantic roleplay

```text
user message + persona dossier -> LLM reply
```

### B. Semantic analysis plus style conditioning

```text
LLM understands message
-> tags emotion/personality
-> renderer writes persona-flavored answer
```

### C. LLM-authored hidden psychology

```text
LLM reads message
-> invents attraction/shame/trust/memory
-> tells renderer to express it subtly
```

### D. Coordinate-only rendering

```text
psychic coordinates -> prose
```

without re-grounding in actual input semantics.

### E. Renderer rescue

```text
actor-bounded computation omits thread
-> renderer sees original message
-> renderer restores thread for completeness
```

### F. Symmetric codec assumption

Treating the middle as a reversible representation transform rather than a history-dependent person transition.

## 15. Current strongest holding

The most faithful current formulation is:

> **The first language-facing function converts the actual user's semantic/pragmatic discourse into a bounded, pre-derived machine representation of the interaction rather than answering it. The developed V3/PFF person then performs the substantive person-specific computation that determines what the input becomes for that actor, what of the actor becomes operative, and what current response consequences follow. Those consequences are narrowed through actor-access and expression jurisdictions. The final language-facing function is re-grounded in the original discourse so it can respond to the exact semantic particulars, but it may only realize the actor-bounded recomputed response and may not restore machine-level comprehension that the person did not lawfully carry forward.**

Therefore:

```text
SEMANTIC_INPUT = PRESERVED_AS_SURFACE_EVIDENCE
SEMANTIC_INPUT -> PRE_DERIVED_INTERACTION_REPRESENTATION = MUST_FACTOR
FIRST_LLM_OUTPUT != PSYCHIC_STATE_CHANGE
MIDDLE_PERSON_COMPUTATION != SEMANTIC_PARAPHRASE_CHAIN
PERSON_SPECIFIC_RECOMPUTATION = MUST_FACTOR
PSYCHIC_OUTPUT != DIRECT_PROSE
ORIGINAL_DISCOURSE_REENTRY = MUST_FACTOR
RENDERER_ANTI_RESCUE = MUST_FACTOR
ROUND_TRIP != REVERSIBLE_CODEC
EXACT_SCHEMA = NOT_YET_ADOPTED
EXACT_LLM_CALL_COUNT = NOT_YET_ADOPTED
ARCHITECTURE = NOT_ADMITTED
```

Terminal token:

`SEMANTIC_TO_PRE_DERIVED_IMPRESSION_COMPUTATION_TO_PERSON_SPECIFIC_TRANSITION_TO_SEMANTIC_ROUND_TRIP_PRESERVED__ORIGINAL_DISCOURSE_REENTERS_WITHOUT_RENDERER_RESCUE__NO_ARCHITECTURE_ADOPTION`
