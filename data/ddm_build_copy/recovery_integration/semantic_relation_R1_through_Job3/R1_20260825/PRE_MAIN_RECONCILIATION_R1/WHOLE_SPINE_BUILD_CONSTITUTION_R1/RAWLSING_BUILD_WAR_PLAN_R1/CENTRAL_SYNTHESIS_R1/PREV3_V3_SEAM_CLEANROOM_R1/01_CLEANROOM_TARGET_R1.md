# 2. THE SEAM'S POSITIVE RESPONSIBILITY

The seam must answer one bounded question:

> Given an exact generated actor, exact world/release context, exact effective time/history point, and an exact downstream request, what objective propositions are lawfully resolvable for this actor/world/time/request, under which authority, currentness, provenance, uncertainty and negative-state ceilings, and through which ingress jurisdiction may V3 consume them?

This requires five distinct capabilities.

## 2.1 Stable world/release/resolution anchoring

The system needs a reproducible anchor identifying the objective-world authority horizon against which a V3 resolution occurred.

This anchor may be a content-addressed manifest/root/release identity rather than one eagerly materialized world object.

It must permit deterministic reconstruction of:

- which producer releases were in scope;
- which rule authorities were current;
- which exact fact/relation authority instances were current;
- which valid/effective time basis governed the resolution;
- which world/context query or actor-position request was executed;
- what result identities and typed blockers were returned.

`WORLD_ROOT_IDENTITY != UNIVERSAL_WORLD_PAYLOAD`.

## 2.2 Typed objective-context resolution

A resolver may select, derive, dereference or reconstruct exact objective propositions relevant to the actor/world/time/request.

It does **not** become semantic owner merely by assembling results.

Every resolved item remains bound to its competent owner and exact authority instance.

The resolver may return heterogeneous propositions. It must not force them into a common scalar coordinate system unless a separately competent transform owner authorizes that exact derived product.

## 2.3 Explicit ingress classification

Every resolved proposition intended for V3 must be classified into an ingress jurisdiction rather than dumped into one generic context blob.

At minimum:

1. `OBJECTIVE_WORLD_FACT`
2. `OBJECTIVE_ACTOR_POSITION_OR_POSITIONED_CONSEQUENCE`
3. `OPPORTUNITY_OR_APPLICABILITY`
4. `NON_EVENT_CONDITION`
5. `DIRECTED_RELATION`
6. `RECURRENT_ACTIVITY`
7. `EVENT_OR_OCCURRENCE_BASIS`
8. `WITNESS_OR_CURRENTNESS_EVIDENCE`
9. `TYPED_UNKNOWN_NEGATIVE_OR_BLOCKER`

These classes may share transport infrastructure but not semantic jurisdiction.

## 2.4 Separate realization gates

Availability to V3 is not realization in V3.

The seam must preserve:

`RESOLVED_OBJECTIVE_FACT != GENERATED_PERSON_FACT`

`OPPORTUNITY != OCCURRENCE`

`APPLICABILITY != ENCOUNTER`

`EVENT_EXISTS != ACTOR_ENCOUNTERED_EVENT`

`NON_EVENT_CONTEXT != SYNTHETIC_EVENT`

`WITNESS != FACT`

`RULE_CURRENT != RULE_APPLIED`

The exact competent V3 owner must perform realization.

## 2.5 Replay / invalidation / succession

A resolved context must be reproducible and selectively invalidatable.

The seam must preserve:

- immutable producer/source identity where applicable;
- semantic claim identity;
- authority-instance identity;
- rule identity;
- rule-application identity;
- world/release identity;
- actor identity;
- effective/valid time;
- dependency closure;
- currentness dimensions;
- supersession lineage;
- determinant-scoped invalidation;
- dependent-only redrive;
- append-only historical explanation;
- deterministic replay.

A changed determinant must not require whole-world rematerialization unless the physical implementation chooses that path for nonsemantic reasons.

# 11. CLEAN-ROOM HOSTILE COURT

## Attack 1 — “This is just a richer context packet.”

**Defense:** No. The architecture is a set of owner-preserving transition contracts. A transport packet may carry refs, but ingress classes, realization gates and authority remain semantically separate.

## Attack 2 — “A resolver becomes a hidden master owner.”

**Defense:** Forbidden. Resolution selects/dereferences producer-owned authorities; `RESOLVER_SELECTION != SEMANTIC_OWNERSHIP`.

## Attack 3 — “Query-on-demand means hidden mutable latest state.”

**Defense:** Forbidden. Every resolution binds a stable world/release/root identity, exact effective/valid time and currentness/replay identity.

## Attack 4 — “The world root recreates the universal master payload.”

**Defense:** Not required. The root may be a content-addressed manifest over producer releases/authority horizons; it need not contain all facts.

## Attack 5 — “Actor-indexed objective position smuggles in psychology.”

**Defense:** Actor index is not subjectivity. Objective position/consequence remains PRE-V3/SDTF-owned until an exact V3 transition occurs.

## Attack 6 — “Everything can be shoved through event ingress.”

**Defense:** Forbidden. OBL062 exists precisely because condition/relation/recurrent-activity semantics must not be event-laundered.

## Attack 7 — “A vector can still become canonical because downstream needs one.”

**Defense:** A vector may be a separately governed derived consumer product. Consumer need does not retroactively redefine the seam.

## Attack 8 — “The LLM can reconstruct the missing person state from context.”

**Defense:** Forbidden by V2/PFF law. Renderer rescue is prohibited; machine understanding is not actor uptake/access.

## Attack 9 — “Missing data can be normalized away to keep execution alive.”

**Defense:** Generic OBL063 survives horizontally: no silent zeroing, renormalization, coefficient redistribution or proxy fallback.

## Attack 10 — “This architecture is too abstract to execute.”

**Defense:** The executable minimum is concrete: stable release/root identity + typed resolution request + authority-bearing result refs + ingress classification + realization gates + deterministic replay/invalidation. Physical storage remains separately selectable.

Court result:

`10 / 10 CLEANROOM HOSTILE ATTACKS SURVIVE WITHOUT REQUIRING_TERMINAL_DRIVER_VECTOR_OR_TYPE_PRODUCT`.
