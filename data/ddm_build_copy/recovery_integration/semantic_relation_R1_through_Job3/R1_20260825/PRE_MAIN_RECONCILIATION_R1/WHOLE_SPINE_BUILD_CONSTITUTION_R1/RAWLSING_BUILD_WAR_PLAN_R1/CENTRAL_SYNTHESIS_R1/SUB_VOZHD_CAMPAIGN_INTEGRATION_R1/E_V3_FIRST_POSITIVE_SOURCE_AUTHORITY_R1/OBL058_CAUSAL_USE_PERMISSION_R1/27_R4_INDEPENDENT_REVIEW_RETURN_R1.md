## Independent finding

The candidate stores `_body_json`, `_write_fd`, `_read_fd`, and `_proc` directly on each `IssuedReceipt`. Ordinary Python object access can read and rebind those slots. `validate_receipt` checks that the body is nonempty, the descriptors are nonnegative integers, and `_proc` is a live `subprocess.Popen`, then trusts `_service_roundtrip`'s returned `decision`.

It does not establish that the read/write descriptors belong to `_proc`, that `_proc` is the child initialized for this receipt, or that the returned response was generated by the source-owned authority child.

The independent court reproduced:

1. exact-type fabricated receipt + caller-created pipes + unrelated live `Popen` + caller response `PERMIT` → `validate_receipt(...) == PERMIT`;
2. genuine source-issued `DENY` receipt, after replacing its parent-visible transport fields with the same caller response path → `validate_receipt(...) == PERMIT`.

Thus source-origin still depends on caller-controlled parent transport state. This is narrower than the R3 defect: the child's one-shot semantic authority is not itself mutable or caller-body-driven, but the parent validation channel is not authenticated/bound to that child.
