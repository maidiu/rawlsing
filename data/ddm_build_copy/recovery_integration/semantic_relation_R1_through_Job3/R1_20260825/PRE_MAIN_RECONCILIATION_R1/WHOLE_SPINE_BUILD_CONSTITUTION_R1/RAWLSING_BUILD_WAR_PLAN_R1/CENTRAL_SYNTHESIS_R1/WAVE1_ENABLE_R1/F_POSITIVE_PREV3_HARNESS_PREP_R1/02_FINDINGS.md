# WAVE 1F — FINDINGS R1

## 1. The direct V554→V557 path is real and should be preferred

Current M1 already implements an independently authorized direct publication route:

`V554_TO_V557_DIRECT`.

The route appears only when:
- M1 has lawful objects to publish; and
- the separate publication authority binds the exact governed use/rule/producer/publisher decision.

This is the shortest current path into V557 for a relation whose semantics do not require V555 or V556.

The first positive Golden Thread should not traverse V555/V556 merely to make the stage diagram look complete.

## 2. M1 positive relation compatibility is upstream of this lane

Current M1's direct basis is explicitly `DIRECT_STRUCTURAL_EMPIRICAL_ADMISSION`; its alternate basis is a V553 temporal object.

WSC001C correctly rules that a future FIELD FORGE relation admission cannot be disguised as either an `EmpiricalFact` or current `StructuralEmpiricalAdmission`.

Therefore the F harness has a hard activation edge on D/E central reconciliation.

This is the one new positive semantic seam before current downstream reuse.

## 3. M1 is worth preserving rather than bypassing

The M1 runtime already supplies several difficult invariants:
- exact basis/equivalence identity;
- temporal completeness/signature discipline;
- typed negatives;
- deterministic replay identity;
- no ambient latest/default selection;
- no winner heuristic;
- valid-empty no-filler behavior;
- separate publication authority.

A future relation-basis solution should adapt/extend into these invariants, not build a parallel V554-like implementation.

## 4. V557 does not reown semantics

M4 wraps actual producer objects and adds publication/use governance.

Existing tests already prove:
- V557 permission cannot exceed producer permission;
- provenance strings cannot grant permission;
- V557 and V558 are distinct identities;
- direct M1, M2 and M3 producer families can coexist without reidentification;
- actor/V3/V2/render classes are rejected from the structural publication repository.

The positive Wave 1 harness should reuse these exact properties.

## 5. V558 does not require a physical architecture winner

M4 supports exact producer locators and immutable repository resolution without imposing one universal backend.

It supports bundle-local/direct material and exact CAS-style external resolution while failing closed on missing bytes or hash mismatch.

FIELD FORGE R2 separately holds that no persistent/source-backed/hybrid physical winner is selected.

Therefore the first positive PRE-V3 integration test must be backend-neutral.

A database should not appear in the execution command unless the selected empirical upstream claim itself requires one; V557/V558 reuse does not independently require it.

## 6. V555 and V556 are conditional, not mandatory middleboxes

M4 can directly ingest an exact M1 V554 publication.

Thus:

`V554 -> V557 -> V558`

is executable without V555/V556.

V555 must be activated only for separately governed mediation-route semantics.

V556 must be activated only for separately governed higher-order route interaction/topology semantics.

Hostile tests should fail if a direct-path orchestrator fabricates either family.

## 7. Typed negatives already have strong regression capital

Current inherited tests already cover:
- M1 valid-empty;
- M1 explicit/temporal/missing/conflicting authority failures;
- M1 hard-negative publication with no F1;
- V557 permission denial;
- V558 missing exact key;
- V558 integrity failure;
- exact external hash mismatch;
- M5 stale currentness;
- M5 signature/ref/provenance/permission corruption;
- PSEPF/V3 zero-positive behavior.

The future Wave 1 integration harness should add only cross-seam assertions, not duplicate every unit test.

## 8. The minimum new hostile assertions are cross-seam

The future positive harness needs exactly the following new integration-level hostile classes:

### HF01 — no semantic reownership
The exact relation admission owner/ref must remain referenced through the M1 basis and V554 object. V557/V558 may add their own governance/repository identity but may not replace semantic owner or proposition identity.

### HF02 — no relation→empirical coercion
The D/E path must never instantiate current `EmpiricalFact` or existing `StructuralEmpiricalAdmission` merely to satisfy M1.

### HF03 — no V555/V556 filler
For the chosen direct relation:
- M2 is not invoked;
- M3 is not invoked;
- publication/repository contain no V555/V556 semantic object.

### HF04 — no permission widening
If admission/M1 allows `REVIEW` only, V557/V558 `CONTEXT` or `ACTIVE_CAUSAL` request must deny.

### HF05 — typed negative is not positive
Any D/E/M1 typed negative must produce no positive F1. If nonpositive F2/B1 context is separately published, it remains nonpositive and cannot feed positive actor effect.

### HF06 — no fuzzy repair
Missing V558 exact key or stale currentness must fail closed; no `latest`, alternate key or filesystem proximity fallback.

### HF07 — physical realization is not semantic authority
Changing a lawful locator/materialization form must not change the producer semantic object, semantic owner or permission ceiling.

### HF08 — structural success still cannot mutate V3
Even after a real positive V558 resolution and optional validated RSC, the current V3 guard must return exact zero effect with the production positive registry empty.

### HF09 — no reverse-lane object injection
PSEPF, ActorComparatorReceipt, V3 actor objects, V2 persona/render artifacts and similar reverse-lane classes must remain rejected from V557/V558 structural repository roots/dependencies.

Lane F does not prefill those values.

## 10. Nonauthoritative unit fixtures remain lawful

Current tests use synthetic M1/M4/M5 objects to exercise API contracts.

That is lawful test infrastructure if their status is explicit.

The future test suite should use the string:

`NONAUTHORITATIVE_INTERFACE_FIXTURE__NO_SEMANTIC_ACCEPTANCE_EFFECT`

for any pre-central or isolated unit fixture.

Such a fixture may prove:
- constructor compatibility;
- deterministic hashing;
- permission enforcement;
- failure behavior.

It may not prove that the FIELD FORGE relation, PRE-V3 admission, M1 relation basis, or positive empirical claim is accepted.

## 12. Inherited subset is intentionally small

The required inherited regression set should stay bounded to:
- M1 V554;
- M4 V557/V558;
- M5 runtime currentness/no-actor-collapse;
- V3 zero-positive guard;

If central fan-in selects a relation that actually needs V555 or V556 semantics, this disposition must be revised at that exact grain.
