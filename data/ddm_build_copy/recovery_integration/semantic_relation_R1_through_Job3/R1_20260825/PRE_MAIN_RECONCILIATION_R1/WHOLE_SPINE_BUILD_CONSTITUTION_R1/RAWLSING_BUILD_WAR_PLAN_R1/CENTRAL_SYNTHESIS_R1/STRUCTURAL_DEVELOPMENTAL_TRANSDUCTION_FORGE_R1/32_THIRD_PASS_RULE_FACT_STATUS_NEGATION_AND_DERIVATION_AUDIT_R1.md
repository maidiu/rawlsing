## 2. Primary-source regression behind this pass

Fresh source checks reinforced the need for these distinctions.

### Dreier

Dreier distinguishes contextual possibilities, positions, participation and personal realization. A position supplies a scope of possibilities but does not itself determine what a person actually does. Coparticipants jointly realize contextual practices, and the consequences of one person's action are not produced by intention alone.

Architectural consequence:

```text
POSITION / CONTEXTUAL POSSIBILITY
!= ACTUAL PARTICIPATION
!= EXTERNAL RESULT
!= SUBJECTIVE REASON
```

### Wright

Wright explicitly distinguishes nominal supervisors from actors with real sanction/command authority, and credential possession from productive deployment. He also treats some relational properties as derivable from actual asset/control relations rather than from nominal labels.

Architectural consequence:

```text
NOMINAL TITLE != RELATIONAL POWER
CREDENTIAL POSSESSION != DEPLOYED RELATIONAL CONSEQUENCE
```

but also:

```text
SOME RELATIONAL FACTS MAY FOLLOW CONSTITUTIVELY
FROM AN ADMITTED RULE/ASSET/POSITION CONFIGURATION
WITHOUT A SEPARATE DISCRETE EVENT.
```

### Kohn / Schooler and Mortimer

They preserve objective work conditions separately from subjective appraisal and repeatedly insist that actual task content, supervision and activity matter more than title. Their evidence also shows that observed associations and latent constructs cannot be treated as direct actor-world facts.

### Palestine / SRT materials

Permit eligibility, checkpoint passage, service capacity, infrastructure condition, actual work commute, household task transfer and care provision form multi-stage chains. Formal eligibility can exist without passage; service rules can exist without current capacity; physical infrastructure conditions can alter institutional service capacity.

These source patterns support the third-pass findings below.

## 3. F10 — R3 needs an explicit consequence/assertion-kind distinction

R3 currently uses a broad ladder:

```text
QUALIFIED / APPLICABLE
!= ACTIVE / REALIZED
```

and requires a witness for `ACTIVE/REALIZED` outputs.

That is directionally correct but still overcompresses several semantically different objective fact kinds.

At minimum the post-review adjudication should distinguish:

```text
A. CONSTITUTIVE / DEONTIC / POSITIONAL DERIVATION
   an objective relation follows from a valid rule + admitted position/state;
   examples: legal eligibility, active duty/obligation, authority scope,
   entitlement, valid restriction, relation-defined dependency.

B. QUALIFIED POSSIBILITY / REACHABILITY
   an objective route/opportunity/channel is available or applicable;
   examples: eligible application route, reachable counterpart,
   permitted action, possible service use.

C. CONTINGENT REALIZED OCCURRENCE / TREATMENT / TRANSFER
   an external process actually occurs;
   examples: gatekeeper decision, sanction event, resource transfer,
   contact, information delivery, attendance/performance.

D. RESULTANT ACTIVE STATE
   a witnessed occurrence or source-state change establishes a persistent
   condition/relation that remains current over an interval;
   examples: current job loss state, ongoing benefit receipt,
   active service denial state, changed household task allocation.
```

These are not four new owners. They are assertion/status semantics needed to decide what counts as sufficient proof.

### Why this matters

A valid law plus an actor's exact status may be sufficient to derive **eligibility** or **obligation** as an objective constitutive fact. Requiring an extra event-like realization witness for the mere existence of the right/duty would overbuild.

By contrast, the same law does **not** prove application, treatment, receipt, use or enforcement.

Therefore:

```text
CONSTITUTIVE FACT
MAY BE PROVED BY RULE + ANTECEDENT FACTS UNDER COMPETENT AUTHORITY

CONTINGENT REALIZED FACT
REQUIRES A SEPARATELY OWNED OCCURRENCE/STATE WITNESS
```

R3's witness law should be interpreted or narrowed accordingly after review.

Suggested metadata name, nonbinding:

`CONSEQUENCE_ASSERTION_KIND`.

## 4. F11 — negation and unknown require general project-wide protection

R3 correctly says active nonaccess may not be inferred from missing evidence, and the R3 reviewer commission explicitly contains a negation court. The third pass finds this needs to become a **general D1' law across P1–P5**, not a P1 example.

Binding candidate:

```text
MISSING EVIDENCE
!= NEGATIVE FACT
!= EXPLICIT DENIAL
!= EXPIRED FACT
!= INAPPLICABLE FACT
!= UNKNOWN FACT
```

Examples:

```text
no recorded benefit transfer
!= proved nonreceipt

no recorded command
!= proved absence of authority

no activity witness
!= proved nonparticipation

no gate decision record
!= denial

no observed contact
!= no channel

no support record
!= no support received
```

A negative D1' fact requires one of:

```text
EXPLICIT NEGATIVE SOURCE/WITNESS;
COMPETENT COMPLETE/EXHAUSTIVE SOURCE SCOPE;
GOVERNED CLOSED-WORLD RULE AT THAT EXACT GRAIN;
EXPLICIT DENIAL/REJECTION/TERMINATION/EXPIRY EVENT OR STATE.
```

Otherwise the correct state is `UNKNOWN / UNPROVED / NO_CURRENT_WITNESS`, not negative actor truth.

This is especially important for nonmodal actors and sparse social histories.

## 5. F12 — constitution currentness, rule currentness and fact currentness must be separate

R3 now requires exact `MECHANISM_RULE_REF`, but the governance consequence should be stated more forcefully:

```text
D1' CONSTITUTION HQ-ADOPTED
!= ANY MECHANISM RULE HQ-CURRENT
!= ANY RULE APPLICATION CURRENT
!= ANY POSITIVE ACTOR FACT CURRENT
```

The theory atlas and P1–P5 classes remain **evidence/normalization artifacts**. They do not automatically populate a runtime rule registry.

After any future HQ adoption of D1', each executable rule still requires competent admission/currentness at its own grain.

No rule may become current merely because:

- it appears in a mechanism card;
- multiple theory lanes support it;
- a source reports an association;
- a plausible implementation exists;
- a mechanism class is adopted;
- D1' would be unable to do useful work without it.

This should become an explicit post-adoption governance law.

## 6. F13 — multi-step composition needs an auditable derivation graph

R3 permits composition of P1–P5 and stores broad `DERIVATION_PROVENANCE`, but does not explicitly require the **direct antecedent fact graph** for each derived fact.

That becomes dangerous in chains such as:

```text
infrastructure damage
-> service capacity reduction
-> actor access constraint
-> household task/resource reallocation
-> linked person's time obligation
```

or:

```text
institutional mark
-> gate presentation
-> gate treatment
-> job nonaccess
-> income/resource state
-> household transfer change
```

The third pass recommends mandatory direct dependency fields at rule-application grain:

```text
RULE_APPLICATION_ID
DIRECT_ANTECEDENT_FACT_REF(S)
DIRECT_SOURCE/WITNESS_REF(S)
DERIVED_FACT_REF
VALID_TIME
DERIVATION_DEPTH OR PARENT STEP REFS
```

### Invalidation law

If an antecedent becomes invalid, superseded or corrected, all dependent D1' facts must be discoverable for determinant-scoped recomputation.

### Circularity law

Same-time self-support is forbidden unless an exact competent owner defines a lawful fixed-point/iterative process.

Forbidden default pattern:

```text
FACT_A_t -> FACT_B_t -> FACT_A_t
```

merely because both rules are individually plausible.

Iterative/cumulative feedback must instead preserve time/state advancement or an explicitly governed fixed-point semantics.

### Evidence ceiling propagation

A derived fact may not silently acquire stronger causal/evidentiary/portability authority than its rule and antecedents permit.

At minimum:

```text
DERIVED AUTHORITY / EVIDENCE CEILING
<= GOVERNED RULE + REQUIRED ANTECEDENT AUTHORITY
```

No inference laundering through composition.

## 7. F14 — counterfactual/projected consequence must remain distinct from current truth

The D1' constitution is likely to be useful for simulation, planning, alternative trajectories and counterfactual evaluation. That creates another noncollapse requirement:

```text
CURRENT ADMITTED FACT
!= COUNTERFACTUAL DERIVATION
!= PROJECTED/PREDICTED CONSEQUENCE
!= QUALIFIED POSSIBILITY
```

A mechanism rule may support questions such as:

> If this actor entered position X under rule Y, what objective consequences would follow?

but the result must remain counterfactual/projected unless the required world/position facts and realization conditions become current under competent authority.

Suggested metadata, nonbinding:

`FACT_MODALITY = CURRENT | QUALIFIED | COUNTERFACTUAL | PROJECTED`.

No counterfactual fact may leak into biography or current V3 state.

## 8. F15 — D1' inputs must allow competent physical/material world facts without category leakage

R3 calls its inputs `STRUCTURAL_SOURCE_FACTS` and generally speaks of social/structural facts. The source corpus includes chains where a competent **nonpsychological material/world fact** is causally relevant to a social consequence:

```text
power/infrastructure outage
-> service capacity
-> actor-specific access/wait/substitute route

transport disruption
-> travel-time/schedule constraint
-> work/care activity consequence
```

The constitution should not force such facts to masquerade as structural/social facts before they can participate.

Post-review clarification should permit exact competent:

`OBJECTIVE_WORLD / MATERIAL SOURCE FACTS`

when a governed social mechanism rule lawfully consumes them.

This does not create environmental determinism. The material fact still requires exact actor/context/relation routing before it becomes a D1' consequence.

Likewise, externally source-owned bodily/biographical facts may be inputs only when the **social rule itself** uses them (e.g. legal age or an explicit institutional eligibility criterion). No private psychology follows.

## 9. F16 — P4 should be process-defined, not bureaucracy-defined

R3 names P4:

`INSTITUTIONAL_GATE_TREATMENT`.

The important irreducible semantics are actually:

```text
EXACT RULE / CRITERIA
+ APPLICANT/TARGET/CUE/RECORD
+ GOVERNED EVALUATION/SELECTION/TREATMENT PROCESS
-> DECISION/TREATMENT RESULT
```

Many high-quality source cases are formal institutions, which makes the current name natural. But the architecture should not create a false boundary where an equally governed gate/evaluation process is informal or semi-formal.

Examples that may need the same semantics include selection/admission by:

- employer or landlord;
- school/clinic/office;
- organized peer group;
- household/kin authority arrangement;
- platform/market intermediary;
- other exact counterpart with a real selection/evaluation role.

Therefore the post-review court should decide whether:

1. P4 keeps its current name but is defined semantically as `GOVERNED_GATE_EVALUATION_TREATMENT`; or
2. the class is renamed without changing the five-class topology.

Do **not** broaden P4 into generic interpersonal recognition. Where there is no actual gate/evaluation/treatment transformation, P2/P5/event semantics remain more appropriate.

## 10. F17 — source construct / measurement / runtime-fact binding remains separate

R3 correctly says theory card != executable rule and regression coefficient != actor truth. A related seam still deserves explicit protection:

```text
SOURCE CONSTRUCT / INDICATOR
!= RUNTIME WORLD FACT TYPE
```

Examples:

- occupation title cannot stand in for substantive complexity;
- a survey's occupational self-direction factor cannot silently become an actor state;
- country classification cannot become institutional configuration;
- group-coded deprivation cannot instantiate actor resource shortage;
- a credential variable cannot prove productive credential deployment.

A mechanism rule that consumes source-backed facts needs an exact semantic/type binding from the source fact to the rule input, under existing source/measurement authority where required.

Suggested rule-contract addition, nonbinding:

```text
INPUT_FACT_SCHEMA_REF(S)
SEMANTIC_BINDING / SOURCE-MAPPING AUTHORITY REF(S)
```

This is not a new D1' owner. It prevents rule authority from laundering a measurement shortcut.

## 11. F18 — causal-use authority should be distinguished from source citation

R3's rule contract includes `SOURCE / CLAIM STATUS`, `CALIBRATION STATUS`, owner and authority. The third pass recommends making the causal-use distinction explicit:

```text
SOURCE SUPPORTS ASSOCIATION/THEORY
!= SOURCE AUTHORIZES THIS EXECUTABLE CAUSAL RULE
```

A production rule registry should therefore identify the competent causal-use/admission basis for the rule, not merely cite evidence.

Possible field, nonbinding:

`CAUSAL_USE_AUTHORITY_REF`.

This is particularly important for observational Kohn/Schooler, Mortimer, Elder and cumulative-inequality findings whose mechanism value is strong but whose coefficients do not license unconditional actor-level causal execution.

## 12. Third-pass scenario replay

### S32-01 — legal eligibility but no application

Rule + actor facts may constitutively establish `ELIGIBLE`.

They do not establish:

```text
APPLIED
EVALUATED
APPROVED
RECEIVED BENEFIT
```

Result: `PASS ONLY WITH ASSERTION-KIND DISTINCTION`.

### S32-02 — active care obligation but no care performed today

A valid relation/rule may establish an active obligation. Actual care performance is a distinct recurrent-activity realization.

Result: `PASS ONLY IF ACTIVE OBLIGATION != PERFORMED ACTIVITY`.

### S32-03 — no callback record

Absent data cannot mean denial unless the data source is complete at the exact gate/time grain or a denial is explicitly witnessed.

Result: `R3 NEEDS GENERAL NEGATION LAW`.

### S32-04 — two D1' rules form an accidental same-time loop

```text
resource scarcity -> exit constraint
exit constraint -> resource scarcity
```

Without an antecedent DAG/time law, each could recursively justify the other.

Result: `DIRECT DERIVATION GRAPH / CYCLE LAW REQUIRED`.

### S32-05 — model asks what would happen after a hypothetical promotion

D1' may derive counterfactual authority/task/resource consequences but may not write them to current actor history.

Result: `FACT MODALITY SEPARATION REQUIRED`.

### S32-06 — power plant outage reduces clinic service capacity

A source-owned material/world fact lawfully participates in a rule chain to service capacity and actor access. It should not be excluded because the first antecedent is physical rather than social.

Result: `OBJECTIVE WORLD INPUT CLARIFICATION REQUIRED`.

### S32-07 — peer group selects a new member using explicit criteria

The causal form resembles gate/evaluation treatment even if it is not a state bureaucracy.

Result: `P4 SEMANTIC SCOPE SHOULD BE PROCESS-DEFINED`.

### S32-08 — occupational self-direction score maps directly to actor work state

Rejected without exact source/runtime semantic binding to first-order task/control facts.

Result: `SOURCE CONSTRUCT != RUNTIME FACT`.

### S32-09 — HQ adopts D1' but no mechanism rules are separately adopted

Correct outcome: D1' semantic authority may exist while the executable rule registry remains empty/partial and no new actor facts are produced.

Result: `CONSTITUTION CURRENTNESS != RULE CURRENTNESS != FACT CURRENTNESS`.
