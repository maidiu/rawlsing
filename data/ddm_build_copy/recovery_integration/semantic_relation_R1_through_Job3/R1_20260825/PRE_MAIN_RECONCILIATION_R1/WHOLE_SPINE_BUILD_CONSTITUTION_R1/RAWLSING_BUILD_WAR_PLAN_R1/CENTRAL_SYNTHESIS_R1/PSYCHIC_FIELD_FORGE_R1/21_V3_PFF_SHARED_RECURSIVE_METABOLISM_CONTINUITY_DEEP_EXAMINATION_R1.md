**Status:** `PRE_ARCHITECTURE_CONCEPT_EXAMINATION__BANKED__MUST_FACTOR__NOT_ARCHITECTURE_ADOPTION__NO_RUNTIME_AUTHORITY`

## 0. Purpose

This examination addresses a major placement refinement raised during direct Vozhd/user synthesis:

> PFF may not be best understood as a wholly separate post-V3 layer that starts only after V3 has finished generating/developing a person. The psychic transition mechanisms needed for live user interaction may substantially overlap with mechanisms already required inside V3's recursive developmental movement. The same person-specific metabolism may operate in two temporal regimes: long-horizon generated-life recursion and fast conversational recursion.

This file asks whether the correct conceptual relationship is closer to:

```text
ONE DEVELOPED PERSON
+ SHARED PERSON-SPECIFIC TRANSITION / METABOLISM LOGIC

used in:

A. V3 life-course recursion
B. PFF interaction-time recursion
```

rather than:

```text
V3 finishes person
-> separate PFF psychology box
-> V2 response
```

No shared module, kernel, service, class, state store, scheduler, LLM contract, or ownership boundary is adopted here.

## 1. Immediate holding

The current strongest pre-architecture hypothesis is:

`PFF_IS_NOT_MERELY_A_V3_POSTPROCESSOR`

`PFF_MAY_BE_FAST_TIMESCALE_RECURSIVE_PSYCHIC_METABOLISM_OVER_THE_SAME_V3_PERSON`

`V3_DEVELOPMENTAL_RECURSION_AND_PFF_CHAT_RECURSION_MAY_SHARE_SUBSTANTIVE_TRANSITION_LOGIC`

but:

`SHARED_TRANSITION_LOGIC != SHARED_PERSISTENCE_AUTHORITY`

`SHARED_TRANSITION_LOGIC != V3_OWNS_PHENOMENOLOGY`

`SHARED_TRANSITION_LOGIC != PFF_CAN_WRITE_DURABLE_V3_STATE`

`SHARED_TRANSITION_LOGIC != ONE_RUNTIME_OBJECT`

This distinction is central.

## 3. Central conceptual distinction: one person, two recursive regimes

A useful current model is:

### 3.1 Developmental recursion

The person moves through generated life.

Possible inputs include, where separately governed:

- encounters;
- relationships;
- successes/failures;
- losses;
- opportunity/exposure;
- rupture;
- practices;
- material/organismic changes;
- remembered prior events;
- internal states;
- social feedback;
- changing expectations and strivings.

The recursion may produce lawful durable consequences such as:

- changed expectation;
- changed striving;
- reinforced/weakened mediator;
- new tension/practice;
- relationship change;
- memory consequences;
- self-model consequences;
- changed attractor trajectory;
- other V3-owned persistent state.

The exact durable mutation remains governed by V3 transition authority.

### 3.2 Interaction-time recursion

The generated person is conversing with the user.

The user contributes actual observable discourse/actions.

The person undergoes:

- current perception/interpretation;
- persona-specific recruitment;
- activation/inhibition/conflict;
- live relational chemistry;
- metaperception / being-seen effects;
- conscious-field changes;
- defense/performance/leakage pressure;
- anticipation of the user's response;
- expression;
- self-observation of expression;
- response to the user's next move.

This repeats every turn.

The recursion is therefore real development **within the interaction**, even when no off-screen life time, age, job history, household history, or world simulation advances.

## 4. Two clocks must not be collapsed

The user's formulation exposes a crucial temporal distinction.

Conversation may advance one sequence while leaving another effectively stationary.

Conceptually preserve:

### 4.1 Interaction / causal sequence

Each user/person exchange creates a new ordered interaction position:

`turn t -> turn t+1`.

The persona has actually experienced the prior turn.

Its live psychic state may therefore differ.

### 4.2 Life-course / age / world-development time

The wider generated world need not automatically advance:

- no automatic birthday;
- no automatic yearly aging;
- no automatic job change;
- no automatic off-screen relationship events;
- no automatic world developments;
- no automatic slow-process update merely because another chat message occurred.

Thus:

`TURN_CURSOR_ADVANCE != AGE_ADVANCE`

`INTERACTION_EXPERIENCE != OFFSCREEN_WORLD_PROGRESSION`

`CHAT_RECURSION != YEARLY_STEP`

`NO_AGE_ADVANCE != NO_PSYCHIC_CHANGE`

This is strongly compatible with WSC001F's refusal to make annual cadence constitutive of V3 runtime.

## 5. The interaction itself can be a genuine experience

The user is not merely supplying prompt text.

From the generated persona's perspective, the user interaction can be an actual relational experience.

Therefore a user message can lawfully be relevant to:

- present emotion;
- perceived acceptance/rejection;

- trust/suspicion;

`USER_MESSAGE != AUTOMATIC_DURABLE_V3_EVENT_EFFECT`

The interaction may first alter only live/session state.

A separately constituted causal-return/admission path must decide which consequences, if any, become durable generated-person history.

## 9. The two-LLM-call idea fits unusually well

The present PFF vision already wants two logically separate LLM-facing operations:

1. an input-side discourse interpretation/encoding function;
2. a final surface renderer.

Historical V3 design capital independently preserved a two-pass LLM pattern:

1. optional `LLM_PROPOSAL` constrained by deterministic/governed admission;
2. render-only second pass.

The two are not automatically identical.

In particular:

- historical V3 Pass 1 proposed candidate generated events/developmental material;
- PFF's proposed input-side call interprets actual interaction into bounded interaction signals/competing readings.

But structurally they share a very important law:

`FIRST_LLM_CALL != STATE_AUTHORITY`

and:

`SECOND_LLM_CALL != CAUSAL_AUTHORITY`

This suggests a common design principle:

```text
LLM-A: perceive / interpret / propose within a bounded ontology

NON-LLM/GOVERNED CORE: decide state consequences under actual person state and authority

LLM-B: realize lawful surface expression
```

The exact number of calls remains architecture work. Two calls are a strong fit, not yet an adopted requirement merely because both historical V3 and current PFF point that way.

## 10. Why one call is conceptually dangerous

A one-call chat design tends to collapse:

```text
user message
+ persona dossier
+ history
-> model invents internal state and response simultaneously
```

That destroys several Rawlsing requirements:

- encoder output can silently become psyche truth;
- actor knowledge and machine causal account collapse;
- hidden causes can leak into first-person explanation;
- no independent person-specific transition can be replayed/falsified;
- renderer wording can retroactively look like evidence of psychology;
- live state becomes prompt ephemera rather than actual recursion.

The two-call structure creates space for an independently governed middle.

The crucial feature is not simply `2` calls. It is:

`PERCEPTION/PROPOSAL AUTHORITY != PSYCHIC TRANSITION AUTHORITY != RENDER AUTHORITY`.

`CHAT_TURN_CAN_CHANGE_THE_PERSON_NOW`

`CHAT_TURN_NEED_NOT_REWRITE_THE_PERSON_DURABLY`

This is not contradiction. It is a timescale/commit distinction.

## 13. Recursive development does not mean every fast state becomes history

Shared metabolism must not erase persistence boundaries.

A live conversation can produce:

- momentary activation;
- session residue;
- relationship-live sensitization;
- actor self-discovery;
- a durable life event.

These are not automatically equivalent.

The mechanism may be continuous while the **persistence destination differs**.

Thus:

`SAME_CAUSAL_PROCESS_FAMILY != SAME_STATE_DESTINATION`

`LIVE_RECURSION != AUTOMATIC_CHECKPOINT_MUTATION`

`DURABLE_V3_COMMIT_REQUIRES_EXACT_ADMISSION`

## 14. The user remains epistemically opaque

The shared-recursion view does not create a hidden model of the human user.

In chat, the generated person's transition must proceed from:

- the user's observable contribution;
- lawful conversation context;
- prior user/person interaction history;
- the generated person's own expectations/models;
- uncertainty and competing readings.

Therefore:

`USER_ACTUAL_HIDDEN_STATE != PFF_INPUT_FACT`

The person may form live hypotheses about the user, just as a human does.

Those hypotheses can be wrong and still have real consequences for the generated person's recursion.

## 15. Generated-generated interaction remains secondary

The current primary product locus remains:

`GENERATED_PERSON <-> USER`.

Generated-generated interaction may become relevant elsewhere, for example if upstream V3 generation requires parent/co-parent interaction, household development, or future multi-person generated scenes.

If such a case is separately grounded, the same shared-recursion hypothesis could become useful there.

But it must not displace the current user-facing PFF problem.

## 16. Parent/co-parent nexus implication

The user's parent/co-parent example exposes a possible upstream application.

If V3 generates two parents as independently developed persons whose encounter/relationship/household history contributes to later child generation, then realistic parent/co-parent development may require the same kinds of person-specific relational metabolism:

- each interprets the other through their own history;
- chemistry/anti-chemistry emerges through repeated interaction;
- conflict and repair affect relationship history;
- significant exchanges become V3 causal events;
- the resulting household/relational history becomes part of the child's causal ancestry/environment.

This is conceptually plausible and consistent with historical V3 genealogy design capital, which preserved:

`Parent1 + Parent2 independent development -> encounter -> relationship -> household -> ChildGenerated -> child development`.

However, no current PFF expansion into a generated-generated simulation owner is adopted here.

## 17. A possible three-layer state view without three separate psychologies

One useful way to think without selecting architecture:

### Layer A — durable person

V3-owned generated causal state/history.

### Layer B — live recursive psychic configuration

Fast-changing, relationship-/situation-specific state generated by the person's current interaction with environment/user.

### Layer C — surface expression

Current actor-limited realization into observable discourse/action.

The same person-specific causal logic can operate across A and B while ownership/persistence remains distinct.

This yields:

`DURABLE_PERSON -> LIVE_CONFIGURATION -> EXPRESSION`

and recursive return:

`EXPRESSION/ENVIRONMENTAL_RESPONSE -> LIVE_CONFIGURATION`

with selective durable admission:

`SIGNIFICANT_LAWFULLY_ADMITTED_EXPERIENCE -> DURABLE_PERSON_UPDATE`.

This is continuous recursion, not one-way layering.

## 18. Implication for the four depth bands

The D/C/B/A bands may be better understood within a recursive process rather than a feed-forward stack.

- D supplies durable causal organization and receives only lawfully admitted lasting change.
- C is a standing actor self-model/ordinary conscious organization continuously pressured by D and B.
- B is current relation-specific recruitment and live configuration.
- A is observable expression which itself becomes new experience/evidence and therefore feeds back into B/C and potentially D.

So:

```text
D <-> C <-> B -> A
          ^      |
          |______|
```

is closer to the phenomenon than:

```text
D -> C -> B -> A -> done
```

No graph architecture is adopted by this notation.

## 19. Implication for the definition of `RAW`

If the shared-recursion hypothesis survives, RAW should become even less like a second person database.

A better conceptual possibility is:

> RAW or its successor represents the **fast-timescale unresolved working configuration** of the same V3 person during interaction.

It may contain/refer to:

- currently recruited durable structures;
- live conflicts;
- current social hypotheses;
- residue from prior turns;
- current access/salience changes;
- current defense configuration;
- unresolved prospective states;
- relationship-specific local condition.

It should not duplicate:

- complete biography;
- all memories;
- durable needs/strivings;
- permanent self-model;
- attractor history;
- causal relationship history.
