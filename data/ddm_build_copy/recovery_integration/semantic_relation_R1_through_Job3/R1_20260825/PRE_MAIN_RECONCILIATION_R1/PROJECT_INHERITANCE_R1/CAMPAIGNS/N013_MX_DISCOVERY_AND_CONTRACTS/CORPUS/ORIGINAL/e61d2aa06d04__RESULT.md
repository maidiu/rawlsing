## 1. Question adjudicated

MX01 asks whether the current candidate-neutral PRE553 query/discovery object model can preserve and replay the strongest historical V549/V549b recursive function:

`parent branch -> exact respondent cohort -> discovered child -> branch-conditioned same-respondent cotravel -> recursive descendant at depth > 1`

The answer is **not yet**.

The current common model is substantially closer than the archaeology state implied, but it stops at the generation boundary needed to make one discovered branch the lawful parent of the next discovered branch.

### 3.2 One-generation recursive child conditioning — PASS

- `RECURSIVE_SUBGROUP_FORK`;

- `BRANCH_CONDITIONED_COTRAVEL`.

For `SINGLE_ATOM`/conjunction rules, `_compile_frontier` takes the declared branch baseline and AND-composes it with the selected child condition. `_combine_predicates` requires the component predicates to share the exact grammar and same-respondent binding law and gives the compiled child predicate exact dependency refs to its input predicates.

That is real semantic progress: a child can be correctly evaluated *inside one bounded discovery invocation*.

## 4. The first irreducible gap

The first missing common capability is:

`DISCOVERED_CHILD -> CANONICAL_REUSABLE_PARENT_FOR_NEXT_DISCOVERY_GENERATION`

Current I05 compiles an exact child `EmpiricalPredicate` internally. The resulting public `DiscoveryResultReceipt` carries its exact `winning_predicate_ref` and depends on that ref.

But the public `ExactBoundedDiscoveryResult` returns:

- authority ref;
- grammar ref;
- evaluated frontier ref;
- receipts;
- empirical fact refs;
- valid-empty flag;
- replay ref.

It does **not** return a canonical catalog of the compiled winning `EmpiricalPredicate` objects or another public/resolvable branch object that can be supplied to `_catalog_atoms` in a later invocation.

That matters because `_catalog_atoms` consumes actual `EmpiricalPredicate` objects and resolves declared atom refs against that supplied object catalog. A bare `winning_predicate_ref` is not itself the next-generation predicate object.

The sealed C11 source repository also does not cure this: it resolves objects committed in the source release; current I05 does not commit its post-ingest compiled child predicates into that repository.

Therefore generation 2 currently requires one of the forbidden substitutes:

- caller reconstruction of the child predicate;
- private `_compile_frontier` state;
- pre-authoring the grandchild from the original fixture rather than consuming the discovered child;
- an out-of-band object store not bound by the current public contract.

Any of those would evade the experiment rather than close it.

## 5. Ancestry is also not yet an exact recursive edge contract

`DiscoveryResultReceipt.branch_or_parent_ancestry_refs` is explicitly set-like.

Moreover, current I05 obtains an atom's `ancestry_refs` from the **input candidate grammar** and passes those refs through to candidate/receipt ancestry. The existing recursive test proves that a supplied ancestry ExactRef survives; it does not prove that I05 automatically creates an exact role-bearing `CHILD -> PARENT` edge.

At depth > 1, a set of opaque ancestry refs cannot by itself distinguish:

- immediate parent;
- grandparent;
- other ancestry/evidence refs.

The compiled predicate dependency graph partly contains the needed direct dependencies, but the compiled child object is precisely the object that is not made publicly resolvable for the next generation.

So the two symptoms are one handoff problem, not two independent architecture demands.

5. a public/common next-generation consumption path;
