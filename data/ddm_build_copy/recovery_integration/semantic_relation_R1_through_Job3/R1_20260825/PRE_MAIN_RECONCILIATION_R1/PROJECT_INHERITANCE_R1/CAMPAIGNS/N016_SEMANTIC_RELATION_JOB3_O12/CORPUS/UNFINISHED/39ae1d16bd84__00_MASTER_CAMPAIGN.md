# FIELD FORGE — ARCHITECTURAL RECONNAISSANCE R1

## Mission

This campaign exists to reconstruct the **achieved architectural mind** needed to continue FIELD FORGE deep scheming without forcing each new architect chat to reread the entire Rawlsing history.

This is NOT a code-execution campaign and NOT a generic repo summary.

The target cognitive state is the state reached at the end of the FIELD FORGE architectural conversation now represented on `agent/field-forge-r1`: the re-imagined **Dva → Trii → Chetiri DAG remains the target architecture**; FIELD FORGE's theory-engineering stack remains an active design constitution; old Rawlsing machinery is excavated aggressively for already-paid-for engineering thought, but ancestry does not grant present authority.

The governing archaeological question for every historical mechanism is:

1. What problem was it actually solving?
2. How did it solve it?
3. Was the FUNCTION sound?
4. Which ontology / authority / substrate assumptions contaminated it?
5. Can the function be detached from those assumptions?
6. Does it already solve, sharpen, complicate, or embarrass a present FIELD FORGE proposal?
7. What must FIELD FORGE inherit, reinterpret, supersede, or reject?

The campaign must preserve both:

- **architectural anti-amnesia** — never fall backward into an older ontology because code exists;
- **engineering anti-amnesia** — never reinvent a poorer version of a mechanism Rawlsing already paid to discover.

## Repo-wide coverage law

Rawlsing contains hundreds of branches. Do NOT assume `main`, a current control branch, or one apparently-final branch contains the whole intellectual inheritance.

This campaign therefore uses two protections:

1. `R00` performs a total branch-family census and orphan detector across the entire repository.

No worker may claim completeness merely because it inspected a few final branches.

## Method law

- Reconnaissance, archaeology, and synthesis only. Do not implement new architecture.
- Do not treat tests passing as proof that an ontology is conceptually right.
- Do not treat historical finality, branch naming, or commit age as authority.
- Distinguish implementation inheritance from conceptual inheritance.
- Salvage at function granularity, not stage granularity.
- Search for negative results, rejected paths, corrections, supersessions, orphan goals, and branch-stranded work.
- Where multiple branches repeat one lineage, identify the family and isolate genuinely novel deltas rather than bloating the return with copies.
- Preserve exact branch/SHA/path receipts.
- If evidence conflicts, report the conflict. Do not harmonize it away.
- If a historical mechanism solved a present problem better than FIELD FORGE currently does, say so explicitly.
- If a present FIELD FORGE conception has no historical support and is genuinely new, say so explicitly.
