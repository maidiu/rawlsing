# DOMINANCE AND MERGE ANALYSIS R1

## Decision

Eight mandatory experiment families reduce to five experiments without losing a discriminating question.

## 1. E1 + E3 + E8 merge into MX03

These three families differ mainly in **which identity is checked after the same destructive event**.

Common operation:

```text
record durable identities
-> delete transformed/intermediate empirical payload
-> reopen exact source + semantic/authority/replay side material
-> rebuild in fresh process
-> compare identities/semantics/refs
```

E1 asks whether logical named-source C11 is exact.
E3 asks whether the release can be reconstructed after carrier deletion.
E8 asks whether an accepted learned release remains a stable historical semantic object after the same intermediate deletion.

A second destructive harness for E8 would duplicate almost all work. Therefore MX03 has two authority-gated phases:

- Phase A: C11/replay now, using accepted AS2B LiTS-I;
- Phase B: learned-product identity only after a lawful accepted learned release exists.

The merge is causally interpretable because a failure is localized by identity layer: source/C11 versus learned release.

## 2. E4 + E7 merge into MX04

A hard-seam versus continuous-DAG comparison is meaningful only if both execute the **same vertical semantic graph**. E7 therefore supplies the parity harness E4 would otherwise have to build separately.

MX04 holds semantics fixed and changes one physical variable:

- `HARD_SEAM`
- `CONTINUOUS_DAG`

This is an efficient merge because the common vertical object graph is the control.

The experiment remains phased where authority is missing. Positive validation/PSEPF branches cannot be invented merely to make the vertical graph look complete; they must return typed blocked states until authority closes.

## 3. E5 must not be merged into A/B/C economics

Recursive branch topology is a common semantic-capability gap. If it were embedded only inside MX05 and a candidate failed or ran slowly, the result would conflate:

- missing common semantic representation;
- candidate adapter defect;
- physical carrier cost;
- search algorithm behavior.

MX01 isolates the semantic question first. Once it passes, the resulting exact workload/oracle may be included identically in MX05.

## 4. E6 must not be merged into A/B/C economics

The same logic applies to component-vector authority. A cheap scalarized implementation is not a performance winner; it is a non-parity implementation.

MX02 therefore determines the common representation/scalarization obligation before carrier ranking.

## 5. MX01 and MX02 should not be merged with each other

Both are small, synthetic/common-contract tests, but their failure implications are different:

- MX01 failure concerns empirical recursive cohort topology and discovery replay;
- MX02 failure concerns structural component-grain authority and scalar projection.

Combining them saves little setup while making a failure less local. They run in parallel instead.

## 6. E2 remains standalone as MX05

Performance must be temporally downstream of semantic parity. Merging performance into any semantic-closure experiment would create incentive to define the capability around whichever candidate is cheapest.

MX05 therefore consumes the outputs of the closure/parity experiments but does not own them.

## 7. Why no separate WVS7 experiment is added

WVS7 documentary/source-cert recovery is already active work with a precise fail-closed HQ join. Recreating a WVS7 experiment here would duplicate a prerequisite campaign and add no architectural information.

The first named-source discriminator uses LiTS-I. WVS7 remains a gate for any later two-source/full-C09 conclusion where governing law still demands it.

## 8. Why no C07 authority experiment is added

Missing positive validation, comparability, PSEPF-model or source-composition authority is not empirically discoverable by a benchmark. An experiment cannot vote a semantic permission into existence.

Those courts are prerequisite governance surfaces. Experiments consume adopted authority or emit typed blocked states.

## 9. Information-gain ordering

1. **MX01 / MX02 / MX03A in parallel** — very high information, small work, distinct failure causes.
2. **MX04** — high information about physical seam necessity and hidden courier assumptions, medium work.
3. **MX05** — very high economic information but only after upstream parity; running early would have low lawful information value despite high compute cost.

## 10. Minimality claim

Removing any of the five loses a distinct unresolved proposition:

- remove MX01 -> recursive functional gap survives;
- remove MX02 -> component-authority gap survives;
- remove MX03 -> named-source carrier/rebuild proposition remains untested;
- remove MX04 -> hard seam versus continuous DAG and whole vertical courier assumptions remain untested;
- remove MX05 -> no actual lifecycle economic discrimination occurs.

Adding separate E1/E3/E8 or E4/E7 harnesses duplicates work without adding comparable information.
