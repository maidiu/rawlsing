# VMESTYE — EVIDENCE, DISPOSITIONS AND FALSE-CERTAINTY LAW
## Each finding has five independent dimensions
**Obligation:** historically valuable/modern still required, validly superseded, obsolete mechanic, outside jurisdiction, unclear.
**Implementation:** original historical source; installed protected; reviewed branch candidate; unreviewed branch; documentary only; absent proved; uninspected.
**Authority:** raw issuer/source; rule/row known; selected at cut; application observed; negative enforced; first consumer; currentness established. A hash without a rule read is not application.
**Behavioral proof:** S0 document; S1 source/callsite; S2 synthetic/fixture executed; independently reviewed scoped tests; original native receipt where issued; whole selected terminal original35 integration (requires separate legitimate issuer and review).
**Consumption:** actual non-test call; actual test-only first consumer; planned/justified future consumer; none yet; consumer unknown. A downstream use case alone is not an invocation.

## Functional conservation statuses (one terminal disposition per row *at a cut*)
`PROVED_CURRENT_SUCCESSOR` — current exact semantic owner + current implementation + exact proper test/receipt + actual consumer where required.
`PROVED_STRONGER_SUPERSESSION` — old valuable function is demonstrably equaled/strengthened by new one with exact negative and semantics preserved.
`PARTIAL_SUCCESSION` — some valuable function actually exists, but specified input/output/grain/rule/reader not fully closed.
`OPEN_FUNCTIONAL_GAP` — evidence demonstrates valuable required behavior absent from the relevant current implementation or consumer, with named owner.
`OPEN_PROOF_GAP` — adequacy/selection/execution not proved; absence NOT asserted.
`HISTORICAL_HEURISTIC_ONLY` — old mechanic was contingent rather than a binding function; its independently valuable part is separately handled.
`ACCIDENTAL_OR_OBSOLETE_MECHANIC` — evidence shows no independent valuable function at current semantic grain.
`OUTSIDE_PREV3__EXACT_OWNER` — truly actor/V3 or other jurisdiction with recipient ID and continued conservation duty, not deletion.
`DUPLICATE_OR_ALIAS` — exact same function-grain canonical ID given.
`NOT_INSPECTED` — coverage work remains.
These are VMESTYE descriptive candidate statuses. For inherited Long Memory terminal legal disposition retain Authority39's six classes exactly (`CURRENTLY_PROVED`, `CURRENTLY_PROVED_BY_STRONGER_SUPERSESSION`, `CURRENTLY_OPEN_FUNCTIONAL_GAP`, `CURRENTLY_OPEN_PROOF_GAP`, `OUTSIDE_CURRENT_PREV3_JURISDICTION__EXACT_OWNER_IDENTIFIED`, `FORMALLY_RETIRED__NO_VALUABLE_FUNCTION_LOST`) when issuing final accepted LMX verdict. Do not silently substitute this richer analysis taxonomy for the adopted one.

## Every status has EVIDENCE + FALSIFIER + OWNER
A row claims functional proof only if `current_owner`, `implemented_symbol_at_sha`, `behavior_receipt` and required `consumer_edge` all exist and support the exact claim. Sourcefree tests may establish some same-grain behavior at sourcefree scope but NEVER native original35 qualification. A partial row must specify precise preserved and missing sub-operations, no generic `PARTIAL`.

## Three central failure modes
1. **Schema similarity:** Same field name, no behavioral proof. Cannot award equivalence.
2. **Authority laundering:** Valid manifest/snapshot reference, but the rule's selected semantic effect is not applied or required negative not enforced.
3. **History-to-present leap:** Old code/test, new documentary obligation, branch candidate and current protected code collapsed into one fictitious pipeline.

## Negative evidence is capital
Preserve typed `REJECT`, `BLOCKED`, inapplicable, no-answer, absent, zero observed, unknown routing, unmet eligibility, noncomparable, not-run, unreviewed and scientifically held distinctly. Restore/mutation negative tests count only for the particular edge proved. Do not equate no search hit to historical absence or a no-selected-current-operation hold to a proved severance.

## Compare against existing five-test decision law
Before `BUILD_NEW`: (1) exact current necessity; (2) prove no adequate lawful successor; (3) actual first-consumer need; (4) suitability/permissions/semantic grain; (5) comparative reuse/compose/repair/new/hold cost. Source: [PROGRAMMA historical function succession law](https://github.com/maidiu/rawlsing/blob/7a5429ffbc48efd25e28c912da80c822e66bc182/PYAT_CONTROL_ROOM/PROGRAMMA_PYAT/05_HISTORICAL_FUNCTION_SUCCESSION_AND_WORK_SELECTION_LAW_R1.md).

## First concrete challenge to any claimed `PROVED`
Ask: which input was present, what changed in the output if the governing rule changed, which original refusal was preserved, did the actual consumer read it, and what exact test proved each? If any answer unproved, narrow the claim.
