# FFIF007 — CLAIM-COMPLETENESS CRITERIA

## 1. Ruling

`CLAIM_COMPLETE`, not `METHOD_COMPLETE`, is the correct finite target. The phrase is lawful only under the mechanical criteria below.

## 2. Required inputs

No closure generation begins without exact:

- CIM proposition and comparison hashes;
- atomic normalized assertion slots;
- independently authorized bundle/co-requirement contract;
- CITC row per slot/loss dimension;
- support/uncertainty contract;
- common semantic input hash;
- constitutive TTAR/PRA/measurement/role refs;
- source-native ancestry ceiling.

If the broad claim has not been split into atomic slots, return `CLOSURE_BLOCKED__CLAIM_NOT_NORMALIZED`.

## 3. Finite generation procedure

### G0 — assertion-slot carrier generation

For each constitutive slot, nominate every currently known lawful object specification whose primitive interface can answer it. Include the direct source/substrate projection whenever it suffices.

### G1 — full-bundle carrier generation

Nominate each currently known single AOS that could answer the complete bundle within CITC, including claim-specific composites already lawfully specifiable before outputs.

### G2 — commitment-lowering challenge

For every nominated stronger object, generate the finite obvious projections that remove nonconstitutive commitments while retaining the claim interface, including as applicable:

- coordinates -> distance -> order/neighborhood;
- full configurations -> direct existence/support/conditional projection;
- graph/hypergraph -> exact incidence/connectivity projection;
- latent/model object -> direct predictive/conditional object where the claim is only target prediction;
- motif inventory -> exact registered signature predicate;
- transport view -> local-only object when transport is not in the claim.

Each generator is a preregistered rule, not an outcome-dependent invention.

### G3 — project-known registry sweep

Search the frozen FIELD FORGE family registry, negative results, prior experiment designs, admitted representation contracts, and successor/open-question capital for named or implicit challengers. Theory may nominate; it cannot authorize.

### G4 — authority/admissibility disposition

Every candidate receives one exact disposition in `05`. Execution inconvenience is not exclusion authority.

### G5 — identity deduplication and split audit

Hash AOS identities. Collapse method aliases. Split family labels that conceal constitutive differences.

### G6 — fresh challenger audit

A sealed reader receives only the CIM/CITC/invariant bundle, common-input schema, known representation registry, candidate U, and disposition grammar. Any obvious lawful missing AOS without a valid disposition fails closure.

### G7 — freeze

Freeze members, exclusions, generators, variant policies, weaker relation plan, minimal-set search rule, time/ref boundary, and limitations before relevant outcomes.

## 4. Pass predicate

`CLAIM_COMPLETE_FINITE_U_PASS` requires:

- every constitutive slot has at least one candidate or `NO_CURRENT_CARRIER` disposition;
- every known claim-relevant challenger is included or validly disposed;
- every commitment-lowering generator was applied;
- no `UNRESOLVED__CLOSURE_FAILS` or blocking known challenger remains;
- fresh audit passes;
- U is finite and every member is hash-identifiable;
- freeze predates comparative outputs.

Having an object for every slot does not imply a sufficient set will succeed empirically. It only makes the search space admissible for the bounded court.

## 5. Too weak / too strong attacks

The rule “include currently known plausible carriers” is too vague without G0–G7 and exact dispositions.

The rule “include every algorithm or parameterization” is too strong and epistemically counterfeit: it multiplies implementations, not claim capabilities.

The rule “include every conceivable future carrier” is impossible and would abolish bounded engineering judgment.

## 6. Closure statuses

- `PASS__CLAIM_COMPLETE_FINITE_U`
- `FAIL__KNOWN_CHALLENGER_OMITTED`
- `FAIL__ASSERTION_SLOT_NOT_CHALLENGED`
- `FAIL__FAMILY_LABEL_LAUNDERING`
- `FAIL__OUTCOME_GUIDED_MEMBERSHIP`
- `ABSTAIN__KNOWN_BLOCKED_CHALLENGER`
- `ABSTAIN__OBJECT_IDENTITY_UNRESOLVED`
- `ABSTAIN__CLAIM_OR_CITC_UNAUTHORIZED`
- `NOT_APPLICABLE__TESTED_SET_ONLY`

No pass status contains the word `EXHAUSTIVE`.
