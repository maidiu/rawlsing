# FFIF002 — SUCCESSOR RECOMMENDATIONS R1

FFIF002 closes the semantic architecture question far enough to name what successor work should and should not do. These recommendations do not mint current authority or execute FFX002.

## 1. Prototype the TTAR schema before building a generic harmonization engine

Next design work should materialize a minimal typed transformation authority receipt schema against a finite set of real Rawlsing source-form cases.

Required prototype properties:

- source-native input state references are immutable and exact;
- authority class is typed;
- claim scope is machine-addressable, not free prose only;
- allowed/forbidden use is explicit;
- loss profile and ancestry state are explicit;
- transform execution is replayable;
- supersession is immutable/versioned;
- no automatic transitive closure occurs.

Do not begin with a universal crosswalk table. Begin with receipts whose inability to generalize without authority is a feature.

## 2. Build a finite hostile-case fixture set

Use actual current source forms spanning at least:

- Arab Barometer literal income versus ordinal income-situation forms;
- certified ordinal response scales from Afrobarometer / Arab Barometer and another family where available;
- one religion/sect/ethnicity/caste/race category system with cross-context temptation;
- education categories across differing credential systems;
- occupation/employment proxy differences across waves;
- all currently representable special response/routing states;
- one continuous/count/duration measurement with bin/rank/standardization alternatives.

The fixture should test authority behavior, not respondent analysis.

## 3. Create a claim-scope contract before large-scale reuse

The hardest open semantic design risk is broad claim scope laundering local permission into global equivalence.

A successor should define:

- immutable claim IDs;
- comparison target;
- population/context scope;
- measurement scope;
- preserved invariant;
- distinctions declared immaterial;
- allowed/forbidden uses;
- a containment test for downstream reuse.

Then hostile-test whether two closely related claims can lawfully share one receipt.

## 4. Reinterpret FFX002 common input around a semantic manifest

FFX002 should not consume a vaguely prepared data frame and rely on narrative assurance that preprocessing was common.

Add a `COMMON_SEMANTIC_INPUT_MANIFEST` containing:

- exact source-native state refs;
- project semantic authority refs;
- TTAR IDs and execution order;
- claim scope;
- special-state semantics;
- transport/comparability invariant;
- loss profiles;
- semantic eligibility universe;
- noncomparable/unresolved states;
- ancestry/replay refs.

Atlas and geometry should attest to the same manifest hash before forking.

## 5. Add a semantic-delta validator for post-fork methods

A representation-specific preprocessing step should be admissible after the FFX002 fork only if it can prove that it did not change:

- state sameness/difference;
- order authority;
- comparability invariant;
- semantic eligibility;
- source-native ancestry.

If it changes any of these, it must return upstream for typed authority and common-input freeze.

This validator should specifically detect sparse-state deletion, complete-case universe drift, category merges, silent NA coercion, and reference-frame changes.

## 6. Keep PRA downstream

Do not expand Position Role Authority to solve equivalence. A successor PRA court should consume already-lawful measurement/transform states and then adjudicate social-position role claims.

The measurement-semantic court should likewise avoid claiming that an authorized order/crosswalk is socially positional.

## 7. Establish source-harmonization inheritance rules

A dedicated bounded successor should distinguish:

- source native category;
- source native harmonized category;
- Rawlsing project crosswalk;
- claim-scoped equivalence;
- transport equivalence.

It should define how inherited source loss and stated source scope constrain later transport.

## 8. Establish transform composition rules

Real analytic views will chain normalization -> order -> collapse -> rank/standardization -> representation transforms.

A successor should define a typed composition algebra with these constraints:

- no receipt may silently strengthen authority class;
- no claim scope may widen through composition;
- loss profiles accumulate monotonically unless genuinely lossless stages follow;
- source-native ancestry remains reachable at every stage;
- composition that creates a new semantic proposition requires a new authority receipt.

## 9. Preserve `NONCOMPARABLE` and `UNRESOLVED` as first-class outcomes

Successor tooling must not be success-biased toward producing a transform. Refusal to equate can be the correct result.

Conversely, `NONCOMPARABLE` should not become lazy default doctrine where bounded equivalence is supported.

## Recommended succession order

1. TTAR schema + finite hostile fixtures.
2. Claim-scope contract / reuse rules.
3. Source-harmonization + transport inheritance.
4. FFX002 common semantic input manifest revision.
5. Post-fork semantic-delta validator.
6. Transform composition rules.
7. Only then: broader execution automation.

## Stop condition

Do not automate equivalence decisions merely because a schema exists. Automation may execute certified rules; finite semantic adjudication remains required wherever evidence, context, or claim meaning determines whether two empirical states may lawfully be treated together.
