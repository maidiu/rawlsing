# FFIF002 — FFX002 COMMON-INPUT IMPLICATIONS R1

## Ruling

FFX002's atlas/geometry duel is invalid if the two arms receive different semantic ontologies under the label `preprocessing`.

The common input therefore must freeze **every decision that changes empirical semantic sameness, difference, order, comparability, or semantic eligibility** before the fork.

## Must be frozen identically before atlas and geometry fork

At minimum:

1. source-native variable/state identifiers and provenance;
2. source-native category meanings and explicit order declarations;
3. special-response-state identities and routing/form semantics;
4. any project-semantic identity/cross-wave correspondence;
5. any claim-scoped equivalence or category collapse used by either arm;
6. any common partition/binning that creates analytic states;
7. cross-context transport/comparability proposition and named invariant;
8. reference population/universe where rank, percentile, or standardization is part of the common analytic state;
9. semantic eligibility/exclusion that changes which empirical events are in the compared universe;
10. loss profiles, authority references, source-native ancestry, replay specifications, and supersession state for all of the above;
11. `NONCOMPARABLE` / `UNRESOLVED` dispositions where they bound admissible common input.

## The decisive test

For proposed transform T, ask:

> Does T change which source-native states are treated as the same, different, ordered, comparable, or semantically eligible for the claim?

If YES: T is a semantic/common-input decision and must be lawfully authorized and frozen before the fork.

If NO, ask:

> Does T only change coordinates, layout, weighting, smoothing, optimization, or other representation mechanics on the already-frozen authorized states?

If YES: T may be representation-specific after the fork, subject to the representation's own method contract.

## May differ after the fork

Provided the semantic test above remains false, the arms may differ in:

- coordinate/layout algorithms;
- geometry-specific scaling that does not create comparability or alter category semantics;
- kernels, bandwidths, neighborhood parameters;
- graphical layout/edge rendering;
- optimization choices;
- model-estimation mechanics;
- supplementary/display treatment that retains the same frozen semantic state universe and does not convert a state into semantic absence;
- deterministic/stochastic implementation details with complete method provenance.

These are method choices, not ontology.

## Standardization boundary

Standardization is split jurisdictionally:

- **before fork:** the proposition that variables/contexts are comparable under reference frame R, and the definition of R if it changes analytic meaning;
- **after fork:** the numeric implementation may differ only if it does not alter the common comparison proposition or empirical universe.

A pooled z-score cannot be used to create cross-context comparability. The comparability authority must pre-exist the z-score.

## Rare-category problem

Geometry may legitimately struggle with sparse categories. That does not grant geometry authority to merge them.

Lawful options:

1. retain the rare state and let the geometry fail/admit instability;
2. treat it supplementary under a method rule if the state remains semantically present and the duel contract permits this asymmetry;
3. issue a bounded claim-scoped category-collapse receipt and apply the same semantic collapse to both arms before the fork;
4. declare the geometry inadmissible for that common input.

Unlawful option:

- merge rare state only in geometry and still call the result a direct duel against an atlas consuming the uncollapsed ontology.

## Missing/special states

If both arms are being compared on common input, they receive the same typed special states and the same frozen semantic eligibility rule.

One arm may subsequently be unable to estimate with a special state and exclude it under its method contract, but that exclusion must remain visible and may itself make the duel non-like-for-like. It cannot rewrite `DK`, `REFUSED`, `ROUTED_NONAPPLICABLE`, or `UNRESOLVED_ROUTING` into a new upstream semantic ontology.

## Alternate encodings

FFX002 may compare alternate representations only when the alternate encoding is itself one of:

- already source/project semantic authority;
- a separately issued claim-scoped TTAR applied as a new common-input condition to both arms;
- a strictly post-semantic representation transform that leaves semantic distinctions unchanged.

The phrase `lawful alternate encoding` should therefore be replaced in successor FFX002 design by an explicit pointer to the transform-authority class and receipt.

## Recommended FFX002 contract revision

Future FFX002 design should add a **COMMON SEMANTIC INPUT MANIFEST** containing, for each consumed field/state:

- source-native state refs;
- project-semantic refs if any;
- TTAR IDs in execution order;
- exact claim scope;
- loss profile;
- special-state policy;
- transport/comparability invariant;
- frozen semantic eligibility universe;
- unresolved/noncomparable dispositions;
- ancestry/replay pointers.

Both atlas and geometry must attest to the same manifest hash before the duel begins.

Post-fork method receipts must attest that they do not change the semantic manifest. If they must change it, they are not continuations of the same duel condition.

## Exact common-input implication

**Any transformation that changes sameness, difference, ordering, comparability, or semantic eligibility belongs upstream of the FFX002 fork and must be frozen identically under typed authority; only transforms that operate on that frozen ontology without changing it may legitimately diverge by representation afterward.**
