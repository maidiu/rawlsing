# FFIF005 — SUCCESSOR RECOMMENDATIONS

## 1. Do not build a new authority service

Implement no autonomous MAR registry. First extend the FFIF003 candidate transport object with a materialized `CLAIM_SCOPED_MAPPING_PLAN` block whose authority fields are exact refs to source/project semantics, TTAR, PRA/role authority, and claim identity.

## 2. Prototype one finite mapping-plan fixture

Use source/codebook objects only—no respondent execution—to prove that the plan can:

- log candidates without admitting them;
- validate edge-by-edge authority;
- enumerate `H`;
- retain ties;
- distinguish partial/set-valued/coarsening maps;
- seal before target score;
- invalidate on TTAR/PRA supersession;
- return `NO_AUTHORIZED_MAP`.

Include hostile education, economic-position, trust-battery, matrix/standalone, and southern-Lebanon-role cases.

## 3. Build mapping-plan hash attestation into FFX002-XC

The optional cross-context extension should require:

- local output hashes;
- mapping-plan hash generated before target comparison;
- prohibited-feature/taint audit;
- exact execution attestation;
- preservation of every alternative-map result.

Any post-freeze plan mutation invalidates the confirmatory transport run.

## 4. Make saturation the default map null

For small finite `H`, enumerate all materially distinct authorized maps. For larger `H`, predeclare a stratified sampler and exact coverage diagnostics.

Always report:

- `N_H`/bound;
- successful-map fraction;
- registered-map rank;
- outcome-optimized envelope;
- successful-map equivalence classes;
- map dependence.

Do not reduce the output to one p-value.

## 5. Add feature-taint governance before automating matching

Deterministic matching is safe only after the selection feature vocabulary is itself authorized and proved independent of the target recurrence. A successor should create:

- feature provenance;
- endpoint/joint derivation flags;
- target-function taint rules;
- pre-target freeze attestations;
- hostile injected-target-feature fixtures.

Until then, deterministic matching may execute exact identity and already-banked rules only.

## 6. Resolve set-valued versus collapsing maps

Create a bounded TTAR composition fixture proving when a multi/one relation:

- preserves every local member as a set-valued predicate;
- aggregates members into one statistic/state;
- loses distinctions;
- requires a new TTAR rather than transport-plan metadata.

This is the most likely leak between FFIF002 and FFIF005.

## 7. Keep PRA prior and local

Do not ask a cross-context map to discover that sect, ethnicity, caste, race, credential, income, or subjective class occupies a social-position role.

The mapping plan consumes exact local role authority. If a proposed abstract role is new, return to PRA/role adjudication before the edge enters `H`.

## 8. Propagate FFIF004 representation statuses

Each local invariant in FFX002-XC should carry:

- `VIEW_ROBUST`;
- `VIEW_INDEXED_BUT_ADMISSIBLE`;
- `MULTI_VIEW_REQUIRED`;
- `UNRESOLVED`.

Then cross map and representation axes explicitly. Do not call a view-sensitive local invariant a stable transport endpoint.

## 9. Preserve no-map outcomes

Materialize distinct failure receipts:

- `NO_AUTHORIZED_MAP` — edge authority absent;
- `NO_IDENTIFIABLE_MAP` — alternatives remain and result depends on them;
- `NONDISCRIMINATIVE_MAPPING_SPACE` — many maps yield the result;
- `INVALID_MAPPING_PLAN` — firewall/family/selection defect;
- `NO_TRANSPORT` — valid plan tested and recurrence not supported.

These are not synonyms and require different successors.
