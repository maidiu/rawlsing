# FFIF001 — GRAPH / HYPERGRAPH HOSTILE AUDIT

## Holding

`EVERYTHING_IS_A_NETWORK` is rejected. Graph/hypergraph survives as a typed view only when node and relation semantics are explicit and replayable.

## 1. Why graph looks temptingly primitive

Graph form can encode:
- respondent-measurement incidence;
- measurement coadministration;
- exact configuration membership;
- conditional-dependence relations;
- similarity neighborhoods;
- source ancestry;
- social interpretation candidates.

That universality is syntax, not semantic neutrality.

## 2. Node ontology problem

Potential nodes include:
- respondents/empirical units;
- question implementations;
- parent source structures;
- answer categories;
- response events;
- configurations;
- motifs;
- contexts;
- latent profiles.

These cannot be mixed into one untyped network without collapsing different grains.

Q629 makes this obvious: its parent prompt, eight answer codes, respondent selection event, and routing gate are not interchangeable nodes.

## 3. Edge ontology problem

Potential edges include:
- member-of source block;
- eligible-for;
- exposed-to;
- responded-with;
- same-unit cooccurrence;
- statistical dependence;
- geometric neighborhood;
- shared ancestry;
- cross-context transport candidate.

An edge label such as `RELATED_TO` would destroy the distinctions FIELD FORGE most needs to preserve.

## 4. Projection problem

Bipartite/hypergraph incidence often becomes a simple graph by projection. Projection manufactures edges:
- co-selection becomes answer-answer adjacency;
- coexposure becomes item-item adjacency;
- shared respondents become configuration similarity;
- shared source block becomes apparent community.

Every projection requires an explicit claim contract. No projected graph may replace its incidence substrate.

## 5. Threshold problem

Weighted dependence/similarity graphs require thresholds or continuous edge interpretation. Threshold choice changes component structure, centrality, and communities. Community detection then compounds the choice.

No threshold/community may become a social formation merely because it is algorithmically stable.

## 6. Missing-edge problem

Absent edge can mean:
- true zero observed relation in exact risk set;
- not coexposed;
- routing-incomparable;
- unresolved authority;
- pruned below threshold;
- missing carrier;
- not tested.

These must be typed separately. Otherwise the graph turns ignorance into topology.

## 7. Where hypergraph is unusually strong

Hypergraph/incidence representation is especially useful for **measurement topology** because it can preserve:
- parent source structures with multiple members;
- respondent-to-exposed-measurement incidence;
- exact k-way coadministration sets;
- overlapping blocks/components;
- ancestry relations.

That is an engineering win, not a claim that society is a hypergraph.

## 8. Contradiction and J

A typed event hypergraph can preserve contradiction and higher-order J very well if hyperedges are exact same-unit joint events over a lawful risk set. A projected dependence graph cannot be assumed to preserve either.

## 9. Disconnected components

Graph representation can honestly preserve disconnected measurement components better than geometry—provided “no edge” is typed as noncomposable/noncoexposed rather than substantive independence.

## 10. BUT HOW audit

### `MEASUREMENT_INCIDENCE_HYPERGRAPH_VIEW`
- **what:** typed incidence view over units, measurements/source structures, and governed exposure/response events.
- **producer:** deterministic topology compiler.
- **inputs:** observation/provenance substrate + source-structure authority.
- **authority:** node/edge type registry; exact exposure authority.
- **computation:** incidence construction only; projections separate.
- **semantic judgment:** which identities are nodes; which relation type an edge denotes.
- **preserves:** overlap, components, higher-order incidence, source topology.
- **destroys:** little if incidence retained; any projection loses higher-order distinction.
- **hostile defeat:** Q629 child codes treated as repeated prompts; absent edge interpreted as independence; projection/community promoted to ontology.
- **consumer:** coadministration admissibility, provenance, graph-specific diagnostics.
- **why over weaker:** useful query/index form for overlapping incidence; not needed as the universal store.

## 11. Ruling

Use graphs to encode named relations. Never use “network” as a solvent that dissolves the need to say what the relation is.
