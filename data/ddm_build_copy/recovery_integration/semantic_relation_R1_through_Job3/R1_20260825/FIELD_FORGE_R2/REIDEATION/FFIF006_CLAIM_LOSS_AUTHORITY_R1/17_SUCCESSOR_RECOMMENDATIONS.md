# FFIF006 — SUCCESSOR RECOMMENDATIONS

## 1. Bank two separate authority objects

Adopt the candidate split only through competent project authority:

- `CLAIM_IDENTITY_MANIFEST` for normalized proposition/comparison identity;
- `CLAIM_INVARIANT_TOLERANCE_CONTRACT` for typed materiality and loss authority.

Bind them by immutable hashes; do not collapse them into a generic query row.

## 2. Normalize FFX002 before execution

Turn each Q01–Q11 design row into atomic CIMs. Split exact existence from prevalence/estimation, prediction from structural claims, and utility/compression from empirical fidelity. Issue bundle contracts only where co-requirement is independently justified.

## 3. Adjudicate rather than inherit thresholds

Treat current FFX002 numbers as candidates. For each exact canary claim, require an evidence basis from claim semantics, source resolution, and the proper error/design model. Leave unresolved claims blocked instead of substituting a conventional default.

## 4. Upgrade CVCR dependency

Require every CVCR to consume matching proposition, comparison, CITC, and support/uncertainty hashes. Missing or divergent hashes must fail before materiality adjudication.

## 5. Preserve the utility firewall in code

Store empirical loss, estimation uncertainty, predictive/query utility, and engineering cost in separate typed tables/fields. No shared scalar column or optimizer objective should permit cross-class compensation.

## 6. Implement hostile freeze tests

Before first execution, test all eight post-hoc mutations named in `10_LOSS_BUDGET_OBJECT_DECISION.md` plus all fixtures in `04_CLAIM_ANTI_LAUNDERING_FIXTURES.tsv`.

## 7. Close institutional authority

This court identifies the needed jurisdiction but does not mint it. A successor must establish who can issue/accept CITCs, required independence from view producers, and how project acceptance/supersession works.

## 8. Keep bounded nonreducibility expensive

Permit it only with atomic claim identity, legitimate empirical bundle authority, CITC, finite candidate universe, transform and weaker-object tests, nuisance/holdout survival, and supersession vulnerability. Consumer-only bundles should yield consumer multi-view requirements, not empirical nonreducibility.
