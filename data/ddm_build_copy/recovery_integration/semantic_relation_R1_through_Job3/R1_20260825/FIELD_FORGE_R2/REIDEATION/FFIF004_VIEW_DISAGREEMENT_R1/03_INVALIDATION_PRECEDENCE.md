# FFIF004 — INVALIDATION PRECEDENCE

## 1. Precedence is constitutional

Pluralism begins only after validity.

A disagreement stage may not reorder gates because a later result is attractive. A high-predictive, visually clean, theoretically legible, or multi-method-supported output remains invalid if an earlier gate fails.

Hard law:

`EARLIER_INVALIDITY_DOMINATES_LATER_VALUE`.

## 2. Ordered court

### P0 — jurisdiction / provenance / execution boundary

Verify:

- exact governed source/currentness refs;
- no respondent claim beyond available respondent authority;
- no forbidden acquisition or semantic authority minted by compute;
- replayable code/specification lineage.

Failure: `INVALID_PROVENANCE_OR_JURISDICTION`.

### P1 — common empirical input lawfulness

Verify where required:

- empirical-unit identity;
- actual exposure/risk set;
- measurement implementation identity;
- source-native ancestry;
- special-state semantics;
- estimand/weight target;
- design/holdout manifest;
- ancestry/leakage firewall.

Failure affecting the comparison: `INVALID_COMMON_INPUT`.

A view that uses a different respondent universe because its method cannot handle the lawful one has not exposed representation sensitivity; it has changed the experiment.

### P2 — semantic-input equality / TTAR freeze

Verify exact TTAR IDs/order and all transformations that change sameness, difference, ordering, comparability, or semantic eligibility.

Unintended mismatch: `SEMANTIC_INPUT_DIVERGENCE`.

Intentional mismatch: split the claim/experiment; do not compare as same-input views.

### P3 — claim identity

Normalize the outputs into the same claim/invariant assertion slots.

Outcomes:

- `SAME_CLAIM_SAME_INVARIANT` -> proceed;
- `SAME_BROAD_QUESTION_DIFFERENT_INVARIANT` -> type as such; no direct contradiction;
- `DIFFERENT_CLAIM` -> `CLAIM_MISMATCH`;
- unresolved -> `AMBIGUOUS_CLAIM_IDENTITY` and abstain.

### P4 — representation-specific admissibility

Each view must pass its own contract, including applicable hostile/null/source-topology tests.

Examples of hard failures:

- geometry forces disconnected exposure components into one metric;
- graph treats unresolved nonedge as absence or independence;
- atlas deletes exact observed minority facts at its lossless floor;
- latent mixture is nonidentified or heldout-null;
- motif appears because questionnaire block ancestry recurs;
- transport map selected because it makes recurrence look strong.

Failure: `INVALID_REPRESENTATION` with view ref and typed reason.

No other valid view can vote the failed view back into admissibility.

### P5 — support / uncertainty / identifiability

Ask whether the normalized assertion is empirically identified at the declared support and uncertainty regime.

Failure outcomes:

- `INSUFFICIENT_EVIDENCE`;
- `NONIDENTIFIABILITY`;
- `LOW_SUPPORT__EXISTENCE_ONLY` where exact existence is known but generalization is not.

### P6 — known-loss explanation

Compare the observed difference to each view's preregistered loss profile.

If the difference is the expected consequence of a declared loss and the affected invariant is not required by the claim:

`KNOWN_LOSS_EXPLAINS_DIFFERENCE`.

If the lost invariant **is** required by the claim, the lossy view may be `INVALID_FOR_CLAIM` even if valid for a narrower role.

### P7 — lawful nuisance / perturbation stability

Test only preregistered lawful variants: metric family, block treatment, thresholds, conditioning specification where the claim permits alternatives, sampling/holdout perturbations, nulls, counterfeit fixtures.

If the substantive output changes beyond tolerance:

`REPRESENTATION_SENSITIVITY` or a stronger typed instability.

If the changes correspond to a changed estimand/claim, return to P3 rather than calling it sensitivity.

### P8 — weaker-object sufficiency

Before retaining a stronger representation, ask whether a weaker empirical object answers all required assertion slots within the declared loss/uncertainty budget without importing the stronger view's semantics.

If yes:

`WEAKER_OBJECT_SUFFICIENT`.

The stronger representation may retain optional diagnostic/compression value but is not necessary for the claim.

### P9 — multi-view necessity / bounded nonreducibility

Only after P0–P8 pass may the court ask whether multiple valid views are jointly necessary.

Possible outcomes:

- `VIEW_ROBUST_COMMON_CLAIM`;
- `REPRESENTATION_DEPENDENCE_RETAINED`;
- `MULTI_VIEW_RETENTION_REQUIRED`;
- `CLAIM_SCOPED_BOUNDED_NONREDUCIBILITY_CANDIDATE`;
- `CLAIM_SCOPED_BOUNDED_NONREDUCIBILITY_SUPPORTED`;
- `UNRESOLVED_COMPARISON`.

## 3. The hardest rule

If a representation changes common semantic input to satisfy its method, the method has not discovered a different structure. It has consumed a different empirical object.

Therefore:

`METHOD_NECESSITY_CANNOT_AUTHORIZE_SEMANTIC_TRANSFORM`.

A rare-category merge, missing-state collapse, respondent pruning, disconnected-component bridge, weighting change, or exposure approximation demanded only by one method must either:

1. already be independently TTAR-authorized and frozen for all compared views;
2. remain representation-local without changing common semantic identity;
3. define a different claim/experiment;
4. or invalidate the view for the proposed comparison.

## 4. No downstream cure

The following never cure P0–P4 failure:

- better fit;
- better prediction;
- lower-dimensional compression;
- interpretability;
- replication inside the same invalid pipeline;
- agreement with other methods;
- theoretical expectation;
- aesthetic coherence.

This is the boundary between representational plurality and epistemic laundering.
