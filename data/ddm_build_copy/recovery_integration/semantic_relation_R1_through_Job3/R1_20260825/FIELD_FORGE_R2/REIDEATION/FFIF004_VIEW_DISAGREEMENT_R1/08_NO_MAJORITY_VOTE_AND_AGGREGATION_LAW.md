# FFIF004 — NO MAJORITY VOTE AND AGGREGATION LAW

## 1. Core prohibition

Rawlsing may not decide empirical truth by counting representations.

Forbidden:

`METHOD_COUNT_VOTING`

`ENSEMBLE_CONSENSUS_AS_TRUTH`

`ROBUSTNESS_BY_NUMBER_OF_MODELS`

`METRIC_COUNT_VOTING`

`ARCHITECTURE_SCORE = weighted_sum(all_desirable_properties)`

These mechanisms are rejected because representation families are neither exchangeable voters nor independent witnesses. Three geometries with related metrics/embeddings may share one upstream equivalence assumption. One exact configuration fact can be destroyed by all three and remains a fact. Conversely, one exotic view does not defeat a robust claim merely because it can encode some different object.

## 2. Why counting methods is epistemically malformed

A vote assumes:

1. each method answers the same proposition;
2. each method is individually admissible;
3. votes are comparable;
4. dependence among methods is either absent or governed;
5. each vote has a justified weight;
6. majority count is linked to the target estimand.

Cross-view representation comparison normally satisfies none of these automatically.

Method families often share:

- common preprocessing;
- common metrics;
- common loss modes;
- common category collapse;
- common instrument topology;
- common semantic authority errors.

Therefore ten methods repeating one hidden ontology do not produce ten independent confirmations.

## 3. No vote across different invariants

A geometry preserving neighborhood order and an atlas preserving exact minority configurations are not ballots on one proposition.

If the claim needs both invariants, adjudicate invariant coverage.

If the claim needs only one, compare only on that required assertion slot.

`DIFFERENT_CAPABILITY != DISSENTING_VOTE`.

## 4. No scalar architecture score

The following dimensions remain separate:

- `DESCRIPTIVE_FAITHFULNESS`;
- `MINORITY_PRESERVATION`;
- `HIGHER_ORDER_PRESERVATION`;
- `UNCERTAINTY_CALIBRATION`;
- `NUISANCE_STABILITY`;
- `PREDICTIVE_VALUE`;
- `COMPRESSION_VALUE`;
- `STRUCTURAL_DISCOVERY_VALUE`;
- `DOWNSTREAM_QUERY_VALUE`;
- `REPLAYABILITY`;
- `SEMANTIC_COMMITMENT`.

A view can dominate on one and lose on another. The architecture may not hide that tradeoff by choosing arbitrary weights.

This preserves the central FFX002 insight that no master score should exist, while removing the remaining temptation to use a longer list of metric wins as an informal master score.

## 5. Allowed aggregation

Aggregation is permitted only when the aggregation itself is the frozen statistical claim.

Examples:

- an explicitly specified ensemble predictor may be evaluated for predictive risk;
- repeated resamples may estimate a stability probability or uncertainty interval;
- multiple measurements may be aggregated under an independently authorized semantic/estimand contract;
- a signature may combine preregistered invariant components under FFIF003-style transport authority.

Even then, the aggregated object supports only its licensed claim. An ensemble with better prediction does not become the truer social representation.

## 6. Replication is not method voting

Independent replication can strengthen evidence when the same claim is tested on genuinely independent heldout/respondent/context evidence under the same authorized semantics.

That differs from running several algorithms on the same observations and counting how many tell a similar story.

The receipt should therefore distinguish:

- `EVIDENCE_REPLICATION_COUNT`;
- `NUISANCE_PERTURBATION_SURVIVAL`;
- `REPRESENTATION_FAMILY_COUNT`.

Only the first two can have direct inferential meaning under an explicit design. The third is descriptive metadata.

## 7. What replaces voting

Use, in order:

1. common-input validity;
2. claim identity;
3. per-view admissibility;
4. invariant coverage;
5. uncertainty/support;
6. known-loss explanation;
7. hostile/nuisance/holdout evidence;
8. weaker-object sufficiency;
9. minimal sufficient object/view set.

The result is an explicit proof path, not a plebiscite among algorithms.

## 8. FFX002 implication

A future FFX002 report must not say:

> Geometry won 11 of 17 metrics.

or:

> Atlas won most robustness checks.

It must say, for each frozen claim/invariant:

- which views were valid;
- what each preserved;
- what each lost;
- whether answers agreed within tolerance;
- what incremental capability was unique;
- whether a weaker object sufficed;
- whether multi-view retention was necessary.

Architecture follows claim sufficiency, not medal count.
