## 2. Supreme composition law

The accepted lineage positively closes the general composition rule as follows.

### Rule C07-1 — default state is distinctness

Two empirical source universes remain distinct unless named positive authority creates a lawful relation between them for a named operation.

Absence of contradiction is not composition authority.

`NO_BRIDGE_AUTHORITY => PRESERVE_DISTINCT_UNIVERSES`

### Rule C07-2 — joint query without pooling is lawful when execution is source-indexed

Two or more universes may be queried in one governed run when all of the following hold:

1. each universe has an exact identity;
2. each universe independently satisfies the source/release/population/routing/design prerequisites required by the operation;
3. the query/predicate semantics are valid for each universe under its own authority;
4. outputs remain tagged by source-universe identity;
5. denominators, weights, routing/risk sets and missing-state interpretations remain universe-local unless separately bridged;
6. no empirical observations are pooled or aggregate estimand manufactured across universes.

Canonical form:

`JOINT_QUERY(U1,...,Un) = { (Ui, RESULT_i) }`

not:

`RESULT(UNION_ROWS(U1,...,Un))`

unless explicit composition authority exists.

This is federated dispatch over distinct universes, not pooling.

### Rule C07-3 — higher-order empirical composition may be a tagged container

A higher-order empirical object may contain multiple empirical universes without semantic pooling only when member identities remain separately addressable and every operation is explicit about its member-wise semantics.

Required properties:

- exact member-universe registry;
- exact source/release/time/population identity per member;
- exact routing/design/weight authority per member;
- replay from every result to its member universe;
- no row-level, denominator-level or estimand-level collapse by default;
- operation-specific authority defining whether the higher-order object supports enumeration, dispatch, source-wise querying, comparison, or true aggregation.

A tagged composition creates a lawful container, not an equivalence class.

`COMPOSED_CONTAINER != POOLED_POPULATION`

### Rule C07-4 — comparison without merger is lawful only under a common comparison contract

Universes may be compared while remaining distinct when:

1. the compared output quantity has the same governed semantic role on both sides, or an explicit bridge defines the translation;
2. each side is computed under its own lawful denominator/design/weight/routing rules;
3. the comparison metric is candidate-neutral and source-neutral;
4. source identities remain visible in the comparison result;
5. the comparison does not imply respondent-level, population-level, scale-level or estimand equivalence beyond what is positively proved.

Potentially lawful comparison surfaces include:

- execution success/failure under the same frozen interface;
- latency/resource cost for the same bounded operation;
- source-wise discovery yield where the counting unit is identically governed;
- typed preservation/replay correctness;
- route parity against the same per-universe acceptance oracle.

None of those alone authorizes pooled substantive empirical estimates.

### Rule C07-5 — noncomparability is a first-class lawful result

If a proposed comparison requires an unproved equivalence in any necessary dimension, the correct result is:

`NONCOMPARABLE_FOR_THIS_METRIC`

rather than forced normalization.

Necessary dimensions may include:

- target population / universe membership;
- source time or release scope;
- question/proposition semantics;
- response-scale semantics;
- routing/applicability/risk set;
- sample design / variance method;
- weight role / estimand;
- respondent/event topology;
- country-specific source authority.

Noncomparability is metric-scoped. Two universes may be comparable for runtime/replay integrity while noncomparable for a substantive population estimate.

### Rule C07-6 — explicit bridge/harmonization authority is mandatory for semantic merger

Any operation that removes, substitutes or normalizes an identity-bearing distinction requires positive bridge authority.

This includes, at minimum:

- pooling respondent rows across source universes;
- combining weights;
- treating different target populations as one population;
- converting source-native scales into a shared substantive scale;
- treating source-native propositions as equivalent;
- merging routing/risk sets;
- assigning one design/variance regime across sources;
- creating a common estimand from source-specific estimands;
- reusing a source-native joint configuration across another source;
- claiming cross-source value/response/scale portability.

Bridge authority must state:

1. source universes covered;
2. exact dimensions harmonized;
3. exact transformation;
4. validity scope;
5. estimand/population meaning;
6. design/weight consequences;
7. information loss or uncertainty introduced;
8. replay/provenance back to pre-bridge identities;
9. forbidden inferences outside bridge scope.

No bridge may be inferred from common schema, common code, common labels, common canonical question IDs, overlapping countries, similar dates, or successful execution.

## 4. Exact C09 multi-universe parity requirement

C09 does not need false substantive comparability to test A/B/C fairly.

It needs a **source-indexed parity matrix**.

For each governed empirical universe `Ui`, freeze before candidate execution:

- `universe_id`;
- source family;
- exact source-byte/release authority;
- time/wave/country scope;
- target population/coverage authority;
- routing/risk-set authority;
- sample/design authority required by the operation;
- weight/estimand authority required by the operation;
- common predicate/query/frontier authority;
- candidate-neutral acceptance oracle;
- exact measurement metrics lawful for that universe.

Primary parity unit:

`(candidate, universe_id, frozen_operation_id)`

When C09 is otherwise authorized, A/B/C must face the same eligible `Ui` under the same frozen operation and acceptance contract.

C09 may summarize performance across universes only for metrics whose aggregation law is already candidate-neutral and does not pool empirical observations.

Examples include:

- number/proportion of governed universe-operation cells passed;
- per-universe runtime/resource metrics summarized across cells;
- exact preservation/replay failures;
- typed missing-authority versus execution-failure counts;
- no-starvation evidence fields.

C09 must not convert a universe that lacks required authority into a numeric zero, candidate failure or lower candidate score.

Use typed outcomes:

`MISSING_UNIVERSE_AUTHORITY`

or:

`NONCOMPARABLE_FOR_THIS_METRIC`

Candidate parity therefore requires the same opportunity and same frozen law per eligible universe, not forced equality of empirical universes.

### C09 launch invariant

`FAIR_MULTI_UNIVERSE_PARITY = SAME_CANDIDATES × SAME_ELIGIBLE_UNIVERSE_CELLS × SAME_OPERATION_LAW × SAME_METRICS`

not:

`FAIRNESS = POOL_ALL_SOURCES`

### Metric-specific eligibility rule

A source-universe cell enters a substantive metric only if the authority required by that metric is positively closed.

If a universe is ready for a runtime/replay metric but not for a design-weighted population metric, C09 may lawfully include the former and type/exclude the latter.

This prevents both false comparability and candidate starvation.
