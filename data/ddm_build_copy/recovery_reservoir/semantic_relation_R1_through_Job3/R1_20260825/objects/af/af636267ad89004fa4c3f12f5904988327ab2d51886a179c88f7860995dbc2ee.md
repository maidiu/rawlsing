# R10E S2/S2B Worker Protocol

## Jurisdiction
This worker adjudicates only the exact implementation IDs in its immutable R10E workbench.
The work combines two pre-graph obligations while preserving their distinct authority:
- **S2**: structural-choice / non-scalar / response-topology authority.
- **S2B**: behavior/exposure endpoint authority.

This is **not Job 3 relation adjudication**. Do not create cross-question relations, J-families, respondent joins, P5 placement, or runtime permissions.

## Governing laws
1. Source/native meaning outranks historical mappings, QSM labels, lexical similarity, embeddings, and empirical association.
2. Fail closed when required source authority is absent or conflicting.
3. Preserve rankings, multi-select structures, nominal choices, explicit tradeoffs, and other non-scalar meanings. Never force a signed or interval scalar representation merely because downstream code prefers one.
4. Behavior remains behavior; exposure remains exposure. Do not convert either into a norm, attitude, motive, personality trait, or latent construct.
5. S2B terminal disposition is exactly one of:
   - `ACCEPT_ENDPOINT`
   - `REJECT_ENDPOINT`
   - `BLOCKED`
   An accepted endpoint must state the actor (when applicable), target/object, and action/exposure semantics explicitly enough for later governed relation-template matching.
6. For S2 rows, use:
   - `PRESERVE_SOURCE_TOPOLOGY` when the source-native response structure already correctly represents the item.
   - `REVISE_TOPOLOGY` only when source evidence proves the current topology label materially wrong or incomplete.
   - `BLOCKED` when source/topology authority is insufficient.
   Record the source-native topology in `s2_governed_topology`; this field may be descriptive and must not invent numeric portability.
7. Do not mutate R9D, R6, P3/P3C, R7J, R10C, or R10D in place. Return successor decisions only inside the worker namespace.
8. Do not silently alter exact question meaning, source-wave identity, response options, universe status, or routing status.
9. Non-applicability, missingness, refusal, don't-know, routed-out, and neutral states remain distinct when the source distinguishes them.
10. A worker may identify a likely upstream defect, but must record it as `BLOCKED` / `worker_blocker_reason`; it may not repair another authority namespace.

## Evidence procedure
For each row:
1. Read the embedded R10D exact question text, response options, topology, semantic lane/role/subrole, routing/universe status and authority status.
2. Where those fields are insufficient—especially rows in `S2_SOURCE_TOPOLOGY_REVIEW`—retrieve the source-native questionnaire/codebook or current governed deep-catalog evidence for that exact source family/wave/variable.
3. Compare the source response structure with the current R10D topology.
4. For S2, disposition topology without scalar coercion.
5. For S2B, decide whether the behavior/exposure item is a lawful future relation endpoint; if accepted, make actor/target/action or exposure semantics explicit.
6. Cite the evidence artifact/locator in `worker_evidence_refs`.
7. State the narrow evidence ceiling and rationale. No person-level moral or causal inference.

## Required return
Return the completed workbench CSV with:
- every assigned row present exactly once;
- no additional implementation IDs;
- all rows terminally dispositioned in their applicable decision fields;
- a completion report with counts by workstream and terminal status;
- a blocker ledger for any `BLOCKED` rows;
- no changes outside the worker namespace.

Central integration will validate coverage, vocabulary consistency, cross-worker collisions, and authority boundaries before any successor release is frozen.
