# Unified worker return field specification

The original `RETURN/WORKER_RETURN_TEMPLATE.csv` is the row authority. Keep all 24 columns and original row order. The first 13 identity/context fields are immutable. Fill **every** mutable cell; use `[]`, `{}`, or `NONE` rather than blank cells where a field is not applicable.

## Recommendation enum

Exactly one of:
- `WORKER_RECOMMEND_ACCEPT`
- `WORKER_RECOMMEND_PARTIAL_ACCEPT`
- `WORKER_RECOMMEND_REJECT`
- `WORKER_RETAIN_EXISTING_GOVERNED_AUTHORITY`
- `WORKER_BLOCKED_NEEDS_VOZHD`

## Recommendation meaning

**ACCEPT:** exact opportunity satisfies the rule under pack authority. `proposed_relation_objects_json` is a nonempty JSON list. `authorized_member_implementation_ids_json` identifies the exact authorized members.

**PARTIAL_ACCEPT:** only a source-governed lawful subset of frozen R13 membership forms the relation. The authorized and rejected member lists must be explicit, disjoint, and justified. Never cherry-pick a plausible subset merely to manufacture a relation.

**REJECT:** pack evidence is sufficient to establish failure of the exact relation prerequisite. This is an exact-opportunity negative only. It is not a claim that the objects can never participate in another relation.

**RETAIN_EXISTING_GOVERNED_AUTHORITY:** use only when `known_r6_relation_ids_fully_contained_json` is nonempty and exact evidence confirms the existing governed relation remains valid. Never use RETAIN as a shortcut around review.

**BLOCKED:** pack evidence or prerequisite authority is insufficient/defective, a canary appears contradicted, T07 is centrally reserved, or a worker-specific override reserves the atom. State a precise `blocker_reason`.

## Proposed relation object schema

Each object in `proposed_relation_objects_json` must include:

```json
{
  "relation_type": "<canonical candidate template class>",
  "member_implementation_ids": ["..."],
  "member_roles": {"question_impl...": "RR_..."},
  "common_identity": "<narrow proposition/end/target/matrix identity>",
  "evidence_basis": ["<pack file + exact raw/member id>"]
}
```

Canonical relation types are taken from `CONTRACTS/S14_R11_OPPORTUNITY_RULE_RELEASE.csv`: `GENERAL_PRINCIPLE_SPECIFIC_APPLICATION`, `GOAL_MEANS`, `COMMITMENT_PERSONAL_COST`, `NORM_EXPECTED_CONDUCT`, `INSTITUTION_CLASS_DIFFERENTIATION`, `RECIPROCAL_ROLE_REVERSAL`, `TARGET_CONDITION_MATRIX`, `COMPLEMENTARY_ROLE_CONVERGENCE`. T07 is worker-blocked.

## `relation_role_structure`

Always a JSON object.

For T06 use exactly this top-level shape:

```json
{
  "rule": "T06",
  "rr_norm": {
    "status": "POSITIVE_RR_NORM|NEGATIVE_RR_NORM|BLOCKED",
    "semantic_unit_id": "...",
    "actor": "...|UNSPECIFIED|BLOCKED",
    "target": "...|UNSPECIFIED|BLOCKED",
    "action_or_rule": "...|UNSPECIFIED|BLOCKED",
    "qualifiers": "...|NONE|BLOCKED"
  },
  "endpoint_or_conduct": {
    "actor": "...|UNSPECIFIED|NOT_REACHED|BLOCKED",
    "target": "...|UNSPECIFIED|NOT_REACHED|BLOCKED",
    "action_or_exposure": "...|UNSPECIFIED|NOT_REACHED|BLOCKED"
  },
  "link": {
    "status": "MATCH|ACTOR_MISMATCH|TARGET_MISMATCH|ACTION_MISMATCH|QUALIFIER_MISMATCH|NOT_REACHED_NEGATIVE_RR_NORM|BLOCKED",
    "basis": "..."
  }
}
```

For other rules use:

```json
{
  "rule": "T03|T04|T05|T08|T09|T10|T11|T09;T10",
  "status": "MATCH|PARTIAL_MATCH|MISMATCH|EXISTING_GOVERNED|BLOCKED",
  "member_roles": {"question_impl...": "RR_..."},
  "common_identity": "...|NONE|BLOCKED",
  "prerequisite_findings": ["..."],
  "basis": "..."
}
```

For T07: `{"rule":"T07","status":"BLOCKED","basis":"T07_RESERVED_CENTRAL"}`.

## Other fields

- `evidence_refs_json`: JSON list naming exact pack-relative evidence files and relevant `raw_origin_id` / implementation IDs / R6 relation IDs. No vague “see evidence”.
- `routing_or_composability_note`: `NONE` unless routing/composability limits the semantic claim; never perform respondent joins.
- `blocker_reason`: exact reason code/text for BLOCKED; otherwise `NONE`.
- `confidence`: exactly `HIGH`, `MEDIUM`, or `LOW`. Confidence does not raise the evidence ceiling.
- `worker_notes`: `NONE` unless a note is useful for reconciliation.
