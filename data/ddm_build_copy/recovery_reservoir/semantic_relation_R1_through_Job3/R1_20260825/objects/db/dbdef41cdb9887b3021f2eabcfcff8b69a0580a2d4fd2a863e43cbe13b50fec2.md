# Meta-governance and user intent — controlling handoff doctrine

This file exists because the project accumulated enough historical work that rediscovery itself became a source of drift. A new chat must preserve the following operating doctrine explicitly.

1. **Organize everything.** Every artifact/surface must have a current role, jurisdiction, quality/completeness status, dependency, and disposition.
2. **Never confuse existence with quality.** A file, review, registry, output, successful run, or old implementation is not authority merely because it exists.
3. **Never hide incompleteness.** State what each piece still needs and what denominator a completeness claim actually covers.
4. **Do not promote weak work to avoid redoing it.** Broad/old mappings may be salvage/retrieval evidence while remaining unsafe as authority.
5. **Do not resurrect obsolete architecture because it once had value.** If a stronger current descendant exists, old code becomes lineage/regression/design evidence, not a parallel pipeline.
6. **Archaeology serves the active project; it does not replace it.** Rediscovered material enters the current spine only if it remains governing, materially reduces current work, specifies a still-missing essential capability, or supplies high-value tests.
7. **Later validated evidence supersedes earlier optimistic claims.** Preserve ancestry, but never let an older “complete/terminal/final” label override a later falsification.
8. **Translate release names back to the plain-English project.** R7/R8/S0/P4/etc. are bookkeeping. The project is: know the questions → know what they measure → know how they relate → observe respondent configurations → place them in structural pressure through time.
9. **No hidden dependencies.** If source bytes or authority bytes remain external, name them exactly. Never say “self-contained” while a silent Library/Mac lookup is still required.
10. **No playing catch-up by invention.** When unsure whether something was already built, search the handoff/ancestry first. When old work is found, quality-audit it before reuse.

The user's priority is expeditious high-quality execution **without losing anything and without lying to ourselves even slightly about what is finished, useful, missing, or obsolete**.
