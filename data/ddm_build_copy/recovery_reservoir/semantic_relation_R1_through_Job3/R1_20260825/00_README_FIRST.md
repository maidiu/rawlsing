# Semantic relation recovery reservoir — R1 through Job3

**Jurisdiction: research reservoir, not live runtime authority.**

This layer exists so future Dva/Trii/Chetiri work can inspect previously created material and discover uses that the present recovery adjudication did not anticipate. Presence here never promotes a historical row, worker recommendation, revoked denominator, or composted verdict into current truth.

Use `OBJECT_INDEX.tsv` to locate byte-preserved objects. Objects are content-addressed by SHA-256 and distributed across the R3 reservoir shards. `FULL_RECOVERY_UTILITY_LEDGER.tsv` covers the entire recovered 4,638-entry tree, including payloads retained only by exact external pointer.
