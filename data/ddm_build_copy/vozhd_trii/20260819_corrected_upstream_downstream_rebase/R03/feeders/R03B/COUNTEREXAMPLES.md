# DR-R03B — HOSTILE COUNTEREXAMPLES

**Authority:** `NON_DISPOSITIVE_HOSTILE_EVIDENCE`  
**Purpose:** finite constructions used to attack retained V554-V558 stage necessity without reopening frozen upstream law.

## CE-B01 — admission is structurally valid but affordance use is denied

Construct an already-temporally-complete `StructuralEmpiricalAdmission` whose structural proposition is lawful, but whose candidate `STRUCTURAL_MEDIATION_INPUT` use is denied by the applicable V554 rule or blocked by a V554-owned pre-route applicability condition.

Hostile bypass:

`StructuralEmpiricalAdmission -> V555`

A V555 route signature could otherwise appear to match a mediator/channel/receiver pattern. But the admission itself owns only the bounded empirical-to-structural interpretation; it does not own positive mediation-input eligibility. If V555 constructs a route without the V554 decision, a structurally meaningful proposition has silently acquired a downstream use permission it did not possess.

A substitute that makes V555 first evaluate the V554 affordance rule, emit a stable affordance identity, preserve V554 applicability/denial state, and only then derive a route has recreated the V554 logical seam.

**Attack result:** `SURVIVES_WITH_QUALIFICATION`.

## CE-B02 — one affordance, two distinct atomic mediation routes

Construct one lawful V554 `BOUNDED_STRUCTURAL_AFFORDANCE` for which governed V555 authority permits two different atomic mediation possibilities, for example:

- route R1 through governed mediation locus/channel M1 to receiver constraint T;
- route R2 through governed mediation locus/channel M2 to receiver constraint T.

The V554 affordance does not itself identify R1 or R2. If V555 is removed and V556 receives only the V554 affordance, V556 has no canonical participant IDs for later interaction rules and must reconstruct mediator/channel/receiver route structure itself.

A substitute that first creates stable R1/R2 route IDs under a V555-equivalent route rule has recreated V555. A substitute that skips stable route identity makes later participant references and route-born conditions ambiguous.

**Attack result:** `SURVIVES_WITH_QUALIFICATION`.

## CE-B03 — two lawful routes with no governed interaction rule

Construct two independently lawful V555 routes R1 and R2 that coexist in the same broad structural context but for which no V556 interaction rule is authorized.

Hostile bypass:

`R1,R2 -> V557`

This bypass is lawful for publication of the two canonical route objects themselves. It proves that V556 must not be a no-op wrapping stage for every route.

Now ask whether R1 and R2 compete, reinforce, buffer one another, reroute one another, or form an attractor-prerequisite motif. Shared source, target, time, geography, or simultaneous resolution is insufficient authority. The correct V556 state may be `VALID_EMPTY_NO_GOVERNED_RULE` rather than an inferred relation.

Deleting V556 therefore does not harm atomic route publication, but it removes the owner that can distinguish:

- no governed higher-order rule;
- governed but no eligible basis;
- governed nonempty n-ary interaction/topology;
- integrity failure.

Moving that decision into V3 would allow actor development to manufacture world-side structural interaction from coincident routes.

**Attack result:** `SURVIVES_WITH_QUALIFICATION`; direct V555→V557 publication is a required qualification.

## CE-B04 — producer permission allows, runtime publication policy narrows

Construct a producer-owned V555 route whose producer causal-use permission allows structural runtime consideration. Then bind a V557 runtime-use policy that denies this object for a particular published collection/use class, or narrows it to review/context-only.

Hostile bypass:

`producer object -> V558 repository`

If V557 is removed and repository inclusion is treated as runtime authorization, producer permission is silently widened into final runtime permission. This violates the monotone rule:

`producer permission >= V557 publication/use permission >= resolver query-relative permission`.

A V558 implementation can physically perform the V557 check, but only by preserving a separately versioned runtime-use policy, per-item authorization record, collection manifest, and closure proof before repository resolution. That is physical co-packaging, not removal of the V557 logical seam.

**Attack result:** `SURVIVES_WITH_QUALIFICATION`; V557/V558 physical co-packaging is a merge candidate, semantic merger is not.

## CE-B05 — immutable producer graph but query-time resolution is nontrivial

Construct a V557-authorized mixed-producer graph containing:

- one producer object with direct temporal support at query time;
- one object that permits a governed latest-prior proxy;
- one object requiring a generated runtime-position binding not yet available;
- one negative/noncomparable object that must remain excluded;
- two equal-rank candidates where no unique winner authority exists.

Hostile bypass:

`V557 manifest + producer locators -> V3`

V3 cannot lawfully decide these by hidden `latest`, filename order, ad hoc interpolation, prevalence, randomness, or LLM inference. The accepted structural boundary requires deterministic read-only resolution, explicit defer/exclude behavior, tied-set or ambiguity handling, selection records, and replay against one immutable bundle/query/policy/binding identity.

Embedding that capability as a library called from V3 is physically possible, but if it retains these separate policies and emits `ResolvedStructuralContext` before developmental causality then it has recreated the V558 logical boundary. If it does not, structural-world selection leaks into actor development.

**Attack result:** `SURVIVES_WITH_QUALIFICATION`.

## CE-B06A — V557/V558 single deployment without logical merger

Construct one executable/library that, in order:

1. applies V557 runtime-publication/use policy to producer-owned objects and emits immutable authorization records/manifests;
2. links only the authorized graph into a V558 immutable repository with producer-preserving locators;
3. resolves a query under a separately versioned resolver policy into `ResolvedStructuralContext`.

This satisfies the accepted authority while using one deployment unit.

Therefore separate deployment/process boundaries are **not** proved necessary by semantic necessity. The independent policy namespaces, records, versions, and outputs remain necessary.

**Attack result:** physical `MERGE_CANDIDATE`; logical V557/V558 merger not proved.

## CE-B06B — duplicate V556 edge wrapper is pure bloat

Construct a V555 route R with stable canonical route ID. Create a V556 row E that is one-to-one with R, adds no participant relation, no new condition, no topology, and differs only by a V556 ID.

E cannot pass the unique-meaning test. The accepted V556 authority says the V555 route is already the canonical base-edge identity. E is removable/reconstructible indexing, not V556 semantics.

**Attack result:** `REMOVAL_CANDIDATE` for the duplicate wrapper, not for the V556 interaction/topology jurisdiction.

## CE-B06C — renamed inherited V554 applicability condition is pure bloat

The V555 completion law requires inherited V554 F2 meaning to remain an exact reference. C' creates duplicate authority and divergence risk.

## CE-B06D — no-op numbered transit is not authority

Construct a producer-owned V554 affordance that is independently runtime-relevant but has no governed V555 route rule. Or construct a V555 route for which no V556 interaction/topology rule is authorized.

Creating a synthetic V555/V556 object solely so the object can continue through the sequence `V554 -> V555 -> V556 -> V557` adds no lawful meaning.

The mixed-producer publication architecture permits producer-owned structural objects to be published by V557 while retaining their own identities. Therefore no-op stage-number transit is bloat.

**Attack result:** `REMOVAL_CANDIDATE` for the no-op transit object; surviving semantic producer stages remain conditional on actual unique work.

## Counterexample checksum

The attacks separate two claims that must not be averaged together:

- **A logical jurisdiction can survive** because its independently governed decision/object/negative authority is indispensable when that semantic is needed.
- **A numbered transit/deployment boundary can still be bloat** when no such decision is needed for a particular object or when multiple logical seams are co-packaged without merging authority.

R03B therefore finds no lawful full-stage logical deletion among V554-V558, while finding concrete removable copies and no-op transit patterns.
