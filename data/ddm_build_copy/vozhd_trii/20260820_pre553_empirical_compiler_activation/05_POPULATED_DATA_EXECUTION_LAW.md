# Populated-data execution law

Remote GitHub/inspectorate environments are not allowed to convert absence of database access into empirical claims. Populated-data certification is a separate exact execution lane.

## Local execution role

A local exact checkout / Codex runner with lawful access to source artifacts or the populated database is used only where populated evidence is required. The local runner does not gain semantic authority by having data access; it executes already-frozen contracts and returns receipts.

## First local gates

1. Inventory exact source/release artifacts and database relations actually available.
2. Produce source-native counts/topology/routing/weight/coordinate diagnostics without normalization claims.
3. Ingest one deliberately bounded source/release into C11 after I02 is accepted.
4. Run source-native↔C11 equivalence protocol. Return `CERTIFIED`, `FAILED`, or `BLOCKED` with exact mismatches.
5. Only certified source/release lanes may support claims of source-equivalent replay.
6. Run exact query fixtures against the populated certified C11 lane.
7. Run bounded discovery and StructuralEmpiricalAdmission on exact accepted authorities.
8. Compile through unchanged V553→V558 and audit the resulting repository.

## Prohibited shortcuts

- no aggregate/count parity as source equivalence;
- no schema presence as populated completeness;
- no silent defaulting for missing topology/routing/weights;
- no treating current normalized V550 shared substrate as C11-equivalent without proof;
- no source deletion after certification;
- no source pooling to increase support unless separately authorized;
- no algorithm tuning against one source that changes semantic truth conditions.

## Evidence returned by each populated run

- exact Git HEAD;
- exact source/release/universe identifiers and immutable hashes where available;
- query/ingest authority hashes;
- code/config hashes;
- row/respondent/event/coordinate/routing/weight counts by typed state;
- rejected/defaulted/coerced count = zero unless exact governed rule authorizes transformation and receipt records it;
- source→C11 equivalence result;
- exact pytest/validation output;
- clean working tree before and after;
- output bundle/repository identities and replay roots.

Populated execution may reveal defects and may block a source. It may not repair contracts on the fly.
