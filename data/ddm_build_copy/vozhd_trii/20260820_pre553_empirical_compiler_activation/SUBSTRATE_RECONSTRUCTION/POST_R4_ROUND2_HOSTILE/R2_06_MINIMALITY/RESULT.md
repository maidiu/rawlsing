## DESTRUCTION_PATHS_FOUND

No unavoidable semantic destruction was found in P0 *as corrected*, but several destructive paths exist if its provisional mechanisms are implemented literally or additively:

- **Member-class reification:** treating every item in P0 §5.3 as a separate mandatory physical relation creates joins and failure surfaces not required by the logical information account. Logical separateness does not imply file/table separateness.
- **Profile semantic leakage:** hard-coded `if WVS`, `if LiTS`, `if SAV/DTA` physical organizations can become meaning branches. Capability-derived execution may differ; downstream C11/I03/I05/I04 meaning may not.
- **Cache-required practicality:** if the no-cache canonical path cannot execute the blind I05/open-world suite, an optional bitmap/index is no longer optional and P0 has hidden a second authority.
- **Late-pruning negative collapse:** filtering before authority/routing/risk/typed-negative resolution can convert unresolved/noncomparable/inapplicable evidence into empty/zero.
- **Normalization labyrinth:** C03 + C07 + C13 over the same field can require more synchronized state than direct event storage and can hide rare exceptions.
- **Compiler cross-product:** C05 + C12 + C08 + C20 produces type-lane x encoding-policy x vector-invariant x source-profile paths; one missed invariant can silently fabricate a valid-looking C11 projection.
- **Integrity ornamentation:** root hash + member hash + format checksum + Merkle/chunk tree without distinct failure jobs multiplies recovery/versioning states while adding no semantic protection.
- **Duplicate truth during migration:** automatic fallback or retained serving rollback means two empirical authorities in practice even if only one is called primary.
- **Benchmark capture:** relative wins (`2x`, `35%`) can reward a candidate that is faster on selected kernels while both candidates already satisfy the workstation envelope and the complex one is globally harder to audit, rebuild, and maintain.

These are repairable because Authority 54 already makes most mechanisms conditional and preserves a uniform C11 boundary.

## COMPLEXITY_MINIMALITY_EFFECT

1. freeze semantic/integrity courts and absolute workstation/resource/practical-runtime boundaries before candidate results are opened;
2. test the cacheless serial bounded `LONG_SHARDED` candidate first;
3. if it passes every required boundary, it wins and synthesis stops;

7. once any candidate passes all pre-frozen boundaries, faster/smaller numbers beyond those boundaries give no architectural credit.

If HQ has not frozen an absolute `practical` runtime boundary for a phase/workload, runtime speed alone cannot justify escalating from a passing simpler candidate. A locally favorable percentage is not a requirement.
