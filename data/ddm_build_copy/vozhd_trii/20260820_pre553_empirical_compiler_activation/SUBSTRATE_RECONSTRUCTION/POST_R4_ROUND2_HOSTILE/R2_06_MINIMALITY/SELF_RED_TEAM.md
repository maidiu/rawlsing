# R2-06 SELF RED TEAM — ATTACK THE MINIMALITY RED TEAM

Status: `HOSTILE_TO_OWN_SUBTRACTION_RULINGS`

R2-06 is dangerous if “minimality” becomes an aesthetic preference for long form rather than a requirement to choose the least complicated **sufficient** mechanism. The following attacks are mandatory checks against this return.

## RT01 — Long-form conservatism becomes inertia

**Attack:** `LONG_SHARDED` is called the baseline and then protected from evidence.

**Failure:** a simpler semantic representation can still be operationally insufficient. Open-world I05 or repeated cold query work may make linear scans impractical even when storage/RSS are excellent.

**Countermeasure:** LONG wins only if it passes every pre-frozen boundary. One failed absolute boundary reopens escalation immediately.

## RT02 — Missing runtime boundary makes “practical” unfalsifiable

**Attack:** reject all complex designs because no numeric practical-runtime law exists.

**Failure:** minimality becomes a veto rather than a court.

**Countermeasure:** HQ must freeze absolute phase/workload runtime boundaries before candidate results. Until then runtime *improvement* cannot justify escalation, but inability to complete an already-frozen court remains a failure if the court has an explicit time cap.

## RT03 — Physical co-location hides logical coupling

**Attack:** because sidecars are discouraged, routing, topology, weights, provenance, or question metadata are stuffed into one long row and repeated massively.

**Failure:** canonical storage can exceed preferred/hard budgets or build/reopen can become slower than a simple true-grain relation.

**Countermeasure:** co-location is a default only where it lowers total burden. Exact R02 true-grain lifting is allowed when the determinant is simple and measured savings close a boundary.

## RT04 — “No caches” benchmark is unrealistically punitive

**Attack:** a lawful disposable index could make a production workload cheap but R2-06 refuses to acknowledge it.

**Failure:** architecture is selected on an intentionally degraded execution path.

**Countermeasure:** cacheless correctness/open-world feasibility is mandatory; after that a cache may be benchmarked as an optional acceleration mechanism. It can influence operational tuning, but it cannot rescue an otherwise infeasible canonical organization if deletion destroys required reachability or violates a pre-frozen baseline feasibility law.

## RT05 — Flat integrity is insufficient for the actual substrate

**Attack:** whole-member hashing forces huge re-reads or cannot guarantee immutable consume-after-verify semantics for remote/ranged access.

**Failure:** the minimal integrity scheme misses a real availability/reopen/verification boundary.

**Countermeasure:** admit Merkle/chunk verification when a named boundary is frozen, partial query closure is independently proven, and chunk hierarchy actually closes the boundary. R2-06 defers; it does not forbid.

## RT06 — Root inventory is not enough for absence

**Attack:** exhaustive root-listed shard scan is assumed complete but shard coverage metadata cannot prove all source/question/event regions are represented.

**Failure:** exact negative queries can falsely close.

**Countermeasure:** add one canonical root-bound completeness structure if and only if the source-to-shard traversal law cannot establish exhaustive coverage from the authoritative inventory itself.

## RT07 — Vectorization may be needed even with long storage

**Attack:** defer C08 because it is Class C and retain per-event Python semantic construction in the hot path.

**Failure:** build RSS/CPU fails even though the physical organization is sound.

**Countermeasure:** vector compiler is orthogonal to organization. A direct bounded vector compiler may write LONG_SHARDED if it reproduces every invariant and the independent oracle passes.

## RT08 — Serial-first becomes a needless wall-time tax

**Attack:** serial bounded build passes memory but misses an explicit workstation wall-time boundary.

**Failure:** R2-06 blocks a safe deterministic parallel pipeline.

**Countermeasure:** once serial determinism/boundedness is proven and a pre-frozen wall-time boundary fails, C15 is an appropriate narrow escalation. Determinism must survive 1/2/N worker variants and queues count toward RSS.

## RT09 — Question-blocked long may be simpler than the red team admits

**Attack:** classify QBL as Class-C-like complexity when it is merely a clustering/sharding choice over the identical event schema.

**Failure:** R2-06 overstates proof cost.

**Countermeasure:** QBL is the preferred *first layout escalation* precisely because it need not introduce new semantics, indexes, or virtual objects. If a projection/read-amplification boundary fails in LONG, QBL can advance before hybrid dense machinery.

## RT10 — Hybrid may be globally simpler than normalized long

**Attack:** reject HYBRID because dense+explicit has two physical forms while LONG requires many normalized dimensions/default/exception joins to hit storage limits.

**Failure:** mechanism count is counted superficially rather than by total coupling.

**Countermeasure:** compare total-system burden. If certified dense blocks plus one explicit escape relation are simpler than the normalization stack needed by long and they pass every boundary, HYBRID may legitimately win.

## RT11 — “One organization globally” becomes source imperialism

**Attack:** force every release into identical physical geometry even when exact capability certificates differ.

**Failure:** neutral semantics are confused with identical physical layout.

**Countermeasure:** prefer one organization across scope, but permit capability-derived block/release physical choices where the common runner proves zero semantic effect. Never dispatch by source family meaning.

## RT12 — Deleting rollback bytes damages recoverability

**Attack:** immediately delete old root after promotion because duplicate steady-state truth is forbidden.

**Failure:** a higher availability/recovery requirement may demand bounded retention.

**Countermeasure:** current authority does not establish that requirement. If higher authority later does, retain exactly one non-serving rollback candidate under an explicit TTL/byte law, fresh verification, and no automatic fallback. Until then rebuild/restore is the minimal law.

## RT13 — Complexity cannot be reduced to mechanism count

**Attack:** candidate A has fewer components but each is opaque; candidate B has more components but cleaner failure boundaries.

**Failure:** “minimal” becomes simplistic counting.

**Countermeasure:** selection is not a scalar mechanism score. Use exact boundaries plus diagnosability: number of canonical truths, semantic ingress paths, source branches, reconstruction dependencies, profile cross-products, invalidation DAGs, recovery states, and invariant implementations.

## RT14 — Independent oracle becomes a second production engine

**Attack:** the one-runner contract independently reimplements every query path and doubles semantic code.

**Failure:** the acceptance mechanism becomes permanent architecture tax and may itself drift.

**Countermeasure:** follow R03 RT29: the independent evaluator stays small—canonicalization/hash recomputation, exact set/incidence/support evaluation, finite blind frontier compilation, comparison, and fault injection. It is release court tooling, not serving query infrastructure.

## RT15 — Baseline event fields become gratuitously repeated

**Attack:** direct long storage carries every authority/dependency/replay ref per event even when an exact question/release determinant is trivially certified.

**Failure:** R2-06 mistakes directness for simplicity.

**Countermeasure:** allow obvious exact true-grain ownership when the certificate is short, total, and reconstruction is one fixed join/map. The red team opposes *stacked* compaction, not all normalization.

## RT16 — Benchmark boundary gaming

**Attack:** freeze absolute thresholds so loosely that every candidate passes, guaranteeing LONG; or so tightly that only a preselected complex candidate passes.

**Failure:** “pre-frozen” does not itself make a benchmark legitimate.

**Countermeasure:** runtime boundaries must derive from the actual workstation/terminal demand envelope and be frozen before candidate measurements by HQ, not chosen by the candidate cell. Include whole-workflow and worst required hostile/open-world cases, not only median marginals.

## RT17 — Cacheless feasibility confused with production latency

**Attack:** require no-cache path to meet the same aggressive latency target as a lawful optional cache.

**Failure:** caches can never earn admission.

**Countermeasure:** split gates: no-cache path must be correct, bounded, open-world, and complete within a frozen fallback/acceptance envelope; optional caches may meet a stricter serving-latency objective if that objective exists. Cache remains deletable truth-wise.

## RT18 — Physical-state co-location allows accidental semantic inference

**Attack:** inline physical and semantic state lanes in one event shard and query kernels start treating adjacency/code relations as meaning.

**Failure:** logical separation is lost despite no sidecar.

**Countermeasure:** schema and validation retain separate typed fields/vocabularies and no implicit transform. Co-location changes only bytes, not authority.

## RT19 — P0 is actually incomplete

**Attack:** a Round-2 sibling later demonstrates one lawful source/C11 occurrence P0 cannot reconstruct, or an I03/I05 workload it cannot execute from canonical truth.

**Failure:** this R2-06 `PASS_WITH_CORRECTIONS` is too generous.

**Countermeasure:** HQ must combine accepted Round-2 returns. One demonstrated semantic destruction changes the relevant mechanism/P0 disposition to reject until concretely repaired.

## RT20 — This return overclaims evidence

**Attack:** organization decision rules are mistaken for measured conclusions.

**Failure:** design-only evidence is laundered into implementation selection.

**Countermeasure:** R2-06 selects **no final organization**. It fixes order, gates, and stop conditions. Final physical selection requires later implementation authority and the one-runner court.

## Self-disposition

`SURVIVES_AS_A_DECISION_PROTOCOL__NOT_AS_A_LONG_FORM_PREFERENCE`.

Reject this return if its rules prevent a more complex candidate from advancing after the simpler candidate demonstrably fails a legitimate pre-frozen whole-machine boundary. The point is not to keep machinery out. The point is to make every piece of machinery prove why the machine needs it.
