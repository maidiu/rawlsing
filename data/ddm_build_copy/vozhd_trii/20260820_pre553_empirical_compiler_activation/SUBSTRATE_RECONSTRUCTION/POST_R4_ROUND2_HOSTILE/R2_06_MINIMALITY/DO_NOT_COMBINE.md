# R2-06 `DO_NOT_COMBINE` LAW

Status: `ROUND2_HOSTILE_SYNTHESIS_VETOES`

This is not a list of mechanisms that can never coexist under any future authority. It is a presumption against cross-products. HQ may override a veto only by naming the pre-frozen boundary that each constituent closes and proving that no smaller subset closes all boundaries.

## DNC-01 — Do not combine three incidence organizations

`LONG_SHARDED + QUESTION_BLOCKED_LONG + HYBRID_DENSE_PLUS_EXPLICIT` as simultaneous persistent canonical serving copies is forbidden.

They are competing organizations, not tiers. The court may build shadow candidates one at a time, but the selected release has one canonical organization. A compatibility projection must be virtual/transient unless separately proven necessary.

## DNC-02 — Do not combine the matrix stack

`HYBRID_DENSE_PLUS_EXPLICIT + canonical question partition copy + persistent predicate bitmap truth + persistent virtual-long copy + late-materialization cache` is rejected.

That bundle creates several synchronized representations of the same incidence. Pick the canonical carrier first. Any later accelerator remains disposable and must not recreate a second required long/matrix truth store.

## DNC-03 — Do not combine triple compaction on one field

`true-grain normalization + default/exception encoding + hot/cold tiering` over the same semantic field is presumptively rejected.

Use the single exact ownership/encoding with the lowest total burden. Two compaction layers require two independent named failures; three require three. “It saves more bytes” is not enough.

## DNC-04 — Do not combine equality inference with semantic deduplication

`raw-vector equality/hash + dictionary dedupe + MR/topology dedupe + canonical-question collapse` is forbidden.

Accepted WVS and MR alias evidence directly defeats this inference. Equal observed data does not authorize identity collapse.

## DNC-05 — Do not combine physical-position identity with repartitioning

`row-group/file/block position as event ID + adjustable row-group/shard size + parallel build` is forbidden.

A physical tuning parameter cannot migrate semantic/replay identity. Transient physical pointers are allowed only below exact immutable source/event identity.

## DNC-06 — Do not combine source-family dispatch with semantic consumers

`source-family compiler/profile selector + I03/I05/I04/V553 source-family branch` is forbidden.

Source-specific reader behavior may exist under the frozen decoder. Physical capability dispatch may exist below C11. Meaning must converge before the common logical boundary.

## DNC-07 — Do not combine compiler cross-product features by default

`exact typed lanes + adaptive per-variable encoding policy + direct vector invariant implementation + source-local compiler family` is rejected as a baseline bundle.

Keep exact typed lanes. Add vectorization only if constructor-heavy compilation fails a boundary. Add adaptive encoding only if standard tuning fails. Source-local compiler families are last-resort physical specialization. No two are admitted merely because each is individually plausible.

## DNC-08 — Do not combine cache tiers

`persistent identity cache + persistent predicate bitmap + materialized query cache + hidden analytical DB/index` is forbidden.

Zero persistent caches is baseline. If one disposable accelerator later earns admission, adding a second requires a separate workload objective and deletion/ablation proof. No cache may contain unique truth.

## DNC-09 — Do not combine a mutable active alias with long-lived caches

`latest/current filesystem alias + path-keyed cache` is forbidden.

Active selection is explicit trusted root identity. Every cache key binds the exact immutable root plus relevant schema/builder/config/authority dependencies.

## DNC-10 — Do not combine hot/cold split with question blocking before proving joins

`hot/cold canonical tiering + QUESTION_BLOCKED_LONG` is rejected by default.

Both split the same logical release along different axes. If replay/I05 needs cold metadata across many question blocks, the cross-product defeats the locality claim. Court QBL alone first.

## DNC-11 — Do not combine QBL with per-question tiny files

`QUESTION_BLOCKED_LONG + one physical file/member per question` is rejected unless a measured backend demonstrates it is necessary.

Question-blocked means bounded blocks, not file explosion. Member count, metadata open cost, integrity hashes, and k-way fanout count toward the decision.

## DNC-12 — Do not combine bitmap absence with routing inference

`physical missing/null bitmap + inferred inapplicability/routing + NOT complement over physical rows` is forbidden.

Physical missingness, semantic state, and routing/risk-set membership are independent. NOT is evaluated only inside the governed exact universe/risk set.

## DNC-13 — Do not combine late materialization with pre-resolution pruning

`late materialization + target/value pruning before authority/routing/risk/negative-state resolution` is forbidden.

A speed path may not erase the evidence needed to distinguish unavailable, unresolved, nonmember, valid-empty, zero-support, or integrity failure.

## DNC-14 — Do not combine multiple integrity layers without independent jobs

`root hash + whole-member hash + format checksum + Merkle tree + cache hash + persisted verified marker` is rejected as an accumulated trust stack.

Baseline jobs are: root identity/authorization, member integrity, full audit, cache self-discard. Add chunk hierarchy only for a named partial-verification/fetch/repair job. A persisted `verified=true` never authorizes a new process.

## DNC-15 — Do not combine Merkle with unproven query closure

`chunk verification + empirical output authorization` is forbidden unless a conservative query dependency/completeness closure is independently proven.

Authenticated selected bytes are not sufficient selected evidence. If closure is unclear, verify the whole member/release or fail closed.

## DNC-16 — Do not combine shadow/rollback with automatic fallback

`active new root + retained old root/shadow + runtime fallback` is forbidden.

A bounded non-serving shadow is allowed for the implementation court. After promotion, old truth loses serving authority immediately. Rollback is explicit, freshly verified, and atomically authorized—not an error handler.

## DNC-17 — Do not combine canonical and cache completeness

`root-bound canonical completeness index + disposable bitmap/Bloom miss treated as additional negative proof` is forbidden.

If completeness is canonical, use that exact structure. Disposable accelerators may guide read order but cannot independently close absence.

## DNC-18 — Do not combine finite query cubes with blind-I05 claims

`precomputed pair/k-way/materialized query cube + claim of unforeseen discovery support` is rejected unless the blind frontier is independently executable from canonical incidence after the cube is deleted.

Preaggregation can accelerate known work. It cannot define empirical possibility.

## DNC-19 — Do not combine candidate-specific runner with common oracle claim

`organization-specific benchmark harness + different reconstruction/export semantics + common pass label` is forbidden.

All candidates enter the same one-runner contract and the same independent R03 lanes. Candidate adapters may expose the common carrier-neutral interface; they may not weaken the court.

## DNC-20 — Do not combine warm-cache metrics with organization selection

`warm-cache latency + relative percentage speedup -> canonical organization winner` is forbidden.

Canonical organization selection uses cacheless correctness/open-world results and pre-frozen absolute boundaries. Warm caches are evaluated only after the organization is independently sufficient.

## DNC-21 — Do not combine relative scorecards into a weighted winner

`storage score + query score + complexity score + pass percentage -> aggregate rank` is rejected.

Correctness/integrity are conjunctive. Resource/practical boundaries are gates. Among candidates passing all gates, the least-complex earlier organization wins. No weighted score can purchase a semantic failure or complexity tax.

## DNC-22 — Do not combine source-local compiler exceptions with downstream repair

`source-local compiler emits incomplete C11 + I03/I05 special-case repairs it` is forbidden.

Every physical compiler must converge to complete shared C11 before downstream execution. A downstream repair is semantic leakage.

## DNC-23 — Do not combine direct vector compilation with candidate self-certification

`vector compiler + vector-generated expected digest/count + parity claim` is forbidden.

The independent oracle recomputes semantic projections/hashes and selected respondent-set truth outside candidate physical logic.

## DNC-24 — Do not combine adaptive policy with semantic data distribution

`observed frequency/range/cardinality -> semantic omission/default/type narrowing` is forbidden.

Physical encoding may adapt only if exact round-trip law is preserved; observed distribution never proves information irrelevance.

## DNC-25 — Do not combine telemetry framework with acceptance dependency

`carrier correctness/selection requires a persistent telemetry service/database` is forbidden.

The common runner emits fixed receipts. Operations tooling is outside this physical truth contract unless later authorized.

## DNC-26 — Do not combine “future-proof” mechanisms without current boundaries

Any two or more deferred mechanisms justified only by hypothetical future scale are rejected.

The current campaign optimizes the frozen whole-machine/workstation envelope. New future requirements can reopen the court with evidence.

## Override law

To override any DNC item, synthesis must record:

1. exact constituent mechanisms;
2. exact pre-frozen boundary failed without each constituent;
3. measured candidate demonstrating the full bundle crosses every failed boundary;
4. proof that every strict subset was tested or mechanically shown insufficient;
5. unchanged R03 oracle/I03/I05/I04/integrity/replay outcomes;
6. total canonical + staging + scratch + cache bytes and per-phase RSS/runtime;
7. new profile/invariant/invalidation/recovery states introduced;
8. deletion/rollback plan if the mechanism later proves unnecessary.

Without that record, the veto stands.
