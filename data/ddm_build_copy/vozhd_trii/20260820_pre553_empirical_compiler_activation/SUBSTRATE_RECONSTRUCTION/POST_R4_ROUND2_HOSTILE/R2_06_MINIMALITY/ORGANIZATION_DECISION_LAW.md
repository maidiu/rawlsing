## Zero-th law — selection is lexicographic, not scored

Every candidate must first pass the same semantic/source/oracle, integrity, replay, bounded-memory, one-copy, and open-world capability gates.

Then it must pass absolute resource and practical-runtime boundaries frozen **before** candidate results are opened.

Among candidates that satisfy every boundary, use the least-complex organization earliest in the escalation order. Faster/smaller performance beyond a passing boundary gives no architectural credit.

A relative percentage improvement is never itself a selection condition.

## Common hard gates for every organization

A candidate is ineligible unless all `G01-G18` hold.

### G01 — exact source-native reconstruction

All applicable accepted source-physical hostile facts reconstruct exactly, including raw value/state/declaration, source row/variable identity, blank values, type/storage metadata, MR declarations, and source-specific physical exceptions.

### G02 — complete C11 M01-M18 equivalence

Full canonical public/internal semantic projections/ref multisets and independently recomputed hashes match the frozen semantic law.

### G03 — one C11 boundary

I03/I05/I04 consume one carrier-neutral invariant-checked view; no profile/source-family semantic ingress exists.

### G04 — cacheless open-world I03

Arbitrary lawful AND/OR/NOT, k-way joint, routing/risk, high-cardinality/string, weight/design, topology, multi-universe, positive and typed-negative queries execute from canonical truth with every optional accelerator deleted.

### G05 — cacheless open-world I05

Post-candidate-freeze blind frontier executes completely without re-ingest, finite predicate vocabulary, source-family semantic branch, or persistent accelerator requirement.

### G06 — exact I04

Admission/nonadmission state, precedence, evidence/authority closure, and positive projection permission are unchanged.

### G07 — topology completeness

Repeated/ranked/ordered/componentized/multiselect/MR alias/overlap and rare event-specific exceptions remain exact; no false `(respondent, question)` uniqueness.

### G08 — state separation

Physical missingness, semantic response/absence state, and routing/applicability remain independently represented and governed even if physically co-located.

### G09 — layout-independent identity

Semantic/replay identity survives shard/block/row-group/compression/temp-path/fs-order and any lawful worker-count changes.

### G10 — bounded whole workflow

Build, seal, reopen, full audit, I03, blind I05, replay, integrity, and candidate adapter do not require corpus-scale Python retention. Backend dictionaries/inventories/queues count.

### G11 — fail-closed integrity

Missing, corrupt, partial, stale, cross-release, wrong-authority, or unauthorized root/member state emits no plausible empirical result.

### G12 — atomic publication

Staging/shadow never serves; content-addressed promoted candidate remains inactive until verified/authorized; active selector is explicit atomic/CAS; mixed-root query is impossible.

### G13 — one-copy authority

Exactly one serving root. Optional caches contain no unique truth. Shadow is non-serving and bounded to the court. No automatic old-root/cache/legacy fallback.

### G14 — full audit

Complete bounded root/member/semantic audit remains possible regardless of any partial/lazy optimization.

### G15 — resource hard gates

At minimum the frozen Authority-52/accepted envelope remains binding:

- peak RSS hard: `<= 4 GiB`;
- WVS carrier hard: `<= 4 GiB`;
- LiTS carrier hard: `<= 3 GiB`;
- CLOSED_35 carrier hard: `<= 32 GiB`.

Preferred boundaries are targets the simpler candidate must satisfy absent an explicitly documented HQ exception:

- peak RSS preferred: `< 2 GiB`;
- WVS carrier preferred: `<= 2 GiB`;
- LiTS carrier preferred: `<= 1.5 GiB`;
- CLOSED_35 carrier preferred: `<= 20 GiB`.

### G16 — practical runtime boundaries

HQ must freeze absolute phase/workload runtime envelopes before candidate results. Required phases include build, reopen, full audit, representative/hostile I03, blind I05, replay, and integrity verification.

If no absolute runtime boundary exists for a phase, a relative speed win on that phase cannot justify added architecture after a simpler candidate already passes all existing gates.

### G17 — source neutrality

Source-family semantic branch count downstream of frozen decoder/common carrier boundary is exactly zero. Capability-derived physical dispatch is allowed only where its inputs are exact sealed physical/grain certificates and its semantic effect is zero.

### G18 — minimum complexity closure

No mechanism in the candidate can be removed while leaving G01-G17 and all frozen boundaries passing. If one can, remove it before selection.

# Decision A — `LONG_SHARDED`

## Definition

One logical event row per occurrence in bounded canonical shards, with only simple exact true-grain metadata ownership that is independently certified. Event-varying raw value/state/semantic state/source coordinates and any unproved event-specific topology/authority stay directly reconstructable from the event incidence. No persistent bitmap/query cache is required.

## LONG wins if and only if L01-L10 all hold

### L01

G01-G18 all pass.

### L02

The dispositive run is cacheless and serial bounded. Optional vector kernels may be used only if separately admitted and parity-proven; they do not change organization.

### L03

No mandatory question-projection/index sidecar is required to satisfy I03/I05 reachability.

### L04

Reopen/full audit stay bounded without eager materialization of event or side-relation corpora.

### L05

Verified authoritative shard inventory plus exact traversal/coverage law is sufficient for exhaustive positive/negative scans; no separate canonical completeness index is required unless independently justified.

### L06

It meets hard resource gates and, absent explicit HQ exception, preferred storage/RSS gates.

### L07

It meets every pre-frozen practical-runtime boundary.

### L08

Its total complexity does not require multiple reconstruction defaults/exception/tier/cache paths merely to recreate one event.

### L09

All accepted heterogeneous hostile shapes fit the common event/metadata contract without source-family semantics.

### L10

Every proposed next mechanism would improve only an already-passing metric rather than close a failed boundary.

## LONG disposition

If L01-L10 pass:

`SELECT_LONG_SHARDED__STOP_PHYSICAL_ESCALATION`

Do **not** build QBL or HYBRID merely to discover whether they are faster/smaller.

## LONG does not fail merely because

- exact fallback is O(N);
- another design compresses better;
- another design is 2x faster on one marginal query;
- a bitmap would make repeated predicates cheaper;
- a matrix appears more modern.

LONG fails only a frozen boundary or hard semantic/integrity condition.

# Decision B — `QUESTION_BLOCKED_LONG`

## Definition

The exact same logical event schema as LONG, but physical canonical shards are clustered into bounded blocks by exact native variable/question coordinates so queries can project fewer event bytes. No separate canonical matrix, persistent bitmap truth, or alternate C11 object family is created.

## QBL may enter court only if Q00 holds

### Q00 — named LONG failure

LONG must pass G01-G14/G17 semantic-integrity laws but fail at least one pre-frozen practical boundary specifically attributable to avoidable reading/decompression of irrelevant question/event shards, projection fanout, or reopen locality.

If LONG's failure is build RSS, source decoding, raw storage size, constructor CPU, publication integrity, or source-specific semantics, QBL is not the targeted remedy unless a mechanical proof links the failure directly to question clustering.

## QBL wins if and only if Q01-Q12 all hold

### Q01

G01-G18 all pass for QBL.

### Q02

The logical event schema and semantic projection are identical to LONG. Only physical clustering/member grouping changes.

### Q03

Question block keys are exact native variable/question identities, not canonical label/value equality and not source-family defaults.

### Q04

Block count/width policy is deterministic and semantically incidental; changing permitted block width leaves logical refs/results identical.

### Q05

The failed LONG projection/read-amplification boundary now passes.

### Q06

No other pre-frozen boundary that LONG passed becomes failed, especially multi-block k-way/blind-I05/replay/full-audit bounds.

### Q07

Arbitrary k-way and multi-block I05 workloads remain cacheless and require no pair/joint precomputation.

### Q08

NOT/routing/risk-set semantics do not use block absence as respondent nonmembership.

### Q09

No one-file-per-question explosion causes member-open/integrity/metadata complexity to miss another boundary; block grouping remains bounded.

### Q10

QBL does not require hot/cold canonical tiers, persistent bitmaps, materialized joint tables, or a persistent virtual LONG copy to pass.

### Q11

Source-family identity is absent from block selection/semantic behavior.

### Q12

After QBL passes all boundaries, additional HYBRID machinery is unnecessary under the stop rule.

## QBL disposition

If Q00 and Q01-Q12 pass:

`SELECT_QUESTION_BLOCKED_LONG__STOP_PHYSICAL_ESCALATION`

# Decision C — `HYBRID_DENSE_PLUS_EXPLICIT`

## Definition

One canonical release containing:

- dense typed incidence blocks **only** where exact immutable geometry/grain certificates prove respondent/question/event coordinate reconstruction; and
- one total explicit-event escape representation for every nonrectangular, repeated/ranked/componentized/MR/exceptional/unproven event.

Dense and explicit are physical forms under one C11 boundary, not separate semantic ontologies.

## HYBRID may enter court only if H00-H04 all hold

### H00 — lower-risk organizations actually insufficient

LONG and the targeted lower-risk remedies were tested. QBL was tested when the failure was a projection/read-amplification problem. A named pre-frozen boundary remains failed.

### H01 — failure source is compatible with HYBRID's mechanism

The remaining failure is materially attributable to repeated event-row/coordinate/value-state representation, scan/materialization overhead, or canonical storage/CPU cost that dense typed incidence can plausibly remove.

### H02 — obvious narrower remedies exhausted

Bounded writer/reopen, standard row-group/compression tuning, one simple true-grain FD lift, fixed exact typed lanes, and—where applicable—QBL did not close the boundary.

### H03 — exact certificates exist before dense omission

For every dense block the runner has accepted R02-style determinant/geometry/grain certificates naming exact coordinate law, scope, reconstruction, exception/fallback and failure behavior. Observed rectangularity/frequency is insufficient.

### H04 — explicit escape is total by construction

Any event that does not satisfy the dense certificate is explicitly represented; overflow/unknown geometry causes fallback to explicit or blocks publication, never silent omission.

## HYBRID wins if and only if H05-H18 all hold

### H05

G01-G18 all pass.

### H06

The named lower-risk failed boundary now passes.

### H07

No lower-risk candidate's previously passing boundary becomes failed.

### H08

The hybrid passes the complete cacheless blind I05 court; no bitmap/index is needed to make dense incidence queryable.

### H09

Dense versus explicit selection uses exact capability/grain certificates only; no `if WVS/EVS/GSS/SAV/DTA` semantic rule.

### H10

At most one dense physical schema family and one explicit-event escape schema are required for the admitted scope unless an additional schema has its own independent failed boundary and proof.

### H11

The explicit escape is not a tiny forgotten exception store: it is root-bound canonical truth with exact coverage and hostile topology tests.

### H12

Physical state, semantic state and routing remain separate typed/logical dimensions; no dense null code collapses them.

### H13

All-row typed-missing, blank strings, zero-incidence declarations, MR aliases, and raw-identical/dictionary-distinct variables survive dense/metadata reconstruction.

### H14

Virtual event reconstruction is one audited C11 path and independently matches full semantic projections/hashes; physical matrix coordinates never enter semantic identity.

### H15

Total cost counts dense members + explicit event members + dimensions/metadata + root/integrity + scratch + any required reconstruction joins. It is not compared using dense payload bytes alone.

### H16

No persistent virtual-long copy, persistent bitmap truth, source-specific repair database, or mandatory materialization cache exists.

### H17

Profile/block relayout and worker-count variants leave semantic identity/results/replay unchanged.

### H18

After HYBRID passes all boundaries, every remaining accelerator/profile/sidecar failing the deletion test is removed.

## HYBRID disposition

If H00-H18 pass:

`SELECT_HYBRID_DENSE_PLUS_EXPLICIT__STOP_PHYSICAL_ESCALATION`

If H03/H04/H08/H14 fails, HYBRID is not repairable by adding caches or source-family exceptions. Return to explicit/lower-risk truth and diagnose.

# Cross-organization stop rule

The selection algorithm is:

```text
freeze courts + absolute boundaries

court LONG_SHARDED
if sufficient:
    select LONG_SHARDED
    stop

classify exact failed boundary
if failure is question-projection/read-amplification:
    court QUESTION_BLOCKED_LONG
    if sufficient:
        select QUESTION_BLOCKED_LONG
        stop

exhaust the narrowest remedy for the named remaining failure

only if failure matches dense-incidence mechanism and exact geometry/grain certificates exist:
    court HYBRID_DENSE_PLUS_EXPLICIT
    if sufficient:
        select HYBRID_DENSE_PLUS_EXPLICIT
        stop

otherwise:
    no organization selected; return named failure to HQ
```

There is no stage:

`build all three -> score them -> pick the fastest`.

The campaign's burden is necessity, not architectural competition.
