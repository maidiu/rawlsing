# R2-01 SELF RED TEAM — ATTACK THE `P0_REPAIRABLE` VERDICT

Status: `HOSTILE_TO_OWN_DISPOSITION`

The court's danger is to turn P0's abundant fallback language into an unfalsifiable design: every destructive mechanism is declared conditional, and every counterexample is answered with “fall back to direct storage.” That can make P0 technically non-destructive while leaving no precise carrier at all. The following attacks therefore target the court's own conclusion.

## RT01 — The information account is broader than the provisional P0

**Attack:** Authority 54 P0 5.3 names relation classes but not every source/C11 field. This court repairs that by supplying a complete field account. That may be a substantive design addition, not merely clarification.

**Defense:** Authority 54 explicitly requires Round-2 to produce the complete P0 information account. The account does not create new semantics or new data; it closes the representation proof P0 was intentionally provisional about.

**Falsifier:** if HQ finds a field in the frozen source/C11 oracle that is absent even from `P0_INFORMATION_ACCOUNT.csv`, the repairable verdict fails.

## RT02 — “Direct fallback” could erase boundedness

**Attack:** Every failed FD can fall back to direct event storage, but perhaps the resulting safe P0 reverts to the same unbounded implementation pattern R4 exposed.

**Defense:** direct storage is an information disposition, not permission for corpus-scale Python retention. R01 already supplies bounded streaming/external-merge/sharded mechanics for direct long incidence.

**Falsifier:** if some direct canonical relation cannot be written/reopened/audited with bounded state without a destructive grain move, P0 is not repairable.

## RT03 — Complete source metadata may not fit the proposed logical owners

**Attack:** source-native storage-slot mechanics, encoding controls, reader receipts, zero-incidence declarations and topology metadata may not map cleanly into release/question dimensions.

**Defense:** P0 need not force every source observation into C11 public objects. It may store exact source-physical metadata as canonical release/question/topology members behind the same source-reconstruction oracle, provided downstream semantics remain neutral.

**Falsifier:** a frozen source-native observation whose determinant is neither release/question/respondent/event nor representable as explicit canonical source metadata defeats the current account until an owner is added.

## RT04 — Arithmetic locator repair may still be too generous

**Attack:** even a source-cell locator `r*V+v` can be wrong if decoder logical-variable order differs from physical storage slots or traversal is not complete/rectangular.

**Defense:** the court conditions it on the exact decoder logical traversal, not SAV slot/header position; explicit `(row_ordinal, variable_ordinal)` fallback is mandatory.

**Falsifier:** any certified scope where `r`, `V`, or `v` is not immutable/reversible blocks C06 there.

## RT05 — Multiple semantic events may not correspond one-to-one to physical cells

**Attack:** explicit event topology still may need source lineage beyond row+variable+occurrence.

**Defense:** the event relation stores the complete frozen `RespondentEvent` identity-bearing projection including event group, occurrence/index, component/subitem, topology refs, authority/dependency refs and producer replay root. No claim is made that the cell coordinate alone reconstructs it.

**Falsifier:** an accepted event whose frozen projection cannot be represented by these fields would reject P0.

## RT06 — Question-grain authority may hide release drift

**Attack:** a question metadata row keyed only by canonical question can merge waves with same-looking questions but different source labels/codes/types.

**Defense:** every question/variable owner is release-local and retains native variable/question identity. Canonical question identity is additive, never the storage key by itself.

**Falsifier:** any cross-release/global question dictionary in implementation violates the court ruling.

## RT07 — Sparse exception completeness is itself expensive canonical data

**Attack:** proving no exception exists may require essentially direct storage, making C07 pointless.

**Defense:** correct; this defeats the optimization, not P0. Minimality requires direct storage when exception bookkeeping approaches direct cost.

**Falsifier:** none against P0; it is a mechanism-deletion result.

## RT08 — Completeness structures can become a second ontology

**Attack:** a canonical index used for exact negatives could encode a finite query vocabulary and narrow I05.

**Defense:** completeness may index physical domains/partitions/exact refs, not define the set of legal predicates/candidates. Arbitrary lawful predicates still have canonical scan fallback.

**Falsifier:** if an unindexed lawful I03/I05 operation cannot be decided without reingest, P0 fails open-world law.

## RT09 — Hot/cold repair can negate late-materialization benefit

**Attack:** if exact closure routinely pulls cold authority/topology/provenance, the split adds complexity without useful pruning.

**Defense:** then delete the split. P0 does not require C13.

**Falsifier:** not semantic; this is a minimality rejection of C13.

## RT10 — Full object projections may duplicate too much

**Attack:** storing complete routing/weight/authority/replay projections at their true grain can still repeat refs and waste bytes.

**Defense:** dictionary/typed physical encoding may compress repeated bytes without changing information grain. Further omission requires exact FD proof. Storage pressure cannot turn repeated authority refs into inferred authority.

## RT11 — Source-native ID as event evidence is easy to forget

**Attack:** once row ordinal becomes the respondent key, an implementation might omit the source's ID variable because it is “not identity.”

**Defense:** the native ID variable remains ordinary source physical incidence/question material and appears independently in the source reconstruction account. Respondent-key authority is a separate C11 field.

**Falsifier:** O1 source-native comparison catches any omitted native ID cell/metadata.

## RT12 — R03 oracle may itself under-specify a future source field

**Attack:** `P0_INFORMATION_ACCOUNT.csv` derives its field vocabulary from frozen Round-1 R03. If source law expands later, the account can become incomplete.

**Defense:** the account is versioned to the frozen Round-2 authority. Future authority/schema changes require a new account/root identity; no “latest schema” fallback.

## RT13 — Query parity could still conceal source loss

**Attack:** all current I03/I05/I04 tests pass after source metadata deletion.

**Defense:** R03 O1 source-native equivalence and O2 full C11 multiset/projection equality precede behavioral gates. This court explicitly rejects behavioral-only acceptance.

## RT14 — Repairable may be too lenient because P0 prose is ambiguous

**Attack:** a hostile court should reject ambiguity rather than repair it.

**Defense:** Authority 54 defines P0 as provisional and explicitly sends R2-01 to produce the complete information account. The proper Round-2 outcome can therefore be `PASS_WITH_REQUIRED_CORRECTIONS` where the architecture can represent the information exactly but the synthesis text needs binding repair.

**Falsifier:** if a destructive path requires changing P0's core architecture rather than tightening ownership/fallback law, disposition must become `ROUND2_REJECT`.

## RT15 — One complete C11 materialization boundary may itself force eager memory

**Attack:** “complete projection” could be interpreted as materializing the whole release.

**Defense:** completeness is per logical object/relation/release proof, not whole-corpus Python residency. A bounded facade can reconstruct one object/batch at a time and stream full equality/audit.

**Falsifier:** if frozen consumers require a corpus-wide in-memory tuple as semantic law rather than an implementation accident, P0 boundedness would conflict with the frozen interface and require HQ adjudication.

## Final self-disposition

The court keeps `ROUND2_PASS_WITH_REQUIRED_CORRECTIONS__P0_REPAIRABLE`, but only because the repaired P0 has a universal conservative fallback: exact direct canonical storage at the true frozen information grain with bounded physical mechanics. Any implementation that treats the conditional mechanisms as presumptive compression rather than optional certified encodings should be rejected before benchmark court.
