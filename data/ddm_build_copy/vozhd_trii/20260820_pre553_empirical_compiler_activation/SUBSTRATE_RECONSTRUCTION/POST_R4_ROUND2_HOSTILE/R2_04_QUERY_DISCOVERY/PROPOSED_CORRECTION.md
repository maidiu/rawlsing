# PROPOSED CORRECTION — `P0_OPEN_WORLD_INCIDENCE_ALGEBRA@1`

Status: `ROUND2_REQUIRED_CORRECTION__PHYSICAL_EXECUTOR_ONLY__NO_SEMANTIC_EXPANSION`

## 1. Purpose

Authority 54 P0 already requires exact open-world I03/I05 behavior, removable accelerators and governed NOT. R2-04 found that those statements need one carrier-neutral executor contract before implementation so a planner cannot satisfy the words while allowing an accelerator/catalog to delimit what canonical evidence is searched.

This correction adds **no new semantic family, predicate operator, I05 family, source relation, admission rule or source authority**. It is an implementation obligation beneath frozen C11/I03/I05/I04.

## 2. Open-world definition

For this physical contract:

> Open-world means that every query/predicate/discovery operation already lawful under frozen authority can be evaluated from canonical release material without source re-ingest and without requiring a prebuilt predicate/value/joint/branch accelerator.

It does **not** mean arbitrary new semantic leaf types are authorized.

It does **not** mean one I05 run has an infinite frontier. Each exact-bounded I05 frontier remains finite/finitely-constructible and authority-fixed before data evaluation.

The forbidden finite vocabulary is the carrier's ingest/index catalog as a global capability boundary.

## 3. Mandatory no-cache operations

Every admitted P0 physical organization must provide a no-cache implementation equivalent to the following abstract operations.

### O1 — exact source/universe resolution

Input: exact release refs + exact universe refs.

Output: exactly one sealed canonical universe context for each requested universe, or the frozen source-scope failure.

No latest/default/fuzzy release lookup. No physical directory enumeration as authority.

### O2 — exact scoped respondent enumeration

Input: exact universe context.

Output: complete deterministic enumeration of canonical `RespondentIdentity` / scoped respondent refs for that universe.

This is the set-algebra namespace. Source-row ordinal equality in another universe has no respondent-linkage meaning.

### O3 — exact primitive leaf evaluation

For any already-authorized frozen leaf, evaluate truth for one scoped respondent from canonical material:

- `SURVEY_RESPONSE_EVENT`
- `TYPED_RESPONSE_STATE`
- `EMPIRICAL_POSITION_COORDINATE`
- `ROUTING_APPLICABILITY_STATE`
- `DERIVED_BRANCH_COHORT`

The implementation may vectorize across respondents, but observed result must equal frozen per-respondent semantics and authority closure.

A missing accelerator entry is not a leaf outcome.

### O4 — exact recursive predicate algebra

Evaluate frozen recursive `AND` / `OR` / `NOT`.

- `AND`: exact intersection/logical conjunction of child truth for the same scoped respondent.
- `OR`: exact union/logical disjunction.
- `NOT`: exact negation only inside the already-closed query respondent/risk-set domain required by frozen I03. Never complement physical rows, block membership or one leaf's present-value domain.

Canonical child identity/order follows frozen predicate law; physical evaluation order may vary if output is identical.

### O5 — exact routing/risk closure before destructive pruning

For every target component and candidate respondent, resolve the exact target+risk-set `RoutingEligibilityFact` under frozen authority before a pruning operation may erase evidence needed to distinguish:

- eligible/applicable;
- explicit nonmember/inapplicable/not asked;
- unresolved/rule unavailable;
- missing/conflicting routing fact/authority.

A value predicate may be evaluated early as an optimization only if doing so cannot suppress the required routing/failure observation.

### O6 — topology-general target event gather

Input: exact scoped respondent + exact target/component.

Output: zero/one/many exact events sufficient to reproduce frozen target semantics, including where applicable:

- native/canonical question identity;
- component/subitem;
- event group/id;
- typed state/value;
- topology kind;
- multiplicity/occurrence;
- semantic order/rank/index;
- authority/dependency/replay material.

A dense scalar lane is merely a fast path when an independent exact topology certificate proves scalar singularity for that scope. Otherwise explicit event/topology material is mandatory.

### O7 — exact governed weight resolution

After denominator membership is established, resolve the requested exact weight basis for every denominator member.

Require frozen exact state/value/design/estimand authority. Missing, invalid, unauthorized or ambiguous weight is preserved as frozen I03 failure/negative behavior. Do not drop the respondent or repair to 1.

### O8 — exact source-scope composition

`SOURCE_INDEXED_MULTI_UNIVERSE`:
- keep selector/respondent namespaces independent;
- evaluate each exact universe separately;
- return source-indexed facts.

`AUTHORIZED_COMPOSITE`:
- require the frozen exact pooling/nonduplication/estimand-composition authority bundle;
- physical co-location/equal ordinals/equal native IDs/equal vectors have zero composition authority;
- do not invent respondent linkage where composition does not require it.

### O9 — canonical refutation/completeness closure

Before emitting an exact negative/absence claim, zero match/support claim, or complete I05 coverage claim, prove that all canonical regions capable of changing the answer are closed.

Lawful proofs are:

1. complete verified canonical scan of the governed refutation domain; or
2. verified canonical root-bound completeness metadata whose contract proves a smaller region exhaustive.

A nonauthoritative bitmap, Bloom filter, zone map, branch cache, stale query result or cache miss cannot supply this proof.

### O10 — carrier-blind I05 frontier boundary

I05 candidate compilation happens before physical planning and may inspect only frozen authority/predicate/query catalogs permitted by I05 semantics.

The physical executor receives a sealed ordered candidate/query-role list. It may not:

- remove candidates because no index exists;
- add candidates because an index exists;
- rank/prune by scan cost or diagnostic score;
- change K/J limits from block geometry;
- return `UNEVALUATED` because an exact query is expensive.

Every candidate receives the frozen terminal exact coverage state.

### O11 — exact branch execution without persistent branch-cache dependence

Branch-conditioned operations must remain executable after deleting all branch bitmaps/selectors.

Canonical material must retain or exactly reconstruct:

- branch definition identity;
- exact membership truth required by frozen predicate semantics;
- ancestry;
- source scope;
- replay authority/refs.

An optional branch selector is only acceleration.

### O12 — diagnostic nonauthority

Cloud/co-signature/MI/NMI/lift/association/tree-style diagnostic material may be computed/reported only within existing frozen permission. It cannot define:

- candidate reachability;
- exact EmpiricalFact existence/state;
- branch membership;
- I04 positive admission.

Diagnostic ablation must preserve the exact frontier and empirical facts.

### O13 — cache/profile erasure parity

For every physical profile and cache policy:

1. delete all declared nonauthoritative accelerators;
2. run the same exact I03/I05/I04 suite;
3. require identical semantic projections/refs/coverage/admission;
4. rebuild caches and repeat;
5. substitute stale cache and require rejection/rebuild before semantic use.

Only performance receipts may differ.

## 4. Required blind frontier gate

After candidate implementation/build configuration and tuning-workload disclosure are frozen, select a deterministic recorded-nonce exact I05 frontier absent from tuning hashes.

Where authority permits, include:

- uncached exact high-cardinality/string atom;
- nested AND/OR/NOT;
- pair cotravel;
- k >= 3 response configuration;
- conditional reversal/Simpson;
- recursive subgroup fork;
- branch-conditioned distribution/cotravel;
- targets/conditioners across multiple physical blocks;
- source-indexed multi-universe operation;
- co-signature/joint facts used by a diagnostic with diagnostic ranking disabled.

Run first with **all optional accelerators deleted**. Candidate count, covered count, exact fact refs and coverage receipts must equal the independent R03 oracle/frozen semantics.

Warm-cache execution may be benchmarked only after the no-cache pass.

## 5. Physical-organization neutrality

The following profiles may satisfy this contract if separately admitted:

- `LONG_SHARDED`
- `QUESTION_BLOCKED_LONG`
- `HYBRID_DENSE_PLUS_EXPLICIT`

They must expose identical logical behavior. A consumer may not branch on the profile to decide semantics.

The contract does not require simultaneous duplicate canonical copies. Profile-equivalence tests use separate shadow candidates/evidence builds under later implementation authority.

## 6. Failure law

Any of the following is a hard open-world failure:

- uncached lawful predicate requires re-ingest;
- cache/index absence changes truth or candidate coverage;
- optional accelerator defines scan/refutation domain and can suppress evidence;
- NOT uses physical-row complement;
- routing/weight/topology blocker is erased by early pruning;
- repeated/ranked/componentized events scalarize;
- cross-universe physical equality produces semantic linkage/pooling;
- discovery candidate is skipped due to physical cost/index availability;
- diagnostic controls exact frontier/fact/admission;
- exact negative depends on a disposable cache miss;
- profile/cache deletion changes an I03 fact, I05 receipt or I04 result.

## 7. Minimality law

This contract proves capability preservation, not that a Class-C profile is worthwhile.

If the simplest `LONG_SHARDED` candidate passes semantic, integrity, resource and practical-query gates, HQ should reject additional question-block/vector/bitmap planner complexity absent a measured blocking deficiency and a material end-to-end cure.
