## 4. DESTRUCTION_PATHS_FOUND

No lawful I03/I05/I04 operation was found that is inherently unrepresentable by P0's retained canonical incidence **if** P0's own stated safeguards are implemented literally. However, P0 is not yet sufficiently constraining to prevent several destructive implementations that would still plausibly claim conformance.

### D1 — ACCELERATOR-DELIMITED FALLBACK

A planner can say “uncached predicates fall back to canonical scan” while using a bitmap/index/catalog to decide *which canonical blocks may contain matches*. A false-negative or incomplete optional accelerator then defines empirical possibility.

This destroys uncached strings, post-freeze combinations, exact negatives, and I05 coverage while superficially retaining a “scan fallback.”

**Required correction:** the no-cache path must derive its scan/refutation domain only from canonical release coverage and exact query authority. Optional accelerators may order or over-approximate work; they may not suppress canonical regions unless a root-bound canonical completeness proof does so.

### D2 — LATE-MATERIALIZATION NEGATIVE ERASURE

If value predicates or target presence are applied before exact routing/risk-set/authority resolution, respondents can disappear before the system learns that routing is unresolved, the risk-set fact is absent, the weight is unauthorized, or the target topology is unsupported.

This converts lawful `UNAVAILABLE` / `UNRESOLVED` / integrity/noncomparability outcomes into false no-match, zero-support or valid-empty outcomes.

**Required correction:** the execution contract must name a strict pre-pruning negative-state phase. No pruning that can erase a blocker occurs before the relevant authority/routing/risk/measure/topology state is closed.

### D3 — PHYSICAL COMPLEMENT AS NOT

Question-block or bitmap implementations are naturally tempted to compute `NOT P` over rows present in a block.

Frozen I03 instead evaluates the predicate for exact respondents inside the governed source/risk-set process. Physical row presence is not eligibility and unresolved routing is not nonmembership.

**Required correction:** `NOT` is exact complement against the already-closed governed respondent set for the query scope, never a file/block/bitmap row complement.

### D4 — CROSS-UNIVERSE ORDINAL ALIGNMENT

Dense layouts can make source-row ordinals look joinable across releases. They are not. `SOURCE_INDEXED_MULTI_UNIVERSE` evaluates each universe separately. `AUTHORIZED_COMPOSITE` requires exact pooling, nonduplication and estimand-composition authority.

**Required correction:** every selector is namespaced by exact `EmpiricalUniverse` / scoped respondent identity. Cross-universe respondent alignment, pooling, deduplication or co-location is impossible absent exact source-relation authority. Physical ordinal equality is never relation evidence.

### D5 — TOPOLOGY SCALARIZATION

A question-oriented dense lane can silently become one `(respondent, question) -> value` cell. Frozen I03 can require multiple exact events for componentized, multiselect, repeated, ordered and ranked targets.

**Required correction:** P0 must expose a topology-general exact event-gather operation that returns zero/one/many exact events plus component/event/order/rank/multiplicity material. Dense scalar access may be a fast path only after a proved topology certificate.

### D6 — BRANCH BITMAP BECOMES BRANCH TRUTH

`DERIVED_BRANCH_COHORT` predicates carry exact membership/replay/ancestry authority. A persisted branch selector is convenient, but if deleting it makes branch-conditioned I05 impossible, the selector contains unique truth and was misclassified as cache.

**Required correction:** exact branch membership/replay remains canonical or exactly reconstructible from canonical material. A branch bitmap is disposable acceleration only.

### D7 — WEIGHT FILTERING BEFORE FAILURE

A column engine may drop rows with missing/nonpositive/unavailable weight material before computing the denominator. Frozen I03 requires exactly one governed weight per denominator member and separately checks design/estimand authority.

**Required correction:** denominator membership is established first; governed weight resolution is exact for every denominator member. Missing/invalid/unauthorized weight produces the frozen negative/error path, not a smaller convenience sample.

### D8 — STORAGE CATALOG LEAK INTO I05 FRONTIER

I05's authority grammar and catalogs define candidates. A physical planner must not compile candidates from “indexed fields,” “bitmap-capable values,” “known question blocks,” or other storage metadata.

**Required correction:** frontier compilation is entirely carrier-blind. Only after candidate identity/order is sealed may the physical executor choose scan/cache strategies for each exact query role.

### D9 — DIAGNOSTIC PRUNING

Co-signature/cloud-like diagnostics can be made cheap in a vector engine and then used to top-k/prune expensive exact candidates.

Frozen I05 forbids this. Diagnostics may report/rank only where separately lawful; they do not control exact frontier coverage or become `EmpiricalFact`.

**Required correction:** perturbing/removing all diagnostics must leave candidate count, candidate identities, exact fact refs and I04 inputs unchanged.

### D10 — NEGATIVE COMPLETENESS MISCLASSIFIED AS CACHE

If an index is necessary to prove that no matching event/respondent exists, it is not an optional cache. R05 already establishes this at integrity level.

**Required correction:** exact absence must arise from a complete verified canonical scan or from a canonical root-bound completeness structure. A disposable accelerator miss is never negative evidence.

### D11 — QUESTION-BLOCK JOIN PATHOLOGY

P0 can remain semantically exact while question-blocked execution becomes operationally disastrous for wide k-way/reversal/recursive workloads. This is not semantic destruction by itself, but it can defeat C09/C11/C21 under the campaign's practical-resource/minimality court.

**Required correction:** no-cache post-freeze workloads must measure block fan-out, bytes read, intermediate selector bytes, repeated scans, spill/scratch and wall time against `LONG_SHARDED`. If exact question blocking is materially worse without curing a blocking resource failure, it loses.
