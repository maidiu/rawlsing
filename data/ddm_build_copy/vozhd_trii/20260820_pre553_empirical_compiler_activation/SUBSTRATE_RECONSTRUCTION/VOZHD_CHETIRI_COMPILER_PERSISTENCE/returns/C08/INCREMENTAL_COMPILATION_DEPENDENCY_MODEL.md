### 4.1 Exact invalidation algorithm

For any governed change `x_old -> x_new`:

1. **Freeze the old lineage.** Never mutate an old source SHA, AuthorityRef, ExactRef, release hash, admission receipt, structural object, or V3 history in place.
2. **Name the changed determinant and declared scope.** Source snapshot, decoder lineage, authority object, contract version, discovery frontier, admission rule, structural object, publication artifact, or P4 cache key.
3. **Find direct dependents by exact provenance/ancestry refs.** No filename proximity, mutable "latest", timestamps, or heuristic similarity.
4. **Take the transitive semantic dependency closure.**
5. **Classify each affected thing** as:
   - P1/P2/P3 historical authority/product/receipt: retain old identity and mint a new identity when lawful;
   - P4 cache: discard/regenerate;
   - P5 staging: discard/resume only under exact build receipts;
   - P6 derivation: recompute on demand.
6. **Rebuild only that closure.** A candidate may impose a coarser *physical* write unit, but that is operational cost, not semantic invalidation.
7. **Publish atomically.** Until a complete new release is sealed, the previous sealed release remains the only serveable release.
8. **Never rewrite existing V3 life/history.** Future generation may select a new sealed structural release only through explicit governed release selection.

## 7. Global rebuild test

A global rebuild is lawful only when at least one is true:

1. the changed governed determinant explicitly has global jurisdiction over the whole affected layer;
2. a complete governed search frontier/release is itself the atomic semantic unit and the change alters that entire frontier;
3. an integrity failure proves the whole authoritative product is untrustworthy and no finer trustworthy partition/receipt exists;
4. the publication object is intentionally one atomic bundle that must be repacked as a whole.

Even then, **global publication/repacking is not global semantic recomputation**. Source, C11, I03, I05, I04 and structural producers are rebuilt only if their own determinant closure is invalid.

Forbidden reasons for global rebuild include:

- "the file is monolithic";
- "the cache was deleted";
- "we usually rebuild everything";
- "a new wave exists";
- "latest changed";
- "it is cheaper to reason about";
- "the persistent LONG is easier to regenerate from scratch."

## 8. Runtime availability and historical truth

Ordinary generated-person runtime consumes sealed structural products rather than live respondent/event incidence. Therefore compiler rebuilds must use a two-generation rule:

```text

        |
        | build in isolated staging
        v
UNSEALED CANDIDATE N+1 --validate--> ATOMIC SEAL N+1
```

No compiler update silently mutates actor facts, relationships, exposure, memory, orientation, attractors, or biography already generated under release N.
