# C07 — BUILD / SERVICE / RUNTIME BOUNDARY

## Holding

There is no lawful single latency/storage boundary shared by all learned-world lifecycles. There is one semantic boundary—learned world versus life—and several physical serving boundaries.

```text
THE PAST
  P1 source + governed source/semantic/decoder/authority roots
      |
      v
BUILD / DISCOVERY
  virtual/materialized logical C11
  I03 exact query
  I05 discovery
  I04 admission
  transient compiler state P5
      |
      +--> empirical-social P2/P3 releases ----> empirical-inference service
      |                                      \-> DDM analytical service
      |
      +--> structural P2/P3 releases ----------> V558/ContextResolver
                                                    |
                                  optional P4 runtime indexes/racks
                                                    |
================ GENERATED-PERSON RUNTIME ================
                                                    v
                                                   V3
                                                    |
                                            THE LIFE develops
                                                    v
                                                   V2

AUDIT/REPLAY may traverse backward through P3 lineage to P2/P1.
```

## Boundary rules

1. C11 is a logical repository/capability contract, not a mandatory storage layout.
2. Compiler/discovery may use large bounded P5 transient worksets and optional P4 caches.
3. Empirical-social learned releases are not deleted merely because V3 does not consume them.
4. Positioned-subject inference is a learned-world service. Per-request results are normally `DERIVE_ON_DEMAND`; exact cache retention is P4 unless a separate publication law elevates a named output to a governed learned release.
5. DDM analytical views may be slower and differently materialized from runtime views.
6. Runtime structural racks/indexes are P4 when fully derivable from P2/P3 products; frequency and rebuild cost do not make them authoritative.
7. Audit/replay may be cold; exact roots, determinants, versions, lineage and integrity receipts must persist.
8. No runtime optimization may pre-generate actor life.

## Runtime fast path

Fast lookup is justified for V558/ContextResolver temporal/geographic/scope resolution and any actually evidenced high-frequency structural lookup. C07 does not invent rack dimensions that consumption evidence has not authorized.

## Slow paths

Source replay, full adaptive-discovery replay, historical cross-universe DDM analysis, validation re-execution and full explanation reconstruction can lawfully be slow if complete, deterministic where promised, and provenance-preserving.

## Cache law

Every P4 cache key must bind the determinants sufficient to prevent semantic staleness: source/release roots as applicable, authority roots, decoder/projection/compiler/model identity, and query/index specification. Cache absence/corruption fails to regeneration, not to a different semantic result.
