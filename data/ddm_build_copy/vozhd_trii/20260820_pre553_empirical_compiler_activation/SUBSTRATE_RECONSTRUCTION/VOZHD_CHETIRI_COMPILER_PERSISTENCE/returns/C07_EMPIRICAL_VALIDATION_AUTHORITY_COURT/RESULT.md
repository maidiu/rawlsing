## 1. Exact current transition that already exists

The accepted exact-bounded I05 line terminalizes **discovery candidates** as follows.

1. A candidate exists only inside an exact pre-data frozen `DiscoveryAuthority` / declared frontier.
2. Exact I03 empirical facts are executed under source/release/risk/measure/topology authority.
3. Exact fact terminal classes can produce:
   - `EVALUATED_NONCOMPARABLE` / `NONCOMPARABLE`;
   - `EVALUATED_MISSING_OR_CONFLICTING_AUTHORITY` / `COVERAGE_LIMITED`;
   - `EVALUATED_VALID_EMPTY` / `VALID_EMPTY`.
4. A candidate is `EVALUATED_UNDERPOWERED` / `INSUFFICIENT_SUPPORT` only under the governed support rule; C05-R1B explicitly forbids inventing a production minimum-support threshold when an operation-valid one is absent.
5. For an evaluable candidate, I05 executes exactly one accepted validator kind:
   - `DISTRIBUTION_DIFFERS_FROM_BASELINE`;
   - `JOINT_NOT_PRODUCT_OF_MARGINALS`;
   - `CONDITIONAL_REVERSAL`;
   - `TARGET_CELL_SUPPORTED`.
6. Exact validator true produces `EVALUATED_SUPPORTED` / `DISCOVERED_RESULT_SUPPORTED`.
7. Exact validator false currently produces `EVALUATED_VALID_EMPTY` / `VALID_EMPTY`.
8. Exact authority denial/missing/conflict remains a typed terminal failure rather than empirical absence.

This is a governed discovery-evaluation state machine. It is not yet the C07 learned-world validation-release state machine.

## 2. What makes a relation VALIDATED today?

**No current accepted general transition positively authorizes that promotion for the full learned-world workload.**

C07's binding noncollapse law remains:

`DISCOVERY_CANDIDATE != VALIDATED_EMPIRICAL_RELATION != STRUCTURAL_ADMISSION`

For the four accepted I05 validator kinds, all mathematical/logical evaluation semantics already exist. HQ does **not** need to invent a significance policy to use them. What is absent is the explicit learned-world promotion/rejection law.

## 3. What makes a relation REJECTED today?

There is no public PRE553 `REJECTED` discovery-result state. C09 nevertheless requires benchmark discrimination between `FOUND_BUT_VALIDATION_REJECTED` and other negatives.

Current I05 cannot supply that distinction from the public state token alone because `VALID_EMPTY` covers both an already-empty/zero-evaluable-evidence terminal and the false branch of an exact validator. Therefore:

`VALID_EMPTY != REJECTED` unless HQ positively adopts a rule that replays the exact evidence path and distinguishes those cases.

A rejection may be lawfully minted only when an exact named validation rule actually executes over authority-complete, sufficiently supported, comparable evidence and returns its explicit negative disposition. Absence, emptiness, low support, noncomparability, missing authority, or unfinished coverage are not rejection.

## 4. UNDERPOWERED / NONCOMPARABLE / other terminal states

Already governed at the discovery layer:

- `UNDERPOWERED` is a support-rule result, not a synonym for validator false. Its numeric or other criterion must come from exact positive authority; no default may be promoted into production policy merely because code has an implementation fallback.

- missing/conflicting authority, authority denial, coverage limitation, and valid-empty evidence remain explicit terminal outcomes and never become rejection or absence by complement.
- structural admission remains separately governed after any empirical validation release.
