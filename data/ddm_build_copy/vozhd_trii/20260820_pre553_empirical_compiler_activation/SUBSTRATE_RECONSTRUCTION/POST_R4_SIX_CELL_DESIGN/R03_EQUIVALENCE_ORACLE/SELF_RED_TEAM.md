# R03 SELF RED TEAM

Status: `HOSTILE_TO_OWN_ORACLE`

The oracle is dangerous if it becomes a new way to certify the carrier by circular agreement. The following attacks are mandatory design objections, not optional future improvements.

## RT01 — R4 contamination

**Attack:** Expected truth is serialized from the accepted R4 carrier and future candidates are compared to it.

**Why this defeats R03:** A loss or invention shared by R4 becomes frozen as “truth.”

**Countermeasure:** Source-native physical truth and frozen semantic-law projections are the authority. R4 physical identity/layout never enters equality. A semantic witness bundle must contain canonical projections and source lineage, not R4 partitions.

**Reject oracle if:** removing all R4 physical artifacts makes expected truth impossible to construct.

## RT02 — candidate self-certification

**Attack:** Candidate export code computes both the observed object and the expected hash/count.

**Countermeasure:** independently recompute canonical projections, hashes, respondent membership and supports outside candidate physical indexing/materialization logic.

**Reject oracle if:** candidate-reported hashes/counts are accepted without independent reconstruction.

## RT03 — shared frozen-code bug

**Attack:** Both candidate and oracle call the same I03/I05 implementation, so a shared semantic defect passes.

**Countermeasure:** run frozen seams **and** a small separately implemented set/incidence evaluator. They must agree before candidate comparison is dispositive.

**Residual risk:** An error in the frozen semantic contract itself is higher-authority repair work, not a carrier-equivalence question. R03 cannot silently reinterpret it.

## RT04 — aggregate parity masks identity destruction

**Attack:** Candidate preserves counts but merges respondents, events, raw-identical variables, or source scopes.

**Countermeasure:** compare canonical object/record multisets, event/respondent membership, ExactRefs, and sensitivity mutations before aggregate query outputs.

## RT05 — WVS/LiTS monoculture

**Attack:** Oracle uses only the proving sources because they are convenient/large.

**Countermeasure:** real-source hostile minimum spans all nine source families and retains the rare cross-corpus exceptions in `HOSTILE_CASES.csv`.

**Reject oracle if:** any source family is represented only by a generic format fixture when checked-in source-specific exception evidence exists.

## RT06 — synthetic fixture imperialism

**Attack:** Generated fixtures replace real source certification because they are easier to control.

**Countermeasure:** generated cases test laws only. A real source passes only against exact source bytes/sealed source witness and exact authority for that source.

## RT07 — recon promoted to semantic authority

**Attack:** SR09-PRE descriptions of variables/labels are treated as semantic harmonization truth.

**Countermeasure:** recon selects hostile physical fixtures only. Canonical semantics require frozen source/authority closure; unresolved text/meaning remains blocked.

## RT08 — compatibility execution becomes text truth

**Attack:** Latin1 compatibility makes EVS 1999/2008 readable, so decoded labels are silently certified as intended text.

**Countermeasure:** execution config and source-text authority are separate oracle dimensions. Label-dependent expected truth remains blocked until documentary authority closes.

## RT09 — “derivable” becomes rhetoric

**Attack:** Candidate omits a field and claims it can be reconstructed without naming a determinant, scope and exception path.

**Countermeasure:** `INFORMATION_PRESERVATION_LEDGER.csv` supplies only frozen proof classes. Anything not actually proved inside one allowed class is `REJECTED_NOT_PROVEN_DERIVABLE`.

## RT10 — ExactRef trust

**Attack:** Candidate stores correct-looking object IDs/content hashes while mutating semantic fields.

**Countermeasure:** recompute hashes from canonical semantic projections independently on every acceptance run.

## RT11 — object equality without completeness

**Attack:** All surviving objects are correct, but some were silently dropped.

**Countermeasure:** compare full expected/observed exact-ref multisets plus source incidence and M01-M18 coverage; missing and extra objects both fail.

## RT12 — storage order confused with semantic order

**Attack:** Oracle requires byte/row order identical to R4 and rejects lawful re-layout, or conversely sorts away ranked/repeated semantic order.

**Countermeasure:** ignore carrier storage order; compare only order/rank fields that are identity-bearing in source/C11 semantics.

## RT13 — native ID convenience

**Attack:** Oracle fixture keys rows by a convenient source ID.

**Countermeasure:** universal replay identity remains source snapshot + row ordinal. Native IDs are separate source fields and may collide/be absent.

## RT14 — inferred routing

**Attack:** Missing response is used as proxy for not asked/inapplicable, letting routing tables disappear.

**Countermeasure:** independent routing/risk-set membership drives I03 denominators; raw absence incidence cannot reconstruct the routing state.

## RT15 — inferred weight

**Attack:** A likely weight variable is chosen or missing weights become 1.

**Countermeasure:** exact weight value and separate design/estimand/normalization authority are compared. Unauthorized numerics stay unauthorized.

## RT16 — relation-by-equality

**Attack:** identical respondent vectors or harmonized labels cause pooling/dedup across universes.

**Countermeasure:** SourceUniverseRelation/negative provenance is an exact authority-bearing observation. Data equality is never relation authority.

## RT17 — negative-state flattening

**Attack:** Candidate returns one generic “no data” condition for missing authority, zero support, noncomparability, valid-empty, routing failure and integrity failure.

**Countermeasure:** I03/I04 typed negative outcomes and reason/authority refs compare exactly.

## RT18 — discovery benchmark memorization

**Attack:** Candidate pre-indexes the exact I05 regression suite and appears general.

**Countermeasure:** freeze candidate + tuning disclosure first; compile a deterministic recorded-nonce blind frontier afterward; exclude disclosed workload hashes.

**Residual risk:** A fully general pre-index is lawful if it actually supports every unforeseen combination without semantic loss. The oracle is not entitled to punish good generality.

## RT19 — blind workload becomes nondeterministic

**Attack:** Hidden randomness protects secrecy but breaks replay.

**Countermeasure:** the nonce is explicit, recorded, content-addressed and replay-bearing. It is unknown before candidate freeze but not hidden afterward.

## RT20 — diagnostic semantic leakage

**Attack:** cloud/association score affects pruning, factual state, or admission.

**Countermeasure:** perturb or disable diagnostics while holding exact facts constant. Frontier/facts/admission must not change unless separate frozen authority explicitly grants such semantics.

## RT21 — cache as secret authority

**Attack:** canonical truth is recoverable only because an index/cache contains material lost from authoritative storage.

**Countermeasure:** delete every declared cache and repeat full semantic/query/discovery/admission checks. Failure after cache deletion is carrier failure.

## RT22 — stale cache passes

**Attack:** path/name-based cache survives a source/release update.

**Countermeasure:** inject cache from another exact release. It must be rejected/rebuilt before semantic use.

## RT23 — corruption laundered as negative query

**Attack:** a missing partition produces “no rows” or `VALID_EMPTY`.

**Countermeasure:** authoritative-member/manifest/ref corruption must fail the integrity gate before query semantics are allowed.

## RT24 — partial publication window

**Attack:** readers observe a partly written replacement release.

**Countermeasure:** pre-seal/partial state is injected and must be nonauthoritative/unopenable.

## RT25 — ambient nondeterminism

**Attack:** filesystem order, hash seed, thread count, locale/TZ or hidden clock changes object ordering/hashes/results.

**Countermeasure:** fresh-process perturbation suite; exact semantic outputs must match. Any relevant locale/TZ dependency must be explicit source/authority material, not ambient state.

## RT26 — over-demanding byte equality

**Attack:** Oracle accidentally requires candidate physical bytes to equal R4 and therefore ceases to be representation-neutral.

**Countermeasure:** only source bytes are byte authority. Candidate carrier bytes may differ arbitrarily if source/logical/failure/replay observations are exact.

## RT27 — under-demanding reconstruction equality

**Attack:** Oracle accepts a candidate because public query behavior matches today, while source physical truth cannot be exactly reconstructed.

**Countermeasure:** O1 source-native equivalence precedes I03/I05/I04 behavior and cannot be waived by successful queries.

## RT28 — incomplete source authority presented as full acceptance

**Attack:** Oracle design is mistaken for CLOSED_35 certification, especially around unresolved EVS text authority.

**Countermeasure:** acceptance is source/surface scoped. `BLOCKED_BY_MISSING_AUTHORITY` is explicit and is not a pass.

## RT29 — implementation bloat

**Attack:** independent oracle grows into a second production engine and accumulates its own hidden semantic policy.

**Countermeasure:** keep reference evaluator intentionally small: canonicalization, exact set membership/support, finite frontier compilation, comparison and fault injection. Source semantics remain external authority.

## RT30 — performance bargaining

**Attack:** A carrier that is much faster is allowed to fail a rare hostile case.

**Countermeasure:** resource numbers are evaluated only after semantic gates. One authoritative mismatch rejects the claimed scope.

## Final self-disposition

The oracle should be rejected if independence cannot be demonstrated with source-native evidence plus separately recomputed canonical/set truth. A sophisticated test suite that merely asks the candidate to agree with itself is worse than no oracle because it launders loss as certification.
