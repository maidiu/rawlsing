# R00 — Original → Dva → Trii/Chetiri Information-Necessity Conservation Court

Status: `ACTIVE__NONDISPOSITIVE_INFORMATION_CONSERVATION_COURT`

## Governing question

R00 does **not** ask whether every historical Rawlsing file has been preserved.

R00 asks:

> What information did the intended original Rawlsing need in order to perform its intended capabilities; which of those capabilities and informational distinctions survive in the true Dva terminal vision; what new informational prerequisites did Dva/Trii/Chetiri introduce; and can every surviving or newly required distinction be traced to a lawful provider, authority, derivation, persistence and replay path without guessing or semantic flattening?

The target universe is therefore the **terminal information requirement universe**, not the historical artifact universe.

## Special hostile tests

### Joint evidence

The old 16-part P1 joint-evidence requirement surface must be checked by *requirement identity*, not by asking whether V550J survives. Later successor evidence that preserves JE requirement IDs counts as conservation evidence; per-wave observability, routing and authority sufficiency remain separate questions.

### QSM

QSM must be decomposed by information class. A later system may lawfully split QSM across multiple normalized authorities, but every terminally necessary class must have a traceable successor or an explicit orphan disposition. No single later carrier is presumed to supersede QSM globally.

### Legacy capability loss

An old algorithm or table may retire only after the capability/information it carried is either:

- proved terminally unnecessary; or
- proved reconstructible / represented under the new architecture.

### New Dva capability overreach

Every new terminal requirement must identify its provider. A well-specified interface with no positive producer authority is a forward orphan or an explicit fail-closed future frontier, not a completed capability.

## Local evidence rule

R00 remains Browser-first, but unlike C02/C05 it may recommend a **bounded local evidence court** when the exact missing proof is known and Browser limitations materially prevent adjudication.

A local request must name:

- exact question;
- exact source/file/hash or machine surface;
- exact operation;
- exact expected proof;
- prohibition on unrelated machine inspection.

No broad local crawl is authorized.
