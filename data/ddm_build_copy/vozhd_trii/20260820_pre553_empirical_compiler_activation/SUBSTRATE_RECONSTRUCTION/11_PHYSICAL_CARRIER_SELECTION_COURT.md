# PRE553 SUBSTRATE RECONSTRUCTION — PHYSICAL CARRIER SELECTION COURT

Status: `FROZEN_BAKEOFF_CONTRACT__EXECUTION_BLOCKED_ON_SR03`

## 1. Decision order

The physical carrier is selected in this strict order:

1. **FLAWLESS EFFECTIVENESS** — exact preservation/replay of the C11 information frontier and exact answers under I03/I05 workload semantics.
2. **FAST** — lowest practical latency/throughput cost for Rawlsing's actual analytical workload, not synthetic database prestige tests.
3. **LIGHT** — minimal disk duplication, resident memory, operational services, configuration, maintenance and failure surface.

A faster or lighter carrier that fails information equivalence is disqualified, not traded off.

## 2. Architecture neutrality

C11 is an information/semantic contract, not a database-product contract. This court selects the physical implementation beneath the accepted repository/query interfaces. It may not reopen I01-I07 or V553-V558 semantics.

## 3. Serious candidate carriers

The court must test at least:

### A. Parquet + DuckDB direct analytical access
- canonical immutable Parquet artifacts;
- DuckDB reads files directly or through deterministic governed views;
- no server required;
- derived caches nonauthoritative.

### B. DuckDB native database file
- same logical C11 relations materialized inside a DuckDB database file;
- tests whether native storage materially improves workload performance enough to justify a second canonical form or alternative canonical form.

### C. PostgreSQL normalized C11
- normalized source-scoped C11 relations in Postgres;
- appropriate indexes chosen by a frozen benchmark specification, not ad hoc tuning after seeing outcomes.

### D. SQLite baseline only if it can represent the frozen logical schema without semantic compromise
- included to test whether its operational lightness is genuinely competitive;
- may be terminated early if a predeclared capability gate fails (for example required analytical execution or scale without impractical index/materialization burden).

No candidate receives authority merely because historical Rawlsing already uses it.

## 4. Proving corpus

The first carrier court uses both:

- WVS Wave 7 SAV: large SAV source, typed user-missing states, rank-slot topology, noninjective native interview ID, weight/design surface;
- LiTS I DTA: DTA source, system missing distinct from ordinary labeled semantic absence codes, clean native ID candidate, multiple weight candidates.

Both must be represented under the same format-neutral source constitution.

## 5. Logical C11 benchmark schema

Every candidate receives logically identical source-equivalent relations sufficient for accepted M01-M18, including at minimum:

- source snapshots/manifests;
- respondents/source-row identity;
- source variables/questions;
- response/event incidence;
- physical + governed semantic state;
- topology/slot/multiplicity incidence;
- routing/applicability/risk-set incidence;
- empirical-coordinate incidence;
- weights/design incidence and authority refs;
- source→canonical mapping/provenance;
- immutable authority/replay refs.

Physical layout may differ only where logical equivalence and deterministic replay are proven.

## 6. Correctness gate — absolute

For each candidate, all of the following must be identical under the same frozen query oracle:

- source snapshot/case/variable/event identities;
- typed physical/semantic-state counts;
- exact same-respondent membership;
- unary distributions;
- 2-way, 3-way and 5-way joints;
- arbitrary lawful k-way conjunction fixture;
- explicit risk-set fixture;
- weighted and unweighted measures;
- ordered/rank-slot fixture;
- typed-absence-sensitive fixture;
- local-category-code fixture;
- minority-departure fixture;
- Simpson/reversal fixture;
- XOR/parity fixture;
- recursive subgroup predicate fixture;
- deterministic replay digest.

Any wrong answer, lost state, respondent reassociation, unauthorized default, nondeterministic identity or unexplainable coercion = `CARRIER_DISQUALIFIED_CORRECTNESS`.

After correctness passes, benchmark the actual Rawlsing operations:

1. source-scoped respondent lookup;
2. one-variable distribution;
3. response × coordinate conjunction;
4. coordinate conjunction with 3 and 5 predicates;
5. response-response 2-way and 5-way joint;

7. raw aggregation;
8. weighted aggregation;
9. branch-conditioned cotravel;
10. Simpson/reversal scan fixture;
11. bounded recursive subgroup queries;
12. bounded XOR/parity fixture;
13. sequential batch representing I05 exact-bounded discovery;

15. repeated warm query batch.

Benchmark query SQL/logical plans are frozen before timing. No candidate-specific semantic shortcuts.

## 8. Measurements

For each candidate record:

### Effectiveness
- correctness gate result;
- deterministic replay result;
- source-equivalence result;
- unsupported semantic/information classes.

### Speed
- cold-start/open latency;
- median and p95 per-query latency;
- full frozen batch wall-clock;
- rows/scanned throughput where meaningful;
- load/materialization time;
- index/build time separately from query time.

### Lightness
- canonical disk bytes;
- additional index/cache/database bytes required for benchmark;
- peak resident memory;
- number of persistent copies of the empirical substrate;
- required background services/daemons;
- configuration/secrets required;
- maintenance operations required for normal replay;
- portability of exact certified artifact.

## 9. Tuning law

One predeclared tuning round is allowed after baseline, based on transparent physical-layout parameters only (partitioning, row-group sizing, indexes, clustering/materialization where applicable). The tuning rules and search space must be frozen before the tuned run.

No semantic changes, denormalization that loses reconstructibility, hand-picked cache of benchmark answers, or candidate-specific alteration of query truth conditions is allowed.

## 10. Selection rule

1. Eliminate every candidate failing correctness/source equivalence.
2. Among survivors, select the fastest carrier on the full frozen I03/I05 workload unless the speed difference is operationally negligible under a predeclared threshold.
3. If performance is operationally tied, select the lighter carrier.
4. A materially heavier carrier may win only if it provides a measured effectiveness or performance capability the lighter carrier cannot provide.
5. The selected physical carrier remains replaceable beneath C11 if later evidence justifies a new court; its product identity never becomes semantic law.

## 11. Expected but nonbinding hypothesis

Current hypothesis: `PARQUET + DUCKDB` is favored because the substrate is append-only/analytical and C11 caches are nonauthoritative. This hypothesis has zero dispositive weight. Only the frozen bakeoff may select it.
