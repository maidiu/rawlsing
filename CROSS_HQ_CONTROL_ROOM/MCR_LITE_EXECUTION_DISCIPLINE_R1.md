# MCR-lite — disciplined execution without administrative recursion

**USER-DIRECTED PROSPECTIVE OPERATING STANDARD · 2026-11-11 · PRE-MAIN / PYAT / SOROK.**

**Applicability and priority:** Wherever current Rawlsing operating instructions invoke `MCR`, read **this MCR-lite execution discipline first**. `MCR: LITE` is the default prospective commissioning/implementation posture. `MCR: REQUIRED` continues to select the existing complete §3A/MCR-C contractual verifier when an authorized task explicitly demands full MCR-C. Historical commissions, source-grained reviews and immutable evidence keep their recorded requirements and verdicts; this is not a global textual replacement or retrospective regrading. Neither mode creates source/science/actor/human rights. Existing source restrictions, competent issuers, exact first-consumer testing and non-disturbance remain hard boundaries. This standard changes the amount of *administrative ceremony*, not the permissible claims.

## Working MCR-lite standard

1. **Preserve the whole mission.** Know what must actually be accomplished. Don't quietly reduce a comprehensive assignment to one demonstrable example.

2. **Inspect before inventing.** Identify the existing code, authority, accepted work, and real missing functionality. Don't commission archaeology that merely repeats established knowledge.

3. **Specify success concretely.** Know what working result must exist, who consumes it, and what would demonstrate failure. Use exact source pins where consequential.

4. **Build the damn thing.** Once the problem is sufficiently understood and execution is authorized, implement. Don't commission another investigation merely to establish permission to plan an implementation.

5. **Test causally, not ceremonially.** Actual positive behavior, a meaningful negative or severance, and restoration. Green tests must prove the claimed dependency.

6. **Preserve competent boundaries.** Engineering success doesn't manufacture scientific truth, source rights, actor authority, or human consent. But those restrictions block only the operations they genuinely govern.

7. **One substantive independent receiving.** Independent review where warranted, with precise defects and finite repairs. No endless chain of reviews of reviews.

8. **Close at the honest grade and move forward.** An accepted sourcefree result is accepted sourcefree engineering. Don't reopen it because native science remains unfinished. Record the remaining problem and pursue the next substantial product capability.

## What is explicitly rejected

**BUREAUCRATIC RECURSION**

Investigation authorization → scoping investigation → feasibility commission → independent feasibility review → review correction → permission assessment → implementation planning → planning review → pilot specification → pilot review → actual work, eventually.

**MCR-LITE**

**Understand → Specify → Execute → Falsify → Independently receive → Integrate**

These aren't always six separately serialized phases. Specification, implementation, testing, and lawful parallel investigation can overlap. An isolated pilot is an instrument, not the product.

## Governing distinction

**Rigor is not proportional to administrative complexity.**

An engineer who identifies the actual consumer, preserves inherited code, fixes the source defect, proves positive/negative behavior, and submits an independently reviewable implementation has exercised more rigor than an agent who produces five perfectly formatted compliance documents without fixing anything.

Equally, passing 94 tests is not enough if none of them exercises the claimed behavior.

**The objective is maximum substantive rigor per unit of friction.**

## Operational interpretation: lightweight by default, full where explicitly requested

- **For a real agent launch:** keep one complete copy-paste instruction, a named implementer/reviewer role, executable scope, actual branch/source cut where material, first consumer, observable positive and negative, qualified runner, three honest engineering/scientific/authority grades, and bounded post-return independent receiving *where warranted*. The `verify_copy_paste_commission_r1.py` `MCR: LITE` path checks this structural minimum. It is NOT permission or substantive acceptance.
- **For an explicitly FULL MCR-C task:** `MCR: REQUIRED` keeps the complete `MCR_COMPLETION_CONTRACT_BEGIN` frozen universe, per-obligation evidence, exact source tuples, return verifier, independent court and all repairs, unchanged. Do not quietly downgrade an existing binding full MCR-C assignment to lite.
- **For an implementation or material repair:** preserve its complete assigned functional tranche, prove the actual first-consumer causal edge, perform a discriminating negative and restoration, and preserve independent judgment where the claim warrants it. A REAL scientific/source/legal/actor grant is never simulated.
- **For reviews, investigations, documentation and small bounded decisions:** select the proportional proof scope. No artificial full source-enumerator, one-register-per-sentence, independent-review-of-a-review or permission-to-commission-a-permission packet without a concrete material reason.
- **For HOLD:** name the missing function or genuinely competent permission and what concrete work can proceed now. A HOLD on an unissued edge cannot become a blanket halt on other lawful code or a claim that an otherwise accepted scoped result is incomplete.
- **For integration:** source-pin the accepted implementation when consequential, inspect the combined first consumer, run relevant regression/fault checks and preserve branch CAS/review rules. Do not re-review the unchanged historical universe.
- **No additional courts, boards, universal registers, schedules or mandatory external agents.** Where a law specifically mandates a source rights decision, qualified scientific review, protected merge check or human consent, that substantive boundary remains.
