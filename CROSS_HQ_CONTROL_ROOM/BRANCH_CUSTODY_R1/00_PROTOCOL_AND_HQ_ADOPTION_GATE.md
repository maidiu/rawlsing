## 2. Branch custody lifecycle (one record per material capability/branch)
Every new commission, adopted design ticket and material source/engineering return must have a **custody ID** at commissioning or discovery:
\`DISCOVERED -> TRIAGED -> RETURNED -> EVIDENCE_ASSESSED -> [REVIEW_PENDING -> REVIEWED_SCOPED] -> DISPOSITIONED -> CONSUMER_PROVED -> CLOSED\`.
Orthogonal holds: \`ACTIVE_VERIFIED\`, \`UNKNOWN_PROCESS\`, \`OWNER_HOLD\`, \`ORIGINAL_SOURCE_HOLD\`, \`SCIENCE_HOLD\`, \`CONFLICT_REPAIR\`; these are not completion.

A dispositive **branch outcome** is exactly one of:
- \`ADOPTED_WITH_CONSUMER\`: exact implementation/producer imported or equivalently adapted into an owner-qualified receiving cut, current consumer executed with negative/severance and independent grade matching claim.
- \`REUSED_EQUIVALENT\`: no import required because exact equivalent source function/semantic behavior is already in the accepted target; provide source/blob and observable consumer equivalence, not mere ancestry.
- \`REJECTED_WITH_FINDING\`: reviewed and rejected at its claim grade; preserve source, falsifier and rationale.
- \`HELD_WITH_OWNER\`: named original scientific/source/host/permission/actor dependency, next operation and first consumer recorded; not CLOSED.
- \`SUPERSEDED_WITH_PROOF\`: newer qualified implementation dominates exact asserted behavior; preserve old identity and comparison; not blanket branch deletion.
- \`ARCHIVED_NONMATERIAL\`: no distinct relevant code/science/receipt beyond adopted evidence; give reason, not based only on branch age or name.

A **branch may be administratively dispositioned but a terminal capability remains open** when its original/consumer condition is unproved. Separate branch disposition from capability acceptance: this is the primary anti-inflation invariant. \`REVIEWED_SCOPED\` is NOT \`ADOPTED_WITH_CONSUMER\`; \`ADOPTED_WITH_CONSUMER\` sourcefree is NOT native scientific source authority.

## 3. Required per-record proof contract
Each live or recovery candidate must minimally record:
\`custody_id; repo; branch; observed_head_sha; observed_utc/cut; control_target_ref+sha; author/operating_HQ; function_or_claim; actual file+blob+named function; original required jurisdiction; test command/result+oracle+falsifier; independent review exact code SHA+review SHA+scope; demanded first real consumer; current owner consumer test/ref; explicit withheld grades; next qualified action; disposition/status; reviewer; gate/record update SHA\`.

Missing evidence is \`UNKNOWN\`/null; **never** fill an absent proof from title, confidence or model inference. The \`01_PRIORITY_RECOVERY_QUEUE.json\` is a *triage seed* and deliberately leaves many fields null. Use \`validate_custody.py\` to prevent accidental claim promotion.

## 4. When each HQ MUST act
**At commission creation (Browser or Codex):** identify the exact previously existing code/branch candidates **before** funding replacement implementation. Query latest census and current branch tips, active flight board/COMMAND edges, returned reviews, actual first consumer. If exact capability already built, turn commission into reuse/integration/negative-evidence ticket. Register before dispatch with candidate SHA, consumer acceptance, required science/source grade and explicit editor/model chosen by user. Never invoke a second owner solely because original HQ is in a different chat.

**At return publication:** worker cannot mark itself integrated. Return a parsable \`RETURN.json\` or equivalent with complete exact SHA, new/modified functional symbols and tests, negative or falsifier, scientific limits, review-needed flag, intended consumer, and source rights. The **receiving HQ** (not the worker) attaches a \`RETURN_INTAKE\` record at next meaningful scheduling boundary. If an original-source or critical native claim, require independent hostile review of the *exact* submitted code before acceptance.

**At independent review:** record exact reviewed code SHA. A repair changes the reviewed cut and demands delta review or full re-review appropriate to scope. Reviewer PASS on a subset cannot close previously failing tests or old unreviewed physical code.

**At either HQ resume/checkpoint:** compare latest *material* branch head deltas against latest observed census, queue, flight board/COMMAND consumer edges and controller leases where accessible. Classify new RETURNS, new reviews, changed code, new held gates. Detect unlinked material branches as \`DISCOVERED_UNINTAKEN\`; immediately assign owner and exact next intake, without inventing a running process. On actual HQ material state change, append immutable accession/readback and update the established Pyat checkpoint or Sorok command through their own existing laws. Do not fork a new control tower.

**Before declaring a capability complete:** perform downstream producer→consumer executable check at the original authorized grade, including negative/ablation, replay, permissions and scope. Mark technical implementation, science acceptance and user-facing/person completion separately. No actual consumer = engineering/review return, NOT terminal completion.

**Before branch deletion, overwrite or automatic cherry-pick:** explicitly prohibited by this protocol until an owner proves status, controls evidence retention, and obtains required permission. Preservation is cheap; blind merge costs semantic custody.

## 5. Recovery triage — highest value first, NOT 2,831 serial courts
1. **Existing accepted/reviewed executable implementation with real pending consumer** (HQ282, C01R2, SRC04 release/consumers, Sorok B1/B2/B3A/BP2P4J and C9): prove target code equivalence and named consumer gap.
2. **Original science or source-grant branch whose result controls a terminal operation** (original C11, wave-specific eligibility, independent-world, Rule A/T, native I03/I05): accept only original competent issuer and scope.
3. **Diverged integration and control branches (10 of 31), plus controller R59/R62/R63:** compare exact functional blobs, reviewer and first consumers; Git behind/ahead alone is not missing code.
4. **Unintaken returns/reviews:** group by claimed *capability ID* and common head SHA, not 1,286 rabochii names as 1,286 new requirements.
5. **Other archival branches:** shallow metadata/index disposition first, expand only if unique functions, authority, accepted tests or terminal consumer are discovered.

\`P0\` recovery does not mean stop independent authorized construction. Assign one bounded estate intake lane per HQ at a time, while already-authorized terminal work continues. Do not create large fleets to re-review name-only 2,831 branches. A \`NO_DIFFERENCE\` branch may be safely disposed at metadata scope only if source/equivalence proof supports that judgment. Cursor refresh and live worker check must be explicit.

## 6. A single no-loss branch-to-consumer handoff
Every material return carries \`BRANCH -> EXACT CODE/SCIENCE ARTIFACT -> INDEPENDENT GRADE -> RECEPTION OWNER -> FIRST CONSUMER -> CURRENT TARGET SHA -> NEXT ACTION\` in one record. The receiver must reply either \`INTAKE_ACCEPTED_SCOPED\`, \`INTAKE_REVISE\`, \`INDEPENDENT_REVIEW_REQUIRED\`, or \`OWNER_HOLD\`; no silence-as-acceptance. When a Browser investigator finds a missing capability, it supplies the code/source/consumer seam; Codex carries out qualified mutation, and Browser evaluates scientific reach. When Codex writes a function, Browser cannot assume semantic or native adoption; both read the **same** evidence ledger.

A custody ID must remain stable through author return, review, repairs and adoption; branches and commit SHAs are revisions underneath it, not separate orphaned projects. A new worker must link its custody ID to existing ones, avoiding false double starts.

## 7. Independent enforcement, minimal reporting
The validator checks **structural custody**, not scientific truth. It fails any CLOSED-like outcome that lacks source/head, author judgment, exact target consumer proof and independent review where demanded. It cannot decide that code actually works. Include the validation command/result in the next authentic HQ checkpoint. If no authenticated runner available, mark \`VALIDATOR_NOT_RUN\` instead of inventing PASS.

A pull request on this branch is a review/intake instrument only. The authorized Pyat and Sorok HQs must independently read and acknowledge this exact SHA; then adopt/amend its *gate* through their existing control systems. Proposed law does not retroactively grant this reserve candidate executive jurisdiction or require Codex to abandon current native work. No unapproved automated branch deletion, merges, worker launches, model switches, or native source reads.
