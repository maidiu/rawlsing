## 0. THE RULE

**A missing prerequisite is not an explanation until HQ identifies the *function* the prerequisite must perform.** HQ/worker must be able to say, in ordinary descriptive terms:

> **We need a thing that takes [specific existing inputs], performs [specific transformation/decision], and emits [specific artifact/behavior] to [actual next consuming function]. It matters because [observable end-product failure]. We already have [inherited candidate carriers], but have not established whether they perform this exact function today. I am asking you directly: HAS THIS ALREADY BEEN BUILT/DECIDED, perhaps somewhere in the historical project, either machine, repository, Library, or retained source records? If yes, WHERE? If not, HQ will own a capability-build/recovery plan, subject to real authority and access limits.**

The default question to the user is MANDATORY for each material capability whose existence is unresolved. **Never quietly assume (a) it must exist somewhere; (b) it cannot be built; or (c) an absent issuer is an indefinitely separate person who will eventually appear.** User verification is a product-development step, not a last-resort courtesy. Ask at the first material discovery of this gap—**not after three weeks of passing sourcefree tests**. Do not repeatedly ask the same question after the user has answered it; preserve the answer in control memory with exact scope.

## 1. TRIGGERS — immediate anti-loop interrupt

The first material return, gate, test or HQ assessment that says any of the following triggers a **functional blocker adjudication in that same HQ intake**:
- `NOT_YET_ISSUED`, `UNKNOWN`, `MISSING_AUTHORITY`, `SOURCE_NOT_GRANTED`, `NO_VALID_OPERATIONS`, `EXTERNAL_BLOCK`, `WAIT_ON_OWNER`, or `HOLD` preventing the terminal original-science/person product;
- a worker says it has delivered the *interface, socket, feeder, admission, test harness, owner-demand list, simulated positive or refusal* but the **real input producer has never been produced**;
- two sequential workers/returns or one repeat on the same node show no new actual original-science/actor/product evidence, even with many additional passing tests;
- a dependency has a circular shape (A waits on B waits on A), an unnamed third-party actor/issuer, or a demand for hundreds of signatures without proving why each is a scientifically irreducible decision;
- code/authority is visibly archived, but its current consumer never calls or imports it.

**No blocked worker can be called operationally DONE without the below minimum analysis.** Worker is allowed to stop prohibited raw/source/actor operations, but must produce a functional missing-capability diagnosis. HQ may accept a narrower engineering return, but is accountable for **converting that diagnosis into an executable recovery/build path**. Do not automatically spawn one reviewer per blocked test.

## 2. FUNCTIONAL GAP CARD — must be completed and brought to the user

1. **ENTRY POINT:** Exact predecessor→consumer edge, functions/classes/modules if known, and real flow end-product affected.

3. **FUNCTION (plain English):** What must the missing thing decide/compute/translate and why. NO jargon-only answer such as 'need issuer-approved U/E_pre'.
4. **OUTPUT:** Exact callable data structures/artifacts: completeness and typed refusals, recipient, schema, existing expected ledger and runtime acceptance, plus identifiable errors.
5. **OBSERVABLE POSITIVE:** A minimal **genuine** source/actor/reasoning consumer effect proving the function exists (e.g. original source measured result reaches unchanged A42 or generated person's actual state changes)—not another synthetic demo.
6. **EXISTENCE CHECK / HONEST CONFIDENCE:** Exact recovered candidate implementations, adopted/manual semantic authority, archived worker/Library/current machine surfaces inspected; what remains uninspected; what proves *already built*, *built but not wired*, *partially built*, *missing*, or *unverified*. Absence from one branch or local session is NEVER evidence of total nonexistence.
7. **USER QUESTION:** Before classifying the function permanently absent, ask the user explicitly whether it was built somewhere and invite exact carrier pointer. Ask once per distinct function, retain their answer in HQ ledger. When they say 'no', proceed to build; when they say 'yes', fetch/test/live-wire; when uncertain, do bounded recovery and design in parallel without fabricating facts.
8. **OWNER AND DISPOSITION:** `REUSE_ALREADY_EXECUTABLE` / `RECOVER_AND_WIRE_EXISTING` / `IMPLEMENT_MISSING_COMPOSER` / `COMPETENT_EXTERNAL_DECISION_REQUIRED` / `GENUINELY_UNAVAILABLE_DATA_OR_LEGAL_PERMISSION` / `MIXED`. 9. **ECONOMICAL ACTION / DEADLOCK PREVENTION:** The largest next real product effect, testable target, time/cost resource class, accepted native host, and independent work that can proceed now. A blocked report without these is **`BLOCKER_DESCRIPTION_INCOMPLETE__HQ_FUNCTIONAL_GROK_REQUIRED`**. A blank future-owner name is not a resolution.

## 3. ABSENCE OF CODE ≠ ABSENCE OF AUTHORITY; AUTHORITY ≠ ABSENCE OF A BUILD TASK

Three distinct cases must **never be fused**:
- **Functional machinery missing/untethered:** The mapping/compiler/owner adapter/actor-generation bridge/consumer does not exist or is not connected. **Build or recover and wire it.** If reuse is possible, **do not reinvent or silently abandon accepted authority.**
- **Scientific or normative content missing:** A competent scientist/source semantic or actor-policy issuer genuinely has not adjudicated a particular population/estimand/question/rule. The function needed is a **decision procedure and issued result**; propose what actual evidence and accountable human/qualified body must decide. Build the tooling that **prepares finite eligible candidate decisions, preserves unknowns and consumes decisions**, but do not hallucinate their authority.
- **Legal/source/host permission missing:** Confirm whether user/source custodian already possesses applicable grant and data on approved host. The action is an **authenticated current permitted-use determination or legitimate issuance**, not writing a fake software permit. Engineering work can proceed without secretly reading original respondents; block precisely only forbidden source work.

An externally competent authority may be a genuinely distinct project owner/discipline, NOT necessarily a mysterious person outside the project. **Ask the user** who performed / may perform that decision. Project-command authorization alone never conveys survey licensing/ethical clearance or source/semantic/model/actor power.
