## 2. Functional architecture and service boundaries

### 2.1 Three planes, deliberately separate

1. **Judgment plane:** authorized *existing* Codex HQ sessions, plus Pyat's competent HQ source of command. Each emits strictly typed decisions: `DISPATCH`, `INTAKE`, `HOSTILE_REVIEW`, `REPAIR`, `BANK_SCOPE`, `INTEGRATE_IF_AUTHORIZED`, `DEFER_DEPENDENCY`, `ASK_HUMAN`, `STOP`. Model output is a *request*, never executable permission by itself.
2. **Control plane:** a persistent TypeScript service with transactionally durable SQLite (WAL, backed up), event queue, policy engine, Git provenance validator, runtime/session reconciler, worker scheduler, cost/quotas, credential isolation, status interface, kill/pause controls and audit log. Holds no scientific authority. Only policy-enforced machine actions run.
3. **Execution plane:** bounded local OpenCode workers on separate verified isolated Git worktrees; optional compatible Codex executor for explicitly chosen jobs; browser-bound agents only when a real supported programmable transport and authorization is proven. **A Git branch appearing is not a launched process; posting a commission is not execution.** Never claim a cloud Browser chat was launched using a local SDK alone.

SDK adapters should be version-pinned and smoke-tested against the actually installed CLI/provider: `@openai/codex-sdk` for local Codex threads and resume, or Codex app-server when its authentication/approval lifecycle is needed; OpenCode's documented SDK/client event/session interfaces where available, falling back to bounded `opencode run --format json` subprocess only with verified flags. Do not hardcode unverified DeepSeek model IDs or OpenCode SDK package names. Validate actual auth, runtime, session and MAX thinking variant by executable probe, not documentation alone.

### 2.2 Unambiguous state and identities

Persist a relational registry with `hq_thread`, `campaign`, `commission`, `worker_run`, `execution_environment_passport`, `review`, `evidence_bundle`, `decision`, `grant`, `notification`, `audit_event`, `budget`.

Minimum commission: immutable `commission_id/revision/hash`, source owner and HQ role/decision ref, exact permitted repository/branch, `base_commit`, blob refs for required specifications, allowance scope, permitted file changes, prohibited reads/operations, parent terminal campaign/consumer, real positive+severance assertion, source/privacy grade, task I/S class, qualified provider/model/reasoning variant, account/editor/host approved or UNKNOWN, reviewer conflicts and acceptance court, return schema and escalation conditions.

Minimum worker-run: `run_id`, scheduler lease and idempotency key, actual PID/session reference (if available), machine/worktree ID, starting Git HEAD, auth preflight result (sanitized), selected actual model config, heartbeat/event watermark, exit result, log/artifact digests, resulting commit SHA, test receipts and execution-grade proof. Never persist provider secrets, source data or respondent records in SQLite/logs.

State machine: `DRAFT → AUTHORIZED → QUEUED → STARTING → RUNNING → RETURN_PENDING_VERIFICATION → VERIFIED_RETURN → HQ_INTAKE → REVIEW_REQUIRED → REVIEW_RUNNING → REVIEW_RETURN → HQ_ADJUDICATION → ACCEPTED_SCOPED|REVISION_REQUIRED|BLOCKED|REJECTED`. Additional `PAUSED_QUOTA`, `NEEDS_RECOVERY`, `ESCALATED_HUMAN`, `CANCELLED`, `ORPHANED_UNKNOWN` states. No implicit transition from `TEST_PASS` to `ACCEPTED`, no promotion from `SOURCEFREE` to original35, no authority via optimistic fallback.

Dispatch is transactionally idempotent: reserve a unique commission/run key, then create a worker session/worktree once; reconcile process and Git evidence after crash before retry. Controller may observe and reconcile older worktrees but must never reset, terminate or restart unknown running sessions merely because a remote ref has not advanced. Queue deliveries are at-least-once; state transition and external-effect deduplication must make them *effectively once*.

### 2.3 Git and independent hostile review

- Every sourcefree implementation worker uses a distinct bounded worktree from exact authorized startup. Check no collision in changed paths, no uncommitted prior content and no existing sessions with the same assignment. Only allowed writing, no shared mutable worktree across agents.
- Independent reviewer runs in a fresh session/context, separate worktree and role/account when independence law requires it. The immutable candidate SHA and frozen scientific/product oracle are review targets; author logs are evidence to interrogate, not a trusted verdict. Reviewer cannot edit the author branch or replace the frozen expected result.
- Hostile-review tests include fault-injected false positives, replacement/preimage/source-hash attack, stale state/cold reopen, same-consumer severance RED/restored PASS, actor/source permission laundering, and contradiction between claim and executed receipt, *as applicable to that commission*. Freeze exact target and expected conditions before review. A review finding is not automatic law; qualified HQ/owner adjudicates.
- Use CAS updates for branch refs and monotone immutable provenance. Protect `main`, current PRE-MAIN control, original sources, scientific authority files, adopted policies and existing worktrees according to current rules. No forced update; acceptance may require separately authorized integration.

### 2.4 HQ continuation and quality of reasoning

On material worker completion: reconcile exact run → verify return and claim-carrying evidence → awaken only the correct existing HQ → provide a compact delta, exact refs and failures → HQ produces `FINDING → INTERPRETATION → ACTION → OWNER` and a revised *whole terminal* flight board → policy-check and enqueue new authorized actions → continue.

HQ must keep noncolliding parallel eligible campaigns running rather than waiting for a single worker/repair. Recompute terminal consumed function for each tranche; preserve Pyat original35 F1–F8/N11 state and Sorok actual admitted-person C0–C12/A0–A5. A single LiTS sourcefree canary or passing reviewer is not universal machine completion; a fluent character demonstration is not enacted actor/scientific authority.

Reviewer independence is a typed constraint, not a prompt adjective. A reviewer must not be the author, expected-result issuer, prior poisoned-context consumer, or owner who is supposed to be independent. Provenance failure escalates; it cannot be waived by self-reported model confidence.

Security: least-privilege file/network tools, secrets in native credential store/env with access restrictions, sanitized passports, no raw respondent source on an unapproved runner, no sending private repository or source data to new providers automatically, path allowlisting, log redaction, manual emergency stop. **Never run unknown untrusted source files as an automation prerequisite.**
