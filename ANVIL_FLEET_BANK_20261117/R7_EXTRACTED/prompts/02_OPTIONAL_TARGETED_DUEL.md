# ANVIL R7 — OPTIONAL targeted adversarial research

**DO NOT DISPATCH AS A DEFAULT.** Use only when H0/architect has named a genuinely consequential unresolved technical or scientific question whose independent analysis could change the decision.

**Both peers receive the EXACT SAME entire frozen common frame, exact source and engineering code references, downstream SEAM/FF/SOROK constraints, historical DDM/K3 evidence, performance/resource/rights boundaries and first-consumer contract.** Both investigate the SAME narrowly specified question and independently reason through its evidence and alternatives. They may reach opposed conclusions, but must not be assigned different halves of the evidence or the project. No one is 'incumbent-only' or 'downstream-only'.

A duel must specify: exact question; reason an independent parallel analysis helps; identical common frame SHA and shared evidence; each separate source/technical argument with falsifiers; one subsequent adjudication incorporating both into the single architecture decision. This is NOT an instruction to build two complete C11 backends or create rival PROGRAMMA records. A full parallel runnable prototype requires separate proof that an analytical decision is impossible and a bounded physical falsifier is necessary.

If a peer identifies a requirement absent from the common frame, the issue returns to the frame owner for shared reconsideration **before** selecting an architecture. If the issue is already analytically settled, do not duel; document the reasoning and advance. Use `r7_integrated.py DECISION` with `basis=TARGETED_DUEL` only for an actually used duel packet. A local check cannot authenticate the analysts' independence or scientific competence.
